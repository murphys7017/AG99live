# 动作小模型训练前置条件与职责边界

本文定义动作小模型进入训练前必须稳定的系统边界。当前项目仍由主模型在同一次 Persona 回复中
生成文本与 `ag99live.motion`；小模型尚未接入正式运行链路，训练输入输出也不在本阶段冻结。

## 1. 当前结论

现在不应先决定小模型固定输出 `axis_levels`、时长、曲线或完整表演计划。Performance Director 和统一
`PerformanceSchedule` 的源码边界已经收口，但编排质量评价标准与可用数据仍未稳定时，
提前冻结训练目标只会把临时规则固化成新的重复所有者。

小模型只能在以下三种候选职责中选择一个主要所有权：

1. 根据文本与有限上下文生成语义动作意图。
2. 根据已确定的语义动作与表达上下文生成表演编排提示。
3. 在证据充分时一次生成两者，但输出仍必须经过 ModelEngine 严格编译。

无论最终选择哪一种，小模型都不能直接生成 Live2D 参数、逐帧数组、Physics 输出或播放时钟。

## 2. 训练前置条件

开始正式微调前必须具备：

- Performance Director 的输入、输出与诊断结构已经稳定。
- Motion Lab 能记录语义输入、编排结果、参数计划和真实播放终态。
- 人工能够区分问题来自主模型、Profile、Director、主动动力学还是 Cubism Physics。
- 已形成可重复的认可、拒绝和问题分类标准。
- VTS 原始录制与 Motion Lab 对话数据均可追溯，但保持独立存储和独立用途。
- 训练、验证和测试按对话或脚本组隔离，避免相邻动作或改写文本泄漏。

在这些条件满足前，录制数据用于标定、观察和评价，不直接宣称为可训练监督数据。

## 3. 输入边界

未来训练输入应只包含完成当前决策所需的信息：

- 当前用户文本。
- 当前助手 canonical text。
- 理解语气所需的有限对话上下文。
- 必要且稳定的角色或模型能力摘要。
- 如果职责是编排，还可包含已经确定的语义动作和可用时长事实。

数据库主键、时间戳、take ID、模型文件路径、schema version、运行日志和调试诊断不进入训练输入。

## 4. 输出边界

最终输出字段必须由真实评价数据反推，而不是从当前规则实现直接复制。稳定前只保留以下原则：

- 语义动作输出使用模型无关语义，不暴露 Live2D 参数 ID。
- 表演编排输出表达离散事件或有界提示，不输出逐帧参数数组。
- 播放总时长、音频 `currentTime` 和 sink 生命周期仍由 PlaybackTimeline 所有。
- 参数绑定、范围约束、关系图和参数计划仍由 ModelEngine 所有。
- 主动参数融合仍由 ActiveParameterMixer 所有。
- 头发、衣服和饰品等被动响应仍由 Cubism Physics 所有。
- 非法输出显式失败，不以默认动作或旧规则补全。

## 5. 数据来源

### 5.1 Motion Lab

Motion Lab 提供真实对话中的文本、主模型语义动作、编排结果、参数计划、播放终态和人工评价。
它适合训练或评估“文本到语义动作”以及“语义动作到表演编排”的决策质量。

### 5.2 VTube Studio 录制器

独立 VTS 录制器保存 tracking input 与 Live2D 参数时间序列，用于：

- 校准语义轴方向、九级锚点和模型可见范围。
- 观察动作起势、保持、回收和 Physics 响应。
- 建立人工表演参考和模型级调校依据。

纯 VTS 参数录制没有真实对话语义，不能直接成为文本到动作的监督样本。后续补充的标注和导出仍需
经过独立审核，不与 Motion Lab 数据库合并。

## 6. 决策门槛

只有在以下问题都有实证答案后，才冻结第一版训练契约：

1. 小模型替代的是主模型的语义动作职责，还是 Director 的编排职责。
2. 哪些字段能稳定提升实际回放质量，而不是复刻当前临时规则。
3. 同一文本的多种合理表演如何表示，避免把方向随机性当作标签冲突。
4. 如何评价长句、多 phrase、停顿、转折、句尾残留和动作多样性。
5. 推理延迟如何与 Persona、TTS 和原子输出段生命周期协调。

在此之前，项目继续使用主模型生成文本和动作，并优先完善表演编排与数据评价闭环。
