# AG99live 动作协议与训练数据链路

> 状态：破坏性统一已落地；运行时与训练导出都以 `motion_steps[].axis_values` 为动作主形态
> 范围：`engine.motion_intent.v4`、Provider 生成、Motion Lab 历史数据、训练数据转换
> 原则：运行时不兼容旧动作形态；历史数据只在离线训练导出时转换

## 1. 统一结论

AG99live 的参数动作统一表示为连续姿态组：

```json
{
  "motion_steps": [
    {
      "axis_values": {"head_yaw": 66.0, "head_roll": 65.0},
      "duration_weight": 1
    }
  ],
  "duration_hint_ms": 1200
}
```

- `motion_steps` 长度固定在 1–4；只有一个稳定姿态也使用 1 个 step。
- 每个 step 只使用 `axis_values` 和 `duration_weight`。
- `axis_values` 是对应语义轴 `value_range` 内的具体数值，可以是小数；`neutral` 是中性基线。
- 不再接受根级 `axis_levels` 或根级 `axis_values`。旧的 `motion_steps[].axis_levels` 也不再进入运行时。
- `motion_resource_id` 仍是完整动作资源的独立执行路径；训练输出不使用资源路径，统一训练为参数动作序列。

## 2. 运行时协议

Provider 的参数动作字段只有 `motion_steps`。Adapter 在校验后补入 `schema_version`、`profile_id`、`profile_revision`、`model_id`、`emotion_label` 等运行时元数据；Provider 可以选择输出 `intent_tags`、`duration_hint_ms` 和资源字段，但参数动作必须是 `motion_steps`。

每个轴的合法范围来自当前 Semantic Axis Profile：

| 字段 | 含义 |
| --- | --- |
| `value_range` | 轴的硬边界 |
| `neutral` | 轴的语义中性值 |
| `parameter_bindings[].output_range` | 语义轴值到渲染参数的映射 |
| `soft_range` / `strong_range` / `extreme_range` | 强度参考和校验信息 |

校验规则：

1. `motion_steps` 必须是 1–4 个非空 step。
2. 每个 step 必须恰好包含 `axis_values`、`duration_weight`；`duration_weight` 为 1–3 的整数。
3. 轴值必须是有限数字，不能是布尔、字符串、`NaN` 或 `Infinity`。
4. 轴 ID 必须属于当前 Profile 的 prompt 轴；数值必须落在该轴 `value_range` 内。
5. 参数动作与资源动作、表达式资源之间的组合冲突会直接失败。

关键实现：

| 层 | 文件 | 作用 |
| --- | --- | --- |
| 后端归一化 | `astrbot_plugin_ag99live_adapter/motion/motion_intent.py` | 只接受 `motion_steps` 的连续数值步 |
| 后端校验 | `astrbot_plugin_ag99live_adapter/motion/payload_validation.py` | 校验轴 ID、数值范围和资源冲突 |
| Provider Prompt | `astrbot_plugin_ag99live_adapter/middleware/interaction_motion/independent.py` | 强制单姿态也输出 1 步，连续动作输出 2–4 步 |
| 参考投影 | `astrbot_plugin_ag99live_adapter/middleware/interaction_motion/prompt_references.py` | 示例和最近动作统一投影为 `motion_steps[].axis_values` |
| 录制与曲线 | `runtime/motion_observation_recorder.py`、`motion/performance_curve.py` | 只记录连续数值形态 |
| 前端 ModelEngine | `frontend/src/model-engine/normalize.ts`、`compiler/` | 解析并编译 1–4 个连续数值 step |

## 3. 训练输入输出协议

当前运行时和训练导出的动作主形态都是 `motion_steps[].axis_values`。`axis_levels` 只作为历史数据迁移来源保留，不能作为当前 Provider 输出或运行时输入。

训练数据不复用运行时的长系统 Prompt，也不把运行时内部状态当作模型输入。导出脚本为每条历史样本生成新的简化 system prompt，并保留有界纯文本历史上下文。

训练输入的当前轮只保留：

```json
{
  "user": "当前用户输入",
  "segment": {
    "speech": "当前 Persona 片段文本",
    "actions": [],
    "tendency": {}
  }
}
```

训练输入明确去掉：

- `motion_guidance`
- `neurobrain_state`
- 图片、工具消息、运行标识和 Provider 元数据

训练 assistant 输出严格为两个字段：

```json
{
  "motion_steps": [
    {"axis_values": {"head_yaw": 66.0}, "duration_weight": 1}
  ],
  "duration_hint_ms": 1200
}
```

`motion_steps` 必须有 1–4 步，`duration_hint_ms` 必须存在且为 320–15000 的整数。训练目标不带 `intent_tags`、资源 ID、schema 身份字段或其他运行时字段。

## 4. 历史数据转换

当前 Motion Lab 数据库（2026-11-08 读取）包含 601 个合并样本：

- `independent_motion / M2_olv_incremental / closed`：529
- `independent_motion / M0_nonstreaming / closed`：52
- 目标形态：`axis_levels` 469、`motion_steps` 112、无目标 20
- 质量：reviewable 16、blocked 585
- 大多数 blocked 样本只带 `neurobrain_state_present`；新训练导出会去掉该输入字段，但保留这批样本

`experiments/spark-x26-action-sft/prepare_dataset.py` 的转换规则：

1. 根级 `axis_levels` 转为一个 `motion_steps` step。
2. 旧 `motion_steps[].axis_levels` 逐步转为 `motion_steps[].axis_values`，保留步骤顺序和 `duration_weight`。
3. 已有连续值直接校验并保留；所有目标都必须有合法 `duration_hint_ms`。
4. 历史 Prompt 没有 `value_range` 时，使用当前轴的默认 `[0,100]` / `neutral=50`；若 Prompt 带有轴范围或锚点，优先使用记录值。
5. `motion_resource_id` 目标不进入参数动作训练集，避免把资源选择混入连续值学习。
6. `segment.speech` 为空时，优先从同一条 Motion Lab 的 `persona_segment.speech` 回填；两处都为空才剔除。

当前数据库的严格转换实测结果：

```text
samples: 530
source_motion_shapes: axis_levels=426, motion_steps=104
conversion_statuses: converted_legacy=530
training output: motion_steps + duration_hint_ms
```

输出目录默认为 `experiments/spark-x26-action-sft/data/continuous/`，数据文件为 `continuous_sft.jsonl`，数据集名为 `spark_x26_continuous`。

## 6. VTS 数据的后续用途

VTS 录制数据仍可用于补充连续值分布：按约 500 ms 停顿切句，从对应时间窗聚合真实参数，再通过 `parameter_bindings` 映射到语义轴 `value_range`。这条数据链路直接生成连续 `axis_values`，不再经过等级量化。

目前录制数据的限制仍然存在：take 为 `interrupted`、只有累计 partial 转写、没有人工标注，且唇形和身体参数覆盖不完整。接入训练前应先做文本清洗、时间窗抽检和语义一致性复核。
