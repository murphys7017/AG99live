# 动作决策小模型目标与数据需求初稿

> 文档状态：目标定义初稿。本文先确定小模型在运行时负责的唯一任务，再从目标反推数据需求。
> VTube Studio 连接、数据库表结构、录制器实现和训练框架不在本稿中定案。

## 1. 目标

训练一个面向当前固定角色的轻量动作决策模型。在助手最终回复文本已经确定后，模型根据当前
回复和有限对话上下文，为一个 `output.segment.v3` 选择一条语义动作指令：

```text
当前用户文本
+ 最近有限对话上下文
+ 当前助手最终回复文本
-> axis_levels
+ duration_hint_ms
+ curve
```

模型只决定“做什么语义动作、动作意图持续多久、采用哪种表演节奏”。它不生成连续
Live2D 参数，不替代 ModelEngine、PlaybackTimeline、语音随动或 Live2D WebSDK。

## 2. 第一版输出边界

第一版每个输出段只生成一个稀疏语义姿态及其时长提示和曲线类别：

```json
{
  "axis_levels": {
    "head_roll": 2,
    "body_roll": 1,
    "mouth_smile": 3
  },
  "duration_hint_ms": 1300,
  "curve": "quick_in_hold_soft_out"
}
```

### 2.1 `axis_levels`

- 取值必须是当前语义轴档案允许的 `-4..4` 整数等级。
- 只允许输出当前档案中暴露给模型的 `primary` 和 `hint` 轴。
- 使用稀疏对象：省略某轴表示本轮不控制该轴，`0` 表示明确回到中性。
- `derived`、`runtime`、`ambient` 和 `debug` 轴不属于模型输出。
- 第一版不输出 `motion_steps`；需要多段姿态变化的长动作暂不进入第一版训练集。

实际可训练轴集合必须在连接 VTube Studio 前，从当前固定模型的
`SemanticAxisProfile` 中读取并冻结，不能直接使用通用轴列表代替。

### 2.2 `duration_hint_ms`

- 表示模型希望语义动作保持的意图时长，不是最终播放时钟事实。
- 取值沿用当前动作协议边界：`320..15000` 毫秒。
- 最终 timing 仍由 ModelEngine 结合真实 segment clock 和音频时长求解。
- 数据库内部保留原始动作起止时间；训练导出可以按后续实验确定的步长量化。

### 2.3 `curve`

模型只选择一个曲线类别：

```text
default
quick_in_hold_soft_out
slow_in_hold_quick_out
pulse_then_settle
soft_breathe
```

模型不输出 `entry`、`hold`、`exit`、`emphasis` 或 `energy`。接入层负责把 `curve`
映射为现有运行时需要的完整 `performance_curve_hint`，ModelEngine 再根据真实 Timeline
求解进入、保持和退出时长。

## 3. 第一版输入边界

训练样本输入使用角色明确的文本消息：

```json
{
  "context": [
    {
      "role": "user",
      "content": "你今天心情怎么样？"
    },
    {
      "role": "assistant",
      "content": "当然很好啦，看到你就更开心了。"
    }
  ]
}
```

约束：

- 当前助手最终可见回复是必需输入，因为动作将伴随这段回复播放。
- 当前用户文本是必需输入，用于解释回复在本轮语境中的含义。
- 最近历史只保留理解语气所需的有限轮次；具体窗口在数据试验后确定。
- 固定角色设定不逐条重复写入样本。
- 数据库 ID、时间戳、来源、模型 ID、profile ID 和 schema version 不进入训练输入。
- `intent_tags` 和单独的 intent text 不作为第一版输入或输出。

纯 VTube Studio 参数录制可以没有文本，但它只能用于轴、等级、时长和曲线标定，不能直接
成为“文本到动作”的监督微调样本。

## 4. 非目标

第一版小模型不负责：

- 生成或改写助手回复。
- 输出 VTube Studio 参数名、Live2D 参数值或逐帧时间序列。
- 输出 `motion_steps`、motion3、exp3、Catalog motion 或资源 ID。
- 输出完整 `performance_curve_hint`。
- 预测嘴型、呼吸、物理、头发、衣服和附件运动。
- 决定最终音频时长、播放时钟或 Timeline 生命周期。
- 绕过现有 `engine.motion_intent.v4 -> ModelEngine -> engine.parameter_plan.v3` 链路。

## 5. 运行时位置

目标接入流程是：

```text
助手 canonical text 与有限上下文就绪
-> 动作决策小模型
-> 严格校验 axis_levels / duration_hint_ms / curve
-> 接入层补充运行时协议字段并展开 curve
-> engine.motion_intent.v4
-> ModelEngine
-> engine.parameter_plan.v3
-> Live2D WebSDK
```

当前 `engine.motion_intent.v4` 仍要求非空 `intent_tags`，而第一版小模型不输出该字段。
接入时是由 Adapter 生成内部值，还是调整正式协议约束，需要在实现方案中单独决定；该问题
不应通过向训练样本加入无意义标签来规避。

## 6. 成功标准

### 6.1 结构正确性

- 输出始终能被严格 JSON 解析。
- 不出现未知字段、未知轴、非法等级或未知曲线。
- 省略轴和显式 `0` 的语义稳定。

### 6.2 动作质量

- 动作与当前助手回复以及用户语境一致。
- 中性回复能保持克制，不把每句话都变成强表演。
- 强度等级、持续时间和曲线选择在实际回放中可区分。
- 同一语义在不同上下文下可以产生合理差异。
- 左右方向等非文本决定因素不会成为互相矛盾的训练噪声。

### 6.3 系统边界

- 小模型输出继续经过现有 ModelEngine 和 Timeline。
- 小模型失败不会产生非法参数计划或绕过协议校验。
- 推理延迟满足当前原子输出与 TTS 生命周期的接入要求。

### 6.4 数据可用性

- 每条训练标签都能追溯到原始参数记录或人工审核结果。
- 修改参数到语义等级的推导算法后，可以从数据库重新生成标签。
- 训练、验证和测试按对话或脚本组隔离，避免改写文本泄漏。

## 7. 从目标反推的数据

目标确定后，数据分为三层。

### 7.1 VTube Studio 标定数据

用途是建立原始参数与语义标签的关系，可以暂时不带文本：

- 中性基线。
- 每个目标语义轴的正负方向。
- 每个轴的弱、中、强和极强幅度。
- 常用头、身、视线和表情组合。
- 动作进入、稳定保持和回收阶段。
- 五种曲线类别的可辨识表演。
- 同一动作的重复录制，用于测量操作者和追踪噪声。

### 7.2 文本配对监督数据

这是实际微调数据，每条必须具备：

- 当前用户文本。
- 当前助手 canonical text。
- 必要的有限历史上下文。
- 审核后的 `axis_levels`。
- 审核后的 `duration_hint_ms`。
- 审核后的单一 `curve`。
- 数据库内部可追溯的原始参数时间序列和审核状态。

### 7.3 独立评测数据

评测集需要专门覆盖：

- 中性和无明显动作回复。
- 开心、安抚、疑惑、调侃、惊讶、严肃、低落和害羞等常见语境。
- 短回应、长解释和多句回复。
- 相似文本在不同上下文中的动作差异。
- 同一语义的不同措辞。
- 左右方向、强弱等级、持续时间和曲线的边界案例。

## 8. 第一轮 VTS 验证目标

第一轮连接 VTube Studio 不以批量生产训练集为目标，只验证：

1. 能稳定取得目标参数及采样时间。
2. 中性基线和正负动作方向可以重复识别。
3. 原始参数能投影到当前 `SemanticAxisProfile` 的九级锚点。
4. 能从录制中识别动作起点、稳定段和回收终点。
5. 同一动作重复录制时，推导等级和时长不会剧烈漂移。
6. 五种曲线中至少能稳定区分具有明显差异的类别。
7. 原始数据写入数据库后能够查询、回放、重新推导和删除。

只有这轮验证通过，才开始录制带文本上下文的正式监督数据。

## 9. 尚待确认

- 当前固定模型最终纳入训练的 `primary/hint` 轴清单。
- 最近对话上下文保留几轮以及最大文本长度。
- `duration_hint_ms` 的训练量化步长。
- 空动作是使用空 `axis_levels`，还是使用显式中性轴集合。
- 左右方向没有明确文本依据时的统一标注策略。
- 当前 v4 协议中内部 `intent_tags` 的接入处理。
- 第一版是否将曲线和语义动作交给同一个小模型一次输出。

这些问题确认后，再形成 VTube Studio 参数订阅清单、录制动作表、数据库写入方案和第一轮
验证用例。
