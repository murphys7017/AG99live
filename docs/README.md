当前阶段快照只保留到这一层：一期功能范围已完成；二期阶段 A 已完成，阶段 B 的 B1-B7 已完成源码收口，
包括共享部位轨道、face 生命周期、hesitation、dynamic residual、speech cues 与语音耦合、主动动力学、
说话随动和相邻音频段 Direct Plan 接管。当前剩余主要是真实观感验收，以及阶段 C/D/E 的后续能力。
动作输出契约与序列结构已在 AG99 源码侧统一：`motion_steps` 使用稀疏轨道语义，并在首次声明时激活对应参数轨道；AstrBot 的 Prompt/Persona 配合与真实链路验收仍单列在
[动作输出契约与序列结构统一方案](./02-设计文档/22-动作输出契约与序列结构统一方案.md)。更细的待修问题和后续优先级不在索引页重复维护。

播放完成需要联合判断两类事实：SessionStore 保存协议槽位和稳定投影，
PlaybackTimeline 保存 required sink 的实时执行状态。即使 text/audio/motion 槽位已经
settled，只要同一 Turn 仍存在开放的 required execution Timeline，就不能启动下一段，
也不能发送 `control.playback_finished`。

## 维护原则

- 文档只描述当前唯一设计和明确的产品边界。
- 已删除的协议、阶段性修复过程和测试结果不进入长期文档。
- 代码与文档冲突时，先沿真实调用链确认产品意图，再同步改正两者。
- 自动 smoke 只验证基础边界；实时 Electron 对话链路才是动作、音频和口型的最终验收。
- 流程图只维护 `.mmd` 源文件，不提交 PNG、SVG 或 PDF 副本。
- 当前桌宠传输只支持同机 `127.0.0.1` / `localhost`。远程 AstrBot 需要单独设计带认证的
  WSS/HTTPS 协议，不能通过放宽现有 `host` 配置实现。
