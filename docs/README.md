# AG99live 文档中心

AG99 是以桌面体验为中心的智能体主应用；AG99live 是 AG99 的身体运行时，负责感知、即时反应、Live2D 表现、音频播放和设备交互。AstrBot 是 AG99 的上游框架与兼容生态来源。

本文档集描述当前源码和运行边界，不保留已完成实施批次、历史问题清单或平行路线图。相关设计文档最后一次整理：**2026 年 10 月 8 日**。

## 文档权威

| 事实 | 唯一来源 | 文档应做什么 |
| --- | --- | --- |
| 协议版本 | `astrbot_plugin_ag99live_adapter/protocol/schema_manifest.json` | 以 manifest 和生成类型为准；协议文档只解释 Schema 职责和使用边界。 |
| 前端协议类型 | `frontend/src/types/protocol.ts` 与生成文件 | 描述解析和使用边界。 |
| Adapter 生命周期 | `astrbot_plugin_ag99live_adapter/` | 描述 AG99 输入、段聚合、服务和清理。 |
| 前端播放和动作执行 | `frontend/src/` | 描述组合根、所有权与终态。 |
| 第三方 Cubism 行为 | `frontend/src/live2d/WebSDK/Framework/` 与 `Core/` | 只引用其公开职责；不修改随附上游文档。 |
| VTube Studio 能力 | 官方 API 与 `vts-data-recorder/` 实现 | 记录本项目实际读取和保存的事实。 |

## 维护规则

1. 修改协议 Schema 时，先更新 manifest 和生成类型，再同步 [协议契约](01-架构与结构/02-WebSocket协议契约.md)。
2. 修改所有权、时钟或终态时，同步播放设计和端到端时序；不要另建“修复记录”文档。
3. 修改动作输入、编译或 profile 时，同步动作语义与 ModelEngine 文档。
4. 将真实运行才能确认的结论写入[当前状态与验收边界](01-架构与结构/06-当前状态与验收边界.md)，避免用静态检查代替运行证据。
5. `README.md`、`frontend/README.md`、插件 README 和录制器 README 只保留各自读者需要的入口信息，并链接到这里的深入说明。
6. Mermaid 图源只作可视化补充；版本、边界和行为结论以本文档集链接的正文与源码为准。
