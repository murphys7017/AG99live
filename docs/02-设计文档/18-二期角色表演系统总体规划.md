# 二期角色表演系统总体规划

本文定义 AG99live 二期的总体产品方向。二期不再以逐项扩大动作范围或修复单个参数表现为主线，
而是把一期已经打通的动作链路组织成能够完成整段表达的角色表演系统。

产品阶段边界以 [一期完成边界与二期入口](../01-架构与结构/06-一期完成边界与二期入口.md) 为准。
当前源码事实与第一批迁移边界见：

- [角色表演主流程与编排职责审计](./19-角色表演主流程与编排职责审计.md)

## 1. 二期目标

一期解决的是：

> 一条消息能够可靠地生成文本、语音和动作，并通过同一时间线驱动 Live2D。

二期解决的是：

> 文本、语音、语义动作、说话手势、视线、表情和 Physics 能否共同组成一段有节奏、
> 有层次、可解释并具有角色感的表演。

二期的评价对象不再是某个轴是否移动，而是一次完整回复是否具备合理的准备、起势、表达、
停顿、强调、收势和残留。

## 2. 总体结构

```text
主模型语义动作 axis_levels / motion_steps
+ canonical assistant text
+ 已解析音频时长与文本 phrase / 标点结构
+ 当前模型 SemanticAxisProfile
+ 可选的最近动作多样性摘要
                 ↓
Performance Director（整段表演编排）
                 ↓
统一参数时间轨道图
                 ↓
ParameterPresentation（主动参数动力学）
                 ↓
ActiveParameterMixer（逐帧贡献融合）
+ SpeechSignalRuntime（执行期实时能量调制）
                 ↓
Live2D WebSDK + Cubism Physics
```

`Performance Director` 是 ModelEngine 内的编排职责，不是新的后端服务、播放器、运行时时钟或
参数融合器。第一版应优先整理现有编译阶段的所有权，不以新增庞大框架为目标。

## 3. Performance Director 的职责

Performance Director 负责把一次回复组织成完整的表演结构：

```text
准备姿态
-> 开口
-> 语义动作展开
-> 停顿与重音手势
-> 视线和面部细节响应
-> 句尾收势
-> 表情残留或回到当前 Cubism base
```

它负责：

- 读取主模型已经给出的语义方向和强度，不重新判断回复情绪。
- 根据文本 phrase、标点结构和音频时长安排语义步骤的时间位置。
- 编排头、身体、视线和面部的启动顺序、延迟、保持、反转停顿与释放。
- 使用最近动作的紧凑摘要降低连续点头或重复同一动作族的概率。
- 输出统一参数时间轨道，交给现有 ParameterPresentation 和 ActiveParameterMixer。
- 保留每个决策的来源，供 Motion Lab 解释和回放。

它不负责：

- 生成回复文本、调用 TTS 或维护对话队列。
- 修改主模型已经确定的核心语义方向。
- 直接输出逐帧 Live2D 参数数组。
- 创建第二套 Timeline、播放器或参数写入路径。
- 手工驱动头发、衣服和饰品等 Physics 输出参数。
- 在编译期读取或预测实时 RMS；实时能量只由 SpeechSignalRuntime 在执行期有界调制。
- 用默认动作、随机动作或兼容分支掩盖正式动作失败。

## 4. 三条建设主线

### 4.1 表演编排

这是二期的核心主线。现有 sequence、SpeechPose、参数时间轨道、gaze、face、hesitation、
release 和 residual 都应成为同一个编排过程的组成部分，而不是继续独立增长。

目标是让不同句型形成不同的表演结构，而不只是获得更大的动作幅度：

- 短句快速起势并自然收回。
- 长句在多个 phrase 之间调整重心和视线。
- 疑问句在句尾保留有限歪头或视线停留。
- 转折前允许短暂停顿，再改变姿态方向。
- 强调位置使用短促动作，不把整段音量直接映射为左右方向。
- 回复结束后允许有限表情残留，再释放到当前 Cubism base。

### 4.2 数据与评价闭环

Motion Lab 不只是历史查看器，而应成为表演质量的评价入口：

```text
真实对话
-> 保存语义输入、编排结果、参数计划和播放终态
-> 人工观看并标记问题或认可样本
-> 对比 Prompt、Profile、Director 和 Physics 阶段
-> 调整规则并积累训练数据
```

在形成稳定评价标准前，不急于训练动作小模型。小模型应学习经过人工筛选的表演决策，
而不是复制仍在变化的临时规则。

### 4.3 产品化与部署

安装更新、AstrBot 配套版本、跨主机认证、OBS 兼容、运行诊断和正式发布体验可以独立推进，
但不能改变表演主链路的所有权，也不应阻塞表演编排与数据闭环。

## 5. 分阶段实施

### 阶段 A：收口表演编排输入与输出（已完成）

- 列出现有 ModelEngine 中所有参与整段表演的输入、阶段和输出。
- 确认 semantic sequence、SpeechPose 和 parameter track graph 的唯一所有权。
- 定义 Performance Director 的内部输入输出契约和诊断信息。
- 统一文本 phrase 与 sequence step 的时间分配，并记录可解释的 estimated alignment。
- 让部位事件、hold、release 和 residual 消费同一份 Schedule。
- 优先迁移和删除重复职责，不新增并行编排路径。

完成标准：同一段表演的 phrase、sequence step 和部位时间结构只由一个编译过程产生，现有播放器和协议保持不变。V4 没有 phrase identity 时只记录近似对应，不伪造精确语义绑定。

当前实现中，`PerformanceSchedule` 已统一保存 phrase、sequence step、semantic-group transition、SpeechPose
start / phrase / release 事件，以及事件到最终 keyframe 或 speech modulation 节点的来源映射。Track Graph
和 SpeechPose 都只消费该 Schedule 的时间结果；前者投影 keyframe，后者只决定 channel、preset、方向和幅度。
`engine.motion_intent.v4`、`engine.parameter_plan.v3`、Timeline、Mixer、WebSDK 与 Cubism Physics 均未改变。

### 阶段 B：补齐部位级表演策略

- gaze 的提前看向、短暂停留、转移和回收策略（第一批已完成）。
- face 的进入、保持、残留和释放策略。
- hesitation 的保持、停顿、反转或继续等编排事件。
- 根据句型、语义转折和表演事件决定 residual，不再只使用 semantic group 固定常数。
- 评估 sequence 是否需要稀疏取得、保持和释放轴控制权；没有真实样本前不扩展外部协议。
- 头先动、身体后跟、视线短暂领先以及有限反向平衡。
- 句尾保持、表情残留和回到当前 base 的释放策略。

当前 gaze 第一批直接复用 `PerformanceSchedule` 和 `engine.parameter_plan.v3`：单姿态先以有限比例
起势，再进入完整视线目标；长句可在 phrase 边界进行一次同方向的小幅转移；sequence 的视线在对应
semantic step 前约 80ms 开始转移。`gaze_release` 只记录 Direct Plan 开始释放所有权的时刻，最终值仍由
现有 plan blend 混回当帧 Cubism base，不增加“先回 Profile neutral 再切回 Idle”的第二段回中。

四步 sequence 已占满 V3 的四个 keyframe 槽位时，优先保留主模型给出的四个语义目标；release 继续由
plan blend 完成，不为了额外回中点扩展协议或删除语义步骤。

完成标准：一次回复能够观察到结构化的部位协作，而不是只有头部点动；所有策略消费阶段 A 的 PerformanceSchedule，不创建部位私有时钟。

### 阶段 C：建立评价闭环

- Motion Lab sequence step 编辑与即时重编译预览。
- 最近动作族、主轴方向和 sequence 使用情况的紧凑摘要。
- 人工认可、问题分类和编排阶段诊断。
- 明确哪些数据可以进入 Prompt 参考，哪些只用于分析。

完成标准：动作质量问题能够定位到主模型、Profile、Director、动力学或 Physics，而不是只凭最终观感猜测。

### 阶段 D：Physics 与模型级表现调校

- 建立 Physics setting 的输入、粒子链、输出和响应诊断。
- 分别调校头发、衣服和饰品的速度、残留和倍率。
- 保持 Physics 由 Cubism 求解，不进入主动参数平滑和 Parameter Mixer。
- Physics diagnostics/profile 只描述模型被动响应能力，不成为 Performance Director 的逐帧控制接口。

完成标准：主动动作与被动物理具有合理速度差和惯性，而不是同步移动或全局放大。

### 阶段 E：数据驱动与动作小模型

- 为 VTS 原始录制数据补充语义标注、审核和训练导出。
- 从 Motion Lab 中筛选真实对话产生的高质量表演样本。
- 评估小模型负责语义动作、表演编排提示或两者之一，避免职责重叠。

训练前置条件与职责边界见
[动作小模型训练前置条件与职责边界](../05-小模型训练/01-动作小模型训练前置条件与职责边界.md)。

完成标准：训练目标、输入字段和输出所有权稳定后，再启动微调。

## 6. 下一步

阶段 A 已完成。下一批进入阶段 B，但不直接扩展 Physics 参数：

源码主流程、职责分散点与最小迁移边界已经记录在
[角色表演主流程与编排职责审计](./19-角色表演主流程与编排职责审计.md)。下一批应先实施：

1. gaze 第一批已完成；通过 Motion Lab 和真实 Live2D 播放观察 lead / dwell / transfer / release 是否自然。
2. 让 face 消费同一事件结构，增加表情进入、保持、残留和释放策略。
3. 在不创建私有时钟的前提下，增加 hesitation、方向反转和句尾 residual 的动力学策略。

Motion Lab 继续读取同一份编排诊断；Physics 保持独立模型调校阶段，不进入表演时间结构。

## 7. 实施纪律

- 先修改和迁移现有实现，只有缺少明确职责载体时才新增模块。
- 不改变一期稳定协议，除非真实数据证明现有协议无法表达必要语义。
- 每类事实只有一个所有者：语义方向属于主模型，表演时间结构属于 ModelEngine，逐帧融合属于
  ActiveParameterMixer，被动物理属于 Cubism Physics。
- 自动测试只做最基础边界检查；真实效果以 AstrBot、TTS、Electron 和 Live2D 联合运行观察为准。
- 发现错误时显式失败并记录阶段诊断，不增加 fallback 掩盖问题。
