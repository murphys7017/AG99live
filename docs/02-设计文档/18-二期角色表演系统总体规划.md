# 二期角色表演系统总体规划

本文定义 AG99live 二期的总体产品方向。二期不再以逐项扩大动作范围或修复单个参数表现为主线，
而是把一期已经打通的动作链路组织成能够完成整段表达的角色表演系统。

产品阶段边界以 [一期完成边界与二期入口](../01-架构与结构/06-一期完成边界与二期入口.md) 为准。
当前源码事实与第一批迁移边界见：

- [角色表演主流程与编排职责审计](./19-角色表演主流程与编排职责审计.md)
- [端到端链路已确认问题与修复边界](./20-端到端链路已确认问题与修复边界.md)

## 1. 二期目标

一期解决的是：

> 一条消息能够可靠地生成文本、语音和动作，并通过同一时间线驱动 Live2D。

二期解决的是：

> 文本、语音、语义动作、说话手势、视线、表情和 Physics 能否共同组成一段有节奏、
> 有层次、可解释并具有角色感的表演。

二期的评价对象不再是某个轴是否移动，而是一次完整回复是否具备合理的准备、起势、表达、
停顿、强调、收势和残留。

## 2. 总体结构

```text
主模型语义动作 axis_levels / motion_steps
+ canonical assistant text
+ provider-neutral speech cues（可选）
+ 已解析音频时长与文本 phrase / 标点结构
+ 当前模型 SemanticAxisProfile
+ 可选的最近动作多样性摘要
                 ↓
Performance Director（整段表演编排）
                 ↓
统一参数时间轨道图
                 ↓
ParameterPresentation（主动参数动力学）
                 ↓
AG99 Live2D Runtime / ActiveParameterMixer（逐帧贡献融合）
+ SpeechSignalRuntime（执行期实时能量调制）
                 ↓
AG99 Live2D Runtime
        ↓
Official Cubism Framework/Core + Physics
```

`Performance Director` 是 ModelEngine 内的编排职责，不是新的后端服务、播放器、运行时时钟或
参数融合器。参数融合由 AG99 Live2D Runtime 内的 `ActiveParameterMixer` 完成；官方 Cubism
`Framework` / `Core` 只负责底层模型、Physics 和绘制。第一版应优先整理现有编译阶段的所有权，
不以新增庞大框架为目标。

## 3. Performance Director 的职责

Performance Director 负责把一次回复组织成完整的表演结构：

```text
准备姿态
-> 开口
-> 语义动作展开
-> 停顿与重音手势
-> 视线和面部细节响应
-> 句尾收势
-> 表情残留或回到当前 Cubism base
```

它负责：

- 读取主模型已经给出的语义方向和强度，不重新判断回复情绪。
- 根据文本 phrase、标点结构和音频时长安排语义步骤的时间位置。
- 编排头、身体、视线和面部的启动顺序、延迟、保持、反转停顿与释放。
- 使用最近动作的紧凑摘要降低连续点头或重复同一动作族的概率。
- 输出统一参数时间轨道，交给 AG99 Live2D Runtime 的 ParameterPresentation 和 ActiveParameterMixer。
- 保留每个决策的来源，供 Motion Lab 解释和回放。

它不负责：

- 生成回复文本、调用 TTS 或维护对话队列。
- 修改主模型已经确定的核心语义方向。
- 直接输出逐帧 Live2D 参数数组。
- 创建第二套 Timeline、播放器或参数写入路径。
- 手工驱动头发、衣服和饰品等 Physics 输出参数。
- 在编译期读取或预测实时 RMS；实时能量只由 SpeechSignalRuntime 在执行期有界调制。
- 用默认动作、随机动作或兼容分支掩盖正式动作失败。

## 4. 三条建设主线

### 4.1 表演编排

这是二期的核心主线。现有 sequence、SpeechPose、参数时间轨道、gaze、face、hesitation、
release 和 residual 都应成为同一个编排过程的组成部分，而不是继续独立增长。

目标是让不同句型形成不同的表演结构，而不只是获得更大的动作幅度：

- 短句快速起势并自然收回。
- 长句在多个 phrase 之间调整重心和视线。
- 疑问句在句尾保留有限歪头或视线停留。
- 转折前允许短暂停顿，再改变姿态方向。
- 强调位置使用短促动作，不把整段音量直接映射为左右方向。
- 回复结束后允许有限表情残留，再释放到当前 Cubism base。

### 4.2 数据与评价闭环

Motion Lab 不只是历史查看器，而应成为表演质量的评价入口：

```text
真实对话
-> 保存语义输入、编排结果、参数计划和播放终态
-> 人工观看并标记问题或认可样本
-> 对比 Prompt、Profile、Director 和 Physics 阶段
-> 调整规则并积累训练数据
```

在形成稳定评价标准前，不急于训练动作小模型。小模型应学习经过人工筛选的表演决策，
而不是复制仍在变化的临时规则。

### 4.3 产品化与部署

安装更新、AstrBot 配套版本、跨主机认证、OBS 兼容、运行诊断和正式发布体验可以独立推进，
但不能改变表演主链路的所有权，也不应阻塞表演编排与数据闭环。

### 4.4 当前基础与剩余工作对照

当前瓶颈不是继续增加动作数量，而是让现有语义动作在时间、语音和运动质感上形成部位协作。
以下对照按当前源码校正，避免把已有能力重复规划成从零开发：

| 方向 | 当前已有基础 | 仍需完成 | 阶段 |
| --- | --- | --- | --- |
| face / hesitation | face 生命周期与 hesitation hold/resume 已通过共享 `PerformanceSchedule` 完成 | 结合真实运行继续观察停顿观感 | B |
| 主动动作动力学 | AG99 Runtime 的 ParameterPresentation 已支持 bounded / spring，参数轨道已有 transition / hold | 有限 anticipation、过冲和语义相关响应；必须由统一轨道表达，不在官方 Cubism SDK 或运行时临时增加第二套动作编排 | B |

| VTS / 动作小模型 | 独立录制器已提供发现、采样、SQLite 录制、查询和删除 | 语义标注、审核、训练导出，以及小模型唯一职责选择 | E |

后续若真实运行再次证明链路状态不可信，应先修复链路所有者，再继续调整动作常数。

## 5. 分阶段实施

### 阶段 A：收口表演编排输入与输出（已完成）

- 列出现有 ModelEngine 中所有参与整段表演的输入、阶段和输出。
- 确认 semantic sequence、SpeechPose 和 parameter track graph 的唯一所有权。
- 定义 Performance Director 的内部输入输出契约和诊断信息。
- 统一文本 phrase 与 sequence step 的时间分配，并记录可解释的 estimated alignment。
- 让部位事件、hold、release 和 residual 消费同一份 Schedule。
- 优先迁移和删除重复职责，不新增并行编排路径。

完成标准：同一段表演的 phrase、sequence step 和部位时间结构只由一个编译过程产生，现有播放器和协议保持不变。V4 没有 phrase identity 时只记录近似对应，不伪造精确语义绑定。

当前实现中，`PerformanceSchedule` 已统一保存 phrase、sequence step、semantic-group transition、SpeechPose
start / phrase / release 事件，以及事件到最终 keyframe 或 speech modulation 节点的来源映射。Track Graph
和 SpeechPose 都只消费该 Schedule 的时间结果；前者投影 keyframe，后者只决定 channel、preset、方向和幅度。
`engine.motion_intent.v4`、`engine.parameter_plan.v3`、Timeline、Mixer、WebSDK 与 Cubism Physics 均未改变。

### 阶段 B：补齐部位级表演策略

阶段 B 的源码缺口、内部事件模型、分批修改、删除边界、最小验证和回滚顺序统一见
[二期阶段 B 部位级表演策略实施计划](./21-二期阶段B部位级表演策略实施计划.md)。本节只保留总体阶段边界，不重复维护实施清单。

- gaze 的提前看向、短暂停留、转移和回收策略（第一批已完成）。
- semantic/gaze 已收口为共享的部位轨道 timing 结果、单 axis 缓存和单投影入口（B1 已完成）。
- face 的进入、保持、转换和释放策略（B2 已完成）。
- hesitation 的保持、停顿、反转或继续等编排事件（B3 已完成）。
- 根据句型、语义转折和表演事件决定 residual，不再只使用 semantic group 固定常数（B4 已完成）。
- 评估 sequence 是否需要稀疏取得、保持和释放轴控制权；没有真实样本前不扩展外部协议。
- 头先动、身体后跟、视线短暂领先以及有限反向平衡。
- 句尾保持、表情残留和回到当前 base 的释放策略。

当前 gaze 第一批直接复用 `PerformanceSchedule` 和 `engine.parameter_plan.v3`：单姿态先以有限比例
起势，再进入完整视线目标；长句可在 phrase 边界进行一次同方向的小幅转移；sequence 的视线在对应
semantic step 前约 80ms 开始转移。`gaze_release` 记录 sequence graph 最终确定的共享 Direct Plan
release 时刻，最终值仍由
现有 plan blend 混回当帧 Cubism base，不增加“先回 Profile neutral 再切回 Idle”的第二段回中。

四步 sequence 已占满 V3 的四个 keyframe 槽位时，优先保留主模型给出的四个语义目标；release 继续由
plan blend 完成，不为了额外回中点扩展协议或删除语义步骤。

face 生命周期同样直接复用共享 `PerformanceSchedule`。`eye / brow / mouth / face` 中实际进入 Direct Plan
且偏离中性值的轴会生成 `face_enter -> 可选 face_settle -> face_transfer -> face_release`。pose 先进入
68% 目标，再在 45ms 起始的有限过渡中稳定到完整表情；sequence 在每个后续 semantic step 开始后约
25ms 转换。四点预算不足时不生成 settle，首点直接使用完整的第一语义目标，因此不会删掉任何 LLM step。
`face_release` 与同一 plan 的全局 blend 起点对齐，不生成 neutral keyframe；`mouth_open` 仍由 runtime/lip-sync
所有，Expression 参数冲突仍由现有资源策略显式拒绝。

hesitation 同样只编译到共享 `PerformanceSchedule`。省略号、破折号、转折、连续软边界、犹豫类
intent tag 和 sequence 真实方向反转会形成候选窗口；编译器只选择一个最强合法窗口，生成
`hesitation_hold -> hesitation_resume` 诊断事件，并以同一绝对 hold 累计延后窗口后的 semantic、gaze、
face 与 SpeechPose 变化。窗口不足或 SpeechPose 无法在 release 前容纳完整停顿时明确编译失败，
不生成非法事件，也不降级为默认动作。

dynamic residual 同样只属于共享 Schedule。semantic、gaze 和 face 根据句尾、emphasis、hesitation、
最终 semantic transition 是否换向和合法尾部预算计算各自的最小占有需求；sequence graph 取最大值
确定 V3 唯一的全局 release 与 graph duration。sequence 可在合法预算内延长，单 pose 只在原有 release
前使用可容纳的 residual。内部 trace 为 `performance_schedule_trace.v6`，外部动作协议和运行时所有权保持不变。

#### B5-pre：Provider 无关的语音提示输入

B5-pre 位于 B4 之后、语音能量耦合之前。它不是新的播放器、Timeline、参数融合器或 TTS Provider
适配层，而是为现有 PerformanceSchedule 补充一类可选的上游表演提示：

当前进度：AstrBot 已完成 `speech_cues` 输出契约、统一规范化和结果后处理 Hook，并已删除旧的
MiniMax 文本标签注入链路；AG99 的跨进程传输字段和 PerformanceSchedule 映射尚未实施。

```text
AstrBot Prompt
  -> spoken_reply + speech_cues
  -> 结果校验与规范化
  -> canonical text / clean TTS text
  -> output segment 的语音提示事实
  -> PerformanceSchedule
```

第一版只允许少量 Provider 无关的标签，例如 `breath`、`sigh`、`laugh`、`chuckle`、`hesitate`
和 `emphasis`。标签描述表演倾向，不直接描述 Live2D 参数、精确时间或动作方向；`phrase_index`
等粗粒度定位只用于编排参考，真实时间仍由音频时钟确定。

B5-pre 的所有权边界如下：

- AstrBot 在模型请求前注入标签规则，在模型结果完成后校验并规范化 `speech_cues`。
- canonical text 继续用于字幕、聊天记录和普通 TTS 文本；语音标签不能污染这些文本。
- Adapter 或输出协议只传递结构化语音提示，不让 AG99 重新解析 Provider 语法，也不把提示塞进 motion payload。
- PerformanceSchedule 将提示映射到现有的 `hesitation`、`speech_phrase`、face 或 speech modulation
  事件，不创建新的时钟、Stage、播放器、Mixer source 或参数写入路径。
- `OnTTSStateChangedEvent` 继续只报告 TTS 生命周期，不承担文本转换或表演提示修改。

如果跨进程传递 `speech_cues` 需要扩展 `output.segment`，必须使用明确的语音字段和同步更新的协议契约；
不能通过未声明的 metadata、motion payload 或重新解析 TTS 文本来绕过协议。只有确认 AG99 需要消费该事实
后才进行协议版本变更，且作为独立批次提交。

B5-pre 完成后再进入 B5：将 `speech_cues` 与真实 RMS、voiced、attack/release 和 emphasis slope
结合。语音标签提供“发生了什么”的语义先验，音频提供“何时发生”的事实，两者共同调制部位活跃度，
但都不能取代主模型的语义动作方向。

完成标准：一次回复能够观察到结构化的部位协作，而不是只有头部点动；所有策略消费阶段 A 的 PerformanceSchedule，不创建部位私有时钟。

### 阶段 C：建立评价闭环

- Motion Lab sequence step 编辑与即时重编译预览。
- 最近动作族、主轴方向和 sequence 使用情况的紧凑摘要。
- 人工认可、问题分类和编排阶段诊断。
- 明确哪些数据可以进入 Prompt 参考，哪些只用于分析。

完成标准：动作质量问题能够定位到主模型、Profile、Director、动力学或 Physics，而不是只凭最终观感猜测。

### 阶段 D：Physics 与模型级表现调校

- 建立 Physics setting 的输入、粒子链、输出和响应诊断。
- 分别调校头发、衣服和饰品的速度、残留和倍率。
- 保持 Physics 由 Cubism 求解，不进入主动参数平滑和 Parameter Mixer。
- Physics diagnostics/profile 只描述模型被动响应能力，不成为 Performance Director 的逐帧控制接口。

完成标准：主动动作与被动物理具有合理速度差和惯性，而不是同步移动或全局放大。

### 阶段 E：数据驱动与动作小模型

- 为 VTS 原始录制数据补充语义标注、审核和训练导出。
- 从 Motion Lab 中筛选真实对话产生的高质量表演样本。
- 评估小模型负责语义动作、表演编排提示或两者之一，避免职责重叠。

训练前置条件与职责边界见
[动作小模型训练前置条件与职责边界](../05-小模型训练/01-动作小模型训练前置条件与职责边界.md)。

完成标准：训练目标、输入字段和输出所有权稳定后，再启动微调。

## 6. 最终目标架构

最终目标不是继续堆叠动作模块，而是让每类决策只有一个所有者：

```text
Persona / LLM
  -> engine.motion_intent.v4
  -> canonical text + optional speech_cues
  -> AstrBot / Adapter 语音提示规范化
  -> ModelEngine / Performance Director
       语义编译、语音事件编排、时间编排、参数轨道
  -> engine.parameter_plan.v3
  -> PlaybackTimeline
  -> AG99 Live2D Runtime
       ParameterPresentation
       SpeechSignalRuntime
       ActiveParameterMixer
       ResolvedParameterFrame
       LAppModel active parameter write
  -> Official Cubism Framework/Core
       Physics / Pose / model.update / Renderer
  -> Live2D visible performance
```

最终边界要求：

- Performance Director 不创建第二套播放器、Timeline、参数混合器或 WebSocket 协议。
- ActiveParameterMixer 是 AG99 Runtime 内唯一的主动参数融合入口。
- 官方 Cubism `Framework` / `Core` 不理解 Turn、文本、语义轴、表演时间或参数来源。
- Physics 只消费最终主动参数帧，不回写主动参数的平滑层或 Mixer。
- 任何新增表演策略都必须进入现有 Schedule、参数轨道和 Runtime 融合链路，不能创建私有时钟或私有写入路径。

## 7. 实施纪律

- 先修改和迁移现有实现，只有缺少明确职责载体时才新增模块。
- 不改变一期稳定协议，除非真实数据证明现有协议无法表达必要语义。
- 每类事实只有一个所有者：语义方向属于主模型，表演时间结构属于 ModelEngine，逐帧融合属于
  AG99 Runtime 的 ActiveParameterMixer，被动物理属于官方 Cubism Physics。
- 自动测试只做最基础边界检查；真实效果以 AstrBot、TTS、Electron 和 Live2D 联合运行观察为准。
- 发现错误时显式失败并记录阶段诊断，不增加 fallback 掩盖问题。
