# 前端结构维护清单

本文只记录当前仍成立的前端结构维护项。已完成的拆分过程、历史对比和临时方案不在本文保留。

## 1. 当前结构原则

- `frontend/src/app/` 是主窗口组合根，只负责装配模块和解释桌面命令。
- `frontend/src/adapter-connection/` 是适配器协议层，只负责 WebSocket、协议边界、入站/出站分发和适配器相关运行时。
- `frontend/src/turn-playback/` 是播放轮次管线，只负责 session、segment、release 和完成协调。
- `frontend/src/model-engine/` 是动作引擎，只负责动作载荷归一化、编译、调度和参数计划启动。
- `frontend/src/desktop-bridge/` 是窗口间桥接层，只负责快照、命令和窗口投影。
- `frontend/src/live2d-renderer/` 是 Live2D 渲染、参数计划播放器，以及 `ParameterPresentationLayer` 的运行时落点。
- `frontend/src/components/` 保持 UI 组件定位；组件不直接访问 `desktop-bridge`、`adapter-connection` 或 WebSocket。
- `frontend/src/views/` 是窗口级组合层，可以读取 `useDesktopBridge()`，并把快照投影成组件 props，把组件事件转成桌面命令。

## 2. 当前结构事实

- `frontend/src/composables/` 不承载当前业务模块；前端功能按领域目录维护。
- `adapter-connection/` 包含 `core/`、`inbound/`、`outbound/`、`runtime/`、`state/`、`history/`、`model-sync/`、`motion-tuning/`。
- `turn-playback/` 承接播放会话、编排、完成协调和端口类型。
- 正式播放材料只允许通过 `commitOutputSegment()` 一次性提交；Store 的生命周期 `mark*` 只能更新已提交段，缺段或重复段直接报错，不再补写晚到音频、文本或动作。
- `desktop-bridge/` 承接快照、窗口命令、投影和桌面桥 facade。
- `desktop-bridge/snapshot.ts` 是快照归一化入口；具体 runtime/model projection/profile authoring/motion tuning 归一化放在 `desktop-bridge/snapshot/` 子目录。
- `desktop-bridge/useDesktopWindowActions.ts` 承接普通窗口最小化和关闭动作，避免通用组件直接访问桌面 API。
- `desktop-bridge/` 内部的快照发布器和命令处理器通过窄端口依赖主控制器注入，不直接依赖完整 composable 返回类型。
- `model-engine/` 包含 compiler pipeline、runtime scheduler、motion start 和静态 stage registry。
- Action Lab / Profile Editor 的核心组件使用 props + events，不直接依赖 `useDesktopBridge()`。

## 3. 当前待维护项

当前前端优先维护顺序：

1. 先保持主控制器组合根清瘦，新增主窗口监听或桥接逻辑放到 `frontend/src/app/` 小模块。
2. 再收敛 `adapter-connection/useAdapterConnection.ts` facade，只暴露窄接口。
3. 保持动作引擎两层分工：compile 侧 `SpeechPoseStage`，runtime 侧 `ParameterPresentationLayer`。
4. 再按动作引擎扩展需要拆分 `types/desktop.ts` 与 `types/protocol.ts`，明确 `plan / talk / runtime / ambient / physics` 的参数所有权。
5. 后端插件结构不纳入本文的前端结构清单。

### 3.0 当前问题台账与处理顺序

本节只保留当前仍会影响维护判断的问题。当前项目设计前提是单前端实例、单适配器实例、一对一连接；不为多连接或多前端实例提前重构。

信任边界规则：

- WebSocket、IPC、BroadcastChannel、localStorage、LLM 输出和 `JSON.parse` 结果不得裸 `as` 后进入业务路径。
- 已经过运行时 parser/guard 校验的数据，可以在校验边界之后用窄 `as` 补齐 TypeScript 类型。
- 内部构造且来源完全受控的数据，可以保留局部断言，但不要把断言当作校验。

优先处理顺序：

1. 修复已确认会造成错误行为的播放、动作同步和安全问题。
2. 补齐信任边界 parser/guard，尤其是仍直接透传的入站消息类型。
3. 收敛 PTT / 麦克风状态判断，避免文案驱动逻辑。
4. 继续瘦身 `desktop-bridge` 快照发布和 Action Lab 热路径。
5. 继续收敛 `adapter-connection/useAdapterConnection.ts` facade 和主窗口组合根。
6. 清理配置、测试脚本、样式和类型契约维护债。
7. 后端 `TurnCoordinator` 和 Live2D scanner 属于后端结构维护项，不纳入前端结构清单。

已确认需要修复的问题：

- **入站协议边界仍有部分深层透传路径**：`parseInboundEnvelope()` 已做基础 envelope 校验，`inboundPayloads.ts` 已覆盖主要 payload；`system.model_sync` 和 `system.motion_tuning_samples_state` 已补入口形状校验。但模型扫描、历史消息、动作调参样本等深层对象仍在各 feature 内继续 normalize。高风险字段应前移到具体 parser，或显式标注 feature-level 校验边界。
- **ModelEngine stage 顺序契约**：`intensityStage -> relation graph -> modeResolverStage` 是有意顺序。`resolvedMode` 描述最终可播放轴值是否仍落在 idle soft range，而不是复述原始 LLM 输入；因此 expressive 输入可以被用户强度设置提升为可见动作。后续不得在没有同步修改该语义与测试的情况下把 mode resolution 前移。
- **原生麦克风 Windows 停止仍缺进程树兜底**：`frontend/electron/main/native-microphone.ts` 使用 `runtime.process.kill("SIGTERM")`。Windows 下主进程退出和 ffmpeg 子进程树清理仍需真实设备回归和必要兜底。
- **AxisDetailForm 直接修改嵌套 props**：`frontend/src/components/AxisDetailForm.vue` 编辑的是父组件传入的 draft 对象，当前功能路径可用，但违反 Vue 单向数据流直觉。维护时应改为显式 update 事件或集中 draft mutation API。

当前结构和性能维护项：

- **麦克风 / PTT 链路仍需真实回归**：按键说话由设置窗口发送桌面命令，主进程发 `desktop:ptt-keydown / desktop:ptt-keyup`，主宠物窗口再启动/停止 adapter runtime。已补 ack 思路后仍需要在真实 uiohook、焦点切换、设备忙、无声输入场景下回归。
- **原生麦克风全局单例符合当前设计，但需写清边界**：`frontend/electron/main/native-microphone.ts` 只有一个 `activeCapture`。这符合当前单宠物窗口、一对一适配器设计，不作为多实例 bug 处理。
- **前端音频播放全局单例符合当前设计**：`frontend/src/playback-timeline/audioSink.ts` 的模块级 `activeAudioElement` 只负责当前单实例 AudioElement 的替换、停止和事件归属校验，不提供全局 clock 查询。真实 clock 必须由本段 `playing` 事件携带给 Timeline；不要把该变量扩展为跨 segment 的时钟或身份来源。
- **原生采集启动确认已初步补齐，仍缺真实设备回归**：主进程现在等待 ffmpeg 输出第一批 PCM 字节后才返回 `{ ok: true }`，启动握手样本只用于 ready 判定，不进入识别；启动期 error/exit/timeout 会返回失败。仍需要在真实 Windows 设备、设备独占和无声输入场景下手测。
- **音频数据格式成本已进入二进制主路径**：Electron / Windows 原生采集已改为 ffmpeg `s16le`，renderer 通过 `input.audio_stream_start` / WebSocket binary `AG99` PCM16LE chunk / `input.audio_stream_end` 发送；Web Audio fallback 也在 renderer 内转 PCM16LE。旧 `input.raw_audio_data` JSON 数组路径仍保留给兼容和调试，不再是当前前端主路径。
- **适配器连接 facade 偏大**：`frontend/src/adapter-connection/useAdapterConnection.ts` 仍承担连接生命周期、子 runtime 装配、对外 API、历史、动作调参、音频播放和模型同步桥接。新增能力应优先落到 `inbound/`、`outbound/`、`runtime/` 或具体 feature 子目录。
- **入站协议 parser 已分层加强**：`inboundPayloads.ts` 新增 `parseModelSummarySnapshot()` / `parseSemanticAxisProfileSnapshot()` / `parseRuntimeCacheErrorsPayload()` 分层 parser，`model_info.models[]` 非空校验、`selected_model` 必填。`parseInboundEnvelopeObject()` 供 window/devtools 入口。`applyUnknownMessage` 改走 parser 而非直接 cast。history / motion tuning feature 端口改用 typed envelope。
- **主窗口组合根偏重**：`frontend/src/app/usePetDesktopRuntime.ts` 同时装配 adapter、bridge、model engine、playback、Live2D player、snapshot publisher 和桌面命令处理。新增主窗口逻辑应继续拆成小控制器。
- **桌面快照同步缺少时序控制** ~~已修复~~：`DesktopRuntimeSnapshot` 增加 `_publisherId`（窗口实例 mount 时生成）+ `_revision`（每次 publish 自增）。接收端对同一 publisher 只接受 revision 严格递增的快照。历史快照通过 `normalizeSnapshot` 的 `...defaultSnapshot` spread 自动补全可选字段，兼容无 revision 的旧快照。
- **运行时快照深拷贝和持久化成本偏高**：`frontend/src/desktop-bridge/usePetRuntimeSnapshotPublisher.ts` 的运行时快照 watch 仍会投影大对象；发布后还会通过 `desktop-bridge` 写入 localStorage 并广播到其它窗口。优先优化方向是减少快照字段、拆出大集合独立通道、只发布引用签名或摘要。
- **动作调参样本重复发布**：运行时快照已经携带 motion tuning samples，另有独立 motion tuning publish 路径。样本数量增加后会重复 `cloneJson` 和跨窗口传输。优先让运行时快照只保留样本计数、状态和最新更新时间，样本本体走独立同步命令。
- **Action Lab 预览全量重算**：`frontend/src/action-lab/parameterActionPreview.ts` 每次会对 action library atoms 做 map 和排序。模型动作库变大后，应按 library 引用、schema/hash 或 selected model revision 做 memo，避免无关状态变更触发全量预览重建。
- **动作运行调度存在小规模线性扫描**：`frontend/src/model-engine/runtime/motionRuntimeScheduler.ts` 查找音频 segment 时会遍历 session segment。当前片段少时可接受；如果后续支持更细粒度流式 segment，应增加 `messageId -> segment` 或 active audio segment 索引。
- **动作 timing 极端值一致性需要测试保护**：`frontend/src/model-engine/timing.ts` 已有 clamp，但 expressive 分段在边界值下需要单元测试锁定 `duration_ms === blend_in_ms + hold_ms + blend_out_ms` 一致性。
- **动作 plan clone 仍有末端断言**：`frontend/src/model-engine/planParser.ts` 已经完整解析主要字段，但 `cloneSemanticParameterPlan()` 返回处仍用 `as SemanticParameterPlan` 合并原对象。应减少保留未知字段，或把需要保留的扩展字段显式白名单化。
- **`cloneJson` 只适合 JSON 数据**：`frontend/src/utils/cloneJson.ts` 会丢弃 `undefined`、函数、symbol，遇到循环引用会抛错。当前用于协议/快照 JSON 形数据时可接受；不要用于非 JSON 运行时对象。
- **类型契约文件膨胀**：`frontend/src/types/desktop.ts` 和 `frontend/src/types/protocol.ts` 已经混合窗口、历史、动作、模型扫描和协议结构。后续拆分时按 `desktop-window`、`desktop-runtime`、`desktop-motion`、`desktop-profile-authoring`、`desktop-history` 和协议领域拆开。
- **测试脚本重复编译**：`frontend/package.json` 的每个测试脚本都单独 `tsc --outDir`，`npm test` 会重复编译多次。维护时应合并为单次测试编译或迁移 Vitest。
- **测试 tsconfig 手动列源文件**：`frontend/tsconfig.test.json` 手动列出大量 src 文件，新增源码容易漏，应改成更稳定的 include 策略。
- **渲染器 tsconfig 不检查 WebSDK 源码**：`frontend/tsconfig.json` exclude 了 `src/live2d/WebSDK/**/*`。当前 `@framework` / `@cubismsdksamples` 是 Vite alias，不是 tsconfig alias；如要检查 WebSDK，应单独建立 SDK typecheck 配置，不要直接把整包塞回 renderer 主检查导致噪音。
- **Electron renderer sandbox 暂未启用**：`BrowserWindow` 当前 `contextIsolation: true`、`sandbox: false`。这是 Electron 桌面应用常见权衡；若未来加载远程内容或扩大外部输入面，需要重新评估。
- **preload API 双命名暴露**：`frontend/electron/preload/index.ts` 同时暴露 `ag99desktop` 和 `api` 时，应明确兼容窗口，避免双入口长期并存。
- **PTT 设置窗口按键捕获使用 capture 阶段**：`frontend/src/settings/useSettingsWindow.ts` 在设置捕获模式下使用 capture 可以理解，但应确保只在捕获激活时安装，并避免影响其它输入控件。
- **Overlay Enter 发送需要确认事件路径**：`frontend/src/views/PetOverlayView.vue` 的 Enter 发送应确认是否存在 form submit 或重复 key handler，避免双发。
- **History refresh 参数死代码**：`frontend/src/views/HistoryWindowView.vue` 的 `refreshHistory(announce = true)` 当前没有实际 announce 行为，后续清理。
- **MotionTuningPanel 样式来源重复**：`.motion-tuning__layout` 同时在全局 CSS 和 scoped CSS 中定义，断点也不一致。应统一到一个来源。
- **Profile Editor 样式分散**：`.profile-editor__*` 部分在全局 CSS，部分在组件 scoped CSS。布局调整时应统一维护边界。
- **DesktopPetCanvas 固定 DOM id**：`id="live2d"` 和 `id="canvas"` 符合当前单实例渲染器设计；若未来支持多实例或测试多挂载，需要改为 ref 传递。
- **Live2D 目录 hash 读取全量文件内容**：`astrbot_plugin_ag99live_adapter/live2d/cache/runtime_cache.py` 和 `semantic_axis_profile.py` 会遍历模型目录并读取文件内容计算 hash。模型目录较大时会拖慢启动或刷新配置。优先考虑 manifest hash（路径、size、mtime_ns），必要时再做深 hash。
- **后端 turn 编排中心过宽**：`astrbot_plugin_ag99live_adapter/runtime/turn_coordinator.py` 同时处理输入分发、事件提交、输出、动作 payload、中断和播放完成。后端集中阶段应拆出输入提交、输出发布、动作广播和 turn lifecycle 子模块。
- **Live2D scanner 规则/IO 混合**：`astrbot_plugin_ag99live_adapter/live2d/scanner/scan.py` 是 3000 行级别模块，混合 schema、扫描、规则和 profile 构建。调整动作库和语义轴时应逐步拆成资源扫描、参数分析、动作分析和 profile 构建。
- **middleware 动作入口仍是后端热点**：`astrbot_plugin_ag99live_adapter/middleware/interaction_motion.py` 仍聚合 Persona Effect 注册、prompt/result contributor、payload 归一化和 legacy plugin hints 工具。后续按 `motion_effects / motion_prompt / motion_result / motion_payload / motion_legacy_plugin_hints` 的依赖方向拆分，避免 contributor 反向依赖注册与兼容解析。
- **后端运行状态对象过宽**：`astrbot_plugin_ag99live_adapter/runtime/state.py` 同时承载配置快照、Live2D 缓存、动作调参和运行期服务引用。新增状态前应先判断其所有者，逐步改成由窄服务对象持有，避免 coordinator 和 service 通过通用 state 形成隐式依赖。
- **统一播放 runtime 仍是前端热点**：`frontend/src/playback-timeline/playbackTimelineRuntime.ts` 同时装配 timeline、sink 生命周期和 SessionStore 端口。继续迁移时优先把纯身份索引、sink 终态推进和 segment execution 分开，但保持 timeline 对播放生命周期的唯一写入权。
- **结构拆分以依赖边界为准**：上述热点不按行数一次性重写。先为待抽职责建立窄输入/输出契约和回归测试，再把叶子职责移出；禁止为了缩短文件制造双向依赖、共享可变状态或新 facade。
- **高频路径日志需要分级**：动作播放、调度、PTT、音频链路存在较多 `console.info`。开发期保留价值高，稳定运行时应引入统一 logger，让 debug/info 可以按环境或命名空间关闭。
- **适配器静态资源可达性是音频播放前置条件**：`output.segment.audio.url` 依赖适配器 HTTP 静态资源服务暴露 `/cache/audio/*.wav`。前端可重写 host，但不能修复后端 HTTP 服务 reset / 不响应；遇到“有 TTS 文件但浏览器无声”时，应同时验证 WebSocket 连接和 HTTP 静态资源 URL。

### 3.1 适配器连接 facade

`frontend/src/adapter-connection/useAdapterConnection.ts` 仍是适配器协议层的总门面。

允许它持有：

- 当前 WebSocket 引用
- 连接生命周期入口
- 子适配器装配
- 对外 adapter API

不应继续塞入：

- 入站事件业务分支
- 出站协议构建细节
- 音频播放细节
- 麦克风采集细节
- 模型同步解析细节

新增能力优先落到 `inbound/`、`outbound/`、`runtime/` 或具体 feature 子目录，再由 facade 暴露窄接口。

### 3.2 主控制器组合根

`frontend/src/app/usePetDesktopController.ts` 是主窗口组合根。

允许它负责：

- 装配 adapter、bridge、model engine、playback、Live2D player
- 解释桌面命令
- 发布主窗口快照
- 安装主窗口特有监听

不应负责：

- 具体协议解析
- 具体动作编译
- 播放 session 状态迁移规则
- Live2D 参数执行细节

当前可继续拆出的独立项：

- 新的主窗口特有监听或桥接逻辑

当前主窗口子控制器：

- `frontend/src/app/usePushToTalkController.ts`：Push-to-talk 键盘和 IPC 监听
- `frontend/src/app/useAmbientMotionPreference.ts`：ambient motion 偏好应用
- `frontend/src/app/useDesktopContextMenu.ts`：右键菜单桥接
- `frontend/src/app/usePetWindowDrag.ts`：宠物主窗口拖动和鼠标穿透桥接

### 3.3 窗口 View 和组件边界

窗口 View 可以：

- 读取 `useDesktopBridge()`
- 请求模型投影或样本同步
- 将快照转换为组件 props
- 将组件事件转为桌面命令

组件应保持：

- props 输入
- emits 输出
- 本地 UI 状态
- 本地编辑和校验逻辑

组件不应直接：

- 调 `useDesktopBridge()`
- 调 `useAdapterConnection()`
- 调 `window.ag99desktop` 做桌面桥接
- 发送 WebSocket
- 修改主运行时状态

### 3.4 桌面桥接端口边界

`frontend/src/desktop-bridge/` 可以定义面向主控制器注入的窄端口。

允许端口描述：

- 快照发布所需的 adapter state 字段
- 命令处理所需的 adapter 方法
- 桥接发布方法
- 动作引擎和快照发布器的最小能力

不应在 `desktop-bridge/` 内部直接依赖：

- `ReturnType<typeof useAdapterConnection>`
- `ReturnType<typeof useDesktopBridge>`
- `ReturnType<typeof useModelEngine>`
- 与当前命令或快照无关的完整 composable API

新增桌面命令时，先扩展对应窄端口，再由主控制器传入具体实现。

### 3.5 桌面快照归一化边界

`frontend/src/desktop-bridge/snapshot.ts` 只作为稳定导出入口。

具体归一化职责按快照类型维护：

- `desktop-bridge/snapshot/runtimeSnapshot.ts`：运行时快照默认值、持久化恢复、播放记录归一化
- `desktop-bridge/snapshot/modelProjectionSnapshot.ts`：模型投影和 Action Lab 预览归一化
- `desktop-bridge/snapshot/profileAuthoringSnapshot.ts`：档案编辑快照归一化
- `desktop-bridge/snapshot/motionTuningSnapshot.ts`：动作调参样本和 effective examples 归一化

新增快照字段时，应优先落到对应子模块；只有跨快照类型的导出才放在入口文件。

### 3.6 类型契约拆分

`frontend/src/types/desktop.ts` 当前仍是桌面侧大合同文件，包含窗口、历史、动作调参、运行时快照、命令等类型。

当它继续膨胀时，优先按事实边界拆为：

- `desktop-window`
- `desktop-runtime`
- `desktop-motion`
- `desktop-profile-authoring`
- `desktop-history`

拆分时保持导入路径一次性更新，不引入重复类型。

### 3.7 测试基础设施

当前测试脚本仍是多个 `tsc --outDir` + `node` 的独立脚本。

维护方向：

- 当前可以保留现有脚本。
- 需要减少重复编译时，优先合并为单次测试编译。
- 如果需要 watch 和覆盖率能力，再迁移到 Vitest。

### 3.8 日志分级

当前前端仍大量使用 `console.info`、`console.warn`、`console.error`。

维护方向：

- 新增统一 logger。
- 保留 warn/error 默认输出。
- debug/info 按环境或命名空间控制。
- 不用 logger 掩盖真实错误，也不把失败路径降级为静默 fallback。
