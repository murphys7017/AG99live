# 前端结构维护清单

本文只记录当前仍成立的前端结构维护项。已完成的拆分过程、历史对比和临时方案不在本文保留。

## 1. 当前结构原则

- `frontend/src/app/` 是主窗口组合根，只负责装配模块和解释桌面命令。
- `frontend/src/adapter-connection/` 是适配器协议层，只负责 WebSocket、协议边界、入站/出站分发和适配器相关运行时。
- `frontend/src/turn-playback/` 是播放轮次管线，只负责 session、segment、release 和完成协调。
- `frontend/src/model-engine/` 是动作引擎，只负责动作载荷归一化、编译、调度和参数计划启动。
- `frontend/src/desktop-bridge/` 是窗口间桥接层，只负责快照、命令和窗口投影。
- `frontend/src/live2d-renderer/` 是 Live2D 渲染、参数计划播放器，以及后续 `ParameterPresentationLayer` 的运行时落点。
- `frontend/src/components/` 保持 UI 组件定位；组件不直接访问 `desktop-bridge`、`adapter-connection` 或 WebSocket。
- `frontend/src/views/` 是窗口级组合层，可以读取 `useDesktopBridge()`，并把快照投影成组件 props，把组件事件转成桌面命令。

## 2. 当前结构事实

- `frontend/src/composables/` 不承载当前业务模块；前端功能按领域目录维护。
- `adapter-connection/` 包含 `core/`、`inbound/`、`outbound/`、`runtime/`、`state/`、`history/`、`model-sync/`、`motion-tuning/`。
- `turn-playback/` 承接播放会话、编排、完成协调和端口类型。
- `desktop-bridge/` 承接快照、窗口命令、投影和桌面桥 facade。
- `desktop-bridge/snapshot.ts` 是快照归一化入口；具体 runtime/model projection/profile authoring/motion tuning 归一化放在 `desktop-bridge/snapshot/` 子目录。
- `desktop-bridge/useDesktopWindowActions.ts` 承接普通窗口最小化和关闭动作，避免通用组件直接访问桌面 API。
- `desktop-bridge/` 内部的快照发布器和命令处理器通过窄端口依赖主控制器注入，不直接依赖完整 composable 返回类型。
- `model-engine/` 包含 compiler pipeline、runtime scheduler、motion start 和静态 stage registry。
- Action Lab / Profile Editor 的核心组件使用 props + events，不直接依赖 `useDesktopBridge()`。

## 3. 当前待维护项

当前前端优先维护顺序：

1. 先保持主控制器组合根清瘦，新增主窗口监听或桥接逻辑放到 `frontend/src/app/` 小模块。
2. 再收敛 `adapter-connection/useAdapterConnection.ts` facade，只暴露窄接口。
3. 再完成动作引擎扩展的两层分工：compile 侧 `SpeechPoseStage`，runtime 侧 `ParameterPresentationLayer`。
4. 再按动作引擎扩展需要拆分 `types/desktop.ts` 与 `types/protocol.ts`，明确 `plan / talk / runtime / ambient / physics` 的参数所有权。
5. 后端插件结构暂不作为前端集中阶段的主线任务。

### 3.0 当前问题台账与处理顺序

本节记录 2026-06-05 审阅后仍需要逐步处理的问题。远程执行器当前处于功能测试阶段，权限、审批和 executor 抽象暂不纳入本轮处理范围。

优先处理顺序：

1. 麦克风和 PTT 当前链路确认。
2. 原生麦克风主进程服务边界收敛。
3. `desktop-bridge` 运行时快照瘦身、去重复发布，并补上版本、来源或时序控制。
4. `adapter-connection/useAdapterConnection.ts` facade 收敛。
5. 主窗口组合根 `frontend/src/app/usePetDesktopRuntime.ts` 继续瘦身。
6. 类型契约文件按领域拆分。
7. 后端 `TurnCoordinator` 和 Live2D scanner 在后续后端集中阶段拆分。

当前问题：

- **麦克风 / PTT 当前链路确认**：按键说话由设置窗口发送桌面命令，主进程发 `desktop:ptt-keydown / desktop:ptt-keyup`，主宠物窗口再启动/停止 adapter runtime。该链路缺少 start/stop ack 和当前链路归属确认，可能出现按键事件已触发但 adapter 未真正进入本段收音的状态。
- **原生麦克风全局单例**：`frontend/electron/main/native-microphone.ts` 只有一个 `activeCapture`。任一 renderer 启动原生采集都会先停止当前采集，适合当前单宠物窗口路径，但不适合作为长期多窗口桌面服务边界。
- **原生采集启动确认不足**：主进程 `spawn` 后立即返回 `{ ok: true }`，没有等待第一帧音频或 ready 信号。ffmpeg 设备启动失败时，renderer 可能先进入“已开启”状态，再通过异步 error/end 回退。
- **音频数据格式成本已进入二进制主路径**：Electron / Windows 原生采集已改为 ffmpeg `s16le`，renderer 通过 `input.audio_stream_start` / WebSocket binary `AG99` PCM16LE chunk / `input.audio_stream_end` 发送；Web Audio fallback 也在 renderer 内转 PCM16LE。旧 `input.raw_audio_data` JSON 数组路径仍保留给兼容和调试，不再是当前前端主路径。
- **适配器连接 facade 偏大**：`frontend/src/adapter-connection/useAdapterConnection.ts` 仍承担连接生命周期、子 runtime 装配、对外 API、历史、动作调参、音频播放和模型同步桥接。新增能力应优先落到 `inbound/`、`outbound/`、`runtime/` 或具体 feature 子目录。
- **主窗口组合根偏重**：`frontend/src/app/usePetDesktopRuntime.ts` 同时装配 adapter、bridge、model engine、playback、Live2D player、snapshot publisher 和桌面命令处理。新增主窗口逻辑应继续拆成小控制器。
- **桌面快照同步缺少时序控制**：`desktop-bridge` 使用 BroadcastChannel 和 localStorage 同步快照，但当前没有 snapshot revision、publisher id 或单调时间戳，多个窗口并发发布时可能旧快照覆盖新快照。
- **类型契约文件膨胀**：`frontend/src/types/desktop.ts` 和 `frontend/src/types/protocol.ts` 已经混合窗口、历史、动作、模型扫描和协议结构。后续拆分时按 `desktop-window`、`desktop-runtime`、`desktop-motion`、`desktop-profile-authoring`、`desktop-history` 和协议领域拆开。
- **后端 turn 编排中心过宽**：`astrbot_plugin_ag99live_adapter/runtime/turn_coordinator.py` 同时处理输入分发、事件提交、输出、动作 payload、中断和播放完成。后端集中阶段应拆出输入提交、输出发布、动作广播和 turn lifecycle 子模块。
- **Live2D scanner 规则/IO 混合**：`astrbot_plugin_ag99live_adapter/live2d/scanner/scan.py` 是 3000 行级别模块，混合 schema、扫描、规则和 profile 构建。后续调动作库和语义轴时应逐步拆成资源扫描、参数分析、动作分析和 profile 构建。

当前性能优化项：

- **运行时快照深拷贝和持久化成本偏高**：`frontend/src/desktop-bridge/usePetRuntimeSnapshotPublisher.ts` 的运行时快照 watch 使用 `deep: true`，并复制历史、后端历史、动作调参样本、动作播放记录等大对象；发布后还会通过 `desktop-bridge` 写入 localStorage 并广播到其它窗口。优先优化方向是减少快照字段、拆出大集合独立通道、只发布引用签名或摘要。
- **动作调参样本重复发布**：运行时快照已经携带 motion tuning samples，另有独立 motion tuning publish 路径。样本数量增加后会重复 `cloneJson` 和跨窗口传输。优先让运行时快照只保留样本计数、状态和最新更新时间，样本本体走独立同步命令。
- **Action Lab 预览全量重算**：`frontend/src/action-lab/parameterActionPreview.ts` 每次会对 action library atoms 做 map 和排序。模型动作库变大后，应按 library 引用、schema/hash 或 selected model revision 做 memo，避免无关状态变更触发全量预览重建。
- **Live2D 目录 hash 读取全量文件内容**：`astrbot_plugin_ag99live_adapter/live2d/cache/runtime_cache.py` 和 `semantic_axis_profile.py` 会遍历模型目录并读取文件内容计算 hash。模型目录较大时会拖慢启动或刷新配置。优先考虑 manifest hash（路径、size、mtime_ns），必要时再做深 hash。
- **动作运行调度存在小规模线性扫描**：`frontend/src/model-engine/runtime/motionRuntimeScheduler.ts` 查找音频 segment 时会遍历 session segment。当前片段少时可接受；如果后续支持更细粒度流式 segment，应增加 `messageId -> segment` 或 active audio segment 索引。
- **音频二进制帧后续性能空间**：当前二进制帧每个 chunk 仍携带 JSON metadata。下一步可把稳定字段下沉到 stream start，只在 chunk header 中保留 stream 索引、seq、payload 长度；同时为 socket backpressure 增加更细的丢帧/降采样策略。
- **高频路径日志需要分级**：动作播放、调度、PTT、音频链路存在较多 `console.info`。开发期保留价值高，长期运行时应引入统一 logger，让 debug/info 可以按环境或命名空间关闭。

### 3.1 适配器连接 facade

`frontend/src/adapter-connection/useAdapterConnection.ts` 仍是适配器协议层的总门面。

允许它持有：

- 当前 WebSocket 引用
- 连接生命周期入口
- 子适配器装配
- 对外 adapter API

不应继续塞入：

- 入站事件业务分支
- 出站协议构建细节
- 音频播放细节
- 麦克风采集细节
- 模型同步解析细节

新增能力优先落到 `inbound/`、`outbound/`、`runtime/` 或具体 feature 子目录，再由 facade 暴露窄接口。

### 3.2 主控制器组合根

`frontend/src/app/usePetDesktopController.ts` 是主窗口组合根。

允许它负责：

- 装配 adapter、bridge、model engine、playback、Live2D player
- 解释桌面命令
- 发布主窗口快照
- 安装主窗口特有监听

不应负责：

- 具体协议解析
- 具体动作编译
- 播放 session 状态迁移规则
- Live2D 参数执行细节

当前可继续拆出的独立项：

- 新的主窗口特有监听或桥接逻辑

当前主窗口子控制器：

- `frontend/src/app/usePushToTalkController.ts`：Push-to-talk 键盘和 IPC 监听
- `frontend/src/app/useAmbientMotionPreference.ts`：ambient motion 偏好应用
- `frontend/src/app/useDesktopContextMenu.ts`：右键菜单桥接
- `frontend/src/app/usePetWindowDrag.ts`：宠物主窗口拖动和鼠标穿透桥接

### 3.3 窗口 View 和组件边界

窗口 View 可以：

- 读取 `useDesktopBridge()`
- 请求模型投影或样本同步
- 将快照转换为组件 props
- 将组件事件转为桌面命令

组件应保持：

- props 输入
- emits 输出
- 本地 UI 状态
- 本地编辑和校验逻辑

组件不应直接：

- 调 `useDesktopBridge()`
- 调 `useAdapterConnection()`
- 调 `window.ag99desktop` 做桌面桥接
- 发送 WebSocket
- 修改主运行时状态

### 3.4 桌面桥接端口边界

`frontend/src/desktop-bridge/` 可以定义面向主控制器注入的窄端口。

允许端口描述：

- 快照发布所需的 adapter state 字段
- 命令处理所需的 adapter 方法
- 桥接发布方法
- 动作引擎和快照发布器的最小能力

不应在 `desktop-bridge/` 内部直接依赖：

- `ReturnType<typeof useAdapterConnection>`
- `ReturnType<typeof useDesktopBridge>`
- `ReturnType<typeof useModelEngine>`
- 与当前命令或快照无关的完整 composable API

新增桌面命令时，先扩展对应窄端口，再由主控制器传入具体实现。

### 3.5 桌面快照归一化边界

`frontend/src/desktop-bridge/snapshot.ts` 只作为稳定导出入口。

具体归一化职责按快照类型维护：

- `desktop-bridge/snapshot/runtimeSnapshot.ts`：运行时快照默认值、持久化恢复、播放记录归一化
- `desktop-bridge/snapshot/modelProjectionSnapshot.ts`：模型投影和 Action Lab 预览归一化
- `desktop-bridge/snapshot/profileAuthoringSnapshot.ts`：档案编辑快照归一化
- `desktop-bridge/snapshot/motionTuningSnapshot.ts`：动作调参样本和 effective examples 归一化

新增快照字段时，应优先落到对应子模块；只有跨快照类型的导出才放在入口文件。

### 3.6 类型契约拆分

`frontend/src/types/desktop.ts` 当前仍是桌面侧大合同文件，包含窗口、历史、动作调参、运行时快照、命令等类型。

当它继续膨胀时，优先按事实边界拆为：

- `desktop-window`
- `desktop-runtime`
- `desktop-motion`
- `desktop-profile-authoring`
- `desktop-history`

拆分时保持导入路径一次性更新，不引入重复类型。

### 3.7 测试基础设施

当前测试脚本仍是多个 `tsc --outDir` + `node` 的独立脚本。

维护方向：

- 短期可以保留现有脚本。
- 中期合并为单次测试编译。
- 长期可迁移到 Vitest，获得 watch 和覆盖率能力。

### 3.8 日志分级

当前前端仍大量使用 `console.info`、`console.warn`、`console.error`。

维护方向：

- 新增统一 logger。
- 保留 warn/error 默认输出。
- debug/info 按环境或命名空间控制。
- 不用 logger 掩盖真实错误，也不把失败路径降级为静默 fallback。

## 4. 审阅规则

每次前端结构改动后，至少检查：

```text
rg "useDesktopBridge|useAdapterConnection|sendCommand" frontend/src/components
rg "@/composables|../composables|src/composables" frontend/src frontend/tests
npm run typecheck:renderer
```

涉及播放链路时追加：

```text
npm run test:adapter-connection
npm run test:coordinator
npm run test:turn-orchestrator
```

涉及动作引擎时追加：

```text
npm run test:model-engine
```
