# 动作链路大更新实施总结

> 文档状态：当前实现总结。覆盖动作生成、显式语义轴关系、播放生命周期、运行时所有权和 Motion Lab 持久化闭环。

## 1. 更新范围

本轮更新不是单点功能，而是对动作生成、值处理、资源执行、播放生命周期、运行时所有权和数据记录的一次完整收口。本文以当前主分支实现为准，不用提交数量描述完成度。

最终主链路为：

```text
Prompt / Persona Effect
-> intent_tags + axis_levels + typed resource intent
-> Adapter strict protocol validation
-> engine.motion_intent.v4
-> ModelEngine compile pipeline
-> SemanticAxisRelationGraph
-> parameter plan
-> ResourcePolicy / expression / catalog motion
-> PlaybackTimeline
-> audio / motion / lip-sync sinks
-> Live2D runtime
-> Motion Lab trace and terminal recording
```

## 2. 动作协议与 Prompt

- Persona Effect 主链路从连续 `axes` 改为九级 `axis_levels (-4..4)`。
- `engine.motion_intent.v4` 成为自动动作主协议；非法等级、未知轴、混用 `axes`、profile 不匹配都会失败，不会降级到 v3。
- `engine.motion_intent.v3` 只保留给官方 `<@anim>` 兼容入口和内部手动预览。
- Prompt 收敛为 system / capability / context 三层，删除重复 JSON、插件名、传输细节和无关实现信息。
- 一个 assistant segment 最多接受一个 `ag99live.motion` effect；重复 effect 不再选择第一个，而是反馈失败。
- 生成方式统一命名为 `single_response_effect`；immediate / final 只描述 segment 阶段。

## 3. 值处理和轴关系图

- semantic profile 升级为 `ag99.semantic_axis_profile.v2`，增加每轴九级锚点和独立 `extreme_range`；`±4` 不再从 strong range 外推，首次加载磁盘 v1 profile 时会显式迁移并持久化为 v2。
- 新增 `ag99.semantic_axis_relation_graph.v1`，由显式边描述 derive 和 `bounded_ratio`，不再根据 `head_`、`body_` 命名猜关系。
- 允许头部和身体反向动作，但限制极端相反扭转；计算基于各轴中性差量，不比较绝对 0-100 数字。
- 轴值范围、派生轴和头身关系统一由 ModelEngine 关系图 stage 处理。
- intensity、coupling 和 speech pose 只产生直接值或候选值，不再各自拥有最终约束权。
- 参数 binding 缺失、范围错误和重复参数目标直接生成 Motion Feedback，不再跳过错误后继续播放。
- 九级非中性值使用 `turn_id + message_id + axis_id + profile hash + transform version` 在当前等级区间内确定性采样；intensity 不能把结果推到相邻等级。
- Prompt 以三级作为普通 Live2D 主要姿态的可见基准，四级作为短时夸张区；七类 v4 示例和当前 revision 的人工样本会作为 capability 参考实际注入。
- `relationEvaluations` 对每条边记录 `within_limit / derived / constrained / skipped`，与只记录实际改值的 `relationAdjustments` 分离。

## 4. 逐帧动作合成与动态约束

- semantic profile 为每个轴定义最大速度、最大加速度、生命动作比例和说话随动最大偏移比例。
- PlanBuilder 将语义轴速度/加速度按 binding 比例映射到 Cubism 参数空间，并为每个参数写入中性目标和 dynamics。
- 语义姿态与说话随动重叠时，ModelEngine 把随动编译为同一参数 owner 的 modulation，不创建第二写入者。
- WebSDK 按“关键帧目标 -> 生命动作 -> 说话 modulation -> 表演曲线 -> 速度/加速度限制 -> Cubism 写入”执行。
- 目标反转时连续减速；离散帧跨越目标时精确停靠，避免目标附近振荡。
- 参数计划缺少中性目标或 dynamics、存在坏 binding、重复参数或越界目标时整份失败，不部分 salvage。
- 旧 semantic profile 自动补齐 dynamics 是一次性配置迁移，不是播放时 fallback。
- 说话随动从固定正弦周期迁移为 `speech_gesture_track` 非周期控制点，当前提供解释、活泼、安抚和强调四种确定性预设。
- `ag99.voice_following_profile.v2` 为身体通道声明明确延迟；ModelEngine 生成轨迹，WebSDK 负责逐帧平滑插值和动态限制。
- 参数计划按音频时长重定时时同步缩放手势控制点，但保持头身跟随延迟为绝对毫秒。

## 5. 删除旧修复和 fallback

- Adapter 和 TurnCoordinator 不再执行 fallback pose repair、expressive floor 或头身约束；旧 RealtimeMotionPlan 生成器已经删除。
- 空动作、全中性动作和非法动作不会生成默认 pose。
- fallback candidate 仅作为 Prompt 参考和诊断信息，不进入运行时值处理。
- 删除旧 fallback 评分、hash 方向推断、repair 统计和遗留 plugin hints 轴解析工具。
- 非法 performance curve、缺失 Timeline 和不可求值的音频同步上下文都会显式失败或记录 skipped reason，不伪装成正常默认值。

## 6. Typed Resource 执行

- Persona Effect 使用 `expression_resource_id` 和 `motion_resource_id` 表达受控资源意图。
- 两种资源不能同时填写；资源不存在、类型错误、未暴露或缺少运行时定位信息时整个动作失败。
- expression 资源只有在参数所有权不冲突时才与 parameter plan 叠加。
- motion 资源作为完整动作主层替代普通 parameter plan，但仍使用同一个 segment motion sink 和 Timeline。
- Live2D runtime 只执行 ModelEngine 已解析的 expression ID、catalog motion 定位或 parameter plan，不参与语义决策。

## 7. 统一播放生命周期

- 文本、音频和动作按 `turn_id + message_id` 聚合；表演曲线只作为 motion intent 内部 hint，不保留第二份顶层事实。
- Orchestrator 只决定何时释放 segment job，PlaybackTimeline 负责执行 audio / motion / lip-sync sink 生命周期。
- 音频存在时只使用真实 `HTMLAudioElement` clock；明确无音频时才允许 synthetic clock。
- motion 在真实 audio started 后立即进入已准备计划；视觉入场延迟只由 performance curve 表达，speech-only motion 使用同一 segment timeline。
- lip-sync 使用当前音频元素的 Web Audio RMS，并把 started / completed / failed 写回 Timeline。
- Web Audio RMS 分别发布口型值和说话能量；随机口型降级只控制嘴型，不会驱动头身说话动作。
- missing sink、时钟缺失、动作启动失败和非法终态迁移不再只记录 warning 后继续运行。
- 标准 AstrBot `send()` 只聚合物理分片，`complete_visible_turn()` 独占队列关闭权；零 segment 和 `synth_finished` 发送失败都会显式失败。
- 原子 segment 提交即进入 ready；text failed 会参与失败回执，Store 与文本/音频待释放队列不一致会让会话失败。
- 迟到的 `playback_finished` 回执不能把已中断 session 从 failed 改回 completed。
- 终态 session 拒绝迟到文本、音频、动作和曲线，拒绝事件不会重新激活 `currentTurnId`。
- 组合身份键改为长度前缀编码，避免 ID 中包含分隔符时发生碰撞。
- 消除了 audio runtime 与 audio timeline controller 的 TypeScript 循环依赖。
- App composition root 直接创建唯一 `PlaybackTimelineRuntime` 与 `BrowserAudioTimelineSink`；Adapter 只提供不可变 execution ports 并执行一次显式 attach。
- Audio `playing` 事件携带绑定本段 AudioElement 的 clock；不存在全局 active clock 查询或 unavailable clock 伪造。
- speech-only motion 使用 ModelEngine 内部 `speech_only` request，只在编译边界适配为 parameter plan，不伪造传输层 motion intent。
- audio-backed canonical text 由 Timeline 延迟到 Audio `playing` 后作为字幕释放；音频起播前失败时字幕和已声明 motion 一并失败，不转换为正常 text-only / motion-only。

## 8. Motion Lab 数据闭环

- `MotionTransformTrace` 记录 profile revision/hash、transform version、原始等级、转换轴值、派生轴、约束结果、资源解析和编译参数。
- 前端记录动作开始、完成、失败和编译反馈；后端记录输入、assistant 输出、effect 收取、intent 解析和动作发送。
- SQLite schema 增加 transform trace、run ID 和 timeline outcome 投影。
- 前端原始事件先写 IndexedDB，再通过 WebSocket 发送。
- 每个事件拥有稳定 `event_id`；后端以 SQLite 主键幂等写入。
- 只有 SQLite 写入完成后，后端才发送 `system.motion_lab_raw_event_recorded`。
- 前端收到匹配回执后才删除 IndexedDB 记录；断线重连使用相同 ID 重发。

## 9. 配置、扫描与兼容边界

- 表演曲线启用时必须显式配置独立 `performance_curve_provider_id`；配置为空、Provider 不存在或类型错误会直接暴露配置失败，不复用当前会话聊天模型。
- Live2D 动作库构建失败会让该模型扫描失败并从本次 model list 排除，不再生成看似成功的空动作库种子。
- 插件配置只读取当前正式配置文件名，不再探测历史配置文件名。
- 隐藏输出清洗只处理当前系统标记与官方 `<@anim>` 标签，不再识别已删除的 `<~...~>` 私有格式。
- 官方 AstrBot `<@anim>` 仍是注入函数不存在时的 v3 兼容传输入口，不是 v4 主链路失败后的 fallback。

## 10. 验证结果

本轮已经通过：

- 前端完整测试套件。
- TypeScript renderer 和 Electron typecheck。
- 后端 288 个单元测试。
- AstrBot 插件结构检查。
- Python compileall。
- Web 构建。
- `git diff --check`。

这些验证证明协议、编译和生命周期的主要逻辑分支成立，但不能替代真实 Provider、TTS、WebSocket、Electron、音频设备和 Live2D 模型的端到端运行验证。

## 11. 13 号文档剩余工作

必须完成的验收项：

1. 真实 AstrBot + Provider + TTS + Electron + Live2D 端到端回归。
2. 验证 audio started、motion delayed start、lip-sync 和最终终态的实际时序。
3. 验证 Motion Lab 在回执前断线后的同 ID 重发与 SQLite 去重。
4. 验证 hybrid 多 segment 不会共享或覆盖 `message_id` 生命周期。

后续工具与诊断：

1. 建立 Motion Lab 历史筛选、回放、评价和训练样本导出工作台。
2. 完善静态 capability Prompt 的 provider 缓存实测，确认真实 token 和响应延迟收益。

可选或长期能力：

1. expression / motion additive、overwrite 和 blend 图规则。
2. 关系图在线学习。
3. 独立动作生成小模型或 `parallel_independent`。
4. 实时生成任意表演曲线，而不是选择预设曲线族。
5. 基于音频停顿、重音和句尾位置生成更细的说话手势片段。
6. 将轴关系约束扩展为逐帧关系图复算。

当前不应为了这些可选能力重新引入 fallback、双重后处理或第二套播放链路。
