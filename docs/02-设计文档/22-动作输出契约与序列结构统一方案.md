# 动作输出契约与序列结构统一

本文是动作输出契约的当前事实，不保存已被替换的同轴序列方案。它区分 AG99live 已完成的实现、
AstrBot 外部配合与尚待真实运行确认的边界。

## 1. 目标边界

```text
AstrBot Persona 输出
-> ag99live.motion Effect arguments
-> AG99 engine.motion_intent.v4
-> ModelEngine 参数轨道编译
-> engine.parameter_plan.v3
-> AG99 Live2D Runtime
```

AG99 不为动作补轴、改名、创建默认动作、增加第二套队列或播放入口。非法输入必须以明确原因失败；
WebSDK 只执行已经编译完成的参数计划，不解释 Persona 的 `motion_steps`。

## 2. 当前动作契约

`ag99live.motion` 必须包含非空 `intent_tags`，并且从以下执行形态中恰好选择一个：

- `axis_levels`：一个语义姿态。
- `motion_steps`：2 至 4 个语义姿态事件。
- `motion_resource_id`：一个已公开、可播放的完整动作资源。

`intent_tags` 只描述意图，不能单独执行。`axis_levels` 的值只能是当前 `SemanticAxisProfile` 暴露轴上的
`-4..4` 整数；未知轴、非法等级、空步骤、形态冲突和缺少执行形态都会被明确拒绝。

### 2.1 稀疏 `motion_steps` 语义

`motion_steps` 是稀疏参数轨道事件，而不是每步重复完整姿态：

1. 每一步都必须有非空 `axis_levels` 和 `duration_weight`。
2. 一个轴在首次声明前不受该序列控制。
3. 轴首次声明后，在后续步骤省略它表示保持上一目标。
4. 显式 `0` 才表示该轴回到语义中性。
5. 首次声明发生在后续 step 时，计划会保留该轴的响应和残余时间，再开始共享淡出；不能在该轴接管前提前释放。
6. 序列使用的轴集合是全部步骤声明轴的并集。
7. `duration_weight` 只描述相对时间；最终毫秒时间仍由 ModelEngine 和音频时钟编排。

例如，第三步只让 `head_pitch` 回中，先前已声明的 `head_yaw` 会保持，而不是被隐式重置：

```json
{
  "intent_tags": ["点头", "强调"],
  "motion_steps": [
    {"axis_levels": {"head_pitch": 3}, "duration_weight": 1},
    {"axis_levels": {"head_pitch": -1, "head_yaw": 1}, "duration_weight": 2},
    {"axis_levels": {"head_pitch": 0}, "duration_weight": 1}
  ]
}
```

## 3. AG99live 实现状态

AG99 源码侧迁移已完成，所有内部调用者使用同一套稀疏序列语义：

- Effect 描述、Prompt 与参考样本不再要求同一轴集合，也不再建议用中性值填充没有明显动作的回复。
- `motion_intent.py`、`payload_validation.py` 和 MotionLab `tuning_store.py` 以全部步骤声明轴的并集校验合法性。
- Prompt 历史摘要按整个序列归约最终轨道状态；`previous_motion` 与 `recent_motion_summary` 不再采用不同语义。
- ModelEngine 为每个实际参数建立轨道，在首次声明的 step 激活；后续缺失步骤只保持目标，不产生中性补点。
- 后续 step 才首次激活的语义轴会参与共享 release 时刻计算，避免其刚开始响应就随原音频时长淡出。
- `engine.parameter_plan.v3` 的每个参数记录 `activation_at_ms`，解析器要求首个 keyframe 与该时刻一致。
- ActiveParameterMixer 仅从已激活参数开始融合；未激活参数继续由 Cubism base、其他合法源和 Physics 决定。
- MotionLab 历史记录以 `CompiledSemanticMotion` 为唯一动作来源；诊断 trace 只用于展示，不再反向决定序列是否可回放、保存或编辑。

这是唯一的序列解释路径；前端不会补中性值，样本、Prompt 和正式输入没有第二套结构规则。

## 4. AstrBot 外部配合

AstrBot Core 不属于本仓库，以下工作需要在 AstrBot 配套分支独立完成、审阅和提交：

1. Persona 通用 Prompt 不得要求无明显动作时只输出 `intent_tags` 或全中性动作。
2. 对标记为每段必发的 `ag99live.motion`，模型必须依注册 Schema 选择一个执行形态。
3. Core 保留结构化 Schema 拒绝，不自动补轴、自动改名或默认生成动作。
4. 增强 Persona Effect 与官方 `<@anim>` V4 兼容入口只可共享 V4 输入契约，不能变成彼此的失败 fallback。

AstrBot 不负责模型 profile、九级采样、稀疏轨道编译、Timeline、参数融合、Physics 或前端播放状态。

## 5. 验收边界

源码静态检查只能确认契约在 AG99 的调用链上统一，不能证明真实角色已经表演。最终需要以同一模型完成
真实 AstrBot、Electron、TTS 和 Live2D 联调，至少确认：

- 合法单姿态与稀疏序列都能从 Effect 到达 `engine.parameter_plan.v3`。
- 只有 `intent_tags`、未知轴和非法等级得到明确失败原因，而不是被静默改写。
- 在第一步后才出现的轴不会提前写入或影响参数融合。
- 在后续 step 才出现的轴会获得完整响应与收束窗口，而不是在接管前进入淡出。
- 后续省略轴保持前一目标，显式 `0` 发生可见回中。

自动测试仅可作为基础输入输出检查；动作观感与跨进程链路必须由真实运行日志和画面验收。

## 6. 非目标

- 不修改官方 Cubism `Framework/Core` 的驱动职责。
- 不把 `performance_curve`、TTS 生命周期或播放状态塞入动作输入契约。
- 不增加 AG99 自己的输入队列、参数融合器、播放器或私有时钟。
- 不在 AstrBot Core 中实现模型专属的参数映射或 Live2D 逻辑。
