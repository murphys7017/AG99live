# 三层动作来源与环境调度计划

> 文档状态 设计与实施计划
> 适用基线 AG99live 1.0.0
> 目标 让三类动作来源共用一个状态准入和播放所有权模型

## 1. 动作来源

### 1.1 LocalActionSource

本地动作来源不请求模型。它使用固定模板、基础呼吸、视线、待机轻晃和收势动作，填充环境表现的高频空档。

默认自动待机使用 `soft_sway`（轻柔晃动）、`small_glance`（左右扫视）和 `relaxed_sway`（舒缓侧摆）。模板以明确的语义轴 ID 选轴，只驱动 `head_yaw`、`head_roll`、`body_yaw`、`body_roll` 和 `gaze_x`；模型缺少对应轴时不改用俯仰或身体抬升轴。`gentle_nod` 和 `breath_pause` 保留在动作设计库中，不进入自动待机轮换，基础连续呼吸仍由 Cubism 负责。

### 1.2 MaterialCompositionSource

素材组合来源使用 `MotionMaterialCatalog` 和 `CompositionRecipe`，在本地生成短动作。它可以由当前状态触发，也可以接受小模型选择的配方或标签。

### 1.3 PersonaMotionSource

Persona 或大模型来源继续沿用现有的对话段动作、预动作和完整动作资源路径。它处理有明确语义和完整上下文的动作。

## 2. AmbientActionDirector 与 AmbientActionScheduler

`AmbientActionDirector` 是环境动作的唯一准入和参数贡献生命周期边界，负责：

- 读取 PresenceStateStore、Turn、Playback 和模型能力。
- 判断当前是否允许环境动作。
- 把环境动作提交到 ModelEngine，并为每个来源保留独立的参数计划。
- 在模型不可用、连接断开或环境动作关闭时让环境贡献进入渐出释放，前景动作、语音和口型通过参数优先级直接接管重叠参数。

本地动作、素材组合动作和模型被动动作共享环境动作准入。最多同时保留三个来源计划，来源优先级交给 `ActiveParameterMixer` 做参数级融合，避免建立多个互相竞争的待机播放器。

`AmbientActionScheduler` 负责环境动作的低频唤醒、来源选择、素材组合冷却和本地回退。它只生产候选并调用 `AmbientActionDirector`，不直接访问 Cubism，也不拥有播放状态。

当前源码已落地第一版准入和自动调度基线：`frontend/src/model-engine/ambient/ambientActionDirector.ts` 接收环境动作候选，检查连接、模型和渲染器就绪、环境动作开关、音频、麦克风、预动作、对话 Turn 和手动预览状态，随后复用 `useModelEngine` 的多个 idle 参数计划。`ambientActionScheduler.ts` 只维护低频调度唤醒、来源选择和冷却，不创建第二个播放时钟。Director 同时发出开始、释放和拒绝事件，动作实验室消费这些事件显示当前环境动作和历史，并保留素材组合元数据。

当前 `output.idle_motion`、`local` 和 `material_composition` 都通过该 director 进入 ModelEngine。空闲时本地动作优先运行，素材组合动作按较长冷却插入；组合失败会回退到本地动作。`model_passive` 仍是兼容的被动动作入口，不等于尚未实现的小模型配方选择。小模型选择、曲线重放、完整播放终态指标和真实表现验收属于后续实施。

## 3. 准入规则

环境动作允许开始的条件：

- WebSocket 和模型已经就绪。
- 没有正在播放的前景动作。
- 没有正在播放的音频或语音段。
- 没有活跃的输入捕获状态。
- 没有未完成的对话 Turn。
- 当前模型存在可用素材。

环境动作需要进入渐出释放的条件：

- 模型切换或模型能力变化。
- 连接断开。
- 环境动作开关关闭或模型暂时不可用。
- 动作过期或组合验证失败。

## 4. 优先级

沿用现有参数混合器的所有权方向：

```text
安全终止
  > Persona 或直接动作计划
  > 口型与音频同步
  > 交互注意力
  > 思考和说话随动
  > 环境动作：model_passive
  > 环境动作：material_composition
  > 环境动作：local
  > Cubism 基础待机回退
```

环境动作保持低优先级参数贡献。模型被动、素材组合和本地动作可以同时存在，由参数混合器按来源优先级和响应权重合成，来源切换通过贡献权重和渐出过程完成。

## 5. 调度策略

### 空闲状态

`AmbientActionScheduler` 负责基础频率。本地动作使用固定的低强度姿态模板，素材组合动作在至少三个已接受的环境动作之后并满足较长冷却时插入。素材目录或 Profile 不可用时仅使用本地模板，Cubism 默认 Idle 继续作为底层回退。

默认空闲组合只选择 `calm_companion` 和 `speech_gap`，并把与本地待机相同的横向轴集合传给组合器。组合器先约束可用轴，再选择主体原子和叠加原子，避免完整素材中的 `head_pitch`、`body_pitch`、`gaze_y` 或呼吸重音重新进入自动待机。其他配方保留供后续明确场景选择。

环境动作按独立的 `ambient` 节奏编译：本地模板时长为 4.2–5.6 秒，自动组合的两种配方使用 3.6–6 秒范围；`idle_motion` 的主体时长限制为 3–10 秒，进入和释放各分配 28%，不再受普通 idle 姿态的 2.2 秒上限影响。头部、身体和视线的关键帧过渡随时长分配到约 0.7–1.6 秒，环境视线使用同一缓慢语义轨道，不使用对话视线的快速切换策略。

编译器可以为最后一次回中和渐出延长计划，最终总时长仍受统一 15 秒上限约束。Director 将实际编译时长返回 Scheduler；下次自动动作在该计划时长加间隔之后安排，实验室日志同时区分提示时长和编译时长。前景动作继续使用 `foreground` 节奏，口型保持原来的音频时钟和参数优先级。

2026-11-17 验证：使用当前 Mk6 扫描缓存核对环境动作编译、关键帧响应和调度边界；同一前景输入的参数计划与修改前一致。TypeScript 类型检查、桌面构建和控制页构建通过。参数曲线回放属于局部验证，重启后的实际动作、Physics 和混合观感仍待实机验收。

### 思考状态

优先使用 `quiet_thinking` 和视线相关素材。对话 Turn 开始后，停止接纳新的环境候选，已存在的环境贡献继续以低优先级参与混合并自然渐出。

### 说话状态

正式动作和语音随动由现有 Persona、SpeechOnly 和口型链路负责。新的环境动作只允许在明确的语音间隙进入，已经接纳的环境贡献继续由参数混合器处理，第一阶段可以直接禁用环境主体片段。

### 长时间等待

提高本地动作和素材组合的候选多样性，降低重复动作权重。动作仍然保持低强度和可回中。

## 6. 小模型入口

小模型不进入高频环境动作循环。它可以在较长间隔或状态变化时提供：

- 配方 ID
- 状态标签
- 强度建议
- 可选素材候选

Adapter 校验结果后交给本地组合器。请求超时、输出无效或 Provider 不可用时继续使用本地策略。

## 7. 诊断

每次环境动作事件记录以下元数据：

- 来源类型
- 配方 ID
- 片段和原子 ID
- 当前 PresentationState
- 准入判定
- 组合结果
- 被抑制或取消的原因
- 实际播放和释放终态

这些信息进入 Motion Lab raw event 和动作实验室诊断视图，不进入对话 PlaybackTimeline 或普通聊天历史。环境动作不伪造 turn/segment；正式对话动作仍由对话播放事件提供权威段序。
