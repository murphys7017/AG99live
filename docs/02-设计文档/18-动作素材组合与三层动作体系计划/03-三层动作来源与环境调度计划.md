# 三层动作来源与环境调度计划

> 文档状态 设计与实施计划
> 适用基线 AG99live 1.0.0
> 目标 让三类动作来源共用一个状态准入和播放所有权模型

## 1. 动作来源

### 1.1 LocalActionSource

本地动作来源不请求模型。它使用固定模板、基础呼吸、视线、待机轻晃和收势动作，填充环境表现的高频空档。

### 1.2 MaterialCompositionSource

素材组合来源使用 `MotionMaterialCatalog` 和 `CompositionRecipe`，在本地生成短动作。它可以由当前状态触发，也可以接受小模型选择的配方或标签。

### 1.3 PersonaMotionSource

Persona 或大模型来源继续沿用现有的对话段动作、预动作和完整动作资源路径。它处理有明确语义和完整上下文的动作。

## 2. AmbientActionDirector

`AmbientActionDirector` 是环境动作的唯一调度器，负责：

- 读取 PresenceStateStore、Turn、Playback 和模型能力。
- 判断当前是否允许环境动作。
- 选择本地动作或素材组合动作。
- 管理动作冷却、过期、重复和取消。
- 把环境动作提交到 ModelEngine。
- 在前景动作、语音、口型、模型切换和断连时收束环境动作。

本地动作和素材组合动作共享环境动作所有权。来源区别通过诊断元数据和候选评分记录，避免建立多个互相竞争的待机播放器。

## 3. 准入规则

环境动作允许开始的条件：

- WebSocket 和模型已经就绪。
- 没有正在播放的前景动作。
- 没有正在播放的音频或语音段。
- 没有活跃的输入捕获状态。
- 没有未完成的对话 Turn。
- 当前模型存在可用素材。

环境动作需要停止或收束的条件：

- Turn 开始。
- 前动作准备成功。
- 音频或 Persona 段开始播放。
- 用户输入变为活跃。
- 模型切换或模型能力变化。
- 连接断开。
- 动作过期或组合验证失败。

## 4. 优先级

沿用现有参数混合器的所有权方向：

```text
安全终止
  > Persona 或直接动作计划
  > 口型与音频同步
  > 交互注意力
  > 思考和说话随动
  > 环境素材组合
  > 本地简单待机
  > Cubism 基础待机回退
```

第一阶段保持环境动作使用低优先级参数贡献。后续只有在诊断证明来源区分对仲裁有实际价值时，才增加新的参数贡献者类型。

## 5. 调度策略

### 空闲状态

本地动作负责基础频率。素材组合动作在较长冷却后插入，选择低强度配方。Cubism 默认 Idle 作为资源不足时的回退。

### 思考状态

优先使用 `quiet_thinking` 和视线相关素材。对话 Turn 开始后，环境动作立即让位给思考随动和预动作。

### 说话状态

正式动作和语音随动由现有 Persona、SpeechOnly 和口型链路负责。环境动作只允许在明确的语音间隙进入，第一阶段可以直接禁用环境主体片段。

### 长时间等待

提高本地动作和素材组合的候选多样性，降低重复动作权重。动作仍然保持低强度和可回中。

## 6. 小模型入口

小模型不进入高频环境动作循环。它可以在较长间隔或状态变化时提供：

- 配方 ID
- 状态标签
- 强度建议
- 可选素材候选

Adapter 校验结果后交给本地组合器。请求超时、输出无效或 Provider 不可用时继续使用本地策略。

## 7. 诊断

每次环境动作记录以下元数据：

- 来源类型
- 配方 ID
- 片段和原子 ID
- 当前 PresentationState
- 准入判定
- 组合结果
- 被抑制或取消的原因
- 实际播放和释放终态

这些信息进入现有播放记录和诊断快照，不进入普通聊天历史。
