# 资源扫描与动作素材库计划

> 文档状态 设计与实施计划
> 适用基线 AG99live 1.0.0
> 目标 建立可缓存、可验证、可组合的模型动作素材索引

## 1. 目标和边界

扫描器负责发现模型资源、解析动作曲线并生成素材索引。扫描发生在模型加载或资源源文件变化时，环境动作循环只读取索引。

首批资源类型如下：

- `model3.json` 作为模型和动作注册入口
- `motion3.json` 作为完整动作和参数曲线来源
- `motion_catalog.json` 作为动作标签、情绪偏置和场景说明
- `cdi3.json` 作为参数、分组和可绑定信息
- `exp3.json` 作为表情叠加资源的分析输入

Physics、Pose 和其他运行时支持文件记录为能力依赖，不自动作为环境动作素材。

## 2. 扫描流程

```text
找到模型目录
  → 读取 model3.json
  → 读取 CDI 和动作目录
  → 按 FileReferences.Motions 解析动作
  → 分析参数曲线和时间窗
  → 建立语义轴映射
  → 生成动作片段和参数原子
  → 生成兼容关系与候选状态
  → 写入运行时扫描缓存
```

当前扫描器主要跟随 `model3.json` 已注册的动作。后续可以增加未注册 `.motion3.json` 的发现报告。未注册资源需要补充 group 和 index，完成注册后再进入可播放候选。

## 3. 素材模型

### 3.1 MotionFragment

动作片段来自同一动作文件、同一时间窗或同一动作域。建议字段包括：

- `fragment_id`
- `source_motion`
- `source_file`
- `source_group`
- `duration_ms`
- `window_start_ratio`
- `window_end_ratio`
- `channels`
- `domains`
- `parameter_ids`
- `intensity`
- `trait`
- `catalog_tags`
- `conflict_groups`
- `profile_identity`

动作片段用于保留多参数的协同关系。

### 3.2 MotionAtom

参数原子是从动作片段中提取的单参数或小范围参数素材。建议字段包括：

- `atom_id`
- `parameter_id`
- `axis_id`
- `primary_channel`
- `polarity`
- `trait`
- `strength`
- `duration`
- `active_window`
- `source_fragment_id`
- `source_tags`
- `compatibility_groups`

现有 `parameter_action_library.v2` 已覆盖大部分元数据。第一阶段复用当前结构，曲线采样可以通过独立的 `curve_ref` 或本地缓存引用保存。

## 4. 素材分类

扫描结果需要区分以下状态：

| 状态 | 含义 |
| --- | --- |
| discovered | 文件被发现 |
| parseable | JSON 和动作曲线可以解析 |
| compatible | 参数可以映射到当前模型和 Profile |
| ambient_candidate | 适合环境动作 |
| foreground_only | 适合前景动作 |
| state_bound | 只允许特定状态使用 |
| suppressed | 因冲突、强度或缺少语义被暂时抑制 |
| rejected | 文件或参数不满足运行时要求 |

每个候选都记录原因，便于动作实验室和现场诊断。

## 5. 初步分类规则

环境动作优先选择：

- 头部、身体、视线和呼吸域
- 低到中等强度
- 时长较短
- 没有口型和唇动参数
- 没有特殊道具或状态切换参数
- 可以安全回中

以下资源默认进入前景或状态专用池：

- 生气、惊讶、强烈情绪
- 手势和道具切换
- 追踪丢失恢复
- 需要独占 Physics 或特殊表情的动作
- 可能覆盖口型、眨眼或语音随动的动作

## 6. 缓存和失效

复用现有 Live2D 运行时缓存和模型源文件哈希。缓存内容至少包含：

- scanner schema version
- model source hash
- semantic profile identity
- material catalog version
- fragments
- atoms
- compatibility summary
- scan diagnostics

模型文件、动作文件、动作目录和 Profile 发生变化时重新生成素材索引。缓存失败时保留诊断，运行时使用已经验证的本地回退动作。

## 7. 验收

- 每个模型都能得到完整动作数量和素材数量报告。
- 无效 JSON、缺失文件和未知参数都有明确原因。
- 同一个模型源文件不发生重复扫描。
- 素材 ID 在同一模型和 Profile 内稳定。
- 未注册动作不会被误判为可播放动作。
- 扫描结果不会改变当前动作播放行为。

## 8. 当前实现进度

第一版 `motion_material_catalog.v1` 已在 Adapter 扫描结果中生成，并随现有 Live2D 扫描缓存保存。当前实现包含以下内容：

- 每个已注册动作先形成一个稳定的 `MotionFragment`，保留动作文件、参数、通道、语义轴、组件和场景标签引用。
- 现有 `parameter_action_library.v2` 中的参数原子被归一化为 `MotionAtom`，保留活动时间窗、源组件和曲线引用，不复制采样曲线。
- 素材统一记录 `ambient_candidate`、`compatible`、`foreground_only`、`suppressed` 和 `parseable` 状态及原因。
- 素材目录记录模型标识、SemanticAxisProfile 标识、Profile revision 和源文件哈希。Profile 更新后目录会同步重建并刷新扫描缓存。
- 当前目录已经通过 `live2d_scan.v4` 的可选字段投影到前端模型同步载荷。前端只接收组合器需要的片段、原子、Profile 身份和诊断摘要，不接收完整曲线和 Adapter 专属字段，目录与已有参数动作库之间只保留组合所需的引用关系。
- 前端组合器只把目录当作只读候选索引，具体参数动作仍通过现有 `parameter_action_library.v2` 对齐，目录和 Profile 身份不一致时拒绝组合。

这一阶段没有读取新的曲线文件，也没有改变现有动作播放行为。完整动作片段的时间曲线重放和运行时调度属于后续阶段。
