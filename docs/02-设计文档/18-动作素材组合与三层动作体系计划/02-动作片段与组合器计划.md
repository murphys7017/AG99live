# 动作片段与运行时组合器计划

> 文档状态 设计与实施计划
> 适用基线 AG99live 1.0.0
> 目标 从素材片段和参数原子生成可验证的新动作

## 1. 设计原则

组合器负责动作计划生成，不直接写入 Cubism 参数。所有结果通过 Semantic Axis Profile、动作校验和 ModelEngine 编译。

组合过程优先保留原始动作的时间和参数相关性。主体使用 `MotionFragment`，变化使用少量 `MotionAtom`。

## 2. 组合配方

配方是模型无关的语义模板。它不直接保存某个模型的参数 ID。

配方至少包含：

- 配方 ID 和版本
- 适用表现状态
- 主体片段的域和数量
- 叠加原子的域和数量
- 允许的并行与顺序关系
- 时长范围
- 强度范围
- 冲突组
- 回中策略
- 最近使用素材的冷却要求

第一批配方建议包括：

| 配方 | 主体 | 叠加 | 使用状态 |
| --- | --- | --- | --- |
| calm_companion | 头部或身体片段 | 呼吸、视线 | 待机、陪伴 |
| quiet_thinking | 头部或视线片段 | 轻微身体、呼吸 | 思考、等待 |
| gentle_acknowledge | 点头或轻晃片段 | 视线、轻微表情 | 认同、安抚 |
| tired_waiting | 低强度身体片段 | 呼吸、视线 | 长时间等待 |
| speech_gap | 短片段 | 视线或头部偏移 | 说话间隙 |

## 3. 组合流程

```text
读取当前 PresentationState
  → 选择可用配方
  → 过滤当前状态不可用的参数域
  → 选择主体片段
  → 选择零到两个叠加原子
  → 检查参数和所有权冲突
  → 对齐时长与时间窗
  → 生成 1–4 个 motion_steps（素材组合器的短计划上限）
  → 调用现有动作校验和编译器
  → 返回可播放计划
```

组合器每次只生成一个短计划。连续动作通过下一次调度继续生成，避免一次计划占用过长时间。

## 4. 冲突和所有权

第一版组合器使用以下规则：

- 口型和 `mouth_open` 在音频播放期间由 LipSync 保留。
- 眨眼参数由 EyeBlink 保留。
- Physics、头发和特殊道具参数不进入普通环境组合。
- 语义动作正在执行时不再启动新的环境主体片段，已有环境贡献按参数优先级继续混合并渐出释放。
- 单个素材组合内部避免重复占用同一参数或语义轴；跨来源贡献由参数混合器按优先级和权重合成。
- 呼吸可以和头部、身体、视线动作叠加。
- 组合失败时回退到本地简单动作或基础待机。

## 6. 曲线保真度路线

第一阶段使用语义重建。组合器读取方向、强度、动作特征和时长，由现有编译器生成缓入、保持和回中。

第二阶段增加曲线片段。扫描器保存归一化时间窗和少量采样点，组合器按照片段时间轴重建参数轨道。曲线素材使用独立版本和按需加载，避免扩大普通模型同步负载。

## 7. 代码落点

建议的实现方向如下：

- Adapter 侧继续扩展 `live2d/scanner` 的素材输出。
- 将 `BaseActionPreviewPanel.vue` 中的组合逻辑抽到纯 TypeScript 模块。
- 组合器放在 ModelEngine 相关目录，避免由 Vue 组件持有运行时规则。
- 组合结果继续调用 `compileParameterMotionIntent`。
- 组合诊断接入现有动作播放记录和桌面快照。

## 8. 当前实现进度

阶段 2 的第一版组合器已经落地在 `frontend/src/model-engine/composer/materialMotionComposer.ts`。

- 当前提供 `calm_companion`、`quiet_thinking`、`gentle_acknowledge`、`tired_waiting` 和 `speech_gap` 五个模型无关配方。
- 组合器先筛选可用主体片段，再按语义轴和参数所有权选择零到两个叠加原子。
- 口型、眨眼、Physics 和特殊前景通道在组合前被排除，主体和叠加原子不会重复占用同一语义轴或参数。
- 相同模型、Profile 和随机种子会得到相同的素材选择和动作意图。
- 输出继续使用 `engine.motion_intent.v4` 的 `motion_steps`，后续由现有 `compileParameterMotionIntent` 进入 ModelEngine 编译。
- `AmbientActionDirector` 已接入现有 `output.idle_motion` 入口，统一检查连接、模型、渲染器、音频、输入、预动作、Turn 和预览状态，并把候选交给多个可混合的 idle 参数计划。
- `AmbientActionScheduler` 已将本地模板和组合器结果接入空闲环境调度，组合动作使用较长冷却并在编译失败时回退到本地动作，不改变现有对话动作路径。
- `AmbientActionDirector` 已发出环境动作的 `started`、`released` 和 `rejected` 生命周期事件；动作实验室按 action ID 显示当前执行和历史。正式对话动作仍按 turn/segment 分组，并优先使用会话的权威 `segmentOrder`，只有旧事件缺少段序时才按事件时间推断。
- 当前组合器仍把主体和原子重建为三步 `neutral → target → neutral` 计划，尚未保存片段内部的时间窗和采样曲线；因此“保留原始动作时间结构”仍是阶段 5 的目标，不是当前实现事实。

## 9. 后续实施边界

下一阶段接入小模型选择时，只允许它选择已注册的配方或有限候选，不能绕过本地组合器和 ModelEngine 校验。真实模型验收仍需补齐回中、重复度、打断和调度间隔记录。

## 10. 验收

- 同一配方在相同素材和随机种子下可复现。
- 组合动作不会越过当前 Profile 的轴范围。
- 主体片段的时间结构得到保留。
- 组合动作不会覆盖口型、眨眼和已开始的前景动作。
- 组合失败可以回到本地动作，不影响对话播放。
- 运行记录能追溯使用的配方、片段和参数原子。
