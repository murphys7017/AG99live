# 动作素材组合验收、性能与发布计划

> 文档状态 设计与实施计划
> 适用基线 AG99live 1.0.0
> 目标 确认素材组合不会破坏现有播放链路，并形成可回退的发布顺序

## 1. 静态验收

每个阶段完成后检查：

- 素材 ID、Profile ID 和模型源哈希一致。
- 组合结果符合 `engine.motion_intent.v4`。
- 参数轴值通过当前范围和关系图校验。
- 组合器不会直接访问 Cubism 模型实例。
- 环境动作不会新增第二个 PlaybackTimeline。
- 现有 Persona、SpeechOnly、口型和完整动作资源路径保持不变。

## 2. 运行验收场景

### 基础空闲

- 连接后角色可以呼吸、眨眼并执行本地待机动作。
- 多次空闲期间不会持续重复同一个素材。
- 素材组合动作完成后可以自然回中。

### 对话和打断

- Turn 开始时停止接纳新的环境候选，已有环境贡献继续参与参数混合，正式动作按优先级接管重叠参数。
- 正式动作不会被环境组合覆盖。
- 语音播放期间口型保持最高参数优先级，环境动作继续作为低优先级贡献参与混合，计划完成或硬失效时进入渐出释放。
- 打断、断连和模型切换会清理所有待机任务。

### 小模型异常

- Provider 超时后继续使用本地策略。
- Provider 返回无效配方时不播放任何未经校验的动作。
- 连续失败不会扩大请求频率。

### 模型差异

- Mk6 可以使用丰富的素材组合。
- DeepSeek 等语义轴较少的模型自动减少组合域。
- 缺少素材或 Profile 的模型可以回退到基础待机。

## 3. 性能观察

重点观察以下指标：

- 模型加载时扫描耗时。
- 扫描缓存命中率。
- 组合器单次生成耗时。
- ModelEngine 编译耗时。
- 环境动作被拒绝、进入渐出释放和过期的次数。
- 小模型请求次数、超时率和回退率。
- 动作开始与音频、口型、前景动作之间的可感知错位。

本地动作和素材组合动作不能在关键播放路径上等待网络请求。组合器应在前端本地同步完成，或提前生成短计划。

## 4. 发布顺序

1. 只发布扫描报告和素材索引，不改变播放行为。
2. 发布组合器预览和诊断。
3. 启用本地动作和固定配方的自动环境调度基线。
4. 在少量模型上启用素材组合并记录真实表现。
5. 增加小模型配方选择。
6. 最后评估曲线片段重放和更复杂的组合。

每一步都保留本地简单动作和 Cubism 基础待机作为回退。

## 5. 回滚边界

出现以下情况时关闭素材组合开关：

- 环境动作覆盖口型或正式动作。
- 组合结果无法通过当前 Profile 校验。
- 模型切换后出现旧素材播放。
- 扫描缓存与模型源文件不一致。
- 组合器造成明显卡顿或播放延迟。
- 小模型请求影响正式对话链路。

关闭组合能力后，ModelEngine、Persona 动作、口型和基础待机继续使用当前基线。

## 6. 现场验收记录

每个模型至少记录：

- 模型名称和源文件哈希
- 可用动作片段和参数原子数量
- 启用的组合配方
- 每种配方的实际表现视频或截图
- 典型冲突和回退记录
- 用户对自然度、重复度和响应速度的评价

现场记录用于更新素材标签、配方约束和模型 Profile。它们不直接改变运行时协议。
