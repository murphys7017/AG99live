# 表演曲线与语音同步设计

> 文档状态：当前实现规格。表演曲线由独立可配置聊天 Provider 选择符号化曲线提示，
> 后端只在原子 motion payload 内附加 ready hint，ModelEngine 再使用本段 Timeline
> duration 求解实际 timing。

## 1. 目标与边界

表演曲线控制动作的时间表现，而不决定动作内容：

```text
动作内容：intent_tags / axis_levels / motion_steps / typed resource
表演曲线：entry / hold / exit / emphasis / energy
实际毫秒：ModelEngine 根据 segment clock 求解
```

边界规则：

- 主回复模型不负责生成曲线。
- 曲线 Provider 不输出 Live2D 轴值、资源 ID、毫秒或 parameter plan。
- 后端不猜音频时长。
- 前端不接收独立 curve patch，不维护第二份曲线状态。
- 曲线不创建独立播放器或 Timeline sink。
- 没有曲线 hint 时使用动作计划自身 timing。
- 携带 hint 但本段没有可用 Timeline duration 时，ModelEngine 明确记录曲线跳过原因，
  移除该可选 hint 后继续编译原动作；不得伪造音频时钟或默认曲线。

## 2. 配置

```json
{
  "enable_performance_curve": true,
  "performance_curve_provider_id": "curve-mini-model"
}
```

| 配置 | 类型 | 规则 |
| --- | --- | --- |
| `enable_performance_curve` | bool | 是否启用独立曲线生成 |
| `performance_curve_provider_id` | string | 启用时必须显式选择聊天 Provider |

`RuntimeState` 的配置规则：

- 开关关闭时不启动曲线请求。
- 开关开启但 Provider ID 为空时抛出配置错误。
- Provider 不存在或不是聊天 Provider 时抛出配置错误。
- 不复用当前 AstrBot 会话聊天 Provider。
- 不复用 `motion_analysis_provider_id`。

## 3. Provider 输入

Result contributor 在同一回复阶段已经同时具备 canonical assistant text 和 motion payload
后只登记 pending 输入。只有 AstrBot 确实进入该回复阶段的 TTS 请求并发出 `generating`
状态时，Adapter 才启动曲线任务。未启用 TTS 的回复不会启动曲线任务。
输入包括：

```json
{
  "turn_id": "turn-xxx",
  "message_id": "message-xxx",
  "assistant_text": "实际回复文本",
  "assistant_reply_keywords": ["调侃", "轻快"],
  "motion_intent_tags": ["teasing", "light"],
  "motion_effect_summary": {
    "axis_keys": ["head_yaw", "body_yaw"],
    "motion_step_count": 1
  },
  "chat_context": []
}
```

数据职责：

- `assistant_text` 是当前轮最终可见回复文本。
- `assistant_reply_keywords` 由 Adapter 从回复文本提取，最多 8 个。
- `motion_intent_tags` 来自当前 motion payload。
- `motion_effect_summary` 只暴露结构摘要，不把完整参数处理交给曲线模型。
- `chat_context` 只取最近的有限上下文。

Provider 调用不写入 AstrBot 当前聊天记录；它是当前 turn 的并行派生任务。

## 4. Hint 协议

Schema：`ag99.performance_curve_hint.v1`

```json
{
  "schema_version": "ag99.performance_curve_hint.v1",
  "curve_family": "quick_in_hold_soft_out",
  "entry": "quick",
  "hold": "steady",
  "exit": "soft",
  "emphasis": "early",
  "energy": "teasing"
}
```

允许值：

| 字段 | 枚举 |
| --- | --- |
| `curve_family` | `default`, `quick_in_hold_soft_out`, `slow_in_hold_quick_out`, `pulse_then_settle`, `soft_breathe` |
| `entry` | `instant`, `quick`, `soft`, `slow` |
| `hold` | `short`, `steady`, `long`, `breathing` |
| `exit` | `quick`, `soft`, `slow` |
| `emphasis` | `none`, `early`, `middle`, `late`, `punctuated` |
| `energy` | `low`, `medium`, `high`, `teasing`, `calm` |

所有字段必填且必须严格命中枚举。未知 schema、未知枚举、非 JSON object 或无法提取 JSON
都会让本次曲线任务失败，不补默认字段。

## 5. 后端任务生命周期

曲线任务使用 AG99 前端 `turn_id + tts_request_id` 作为后台任务身份。前端 turn 由 AstrBot
TTS 状态的 `external_correlation_id` 明确携带；运行记录另存 AstrBot `tts_turn_id` 和逻辑
`message_id`。Result contributor 先为当前 immediate/final 阶段登记 pending 输入；AstrBot
`on_tts_state_changed` 发出 `generating` 后，Adapter 使用同一次 TTS 的身份启动请求，随后输出层
把 request ID 绑定到真实 `turn_id + message_id` 段。每个音频生成生命周期拥有独立
`tts_request_id`，hybrid 的 immediate 与 final 不共享任务。
`PerformanceCurveRuntime` 保证同一 request ID 最多接受一次请求：

```text
Persona result contributor 获得 canonical text + motion
  -> register pending input for this reply phase
  -> AstrBot starts this phase's TTS materialization
  -> on_tts_state_changed(generating)
  -> start(request) with frontend turn_id + tts_turn_id + message_id + tts_request_id
  -> performance_curve.requested
  -> Provider text_chat 与 AstrBot TTS 并行
  -> normalize strict hint
  -> performance_curve.resolved 或 performance_curve.failed
```

`TurnCoordinator` 在构造该段 motion slot 时执行唯一一次 ready 检查：

- ready：把 hint 写入 `motion.payload.performance_curve_hint`，记录 `performance_curve.attached`。
- not ready：取消曲线任务，motion payload 不带 hint，记录 `performance_curve.skipped`。
- failed：Provider 自身记录 `performance_curve.failed`，motion 仍不等待并正常出站。
- disabled：不创建请求，也不改变 motion payload。
- 仍在运行的任务在检查失败后取消，不在音频出站后继续补发。
- 段完成检查后清理该 key；turn 关闭时取消该 turn 的遗留任务。

曲线任务慢于原子段出站时不会阻塞 TTS 或播放。这是“可选增强未赶上”的明确 skipped
结果，不是协议 fallback；原 motion payload 仍按自身合法 timing 播放。

## 6. 唯一协议承载点

曲线只存在于 motion payload 内：

```json
{
  "motion": {
    "state": "present",
    "payload": {
      "schema_version": "engine.motion_intent.v4",
      "axis_levels": {},
      "performance_curve_hint": {
        "schema_version": "ag99.performance_curve_hint.v1"
      }
    }
  }
}
```

禁止：

- `output.segment.v3` 顶层 `performance_curve`。
- 独立 `engine.performance_curve_hint` 消息。
- segment 提交后的 late patch。
- Store 根据后续消息修改已提交 motion。

## 7. 前端求解

前端协议边界先严格解析 hint。ModelEngine 编译时执行：

```text
performance_curve_hint
  + matched segment clock
  + remaining duration
  -> resolvePerformanceCurveTimeline()
  -> resolveMotionTiming()
  -> blend_in_ms / hold_ms / blend_out_ms / curve_preset
```

Timeline 规则：

- audio segment 使用本段 AudioElement clock 的 duration 和 currentTime。
- explicit motion-only segment 可以使用本段 synthetic clock。
- `audio_unavailable`、clock 缺失、duration 缺失或 duration 非法时，该可选 hint 被明确标记为
  `performance_curve_skipped:<reason>`，然后从本次编译输入中移除。
- 不使用 SessionStore 音频时长估计，也不退回 `duration_hint_ms` 掩盖 clock 错误。

若 motion payload 本身没有 hint，`resolveMotionTiming()` 可以按 audio target duration、
`duration_hint_ms` 或动作默认 timing 正常工作。

当前曲线族映射到预设：

| curve family | curve preset |
| --- | --- |
| `default` | `smooth_hold` |
| `quick_in_hold_soft_out` | `snap_hold_soft_release` |
| `slow_in_hold_quick_out` | `slow_build_quick_release` |
| `pulse_then_settle` | `pulse_settle` |
| `soft_breathe` | `breathing_swell` |

当前实现将曲线求解为 parameter plan 的进入、保持和退出 timing。它尚未生成任意逐帧方程，
也不改变 axis values。

## 8. Speech-Only

正式 motion 缺失且模型支持 voice-following 时，ModelEngine 使用内部 `speech_only` request。
它可以复用同一个 audio Timeline 和基础 timing，但当前后端曲线任务要求 canonical text 与正式
motion payload 同时存在，因此不会为纯 speech-only 路径生成新的 Provider hint。

不得为了给 speech-only 添加曲线而伪造 `engine.motion_intent.v4` 传输 payload。

## 9. Motion Lab

后端记录：

```text
performance_curve.requested
performance_curve.resolved
performance_curve.failed
performance_curve.attached
performance_curve.skipped
```

请求与 Provider 结果使用 `turn_id + tts_request_id`；输出段直接从自身 TTS delivery metadata
取得 request ID，并且只有曲线 runtime 确认拥有该请求时才绑定。attached / skipped
事件使用真实输出 `turn_id + message_id`，并在 raw 数据中保留 request ID 以完成关联。
记录包含：

- Provider ID。
- assistant text 与提取关键词。
- motion intent tags / effect summary。
- 原始 completion text。
- normalized hint。
- latency 或 failure/skipped reason。

前端动作播放记录继续保存最终 `plan.timing`、`curve_preset` 和 diagnostics，便于比较模型选择与实际求值结果。

## 10. 失败规则

| 失败 | 行为 |
| --- | --- |
| 专用 Provider 配置无效 | RuntimeState 配置加载失败 |
| Provider 输出非法 | 记录 `performance_curve.failed`，不附加 hint |
| 同 key 重复启动 | 拒绝第二次请求 |
| 段出站前未 ready | 取消任务并只记录 `performance_curve.skipped` |
| attached hint 非法 | motion 协议边界拒绝 |
| attached hint 无可用 Timeline duration | 记录明确 skipped 诊断，移除可选 hint 后编译原动作 |
| 曲线任务或记录失败 | 不修改已经合法的主回复文本、音频和原 motion 协议事实 |

## 12. 运行验收

基础边界 smoke 只确认配置、枚举和 hint 附加位置。真实链路验收必须观察同一个
`turn_id + message_id + tts_request_id`：曲线只在 TTS `generating` 后启动，不阻塞 TTS，
未赶上 segment egress 时只记录 skipped；hint 已附加时由真实 AudioElement duration 求解动作
进入、保持和退出。
