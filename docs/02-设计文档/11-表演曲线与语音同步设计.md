# 表演曲线与语音同步设计

> 文档状态：MVP 已实现，逐帧曲线播放器仍为后续计划。
>
> 本文定义 AG99live 的“表演曲线”能力：在助手文本生成完成后，使用独立可配置的表演曲线 Provider 发起一次不写入聊天历史的辅助调用，生成有限枚举的曲线提示，再由前端 ModelEngine 根据真实音频时长求解最终参数计划 timing。当前已落地 MVP：曲线 hint 可随 `engine.motion_intent.v4` 进入前端，并解算为现有 `blend_in_ms / hold_ms / blend_out_ms`；完整逐帧权重曲线仍未实现。

## 1. 目标

当前动作链路已经可以把 `engine.motion_intent.v4` 编译为 `engine.parameter_plan.v2`，并在音频起播后使用真实音频时长做 `audio_sync` timing。下一步希望让动作不只是“有参数”，还要有更像表演的进入、保持、强调和退出节奏。

目标能力：

- 主回复生成仍只产出回复内容和动作意图；表演曲线作为同一轮聊天语境下的辅助 Provider 调用，不写入 AstrBot 聊天历史。
- 插件配置提供启用开关和独立曲线 Provider 选择；未配置独立 Provider 时才回退到当前会话聊天 Provider。
- 曲线提示在文本生成完成后异步生成，不阻塞 TTS 或播放。
- 曲线提示必须绑定 `turn_id`，优先绑定 `turn_id + message_id`，避免跨轮错配。
- 小模型只输出有限枚举关键词，不直接输出毫秒、不输出最终参数计划。
- 前端拿到真实音频时长后，将曲线提示求值为 `blend_in_ms / hold_ms / blend_out_ms` 等执行 timing。
- 生成、失败、附加到动作 payload 的过程都写入 Motion Lab SQLite raw events。

当前 MVP 限制：

- 后端当前能在 `emit_message_chain()` 拿到可见文本后启动曲线任务；动作 payload 会先按原链路出站并在前端等待音频，后端在音频出站前做一次曲线 ready 检查。若此时曲线已完成，则用同一 `turn_id / message_id` 发送独立 `engine.performance_curve_hint` patch，前端在 motion 释放给 ModelEngine 前合并到 intent；若仍未完成，则取消该任务并记录失败，播放回退默认 timing。
- 由于 `emit_message_chain()` 收到 `Record` 时语音文件通常已经由 AstrBot 上游生成完成，更早的“文本完成后、TTS 合成中”启动点需要后续接入 AstrBot 更前置钩子。
- 前端只把曲线 hint 解算成现有 timing 三段，不做每帧曲线权重。

非目标：

- 不让曲线小模型生成 Live2D 参数轴。
- 不让曲线小模型选择 motion3、exp3、catalog motion 或资源文件。
- 不用曲线生成阻塞文本展示、TTS 合成或音频播放。
- 不把后端变成 `engine.parameter_plan.v2` 编译器；最终 timing 求值仍由前端 ModelEngine 完成。

## 2. 总体链路

计划链路：

```text
用户输入
  -> TurnCoordinator begin_turn 得到 turn_id
  -> 主模型生成助手文本
  -> on_decorating_result / emit_message_chain 前后拿到可见助手文本
  -> PerformanceCurveService 异步调用表演曲线 Provider
     key = turn_id + message_id
     output = ag99.performance_curve_hint.v1
  -> TTS 同时合成音频
  -> Adapter 发送 engine.motion_intent / engine.performance_curve_hint / output.audio
  -> 如果曲线 hint 已完成，则附加到 motion intent 或同 segment 上下文
  -> 前端音频起播，得到真实 audio duration
  -> ModelEngine TimingStage 使用 duration + curve hint 求解 timing
  -> Live2D runtime 执行 engine.parameter_plan.v2
```

关键原则：

- `turn_id` 是轮次归属的硬边界。
- `message_id` 是 segment 归属的硬边界。
- 曲线结果是 best-effort 辅助信息，缺失时必须回退现有 timing。

## 3. 配置

插件配置项：

```json
{
  "enable_performance_curve": true,
  "performance_curve_provider_id": "curve-mini-model"
}
```

字段说明：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enable_performance_curve` | bool | `false` 或灰度阶段 `true` | 是否启用表演曲线生成 |
| `performance_curve_provider_id` | string | `""` | 独立表演曲线聊天 Provider；留空时回退到当前会话聊天 Provider |

Provider 选择规则：

- 若配置了 `performance_curve_provider_id`，优先使用该聊天 Provider 发起辅助调用。
- 若 `performance_curve_provider_id` 留空，回退到当前会话聊天 Provider。
- 不使用 `motion_analysis_provider_id` 作为默认曲线 Provider。
- 曲线辅助调用不写入 AstrBot 聊天历史。
- Provider 不可用时只记录失败，不影响回复和播放。

RuntimeState 计划新增字段：

```python
enable_performance_curve: bool
performance_curve_provider_id: str
selected_performance_curve_provider: Provider | None
```

## 4. 曲线 Hint 协议

### 4.1 小模型输入上下文

曲线辅助调用不是重新生成动作参数，但它必须拿到主模型已经产生的语义材料，否则只能根据裸文本猜节奏。

后端调用曲线 Provider 时至少传入：

```json
{
  "turn_id": "turn-xxx",
  "message_id": "message-xxx",
  "assistant_text": "可见助手回复文本",
  "assistant_reply_keywords": ["调侃", "轻快", "解释"],
  "motion_intent_tags": ["teasing", "light", "self_intro"],
  "motion_effect_summary": {
    "intent_tags": ["teasing", "light"],
    "axis_keys": ["head_yaw", "mouth_smile"],
    "resource_id": ""
  },
  "chat_context": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ]
}
```

字段来源：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `assistant_text` | `emit_message_chain` 中剥离 inline 标记后的可见回复 | 必填；曲线的主要语义依据 |
| `assistant_reply_keywords` | 主模型返回的文本关键词；缺失时由本地从 `assistant_text` 做轻量提取 | 推荐；用于捕捉语气、句式、强调点 |
| `motion_intent_tags` | `ag99live.motion` Persona Effect / resolved motion payload | 推荐；动作参数不用重新生成，但关键词对曲线有价值 |
| `motion_effect_summary` | middleware 对 effect_calls 的摘要 | 可选；帮助曲线模型理解动作大致类型 |
| `chat_context` | Motion Lab 当前 chat buffer | 可选；用于理解上一轮语气和上下文 |

注意：

- 曲线小模型可以读取动作关键词，但不能输出动作轴。
- 如果主模型已经给了 `intent_tags`，曲线模型应该优先使用这些关键词。
- 如果 `intent_tags` 晚于曲线任务可用，MVP 可以先只用 `assistant_text + assistant_reply_keywords`，后续再在 middleware result 阶段补发更完整的曲线请求。
- 记录到 Motion Lab 时，应保存曲线模型实际使用的文本和关键词，便于后续训练样本对齐。

### 4.2 输出协议

新增内部 hint schema：

```json
{
  "schema_version": "ag99.performance_curve_hint.v1",
  "curve_family": "quick_in_hold_soft_out",
  "entry": "quick",
  "hold": "steady",
  "exit": "soft",
  "emphasis": "early",
  "energy": "low"
}
```

允许枚举初版建议：

| 字段 | 候选值 | 含义 |
| --- | --- | --- |
| `curve_family` | `default`, `quick_in_hold_soft_out`, `slow_in_hold_quick_out`, `pulse_then_settle`, `soft_breathe` | 曲线族 |
| `entry` | `instant`, `quick`, `soft`, `slow` | 进入速度 |
| `hold` | `short`, `steady`, `long`, `breathing` | 中段保持方式 |
| `exit` | `quick`, `soft`, `slow` | 退出方式 |
| `emphasis` | `none`, `early`, `middle`, `late`, `punctuated` | 强调位置 |
| `energy` | `low`, `medium`, `high`, `teasing`, `calm` | 表演能量 |

约束：

- 小模型只能输出上述字段。
- 未知字段丢弃并写 diagnostics。
- 未知枚举值回退到字段默认值。
- hint 不包含毫秒、不包含参数值、不包含最终 `engine.parameter_plan.v2`。

## 5. 曲线方程与求值

小模型输出是 symbolic spec，本地 builder 将其转换为归一化方程。

输入：

```text
duration_ms = 当前音频真实剩余时长或目标时长
hint = ag99.performance_curve_hint.v1
mode = idle / expressive
speechActive = true / false
```

输出：

```json
{
  "duration_ms": 2400,
  "blend_in_ms": 240,
  "hold_ms": 1680,
  "blend_out_ms": 480
}
```

求值规则初版：

| `entry` | 进入比例 |
| --- | --- |
| `instant` | 0.04 |
| `quick` | 0.10 |
| `soft` | 0.16 |
| `slow` | 0.24 |

| `exit` | 退出比例 |
| --- | --- |
| `quick` | 0.12 |
| `soft` | 0.22 |
| `slow` | 0.30 |

安全 clamp：

- `blend_in_ms`: 60-480
- `blend_out_ms`: 100-720
- `hold_ms`: 不低于 120
- `duration_ms`: 仍受现有 `MIN_MOTION_DURATION_MS / MAX_MOTION_DURATION_MS` 保护

曲线族可以进一步修正比例：

- `quick_in_hold_soft_out`: 进入偏快、退出偏软。
- `slow_in_hold_quick_out`: 进入偏慢、退出偏快。
- `pulse_then_settle`: 进入后允许前段强调窗口，后段更稳。
- `soft_breathe`: 适合低能量说话，进入和退出都偏软。

后续可扩展 `accent_windows`：

```json
{
  "accent_windows": [
    { "at": 0.18, "strength": 0.55, "shape": "pulse" }
  ]
}
```

MVP 不要求 runtime 使用 `accent_windows`，可以先只记录和诊断。

## 6. 播放应用方式

表演曲线的播放应用分两层，不建议一开始就把 Live2D runtime 改成任意曲线播放器。

### 6.1 MVP：求解为现有 timing

当前 `engine.parameter_plan.v2` 已经有：

```json
{
  "timing": {
    "duration_ms": 2400,
    "blend_in_ms": 240,
    "hold_ms": 1680,
    "blend_out_ms": 480
  }
}
```

Live2D runtime 当前根据这三个阶段和 `smoothstep` 做全局 easing。MVP 应该复用这条路径：

```text
performance_curve_hint + audio_duration
  -> resolvePerformanceCurveTiming()
  -> blend_in_ms / hold_ms / blend_out_ms
  -> 现有 parameter_plan timing
  -> 现有 Live2D 播放器执行
```

这样第一阶段只改变“进入多快、保持多久、退出多软”，不改变参数计划播放器协议。

示例：

```text
curve_family = quick_in_hold_soft_out
audio_duration = 2400ms

entry ratio = 0.10
exit ratio = 0.22

blend_in = 240ms
blend_out = 528ms
hold = 1632ms
```

优点：

- 不需要重写播放器。
- 对旧 payload 完全兼容。
- 可通过现有 motion playback record 观察最终 timing。
- 小模型慢或失败时，仍走当前默认 `resolveMotionTiming()`。

### 6.2 进阶：参数计划携带曲线描述

如果 MVP 证明有价值，再扩展 `engine.parameter_plan.v2` 或后续 v3，让参数计划携带完整曲线描述：

```json
{
  "performance_curve": {
    "schema_version": "engine.performance_curve.v1",
    "curve_family": "pulse_then_settle",
    "easing": {
      "entry": "ease_out_cubic",
      "hold": "micro_drift",
      "exit": "ease_in_out_soft"
    },
    "accent_windows": [
      { "at": 0.18, "strength": 0.55, "shape": "pulse" }
    ]
  }
}
```

这时 Live2D runtime 不再只看 `blend_in/hold/blend_out`，而是每帧计算：

```text
normalized_time = elapsed_ms / duration_ms
curve_weight = performance_curve(normalized_time)
parameter_value = base + (target - base) * curve_weight
```

进阶版适合做：

- 前段强调。
- 中段微呼吸。
- 退出前回看或轻微停顿。
- 依据标点或语气切分多个强调窗口。

但这会增加 runtime 协议、播放器和测试复杂度，所以不作为第一阶段。

## 7. 后端实现计划

### 7.1 新增模块

建议新增：

```text
astrbot_plugin_ag99live_adapter/
  motion/
    performance_curve.py
  prompts/
    performance_curve.py
```

`motion/performance_curve.py` 负责：

- Provider 调用封装。
- 曲线输出 JSON 提取。
- hint normalize / validate。
- 异步任务管理。
- Motion Lab 事件记录。

`prompts/performance_curve.py` 负责：

- system prompt。
- user prompt。
- 枚举字段说明。
- 少量固定 few-shot。

### 7.2 RuntimeState

新增：

```python
self.enable_performance_curve = False
self.performance_curve_provider_id = ""
self.selected_performance_curve_provider = None
```

刷新配置时：

- 读取 `_conf_schema.json`。
- 开关启用时，优先绑定 `performance_curve_provider_id` 指定的聊天 Provider。
- 若未配置独立 Provider，则回退到 AstrBot 当前会话正在使用的聊天 Provider。
- 获取失败时记录 runtime diagnostic，但不影响主链路。

### 7.3 TurnCoordinator 集成点

当前 `emit_message_chain()` 已在文本拆分和音频发送之间拿到：

- `turn_id`
- `segment_message_id`
- `reply_text`
- `raw_reply_text`
- `platform_extras`

计划在 `reply_text` 确定后启动曲线任务。任务输入要同时携带可见回复文本和可获得的关键词：

```python
curve_key = f"{turn_id}:{segment_message_id}"
runtime_state.performance_curve_service.start(
    turn_id=turn_id,
    message_id=segment_message_id,
    assistant_text=reply_text,
    assistant_reply_keywords=resolve_assistant_reply_keywords(event_or_result),
    motion_intent_tags=resolve_motion_intent_tags(platform_extras_dict),
    motion_effect_summary=resolve_motion_effect_summary(platform_extras_dict),
    chat_context=self._motion_lab_chat_context(),
)
```

不要 await 长时间任务。发送 motion payload 时尝试读取已完成结果：

```python
curve_hint = runtime_state.performance_curve_service.get_ready(
    turn_id=turn_id,
    message_id=segment_message_id,
)
```

如果 ready：

- 若 motion 出站时已 ready，附加到 motion payload 并记录 `performance_curve.attached`。
- 若音频出站前才 ready，发送 `engine.performance_curve_hint` patch 并记录 `performance_curve.egress_sent`。

如果未 ready：

- 不阻塞。
- 音频出站前仍未 ready 时，取消当前曲线任务并记录 `performance_curve.failed`，原因可用 `not_ready_before_audio_egress`。
- 前端走默认 timing。

### 7.4 Payload 附加位置

优先方案：附加到 `engine.motion_intent.v4`：

```json
{
  "schema_version": "engine.motion_intent.v4",
  "intent_tags": ["..."],
  "axis_levels": { "...": 1 },
  "performance_curve_hint": {
    "schema_version": "ag99.performance_curve_hint.v1",
    "curve_family": "quick_in_hold_soft_out",
    "entry": "quick",
    "hold": "steady",
    "exit": "soft",
    "emphasis": "early",
    "energy": "low"
  }
}
```

注意：

- 这是 intent 的可选辅助字段。
- normalize 层要接受该字段并只保留合法 hint。

备选方案：作为 envelope payload 旁路字段传输。但这会让 ModelEngine 获取成本更高，MVP 不推荐。

## 8. 前端实现计划

### 8.1 类型与归一化

新增类型：

```ts
export interface PerformanceCurveHint {
  schema_version: "ag99.performance_curve_hint.v1";
  curve_family: string;
  entry: string;
  hold: string;
  exit: string;
  emphasis: string;
  energy: string;
}
```

`SemanticMotionIntent` 增加可选字段：

```ts
performance_curve_hint?: PerformanceCurveHint;
```

`normalizeMotionPayload()` / `planParser` 不直接求值，只做：

- schema 校验。
- 枚举 normalize。
- 非法值回退或丢弃。

### 8.2 TimingStage

`CompileOptions` 增加：

```ts
performanceCurveHint?: PerformanceCurveHint | null;
```

或直接从 `context.intent.performance_curve_hint` 读取。

`timingStage` 调整为：

```text
targetDurationMs + speechActive + performance_curve_hint
  -> resolveMotionTiming()
```

`resolveMotionTiming()` 增加可选参数：

```ts
performanceCurveHint?: PerformanceCurveHint | null;
```

如果 hint 合法：

- 用 hint 生成比例。
- 根据 `targetDurationMs` 或 `duration_hint_ms` 求出实际 timing。
- diagnostics `timingSource` 可扩展为 `performance_curve_audio_sync` / `performance_curve_hint`，或先保留 `audio_sync` 并在 warnings 写入 `performance_curve_applied`。

MVP 建议少改公共类型，并只把曲线求解为现有 timing：

- `timingSource` 暂不新增枚举。
- warnings 添加：
  - `performance_curve_applied:quick_in_hold_soft_out`
  - `performance_curve_dropped:invalid_schema`

### 8.3 播放记录与 Motion Lab

`DesktopMotionPlaybackRecord` 已记录 `plan.timing` 和 diagnostics。新增后可看到最终求值 timing。

前端不直接写 SQLite；仍通过后端 Motion Lab raw event 记录：

- 后端记录 hint 生成事件。
- 后端记录 hint attached 事件。
- 前端现有 playback started/completed 事件保持不变。

新增 event types：

```text
performance_curve.requested
performance_curve.resolved
performance_curve.failed
performance_curve.attached
```

事件字段约定：

```json
{
  "event_type": "performance_curve.resolved",
  "turn_id": "turn-xxx",
  "message_id": "message-xxx",
  "source_route": "performance_curve_provider",
  "phase": "performance_curve",
  "assistant_text": "可见助手回复",
  "payload_kind": "ag99.performance_curve_hint.v1",
  "raw": {
    "provider_id": "curve-mini-model",
    "assistant_reply_keywords": ["调侃", "轻快"],
    "motion_intent_tags": ["teasing", "light"],
    "curve_hint": {},
    "completion_text": "{}",
    "latency_ms": 320
  }
}
```

隐私和体积策略：

- `assistant_text` 可保留，因为训练样本本身需要文本。
- prompt 可先不完整保存，或只保存截断版。
- completion_text 可保存原始文本，便于调试小模型输出。
- 失败事件记录 failure_reason，不记录异常堆栈全文。

## 10. 并发与生命周期

任务 key：

```text
{turn_id}:{message_id}
```

要求：

- `turn_id` 为空不启动任务。
- `message_id` 为空时可退化为 `{turn_id}:__default__`，但应记录 warning。
- 同 key 新任务会替换旧任务。
- turn 结束后可清理过期任务和结果。
- 结果缓存短期保留，用于 attach 和 Motion Lab 记录；不进入长期 runtime cache。

建议结构：

```python
class PerformanceCurveRuntime:
    def start(...)
    def get_ready(turn_id, message_id) -> dict | None
    def fail_if_not_ready(turn_id, message_id, reason) -> bool
    def cancel_turn(turn_id)
    def prune_expired()
```

失败模式：

| 失败 | 行为 |
| --- | --- |
| 当前会话 Provider 不可用 | 不启动或记录 `performance_curve.failed` |
| 输出非 JSON | 记录 failed，播放回退默认 timing |
| hint 非法 | normalize 后回退字段默认值；严重非法则丢弃 |
| 任务晚于 audio egress 前检查完成 | 取消任务，记录 `performance_curve.failed:not_ready_before_audio_egress`，不发送 patch |

## 11. 实施阶段

### Phase 1：协议与纯函数

- 定义 `ag99.performance_curve_hint.v1`。
- 新增后端 normalize / validate。
- 新增前端类型与 normalize。
- 新增前端 timing builder 纯函数和单测。
- 明确曲线 Provider 输入中的 `assistant_text / assistant_reply_keywords / motion_intent_tags` 字段。

验收：

- 合法 hint 能生成稳定 timing。
- 非法 hint 回退默认 timing。
- 旧 motion intent 不受影响。

### Phase 2：配置与 Provider

- `_conf_schema.json` 新增配置项。
- `RuntimeState` 在启用时优先绑定 `performance_curve_provider_id`，留空时回退到当前会话聊天 Provider。
- 新增 prompt builder。
- 新增异步曲线生成服务。
- 写入 `performance_curve.requested/resolved/failed`。
- Motion Lab 记录曲线模型实际使用的回复文本和关键词。

验收：

- 当前会话 Provider 不可用时无行为回归。
- Provider 慢、未 ready 或失败不阻塞 TTS 和播放。
- resolved/failed 能写入 Motion Lab SQLite。

### Phase 3：后端 attach

- 在 `emit_message_chain` 里按 `turn_id + message_id` 启动曲线任务。
- 在 motion payload egress 前尝试附加 ready hint。
- 在 audio egress 前再次检查；若此时才 ready，则发送独立 `engine.performance_curve_hint` patch。
- 记录 `performance_curve.attached` / `performance_curve.egress_sent`。

验收：

- 同 turn 多 segment 不串线。
- 无 hint 时仍按现有 timing 播放。
- 有 hint 且 motion 尚未释放时，前端能在编译前拿到 `performance_curve_hint`。

### Phase 4：前端求值

- `SemanticMotionIntent` 接收 `performance_curve_hint`。
- `engine.performance_curve_hint` patch 按 `turn_id + message_id` 暂存到同 segment。
- motion 释放给 ModelEngine 前把 patch 浅合并到 semantic intent。
- `TimingStage` 使用 hint + audio duration 求值。
- diagnostics 标记曲线是否应用。
- MVP 仅输出现有 `blend_in_ms / hold_ms / blend_out_ms`，不扩展播放器曲线权重。

验收：

- 音频同步场景下 timing 根据真实音频时长变化。
- preview / no-audio 场景回退 `duration_hint_ms` 或默认值。
- 播放记录里能看到最终 plan timing。

### Phase 5：调试和动作实验室展示

- Motion Lab 查询页后续可展示曲线 hint、最终 timing 和播放结果。
- Action Lab / 历史动作工作台可显示曲线族和进出速度。

验收：

- 用户能按 `turn_id` 看到文本、动作 intent、曲线 hint、最终 playback 事件。

## 12. 测试计划

后端单测：

- Provider 未配置不启动任务。
- Provider 返回合法 JSON，生成 normalized hint。
- Provider prompt 包含 `assistant_text` 和可用的回复关键词。
- 曲线任务未赶上音频出站前检查时写 failed，不抛到主链路。
- 同一 `turn_id + message_id` 正确读取 ready result。
- Motion Lab 写入 requested/resolved/failed/attached。

前端单测：

- `resolveMotionTiming()` 默认行为保持不变。
- `quick_in_hold_soft_out` 在 2400ms 下生成预期 timing。
- 曲线 hint 只影响最终 timing，不改变参数轴值。
- 极短 duration 下 clamp 后仍合法。
- 非法 hint 被丢弃并回退默认 timing。
- speech-only payload 也能使用 hint，但没有 hint 时保持现状。

集成验证：

- 文本回复后 TTS 期间曲线任务并行启动。
- 音频起播后动作 timing 跟音频时长对齐。
- 小模型慢于 TTS 时不阻塞播放。
- Motion Lab raw events 可按 `turn_id/message_id` 串起。

## 13. 风险与取舍

主要风险：

- 小模型慢，曲线结果来不及赶上 audio egress 前检查。
- 字段过多让协议和调试复杂度上升。
- 多 segment turn 中 `message_id` 错配会导致曲线用错。
- 曲线生成成功但前端没有音频 duration 时只能按 hint/default 求值。
- MVP 只能控制全局进入/保持/退出，不能做真正的分段参数权重波形。

取舍：

- MVP 不等待曲线任务，不补发完整 motion；只允许按 `turn_id + message_id` 发送窄 `engine.performance_curve_hint` patch。
- 小模型只输出枚举，牺牲自由度换稳定性。
- 前端求值优先使用真实音频时长，后端不猜最终毫秒。
- 数据库记录完整 trace，训练页后续再做筛选视图。
- 真正的每帧曲线权重播放器放到第二阶段，避免第一阶段过度扩大协议。

## 14. 推荐第一步

第一步不要直接接 Provider。建议先做纯函数和协议骨架：

1. 后端定义 `normalize_performance_curve_hint()`。
2. 前端定义 `PerformanceCurveHint` 和 `resolvePerformanceCurveTiming()`。
3. `engine.motion_intent.v3/v4` 允许携带可选 `performance_curve_hint`，自动主链路使用 v4。
4. 单测确认默认行为不变。

这样可以先把“方程求值”和“协议承载”打稳，再接异步小模型和数据库事件。
