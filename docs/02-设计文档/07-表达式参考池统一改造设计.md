# 表达式参考池统一改造设计

更新时间：2026-05-20

## 1. 目标

分阶段建设动作 LLM 的参考池。

当前阶段先接入扫描产物（`expression_example_library`），让用户可以在调参面板中查看模型原生表达式参考，并切换是否提供给 LLM。

后续阶段再把扫描产物和用户调参样本（`motion_tuning_samples`）合并成同一套统一参考池列表。

## 2. 数据流现状

后端扫描 → .exp3.json → scan.py → constraints.expressions
→ `_build_expression_example_library()`（原始值→0-100语义轴值）
→ `model_info.models[*].expression_example_library.examples`
→ `RuntimeState.model_info`
→ `system.model_sync`
→ 前端 `selectedModel.expression_example_library.examples`
→ `buildModelProjectionSnapshot()`
→ 调参面板展示

当前事实源：

- 后端 `RuntimeState.model_info.models[*].expression_example_library.examples` 是表达式参考的当前有效状态。
- prompt 选择 model native few-shot 时读取同一个 `RuntimeState.model_info`。
- 前端调参面板只展示后端同步后的模型投影，不单独重算表达式参考。

## 3. 新增协议消息

| 消息类型 | 方向 | 用途 |
|---|---|---|
| `system.expression_example_override_save` | 前端→后端 | 保存覆盖（model_name、example_id、enabled、feedback、tags） |
| `system.expression_example_override_delete` | 前端→后端 | 删除覆盖（model_name、example_id），恢复模型默认状态 |
| `system.expression_example_overrides_state` | 后端→前端 | 推送覆盖状态 |

覆盖项作用域：

- 覆盖项必须带 `model_name`。
- 同名表达式只在对应模型内生效，避免不同模型的 `happy`、`angry` 等表达式互相串扰。
- 用户关闭表达式时保存 override；用户重新开启时删除 override，表示恢复默认。

## 4. 默认值策略

`EXPRESSION_KEYWORD_REFERENCES`（7 组关键词参考）和 `DEFAULT_SELECTOR_FEW_SHOT_EXAMPLES`（5 个示例）保留为 prompt 的兜底参考。

few-shot 来源顺序保持：

1. 用户确认过的 `motion_tuning_samples`
2. 当前模型启用状态下的 `expression_example_library.examples`
3. 默认示例

禁用的扫描表达式不进入 model native few-shot 候选。

## 5. 涉及文件（11个）

### 后端（5个）

1. `protocol/constants.py` — 新增三个消息类型常量
2. `runtime/state.py` — 新增 `expression_example_overrides` 存储字段、`save/delete/list` 方法
3. `runtime/cache/runtime_cache.py` — cache schema 新增 `expression_example_overrides` 段
4. `prompts/motion_selector.py` — 从当前 `RuntimeState.model_info` 读取已应用 override 的表达式参考
5. `services/frontend_system_service.py` — 新增消息处理分支

### 前端（6个）

6. `types/protocol.ts` — 新增消息类型声明
7. `types/desktop.ts` — 新增 `DesktopExpressionExample` 类型，扩展 `DesktopModelProjectionSnapshot`
8. `desktop-bridge/snapshot.ts` — 归一化处理
9. `composables/usePetRuntimeSnapshotPublisher.ts` — 提取 expression_example_library 注入 snapshot
10. `components/MotionTuningPanel.vue` — 展示扫描表达式参考并切换是否提供给 LLM
11. `composables/useAdapterConnection.ts` — 新增状态字段与入站事件处理

## 6. 实施顺序

1. 后端核心：state.py + runtime_cache.py
2. 协议：constants.py + builder.py + parser.py
3. 后端服务：frontend_system_service.py
4. 前端类型：protocol.ts + desktop.ts + snapshot.ts
5. 前端发布：usePetRuntimeSnapshotPublisher.ts
6. 前端 UI：MotionTuningPanel.vue
7. prompt 改造：motion_selector.py
