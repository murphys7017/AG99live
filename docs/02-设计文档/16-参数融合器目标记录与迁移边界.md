# 参数融合器目标记录与迁移边界

> 状态：实施中。本文是当前主动参数融合迁移的目标记录，只描述目标结构、范围和验收条件。

## 1. 要解决的问题

当前 WebSDK 的一帧内已有多个主动参数来源：Cubism motion/idle、expression、drag、breath、
语义参数计划、说话手势、口型和语音能量。它们按 `LAppModel.update()` 的书写顺序直接或间接影响
模型参数，导致同一参数的组合、优先级、范围裁剪和诊断分散在不同位置。

这不是要重建 Timeline、动作语义编译或 Cubism Physics，而是要收回它们之间的参数写入权：

```text
各模块已计算好的参数贡献
  -> Parameter Mixer
  -> ResolvedParameterFrame
  -> LAppModel 唯一主动参数写入
  -> Cubism Physics / Pose / update / draw
```

## 2. 目标

Parameter Mixer 是 WebSDK 前的窄运行时组件。它在每一帧：

1. 读取 Cubism motion、expression、drag、breath 已产生的 base parameter snapshot。
2. 接收主动来源提交的确定性参数贡献。
3. 以显式 `replace`、`add`、`multiply`、权重和优先级组合贡献。
4. 依据模型运行时的最小/最大值裁剪结果。
5. 产出带来源诊断的唯一 `ResolvedParameterFrame`。
6. 由 `LAppModel` 在 Cubism Physics 前一次性写入该帧。

第一个迁移批次覆盖：

- direct parameter plan 的静态姿态、序列轨道、说话手势轨道与 `ParameterPresentation` 结果；
- HTMLAudioElement RMS 产生的 lip-sync mouth contribution；
- 独立 `SpeechSignalRuntime` 管理的 speech-energy signal 与包络。

`ParameterPresentation` 保留为 direct plan source 的时间轨道和主动动力学求值器；它不再拥有跨来源
组合或模型写入权。九级语义轴转换、随机采样和参数绑定仍只属于 ModelEngine，Parameter Mixer 不增加
随机，也不重新解释 `axis_levels`。

`SpeechSignalRuntime` 不属于 Parameter Mixer。它以音频 sink 创建的 source identity 管理一段活动音频的
mouth 与 energy 值，在 source 显式结束后释放原始信号，并仅计算说话手势需要的 head/body 包络。它不
解析、组合或写入 Live2D 参数；Mixer 只接收已经计算好的 lip-sync contribution。

## 3. 非目标

以下职责不迁入 Parameter Mixer：

- PlaybackTimeline、时钟、segment 生命周期、sink 成功或失败语义；
- LLM 动作决策、`motion_steps`、九级等级采样、语义轴关系图和参数计划编译；
- 音频 RMS 分析、口型降级策略和说话手势规划本身；
- catalog motion、expression 的资源选择和播放器生命周期；
- Cubism Motion、EyeBlink、Expression、drag、breath、Physics、Pose、`model.update()` 与 draw；
- Motion Lab 持久化、VTube Studio 录制和训练数据导出。

Cubism Motion/Expression 等原生运行仍先写出 base snapshot。融合器只统一 AG99 主动参数层，绝不直接写
`Phy*`、`Anim*`、marker 或其它由 Cubism Physics/动画系统拥有的参数。

## 4. 所有权与输入

| 输入 | 所有者 | 进入融合器的形式 |
| --- | --- | --- |
| Cubism base values | Cubism Motion / Expression / drag / breath | 只读 base snapshot |
| 语义参数计划 | ModelEngine + direct plan source | `replace` contribution |
| 说话手势 | SpeechPoseStage + direct plan source | `replace` contribution，已在 source 内形成轨道 |
| speech energy | lip-sync sink + SpeechSignalRuntime | 只读 signal，供说话手势 source 调节幅度 |
| lip sync mouth | lip-sync sink + SpeechSignalRuntime | `add` contribution |
| 物理输出 | Cubism Physics | 不进入融合器 |

`replace` 表示相对 base 的显式目标，可带混合权重；`add` 表示在当前已解析值上的偏移；`multiply` 为后续
确有需要的比例修正预留。相同参数的贡献必须按稳定优先级解析，最后只保留一个数值。冲突不能依赖调用
顺序隐式决定。

## 5. 迁移原则

1. 先提取现有 direct plan、口型和 speech-energy 的真实行为，再收敛到一个出口；不得新增旧新双轨。
2. 每个主动来源只负责计算自己的值，不调用 `CubismModel.setParameterValueById()`。
3. `LAppModel` 只在融合结果应用点写主动参数；写入失败必须让关联 direct plan 明确失败。
4. mouth 与语义动作若命中同一参数，必须按显式规则组合，不能由“谁最后写入”决定。
5. 各 source 的值、操作、权重、范围裁剪和最终值必须能以低频诊断追溯。
6. 参数融合器不做 fallback。缺少必需运行时参数、不可写绑定或无效贡献必须可见失败。
7. 音频 source 必须显式 begin、write、end；不得用更新时间超时隐式丢弃 mouth 或 speech-energy 信号。

## 6. 完成标准

- direct plan 与 lip-sync 不再在不同帧阶段分别写模型参数。
- WebSDK 主动参数在 Physics 前只有一个融合后的写入出口。
- `ParameterPresentation` 不再自行与跨来源结果竞争，也不保存第二套范围/写入规则。
- speech energy 仅作为确定性 source signal，且不以逐帧随机方式改变姿态方向。
- Parameter Mixer 不持有音频缓存、source 生命周期或超时清理规则。
- 运行日志可以回答某参数在某帧的 base、各贡献、裁剪与最终值。
- 真实 Electron 对话需验证：语义动作、口型、说话随动和 Cubism Physics 同时可见，且计划结束释放时不跳变。

最小自动验证只覆盖融合器的正常组合与非法贡献拒绝；它不能替代真实模型、音频和 Physics 验收。
