# 预录制资产层与实时语义动作的分工设计

> 文档状态：未来资产层边界文档。
>
> 本文只说明预录制 motion / expression / catalog 资源未来如何作为独立 Asset Accent Layer 接入。它不是当前 LLM 自动动作输出契约。当前动作入站契约以 [动作意图标签化与资源派生设计](./10-动作意图标签化与资源派生设计.md) 为准。
>
> 资源层可以在未来消费受控 `resource_id`，但不能把 `choice`、`motion_id`、`motion3`、`exp3` 或 catalog selector 重新带回普通自动动作链路。

## 目标

本文记录一个已确认保留、但暂缓实现的动作演进方案：在继续以实时语义动作生成为主链路的前提下，保留预录制 motion / expression / catalog 资源作为未来的高质量资产层。

当前优先级仍是先稳定 `intent_tags + axes + optional resource_id` 的语义动作主链路。本文不要求立即实现资产播放策略，也不改变当前自动动作必须先产出 `engine.motion_intent.v3` 的边界。

目标分工：

```text
日常对话 / 语义姿态 / 说话随动
  -> engine.motion_intent.v3
  -> Frontend ModelEngine
  -> engine.parameter_plan.v2
  -> Live2D runtime

特殊手势 / 高质量表情 / 事件反馈 / 失败兜底
  -> Asset Accent Layer
  -> 预录制 motion3 / exp3 / asset pose
  -> 与实时参数计划协调或混合播放
```

## 与当前主链路的关系

当前自动动作链路仍然只允许输出 `engine.motion_intent.v3`。预录制资产层不是把 `catalog_motion` 重新塞回当前 LLM 自动动作链路，也不是让 LLM 直接返回 `motion_id`、`choice`、`motion3` 或 `exp3`。

当前主链路保持不变：

```text
AstrBot / Adapter 生成语义动作 intent
  -> Adapter normalize / repair / fallback
  -> engine.motion_intent.v3
  -> Frontend ModelEngine 编译为 engine.parameter_plan.v2
  -> Live2D runtime 执行参数计划
```

预录制资产层的定位是未来的独立增强层。它可以读取语义、事件、用户命令和当前播放状态，但必须通过明确的策略仲裁后才触发资产播放，不能让大模型裸选资源文件。

## 为什么要保留这条路径

实时语义生成和预录制资产解决的问题不同。

实时语义生成的优势：

- 可以贴合每一句回复的语义、语气和时长。
- 可以和语音、口型、说话随动、视线、头身姿态连续协同。
- 可以避免角色表现被固定素材库锁死。
- 可以让同一个情绪在不同上下文里有细微差异。

预录制资产的优势：

- 模型作者或用户精修过的动作质量更高。
- 特定手势和表情的节奏、曲线和完成度更稳定。
- 礼物、关注、按钮命令等强事件更适合固定高识别度反馈。
- 当实时语义生成失败、太弱或不适合表达某个固定动作时，可以作为可控兜底。

因此不应二选一。更合理的方向是：日常生命感由实时语义层承担，少数强表现点由资产层补强。

## 三层动作体系

### 1. Living Layer

Living Layer 是角色持续存在的本底层。

典型内容：

- 呼吸
- 眨眼
- 空闲微动
- 物理响应
- 基础视线和待机状态
- 语音口型等 runtime 驱动参数

这层不应由 LLM 每轮显式生成，也不应被预录制资产长期占用。它负责让角色一直“活着”。

### 2. Semantic Motion Layer

Semantic Motion Layer 是当前自动动作主层。

典型内容：

- 日常聊天姿态
- 跟随文本语义的头身动作
- 说话时的随动和强调
- 情绪强弱、犹豫、回避、惊讶、调侃等语义姿态
- 根据音频长度或 segment 状态重定时的参数计划

这层继续走：

```text
engine.motion_intent.v3 -> ModelEngine -> engine.parameter_plan.v2
```

它是默认路径。只要用户或系统没有明确触发特殊资产，普通回复都应优先使用这层。

### 3. Asset Accent Layer

Asset Accent Layer 是未来保留的高质量强调层。

典型内容：

- 招手、鞠躬、鼓掌、比心、庆祝等固定手势。
- 害羞、震惊、得意、强烈惊喜等作者精修表情。
- 直播事件反馈，例如礼物、关注、订阅、高价值互动。
- 用户按钮或快捷指令触发的明确动作。
- 实时语义生成失败、过弱或无法覆盖固定表现时的可控兜底。

这层不替代 Semantic Motion Layer。它只在“固定资产明显更合适”的场景中短时接管或叠加。

## 使用策略

默认策略：

- 普通对话使用实时语义生成。
- 说话随动、微表情、语义姿态使用实时语义生成。
- 明确固定手势、直播事件、用户按钮命令使用预录制资产。
- 强情绪但没有固定形状时使用实时语义生成。
- 强情绪且存在高质量专用资产时使用混合模式。
- LLM 结果无效或表现太弱时，先走语义 fallback pose；未来可按策略升级到资产兜底。

决策表：

| 场景 | 推荐路径 | 原因 |
| --- | --- | --- |
| 日常聊天回复 | 实时语义生成 | 需要贴合文本和语气 |
| 说话时头身随动 | 实时语义生成 | 需要和音频时长、口型连续协同 |
| 微表情和轻姿态 | 实时语义生成 | 不值得打断角色连续性 |
| 长句中的强调、疑问、转折 | 实时语义生成 | 需要按 segment 和语义变化重定时 |
| 招手、鞠躬、鼓掌、比心 | 预录制资产 | 固定手势质量和识别度更重要 |
| 礼物、关注、订阅等事件 | 预录制资产 | 事件反馈应稳定、明确、可复用 |
| 用户点击动作按钮 | 预录制资产 | 用户意图是触发一个确定动作 |
| 专用 exp3 强表情 | 资产或混合 | 作者精修表情通常优于实时拟合 |
| 强情绪但无专用资产 | 实时语义生成 | 继续保持语义驱动 |
| LLM 动作无效或太弱 | fallback pose，未来可资产兜底 | 保证可播放且可控 |

## 混合播放策略

未来实现资产层时，应优先支持混合模式，而不是只做互斥播放。

可行混合方式：

- exp3 或 asset pose 作为短时表情基底，实时语义层继续控制头、身、视线和说话随动。
- motion3 播放固定手势时，临时降低语义层对同参数的写入权重，避免抢参数。
- 资产播放结束前进入 blend out，让实时语义层接回角色姿态。
- 对说话中的资产触发，保留口型和必要 voice following，不让固定动作压死语音表现。

参数所有权原则：

- `runtime` 参数优先保护口型、呼吸、眨眼等生命感。
- 资产层只短时占用它实际需要的参数。
- 语义层在资产占用参数上降权或暂停，在未占用参数上继续工作。
- 所有接管、降权和恢复都应进入 diagnostics，方便排查“为什么这次没动”。

## 触发与仲裁

未来不应让 LLM 直接选择资源文件。推荐增加一个资产策略仲裁层：

```text
文本语义 / 事件类型 / 用户命令 / 当前播放状态
  -> Asset Policy / Arbitration
  -> allow / deny / mix / fallback
  -> Asset Accent Layer
```

仲裁层至少应检查：

- 触发来源：用户命令、系统事件、LLM 语义建议、fallback。
- 当前 turn / segment 状态：是否正在播放音频，是否允许打断。
- 资产类型：motion3、exp3、asset pose 或组合。
- 参数冲突：是否会覆盖口型、说话随动或当前关键动作。
- 冷却时间：同一资产是否短时间重复触发。
- 优先级：用户命令和高价值事件高于普通语义建议。
- 可恢复性：资产结束后是否能平滑回到语义层。

LLM 可以在未来提供“动作意图建议”，例如 `wave_intent`、`celebration_intent`，但最终资源选择必须由策略层根据白名单和上下文决定。

## catalog motion 的后续定位

`catalog_motion` 不应回到当前自动动作协议中。它未来可以重新定位为资产索引或工具层能力，而不是 LLM 输出契约。

允许的定位：

- 动作实验室的素材浏览、预览、标注和评分。
- 资产策略层内部的白名单索引。
- 用户按钮命令映射到具体资产。
- 系统事件映射到具体资产。
- fallback 或混合播放策略可引用的受控资产。

不允许的定位：

- prompt 注入完整 motion catalog 让 LLM 选择。
- LLM 直接输出 `choice=catalog`。
- LLM 直接输出 `motion_id` 作为播放目标。
- 后端把普通自动动作结果转成 `engine.catalog_motion.v1`。
- fallback 绕过语义 intent，直接播放旧 motion / expression。

## 非目标

本文不做以下事情：

- 不改变当前 `engine.motion_intent.v3` 自动动作契约。
- 不恢复旧的 catalog selector 自动链路。
- 不要求当前修复批次实现资产层。
- 不把 motion3 / exp3 注入到 LLM prompt 中作为可选动作列表。
- 不让前端绕过 ModelEngine 直接修改主运行时事实。
- 不删除动作实验室、预览、手动调试和模型扫描能力。

## 后续实现计划

建议在当前文本、动作、语音链路问题修复完成后，再按以下顺序推进：

1. 资产盘点：扫描 motion3、exp3、用户手调样本，建立只读资产索引。
2. 资产标注：给资产补充类型、适用场景、参数占用、时长、是否可打断、冷却时间。
3. 策略仲裁：新增 Asset Policy，先支持用户按钮和系统事件，不接入普通 LLM 自动链路。
4. 播放协调：定义资产层与 Semantic Motion Layer、Living Layer 的参数所有权和 blend 规则。
5. 诊断投影：记录资产触发、拒绝、混合、降权和恢复原因。
6. 小范围接入：先接固定按钮或直播事件，再评估是否允许 LLM 只输出受控“动作意图建议”。
7. 回归验证：覆盖音频播放中触发资产、资产结束回接语义层、连续事件冷却、fallback 等场景。

这条路径的判断标准不是“能不能播放旧素材”，而是：是否能在不破坏实时语义生命感的情况下，把少数高质量固定动作作为表现增强点接入。
