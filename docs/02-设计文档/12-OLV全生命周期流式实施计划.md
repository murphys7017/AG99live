## 职责、数据流与不变量

```text
正常输入 → 现有 Turn → Core Persona 小记录解析
                           ├─ 安全 speech 增量 → 文本流 → 桌面字幕
                           ├─ 同一可见增量 → Core PCM 服务 → Adapter → 有界播放 worker
                           └─ 合法意图 → Adapter 动作任务 → 完整合法 payload → 现有身体时间线
```

- **Core**拥有正常会话、Persona/内容校验、唯一 TTS Provider 消费及文本/音频生产终态。已提交前缀不可撤回，后续错误保留前缀并明确失败。
- **Adapter**沿用 TurnCoordinator、OutputSegmentCoordinator 和连接绑定 writer，拥有动作任务、发送顺序、信用等待及断线清理。Core→Adapter 是进程内事件边界，不另建网络协议或聊天 Turn。
- **桌面**沿用 SessionStore、PlaybackTimeline、ModelEngine 和同一输出图；拥有实际消费、口型、指定设备及本地结算。总时长未知可起播，欠载时播放时钟不虚走。
- 文本、音频、动作各自维护身份、序号和终态；段序与采样归属不随 Provider 完成顺序改变。同一内容不混用 M0 完整段和 M2 增量投递。
- 音频不等动作成功/失败；无音频动作可独立执行，过期或失败动作明确结算。默认 speech-only 不抢占仍 open 的语义动作流。
- `synth_finished` 代表生产关闭；桌面继续排空已接纳音频，所有本地任务结算后才发播放回执，后端据此结束 Turn。
- 取消、断线及代次退休必须唤醒排队/信用/播放等待；旧数据不能进入新 Turn，不重试可能已部分发送的歧义帧，不静默丢采样。
- 不兼容可选插件按既有调用期策略隔离并记录；不能跳过内容安全、身份和交付校验以换取速度。

## 配套加载与验收顺序

1. 核对当前 Core、Adapter、桌面构建及实际加载版本；未知项标 unknown，不能把部署副本一致当成已加载。
2. 核对 `olv.audio_credit.v1` 双端 manifest/runtime-settings 协商。必须配套加载后重连，字段与失败语义以 13 契约为准。
3. 取得真实 M2 冷/热短回复、两至三段、长回复/慢消费、首 PCM 前/播放中打断、断连重连、纯动作/动作迟到的记录。
4. 关联 frontend/Core/Persona/段身份，分别测首有效文本、首 PCM、软件首采样、首动作、生产结束与实际排空；记录失败、欠载和段间间隙。
5. 与可比 M0 条件对照后判断瓶颈；资源允许时增加样本，低样本不报告稳定 p95。实际缺口和失败如实记录，不承诺固定毫秒或提速比例。

具体场景、指标口径及退出条件使用 Core 14，不在本文件复制另一份验收清单。重启、模式切换、真实请求与发布遵循当前用户授权，本次文档整理未执行这些操作。

## 后续设计的边界

**动作小记录（T6/R6）：**当前 reader 累计完整响应，在 EOF 后解析 JSON，桌面也不替换已释放/本地终态的 payload。需先定义可独立校验执行的闭合记录、顺序/revision、有效窗口、音频采样或 segment_now 锚点及参数所有权，再同步 producer prompt、parser、协议协商和身体执行。不能截取半截旧 JSON，不能把 profile_revision 当作动作修订，不能让最终聚合重播已执行前缀。完成标准包括真实首动作早于模型 EOF、坏记录前缀保留、去重、打断和视觉连续性。

**保留用户约束：**暂不重构 Prompt；Memory 读取已发布快照、后台独立更新，不新增等待本轮记忆更新的屏障。复用已有麦克风触发准备，文本输入检测暂不做。

**按证据评估：**额外连接准备、首文本段头负担、ASR revision、AudioWorklet 和跨语义段连续 TTS 不是本轮已完成项目。先证明瓶颈与收益；跨段合成须证明采样归属，不直接移除 flush，不另建播放器/时钟或通用人格决策器，不修改 C++ runtime。

**历史待查：**M0 03:12 首段有 motion_ended 而无 motion_started，旧指标不能区分失败/中断；新日志已区分成功、失败、打断，但根因仍未确定。不能将 M2 speech-only 修正写成该历史问题的已验证修复。

**后到动作修正：**15:39–15:42 五轮 M0 的首段因缺少起播前预编译失败，已补已知时长窗口内的准备与接入采样归零。15:54 两轮实际 M2 的五段又因 PCM 总长未知而全部被拒绝；现保留 null 音频总长，使用既有有界动作时长准备，继续跟随原音频 reader，保留合法曲线与打断。M0/M2 公共案例均接入真实 ModelEngine/编译器，修复前复现、修复后通过，完整 Electron 构建通过；最终硬件接口仍为隔离接纳。真实设备方向、视觉交接及修复后成功 M2 仍待现场复测；不据新样本追认 03:12 旧样本的具体根因。
