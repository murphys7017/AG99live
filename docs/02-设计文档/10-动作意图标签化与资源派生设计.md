# 动作意图标签化与资源派生设计

> 文档状态：当前动作生成链路的权威规格。
>
> 本文是 prompt 构建、LLM 输出解析、middleware / inline 接收层、资源引用边界、调参样本和前端展示的当前依据。旧的 fallback pose 自动评分、运行时 repair、catalog selector 自动链路和直接让模型选择 motion / expression 文件的方案不再作为开发依据。

## 目标

AG99live 自动动作主链路只产出语义动作 intent，再由前端 `ModelEngine` 编译成 Live2D 参数计划：

```text
AstrBot / Adapter 生成动作入站 intent
  -> Adapter protocol normalize / resource validation / diagnostics
  -> engine.motion_intent.v4
  -> Frontend ModelEngine
  -> engine.parameter_plan.v2 或已解析 catalog motion
  -> PlaybackTimeline motion sink
  -> Live2D runtime
```

本链路的目标不是把动作重新做成情绪分类器，也不是让 LLM 裸选资源文件，而是把三类职责拆清楚：

1. `intent_tags` 描述本轮表演意图，保持模糊、开放、可组合。
2. `axis_levels` 用七级方向强度生成可编译、可播放的语义动作骨架。
3. `expression_resource_id` / `motion_resource_id` 明确引用受控资源；前者可叠加，后者是完整动作主层。

系统仍然以语义轴生成为主。资源文件可以作为姿态参考或受控 typed resource 输入，但不能把普通自动动作链路带回 `choice` / `motion_id` / `motion3` / `exp3` 选择器。

## 核心原则

### 1. 模糊语义和明确资源分离

模糊层描述“像什么”：

- 情绪
- 语气
- 姿态
- 关系感
- 场景感

明确层只描述“选哪个”：

- `expression_resource_id` 或 `motion_resource_id`

普通动作不要求 LLM 输出资源类型、资源名、文件名或 `kind` 枚举。

### 2. LLM 只输出入站意图

LLM 输出：

- `intent_tags`
- `axis_levels`
- 可选 `duration_hint_ms`
- 可选 `expression_resource_id` 或 `motion_resource_id`，但不能同时填写

LLM 不输出：

- `emotion_label`
- `summary`
- `choice`
- `motion_id`
- `motion3`
- `exp3`
- 资源文件路径或底层播放定位信息

### 3. 派生字段由系统生成

`emotion_label` 和 `summary` 由系统生成，但不参与语义值修复。

- `emotion_label` 由 `intent_tags` 派生。
- `summary` / diagnostics 由系统生成。

### 4. 资源 ID 必须可校验

如果某个表情或动画资源要被显式引用，它必须拥有稳定、唯一、可校验的 ID，并通过对应的 typed resource 字段提交。

- 白名单来源：当前模型 `motion_catalog.json` 中 `motions` 和 `expressions` 下 `expose_as_resource=true` 或 `is_resource=true` 的条目。
- 命中白名单：保留为受控资源意图。
- 未命中白名单：拒绝整个 effect，并写入 diagnostics。
- 缺省：正常，不代表错误。

- expression 资源必须声明参数所有权；与 parameter plan 冲突时拒绝。
- motion 资源必须能解析出 group/index/file/priority，并替代 parameter plan 执行。
- 两类资源都由当前 segment 的 PlaybackTimeline motion sink 启动和收口；失败不会降级为轴动作。

### 5. Neutral 不是动作兜底

显式中性值必须由 ModelEngine 按输入语义处理；空、非法或全中性动作不得被改造成默认姿态。

prompt 示例不能使用全 neutral 等级。示例使用当前 profile 暴露轴和合法七级值生成，只展示结构，不代表默认动作。

## Prompt 构建

Prompt 的目标是让 LLM 根据本轮回复语义，生成一组模糊意图标签和可播放的语义轴目标。它不应该诱导模型做情绪粗分类，也不应该诱导模型做资源文件选择。

### 注入内容

Prompt 使用三层挂载边界：

1. system：只包含 Live2D 动作任务、选择原则和 effect 输出字段要求。

2. capability：包含当前可控语义轴、七级刻度、角色风格、姿态参考和 typed resource 候选：
   - axis id
   - 语义解释
   - `-3..3` 七级语义
   - 负方向 / 正方向含义
   - 使用约束
   - 控制角色

   代表性姿态参考：
   - 来自用户手调样本、expression 抽取、motion catalog semantic extract 或参考候选。
   - 只展示语义描述和姿态参考，不作为运行时修复输入。
   - 不暴露 motion3 / exp3 文件路径。
   - 不让 LLM 直接选择这些旧资源。

   可选资源候选：
   - 来自当前模型 `motion_catalog.json` 的 `motions` 和 `expressions`。
   - 只有 `expose_as_resource=true` / `is_resource=true` 的条目可以进入候选。
   - 候选数量由 catalog 条目的暴露开关控制，主链路不做固定数量截断。
   - 只暴露 `resource_id`、`resource_type`、`label`、`tags`、`recommended_scenarios`、`description`、`intensity`；expression 额外暴露语义级 `conflicting_axis_ids`。
   - 不暴露底层 Live2D 参数 ID；模型选择 expression 时必须省略 `conflicting_axis_ids` 中的轴。
   - 不暴露文件路径。
   - 不把资源目录做成“让模型挑文件”的清单。

3. context：只包含本轮动态上下文和上一动作关键轴等级。省略轴与显式 `0` 始终保持可区分。

Persona Effect schema 负责 JSON 结构约束；Prompt 不重复展示完整 JSON 示例，也不暴露插件名、profile 文件、候选来源或传输实现。

### Prompt 输出契约示例

middleware-first 使用 AstrBot Persona Effect `ag99live.motion`。模型只填写该 effect 的 `arguments`，不要输出 `plugin_hints` 外壳：

```json
{
  "intent_tags": ["认真解释", "微微前倾", "看向用户"],
  "duration_hint_ms": 1000,
  "axis_levels": {
    "head_yaw": 1,
    "head_pitch": -1,
    "body_pitch": 1,
    "gaze_x": 1,
    "mouth_smile": 2
  }
}
```

如果存在适合且被 prompt 暴露的受控资源，可以附加其中一个 typed resource 字段：

```json
{
  "expression_resource_id": "expr_thanks_smile"
}
```

typed resource 不替代 `axis_levels`。即使选择资源，也必须输出语义轴等级用于校验、trace 和语义归因。

当 AstrBot 运行环境没有 Persona Effect 注入函数时，才启用官方 `<@anim {...}>` 兼容传输：标签只包一层 `{ "mode": "inline", "intent": ... }`，其中 `intent` 仍必须满足当前 `engine.motion_intent.v3` 契约。该路径不是 `ag99live.motion` 失败后的兜底；主链路 payload 无效时应暴露错误，而不是改走 inline。

兼容标签示例：

```text
回复正文。<@anim {"mode":"inline","intent":{"schema_version":"engine.motion_intent.v3","profile_id":"pet.semantic.v1","profile_revision":2,"model_id":"pet","mode":"expressive","intent_tags":["认真解释","微微前倾","看向用户"],"duration_hint_ms":1000,"axes":{"head_yaw":54,"head_pitch":46,"body_pitch":57,"gaze_x":53,"mouth_smile":58}}}>
```

兼容路径的约束：

- 只有 Persona Effect 注入能力不可用时，prompt 才应要求输出 `<@anim>`。
- Persona Effect 可用时，`<@anim>` 即使出现在原始回复里，也只会被可见文本清洗，不作为动作入口。
- `<@anim>` 内部只接受 `engine.motion_intent.v3`；旧 `parameter_plan`、`motion_id`、`choice` 或 v1/v2 intent 都应被拒绝。
- 无效 `<@anim>` 不触发 fallback pose、不触发 speech-only 替代动作，也不替换主链路动作。

## LLM 入站契约

LLM 入站 payload 收敛为：

```json
{
  "intent_tags": ["感激", "温和", "低头致谢"],
  "expression_resource_id": "expr_thanks_smile",
  "duration_hint_ms": 1000,
  "axis_levels": {
    "head_pitch": -1,
    "mouth_smile": 2
  }
}
```

必须输出：

- `intent_tags`
- `axis_levels`

可选输出：

- `expression_resource_id`
- `motion_resource_id`
- `duration_hint_ms`

不得输出：

- `emotion_label`
- `summary`
- `choice`
- `motion_id`
- `motion3`
- `exp3`
- `kind`

## 字段职责

### intent_tags

主语义字段。

规则：

- 可以同时包含情绪词、动作词、场景词、关系词。
- 保持输入顺序。
- 去空、去重。
- 不设语义枚举，不要求固定上限。
- 实现层可保留宽松长度保护，防止异常 payload。
- 不应包含文件名、资源 ID、协议字段名。

示例：

```json
["感激", "温和", "低头致谢", "轻微开心"]
```

### axis_levels

真实动作字段。

规则：

- 只能使用当前 `SemanticAxisProfile` 暴露给 LLM 的 axis id。
- 只接受 `-3..3` 整数等级。
- `0` 表示明确回到中性；省略表示本轮不控制该轴。
- 不接受连续值、数字文本或 `{ "value": number }` 旧嵌套格式。
- ModelEngine 按当前 profile 的 `level_anchors` 转换为实际轴值。
- 不要求每次全量输出，但应覆盖本轮语义需要的头、身、视线和表情细节。

示例：

```json
{
  "head_yaw": 1,
  "body_pitch": 1,
  "gaze_x": 1,
  "mouth_smile": 2
}
```

### expression_resource_id / motion_resource_id

明确资源引用字段。

规则：

- 可选。
- 必须命中 `motion_catalog.json` 中显式暴露且类型匹配的 resource 候选。
- 不命中候选就拒绝整个 effect，并写入 diagnostics。
- 不允许靠 `emotion_label` 自动推断。
- 不允许同时填写两个字段，也不允许替代 `axis_levels`。
- expression 与无参数冲突的 parameter plan 叠加。
- motion 作为完整动作替代 parameter plan，但不绕过 ModelEngine 或 Timeline。

示例：

```json
"expression_resource_id": "expr_thanks_smile"
```

### emotion_label

兼容显示字段，不再是模型输出目标。

派生规则：

```python
emotion_label = "-".join(intent_tags)
```

用途：

- 日志。
- 旧前端兼容。
- 调参样本短摘要。
- UI 显示。

它不参与 prompt 输出目标，也不作为资源推断入口。

## 后端接收流程

后端收到 LLM 入站 payload 后按顺序处理：

1. 解析 JSON。
2. 拒绝旧 selector 字段：`choice`、`motion_id`、`motion3`、`exp3`、catalog motion 等。
3. 归一化 `intent_tags`。
4. 派生 `emotion_label`。
5. 校验 typed resource：
   - ID 必须命中对应类型的 catalog resource 白名单。
   - 两个字段同时非空、类型错配或未命中时拒绝整个 effect。
6. 归一化 `duration_hint_ms`。
7. 严格校验 `axis_levels`：
   - 只接受当前 profile 暴露轴的 `-3..3` 整数。
   - 任一等级非法时拒绝整个 payload，不部分保留。
   - 混入 `axes` 时拒绝，不改发 v3。
8. 输出 `engine.motion_intent.v4`，不执行语义轴 clamp、fallback pose repair、expressive floor 或头身关系约束。
9. 前端 ModelEngine 根据 profile 锚点转换等级，再执行关系图约束和参数计划编译。

## 后端输出结构

后端最终发送给前端的是 v4 结构：

```json
{
  "schema_version": "engine.motion_intent.v4",
  "profile_id": "...",
  "profile_revision": 1,
  "model_id": "...",
  "mode": "expressive",
  "intent_tags": ["认真解释", "微微前倾", "看向用户"],
  "emotion_label": "认真解释-微微前倾-看向用户",
  "duration_hint_ms": 1000,
  "expression_resource_id": "expr_thanks_smile",
  "motion_resource_id": "",
  "axis_levels": {
    "head_yaw": 1,
    "head_pitch": -1,
    "body_pitch": 1,
    "gaze_x": 1,
    "mouth_smile": 2
  },
  "summary": {
    "axis_count": 5,
    "intent_tag_count": 3,
    "source": "persona_effect"
  }
}
```

注意：

- `emotion_label` 是系统派生字段。
- `summary` 是系统诊断字段。
- 前端播放不应依赖 diagnostics 才能执行基础动作。

## Fallback 候选来源

候选来源优先级：

1. 用户手调样本。
2. expression / motion catalog 中可映射到语义轴的姿态抽取。
3. 当前 profile 可解释语义姿态。
前三层可以作为 prompt 风格样本和诊断参考，但不会在自动动作链路中被评分、替换或转换成隐式 axes。

旧 expression / motion 文件可以作为姿态参考抽取来源；只有显式暴露并由 typed resource 字段选中的资源才能进入播放策略。

## 候选参考

候选只用于 Prompt 展示、Motion Lab 诊断和后续人工筛选，不参与当前运行时动作选择或修复。

## 资源层边界

当前自动动作链路不恢复旧资源选择器，而是在 v4 effect 内提供严格 typed resource 意图。

允许：

- 资源作为 prompt 示例抽取来源。
- `motion_catalog.json` 中显式暴露的 motion / expression 作为 typed resource 候选。
- ModelEngine `resourcePolicy` 校验资源存在性、类型、参数所有权和运行时定位信息。
- expression 无冲突时与 parameter plan 同步启动；motion 替代 parameter plan 进入 catalog player。
- 资源执行仍共享当前 segment 的 PlaybackTimeline motion sink 与终态。

不允许：

- prompt 注入完整 motion catalog 让 LLM 选择。
- LLM 输出 `choice=catalog`。
- LLM 输出 `motion_id` 作为播放目标。
- LLM 直接输出 `motion3` 或 `exp3`。
- 普通自动动作绕过 `engine.motion_intent.v4` 直接播放旧资源。

当前第一版 Asset Policy / Arbitration：

```text
语义 intent / typed resource / 当前模型能力
  -> Asset Policy
  -> expression: no-conflict layer / reject
  -> motion: replace parameter plan / reject
  -> PlaybackTimeline motion sink
```

当前不启用隐式 blend 或错误 fallback；更复杂的混合必须先进入关系图显式建模。

## 落地核对清单

实现代码必须满足：

- interaction middleware prompt 使用 `intent_tags`、typed resource、`duration_hint_ms`、`axis_levels`。
- interaction prompt 不要求 LLM 输出 `emotion_label` 或 `summary`。
- middleware / inline 接收层都能接收 `intent_tags`，并由系统派生 `emotion_label`。
- typed resource 做 catalog 白名单和类型校验；未命中、错配或冲突时拒绝并写 diagnostics。
- fallback candidate 不参与运行时评分或动作修复。
- downstream v4 payload 可以保留系统派生的 `emotion_label`；不再包含已废弃的 fallback pose 字段。
- inline contract 示例不使用全 neutral 轴值，不要求 LLM 输出 `summary`。
- Persona Effect schema 约束结构，system Prompt 不重复完整 JSON 示例；capability 单独提供轴与资源能力。
- Motion Lab 保存 raw levels、resolved/constrained axes、compiled parameters、profile hash、transform version、run id 和 timeline outcome。
- 废弃 realtime selector 不进入主生成链路；如保留适配代码，也必须同步到本文契约。
- 前端调参面板和样本存储以 `intent_tags` 作为主展示字段。

文档入口只收敛到本文作为当前动作生成规格。实现进度不在本文记录，避免把阶段性状态误读成长期规范。

## 测试要求

后续测试至少覆盖：

- `intent_tags` 数组、字符串、重复、空值的归一化。
- `emotion_label` 由全部 tags 拼接得到。
- LLM 入站 prompt 不要求 `emotion_label`。
- LLM 入站 prompt 不要求 `summary`。
- Prompt 不重复完整 JSON 格式示例。
- typed resource 命中对应类型候选时保留。
- typed resource 未命中、类型错配或同时填写时拒绝。
- expression 参数冲突时拒绝；motion 必须走 catalog player 而不是 direct parameter player。
- fallback candidate 不参与运行时评分或动作修复。
- middleware 严格接收 v4 `axis_levels`；inline 严格接收 v3 flat `axes`，两者不互相 fallback。

## 非目标

本文不做以下事情：

- 不允许资源绕过 ModelEngine 或 PlaybackTimeline。
- 不把文件路径、group/index 等底层定位暴露给 LLM。
- 不把 `emotion_label` 重新变成模型分类目标。
- 不恢复旧自动 catalog selector。
- 不把资源层和语义层重新混成一个协议字段。
- 不要求删除动作实验室、手动调试、模型扫描或 Live2D SDK 资源加载能力。

## 预期效果

落地后链路应满足：

- LLM 输出自由组合的语义标签，而不是单点粗分类。
- LLM 输出真实可编译 `axis_levels`，而不是连续伪精确值或旧资源选择。
- Prompt 示例来自真实模型姿态抽取，而不是全 neutral 模板。
- 明确资源使用 typed resource ID，并受白名单、类型和所有权约束。
- `emotion_label`、`summary` 都由系统派生；fallback candidate 只用于参考和诊断。
- 语义动作和资源动作边界清楚，后续可以演进资产层而不污染主链路。
