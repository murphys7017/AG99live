# 动作意图标签化与资源派生设计

> 文档状态：当前动作生成链路的权威规格。
>
> 本文是 prompt 构建、LLM 输出解析、middleware / inline 接收层、fallback 派生、资源引用边界、调参样本和前端展示的当前依据。旧的 `emotion_label + fallback_pose_id` 模型输出契约、catalog selector 自动链路和直接让模型选择 motion / expression 文件的方案不再作为开发依据。

## 目标

AG99live 自动动作主链路只产出语义动作 intent，再由前端 `ModelEngine` 编译成 Live2D 参数计划：

```text
AstrBot / Adapter 生成动作入站 intent
  -> Adapter normalize / repair / fallback / diagnostics
  -> engine.motion_intent.v3
  -> Frontend ModelEngine
  -> engine.parameter_plan.v2
  -> Live2D runtime
```

本链路的目标不是把动作重新做成情绪分类器，也不是让 LLM 裸选资源文件，而是把三类职责拆清楚：

1. `intent_tags` 描述本轮表演意图，保持模糊、开放、可组合。
2. `axes` 生成可编译、可修复、可播放的语义动作骨架。
3. `resource_id` 明确引用受控资源文件，只作为资源意图入口，不替代语义轴。

系统仍然以语义轴生成为主。资源文件可以作为提示样本、fallback 候选来源或未来资产层输入，但不能把普通自动动作链路带回 `choice` / `motion_id` / `motion3` / `exp3` 选择器。

## 核心原则

### 1. 模糊语义和明确资源分离

模糊层描述“像什么”：

- 情绪
- 语气
- 姿态
- 关系感
- 场景感

明确层只描述“选哪个”：

- `resource_id`

普通动作不要求 LLM 输出资源类型、资源名、文件名或 `kind` 枚举。

### 2. LLM 只输出入站意图

LLM 输出：

- `intent_tags`
- `axes`
- 可选 `duration_hint_ms`
- 可选 `resource_id`

LLM 不输出：

- `emotion_label`
- `fallback_pose_id`
- `summary`
- `choice`
- `motion_id`
- `motion3`
- `exp3`
- 任何资源类型枚举

### 3. 兼容字段由系统派生

`emotion_label` 和 `fallback_pose_id` 仍可存在于最终 `engine.motion_intent.v3` payload 中，但它们不是模型输出目标。

- `emotion_label` 由 `intent_tags` 派生。
- `fallback_pose_id` 由系统根据 `intent_tags + resource_id + axes` 派生。
- `summary` / diagnostics 由系统生成。

### 4. 资源 ID 必须可校验

如果某个表情或动画资源要被显式引用，它必须拥有稳定、唯一、可校验的 `resource_id`。

- 命中白名单：保留为受控资源意图。
- 未命中白名单：丢弃，并写入 diagnostics。
- 缺省：正常，不代表错误。

`resource_id` 现在不直接触发播放。未来是否播放资源，应该由独立资产策略层仲裁。

### 5. Neutral 只作为系统安全兜底

`neutral` 只能作为系统内部最后兜底姿态，不能作为 LLM 的输出目标，也不应作为 prompt 风格样本主来源。

prompt 示例不能使用全 neutral / 全 50 轴值。示例应来自真实模型姿态抽取，或在没有候选时使用程序生成的轻度偏移值。

## Prompt 构建

Prompt 的目标是让 LLM 根据本轮回复语义，生成一组模糊意图标签和可播放的语义轴目标。它不应该诱导模型做情绪粗分类，也不应该诱导模型做资源文件选择。

### 注入内容

系统只注入四类信息：

1. 当前 Live2D 模型身份：
   - `model_id`
   - `profile_id`
   - `profile_revision`

2. 当前可控语义轴：
   - axis id
   - 语义解释
   - value range
   - 低值 / 高值含义
   - 使用约束
   - 控制角色

3. 代表性动作风格样本：
   - 来自用户手调样本、expression 抽取、motion catalog semantic extract 或 fallback candidate。
   - 只展示语义描述和转换后的 flat axes。
   - 不暴露 motion3 / exp3 文件路径。
   - 不让 LLM 直接选择这些旧资源。

4. 可选资源候选：
   - 只暴露 `resource_id`、`label`、`prompt_tags`、`recommended_scenarios`、`description`、`intensity`。
   - 不暴露 `kind`。
   - 不暴露文件路径。
   - 不把资源目录做成“让模型挑文件”的清单。

### 格式示例来源

格式示例不手写全 50，也不从 neutral 直接生成。

优先级：

1. 用户手调样本。
2. expression / motion catalog 的语义轴抽取结果。
3. fallback pose candidates 中非 neutral、骨架覆盖较好的代表姿态。
4. 程序生成的轻度语义偏移兜底。

选择规则：

- 排除 `neutral` / `idle` / `default` 这类候选。
- 优先包含 head / body / gaze 骨架。
- 优先包含表情细节轴，例如 `mouth_smile`、`eye_smile`、`brow_bias`。
- 优先有 `recommended_scenarios`、`description` 或姿态描述。
- 轴值应明显偏离 soft range，避免全中性。
- 只取 3 到 5 个关键轴，不把完整 axes 列进格式示例。

示例只展示合法结构和幅度，不代表默认姿态，也不应该被模型照抄。

### Prompt 输出契约示例

middleware-first 的 `plugin_hints.ag99live_motion` 示例：

```json
{
  "plugin_hints": {
    "ag99live_motion": {
      "intent_tags": ["认真解释", "微微前倾", "看向用户"],
      "duration_hint_ms": 1000,
      "axes": {
        "head_yaw": 54,
        "head_pitch": 46,
        "body_pitch": 57,
        "gaze_x": 53,
        "mouth_smile": 58
      }
    }
  }
}
```

如果存在适合且被 prompt 暴露的受控资源，可以附加：

```json
{
  "resource_id": "expr_thanks_smile"
}
```

`resource_id` 不替代 `axes`。即使输出了 `resource_id`，也必须输出语义轴。

inline-first 的 `<@anim>` 示例：

```text
给用户看的自然语言回复。

<@anim {"mode":"inline","intent":{"schema_version":"engine.motion_intent.v3","profile_id":"...","profile_revision":1,"model_id":"...","intent_tags":["轻松说明","微微前倾","看向用户"],"duration_hint_ms":1000,"axes":{"head_yaw":58,"body_pitch":57,"gaze_x":56,"mouth_smile":64}}}>
```

inline intent 内同样不输出 `emotion_label`、`fallback_pose_id` 或 `summary`。

## LLM 入站契约

LLM 入站 payload 收敛为：

```json
{
  "intent_tags": ["感激", "温和", "低头致谢"],
  "resource_id": "expr_thanks_smile",
  "duration_hint_ms": 1000,
  "axes": {
    "head_pitch": 42,
    "mouth_smile": 66
  }
}
```

必须输出：

- `intent_tags`
- `axes`

可选输出：

- `resource_id`
- `duration_hint_ms`

不得输出：

- `emotion_label`
- `fallback_pose_id`
- `summary`
- `choice`
- `motion_id`
- `motion3`
- `exp3`
- `kind`

## 字段职责

### intent_tags

主语义字段。

规则：

- 可以同时包含情绪词、动作词、场景词、关系词。
- 保持输入顺序。
- 去空、去重。
- 不设语义枚举，不要求固定上限。
- 实现层可保留宽松长度保护，防止异常 payload。
- 不应包含文件名、资源 ID、协议字段名。

示例：

```json
["感激", "温和", "低头致谢", "轻微开心"]
```

### axes

真实动作字段。

规则：

- 只能使用当前 `SemanticAxisProfile` 暴露给 LLM 的 axis id。
- 只接受 flat number。
- 不接受 `{ "value": number }` 旧嵌套格式。
- 轴范围以当前 profile 的 `value_range` 为准。
- 不要求每次全量输出，但应覆盖本轮语义需要的头、身、视线和表情细节。

示例：

```json
{
  "head_yaw": 54,
  "body_pitch": 57,
  "gaze_x": 53,
  "mouth_smile": 58
}
```

### resource_id

明确资源引用字段。

规则：

- 可选。
- 只能命中 prompt 暴露或系统允许的候选集合。
- 不命中候选就丢弃，并写入 diagnostics。
- 不允许靠 `emotion_label` 自动推断。
- 不允许替代 `axes`。
- 不直接触发播放。

示例：

```json
"expr_thanks_smile"
```

### emotion_label

兼容显示字段，不再是模型输出目标。

派生规则：

```python
emotion_label = "-".join(intent_tags) or "motion"
```

用途：

- 日志。
- 旧前端兼容。
- 调参样本短摘要。
- UI 显示兜底。

它不参与 prompt 输出目标，也不作为资源推断入口。

### fallback_pose_id

语义轴兜底字段，不再是模型输出目标。

用途：

- 当 `axes` 太弱、缺骨架、非法或需要修复时，提供可编译语义姿态。
- 用于补 head / body / gaze 骨架。
- 用于 diagnostics 和调参闭环。

派生输入：

- `intent_tags`
- `resource_id`
- `axes`
- 候选的 `prompt_tags`
- 候选的 `recommended_scenarios`
- 候选的 `pose_descriptors`
- 候选骨架覆盖度
- 候选来源优先级

`fallback_pose_id` 不是资源播放 ID，不代表直接播放旧 motion / expression。

## 后端接收流程

后端收到 LLM 入站 payload 后按顺序处理：

1. 解析 JSON。
2. 拒绝旧 selector 字段：`choice`、`motion_id`、`motion3`、`exp3`、catalog motion 等。
3. 归一化 `intent_tags`。
4. 派生 `emotion_label`。
5. 校验 `resource_id`：
   - 命中白名单则保留。
   - 未命中则清空，并写入 diagnostics。
6. 归一化 `duration_hint_ms`。
7. 归一化 `axes`：
   - 丢弃未知轴。
   - clamp 越界轴。
   - 拒绝旧嵌套 axis payload。
8. 根据 `intent_tags + resource_id + axes` 计算 fallback decision。
9. 如果 axes 缺失、太弱或骨架不足，则使用 fallback pose 修复或替换。
10. 应用必要的 expressive floor。
11. 输出兼容的 `engine.motion_intent.v3`。

## 后端输出结构

后端最终发送给前端的是兼容 v3 结构：

```json
{
  "schema_version": "engine.motion_intent.v3",
  "profile_id": "...",
  "profile_revision": 1,
  "model_id": "...",
  "mode": "expressive",
  "intent_tags": ["认真解释", "微微前倾", "看向用户"],
  "emotion_label": "认真解释-微微前倾-看向用户",
  "duration_hint_ms": 1000,
  "resource_id": "",
  "fallback_pose_id": "serious_explain",
  "axes": {
    "head_yaw": 54,
    "head_pitch": 46,
    "body_pitch": 57,
    "gaze_x": 53,
    "mouth_smile": 58
  },
  "summary": {
    "axis_count": 5,
    "intent_tag_count": 3,
    "fallback_score": 32,
    "fallback_reasons": ["tag_overlap:2", "descriptor_overlap:1"],
    "matched_candidate_id": "serious_explain",
    "fallback_used": false
  }
}
```

注意：

- `emotion_label` 是系统派生的兼容字段。
- `fallback_pose_id` 是系统派生的语义姿态候选。
- `summary` 是系统诊断字段。
- 前端播放不应依赖 diagnostics 才能执行基础动作。

## Fallback 候选来源

候选来源优先级：

1. 用户手调样本。
2. expression / motion catalog 中可映射到语义轴的姿态抽取。
3. 当前 profile 可解释语义姿态。
4. 默认 neutral 安全兜底。

前三层可以作为 prompt 风格样本和 fallback pose 候选。进入自动动作链路前，它们必须被转换成 flat axes。

旧 expression / motion 文件可以作为抽取来源，但不能作为普通自动动作结果被直接播放。

## Fallback 评分

评分参考：

- `resource_id` 精确命中给高分。
- `intent_tags` 与候选 `prompt_tags` / `tags` / `emotion_bias` 重合给加分。
- `intent_tags` 与 `recommended_scenarios` 重合给加分。
- 当前 `axes` 姿态描述与候选 `pose_descriptors` 重合给加分。
- 候选包含完整 head / body / gaze 骨架给加分。
- 来源越接近用户手调样本，优先级越高。
- 如果当前 `axes` 与候选姿态明显冲突，应减分。

低于阈值时回落默认 neutral。neutral 只作为内部安全兜底，不进入 LLM 输出契约。

## 资源层边界

当前自动动作链路不恢复旧资源选择器。

允许：

- 资源作为 prompt 示例抽取来源。
- 资源作为可校验 `resource_id` 候选。
- 资源 ID 被记录、展示、诊断。
- 未来资产策略层消费 `resource_id`。

不允许：

- prompt 注入完整 motion catalog 让 LLM 选择。
- LLM 输出 `choice=catalog`。
- LLM 输出 `motion_id` 作为播放目标。
- LLM 直接输出 `motion3` 或 `exp3`。
- 普通自动动作绕过 `engine.motion_intent.v3` 直接播放旧资源。

未来如果接入预录制资产播放，应走独立 Asset Policy / Arbitration：

```text
语义 intent / resource_id / 事件 / 用户命令 / 当前播放状态
  -> Asset Policy
  -> allow / deny / mix / fallback
  -> Asset Accent Layer
```

资产层只能作为少数强表现点的增强，不替代语义轴主链路。

## 落地核对清单

实现代码必须满足：

- interaction middleware prompt 使用 `intent_tags`、`resource_id`、`duration_hint_ms`、`axes`。
- interaction prompt 不要求 LLM 输出 `emotion_label`、`fallback_pose_id` 或 `summary`。
- middleware / inline 接收层都能接收 `intent_tags`，并由系统派生 `emotion_label`。
- `resource_id` 做白名单校验；未命中候选时丢弃并写 diagnostics。
- fallback 选择基于 `intent_tags + resource_id + axes` 做候选打分。
- downstream v3 payload 可以保留 `emotion_label` 和 `fallback_pose_id` 作为兼容字段。
- inline contract 示例不使用全 neutral 轴值，不要求 LLM 输出 `summary`。
- middleware/plugin_hints 格式示例优先从真实姿态候选抽取 3 到 5 个关键轴。
- 废弃 realtime selector 不进入主生成链路；如保留适配代码，也必须同步到本文契约。
- 前端调参面板和样本存储以 `intent_tags` 作为主展示字段。

文档入口只收敛到本文作为当前动作生成规格。实现进度不在本文记录，避免把阶段性状态误读成长期规范。

## 测试要求

后续测试至少覆盖：

- `intent_tags` 数组、字符串、重复、空值的归一化。
- `emotion_label` 由全部 tags 拼接得到。
- LLM 入站 prompt 不要求 `emotion_label`。
- LLM 入站 prompt 不要求 `fallback_pose_id`。
- LLM 入站 prompt 不要求 `summary`。
- 格式示例不使用全 neutral / 全 50 轴值。
- `resource_id` 命中候选时保留。
- `resource_id` 未命中候选时拒绝。
- `fallback_pose_id` 由候选评分派生。
- inline / middleware 两条路径都能接收新契约。

## 非目标

本文不做以下事情：

- 不把 `resource_id` 直接变成资源播放指令。
- 不把资源类型 `kind` 暴露给 LLM。
- 不把 `emotion_label` 重新变成模型分类目标。
- 不恢复旧自动 catalog selector。
- 不把资源层和语义层重新混成一个协议字段。
- 不要求删除动作实验室、手动调试、模型扫描或 Live2D SDK 资源加载能力。

## 预期效果

落地后链路应满足：

- LLM 输出自由组合的语义标签，而不是单点粗分类。
- LLM 输出真实可编译 axes，而不是旧资源选择。
- Prompt 示例来自真实模型姿态抽取，而不是全 neutral 模板。
- 明确资源文件使用明确 `resource_id`，并受白名单约束。
- `emotion_label`、`fallback_pose_id`、`summary` 都由系统派生。
- 语义动作和资源动作边界清楚，后续可以演进资产层而不污染主链路。
