# 语义动作生成链路与 fallback 设计

> 文档状态：语义轴主链路目标文档。
>
> 本文定义的“自动动作链路只产出 `engine.motion_intent.v3`、不恢复 catalog selector、fallback pose 仍是语义轴”的方向仍然成立。当前开发正在实现本文的主目标。
>
> 但本文早期示例中“LLM 输出 `emotion_label` / 必填 `fallback_pose_id`”的入站契约已经被 [动作意图标签化与资源派生设计](./10-动作意图标签化与资源派生设计.md) 修订。当前 prompt 构建、接收层归一化和测试验收以 10 号文档为准：LLM 只输出 `intent_tags`、`axes`，可选输出 `resource_id` / `duration_hint_ms`；`emotion_label` 和 `fallback_pose_id` 由系统派生。

## 目标

本文描述 AG99live 当前大模型动作生成链路：一次 AstrBot 请求产出用户可见文本，同时产出一个由语义轴组成的动作 intent。动作 intent 经过适配器归一化、修复和必要 fallback 后，统一发送给前端 `ModelEngine`，再编译为 Live2D 参数计划播放。

目标主链路：

```text
AstrBot / Adapter 生成语义动作 intent
  -> Adapter normalize / repair / fallback
  -> engine.motion_intent.v3
  -> Frontend ModelEngine 编译为 engine.parameter_plan.v2
  -> Live2D runtime 执行参数计划
```

本文只约束“大模型生成动作并返回播放”这条自动链路。旧播放文件、motion3 动画、exp3 表情、catalog motion、动作实验室、预览和手动调试能力可以继续存在，但不能再参与这条自动生成链路。

## 核心结论

- 自动动作链路只产出 `engine.motion_intent.v3`，不再让 LLM 选择或返回 catalog motion、motion3 动画、exp3 表情或旧播放文件。
- LLM 不生成 `choice` 字段。不存在 `choice=generate` / `choice=catalog` 的选择过程。
- LLM 的输出轴应尽可能完整，而不是限制为 5 到 8 个。重点是覆盖动作骨架轴，再补充表情细节轴。
- `axes` 使用 flat number 格式：`"head_yaw": 62`。不兼容、不鼓励、也不接受 `"head_yaw": {"value": 62}`。
- `idle` 不属于本轮 LLM 动作输出职责。idle 是系统本底自动运行部分，由 runtime 自己维持。
- fallback pose 是语义轴示例，不是旧表情或旧动画文件。fallback 候选优先来自用户保存的手调结果，其次来自模型 `Expressions/*.exp3.json` 的显式参数抽取，再其次来自当前 `SemanticAxisProfile.parameter_bindings` 可映射参数抽取；三层都不可用时才用 neutral 安全兜底。最终 payload 必须是 v3 语义轴。
- `middleware-first` 和 `inline_first` 是两条互不兜底的接入路线。它们共享修复和 fallback 规则，但不共享解析入口。

## 路线选择

动作链路启动前先按 `motion_generation_mode` 或等价运行态能力选择路线：

```text
motion_generation_mode == "split_after_reply"
  -> middleware-first

motion_generation_mode == "inline_first"
  -> inline_first
```

路线选择完成后，本轮只执行选中的路线：

- `middleware-first` 只读取 interaction middleware 的 `plugin_hints.ag99live_motion`。
- `inline_first` 只读取 assistant 文本末尾的 `<@anim ...>`。
- `middleware-first` 缺失 plugin hints 时，不回头解析 `<@anim>`。
- `inline_first` 缺失 `<@anim>` 时，不读取 interaction plugin hints。
- 两条路线只在最终 `engine.motion_intent.v3` 出口汇合。

## 请求上下文

无论走哪条路线，注入给 LLM 的动作上下文都应包含：

- 当前 Live2D 模型身份：
  - `model_id`
  - `profile_id`
  - `profile_revision`
- 当前模型可控制语义轴：
  - axis id
  - 语义解释
  - `value_range`
  - 中性值
  - 低值 / 高值含义
  - 使用约束
- 代表性 fallback pose 候选：
  - `id`
  - `label`
  - `emotion`
  - `source`
  - `priority`
  - `duration_ms`
  - `axes`
  - 简短场景说明
- 当前路线对应的输出格式。
- 必填 `fallback_pose_id`。

上下文中不注入旧 motion3 动画 catalog、旧 exp3 表情模板、旧播放文件分析结果，也不提示 LLM 在旧素材和生成参数之间做选择。

## LLM 输出原则

LLM 的职责是根据本轮回复语气生成一个语义姿态目标，并选择一个 fallback pose id。它不负责 idle 本底，也不负责选择旧动画或旧表情。

LLM 应尽可能完整输出当前语义动作所需的轴。优先级如下：

- 头部骨架：左右转头、点头/抬头、歪头。
- 身体骨架：身体左右扭、左右倾、前后姿态。
- 视线与眼部：视线方向、睁眼强度、笑眼/眯眼。
- 表情细节：嘴角、嘴部偏移、眉毛细节。
- 运行时轴：例如 mouth_open、breath，只有文本明确需要张嘴、哈欠、惊讶呼吸等状态时才输出；一般由 runtime 自己处理。

prompt 应明确告诉 LLM：

- 不要只输出嘴角、眉毛这类弱表情细节。
- 明确情绪、转向、强调、回避、惊讶或调侃时，必须优先建立头部和身体动作骨架。
- 如果一个轴和本轮语义相关，就应输出；不要为了“少量轴”而丢掉关键动作信息。
- fallback pose 只是兜底选项，不代表主动作应该照抄示例。

## Middleware-first 输出形态

`middleware-first` 是 AG99live 当前默认主路径。动作内容必须进入 interaction decision 的 `plugin_hints.ag99live_motion`，不要写入用户可见文本、`immediate_spoken_reply` 或 `core_task_spec`。

目标结构：

```json
{
  "plugin_hints": {
    "ag99live_motion": {
      "emotion_label": "happy",
      "duration_hint_ms": 1000,
      "fallback_pose_id": "happy_smile",
      "axes": {
        "head_yaw": 54,
        "head_pitch": 62,
        "head_roll": 58,
        "body_yaw": 53,
        "body_roll": 59,
        "body_pitch": 61,
        "gaze_x": 54,
        "gaze_y": 58,
        "eye_smile_left": 78,
        "eye_smile_right": 78,
        "mouth_smile": 84
      }
    }
  }
}
```

`AG99liveMotionResultContributor` 从 `_interaction_plugin_hints` 读取该对象，执行 normalize / repair / fallback，然后生成 `client_objects`，最终由 turn coordinator 广播 `engine.motion_intent`。

## Inline-first 输出形态

`inline_first` 是官方 AstrBot 兼容路径。动作内容必须写在 assistant 主回复末尾的 `<@anim ...>` 标签中，adapter 负责剥离标签并提取 motion。该路线不依赖 interaction `plugin_hints`。

目标结构：

```text
给用户看的自然语言回复。

<@anim {"mode":"inline","intent":{"schema_version":"engine.motion_intent.v3","emotion_label":"happy","duration_hint_ms":1000,"fallback_pose_id":"happy_smile","axes":{"head_yaw":54,"head_pitch":62,"head_roll":58,"body_yaw":53,"body_roll":59,"body_pitch":61,"gaze_x":54,"gaze_y":58,"eye_smile_left":78,"eye_smile_right":78,"mouth_smile":84}}}>
```

inline 兼容路径可以继续使用现有 `<@anim>` 标签，但 `intent` 内部只允许语义动作字段，不允许 `choice`、`motion_id`、catalog motion 或旧嵌套 axis payload。

## Fallback Pose 候选来源

fallback pose registry 不是凭空新建一份静态列表，而是从现有可控样本中生成“语义轴候选集”。它的输入来源按优先级分为三层：

1. 用户保存的手调结果。
2. 模型 `Expressions/*.exp3.json` 表情参数抽取。
3. 当前 `SemanticAxisProfile.parameter_bindings` 可映射的表情参数抽取。

这三层来源都只能作为 fallback pose 和 prompt 示例来源，不能让自动链路直接播放旧表情文件或旧动画文件。也就是说，来源可以是旧资源或用户样本，但进入 LLM 自动动作链路前必须被转换成 flat axes 语义姿态。

### 用户手调结果

用户保存的手调结果优先级最高，因为它代表用户已经认可过的角色表现。现有 `motion_tuning_samples` / `motion_tuning_reference_examples` / `list_effective_motion_tuning_examples()` 链路可以作为这层来源的基础。

转换规则：

- 只使用启用给 LLM 参考的样本。
- 只使用当前 `profile_id` 和 `profile_revision` 匹配的样本。
- 使用用户调整后的 `adjusted_axes`，不使用原始未调整值。
- 只保留当前 `SemanticAxisProfile` 中可控的轴。
- 样本必须有足够的有效轴和可解释场景，才能进入 fallback pose 候选集。
- id 可从 sample id、emotion、tags 组合生成，必须稳定。

### Expressions 表情参数抽取

模型 `Expressions/*.exp3.json` 是第二优先级来源。它们可以提供模型作者预置的表情参数姿态，但不能在自动链路里直接作为 expression 播放。

转换规则：

- 读取 expression scan / constraints 中已经抽取出的表情参数。
- 将其映射到当前 `SemanticAxisProfile` 的 axis id。
- 丢弃无法映射到当前语义轴的参数。
- 丢弃服装、控制器、附件、marker、纯运行时轴等非表情姿态内容。
- 生成的 fallback pose 只保存 flat axes，不保存原始 expression 文件路径作为播放目标。

### SemanticAxisProfile 参数映射抽取

如果某些 expression 只有 `dominant_parameters`、`parameter_ids` 或其他可映射参数 ID，而没有完整可用的目标数值，可以用当前 `SemanticAxisProfile.parameter_bindings` 判断它是否能映射到语义轴。这个来源仍然是“从表情参数抽象出语义姿态”，不是播放 expression 文件。

转换规则：

- 遍历当前可提示给 LLM 的语义轴。
- 只接受能通过 `parameter_bindings.parameter_id` 命中 expression 参数 ID 的轴。
- 如果 expression 缺少明确 value，可按该轴绑定关系生成一个保守姿态值，并按 `value_range` clamp。
- 丢弃无法映射到当前 profile 的参数。
- 丢弃 control_role 不允许 LLM 控制的轴。

### Neutral 安全兜底

如果三层候选都无法提供可用 pose，再根据当前 `SemanticAxisProfile` 的中性值生成默认 `neutral` pose。它只用于保证 fallback 有一个可播放、可编译、不会回到旧素材播放的最后出口，不作为 prompt 风格样本主来源。

## Fallback Pose 结构

fallback pose 的最终结构必须是语义姿态：

```json
{
  "id": "happy_smile",
  "label": "开心微笑",
  "emotion": "happy",
  "source": "motion_tuning_sample",
  "priority": 100,
  "description": "正向反馈、满意或轻松调侃时使用。",
  "duration_ms": 1000,
  "axes": {
    "head_yaw": 54,
    "head_pitch": 62,
    "head_roll": 58,
    "body_yaw": 53,
    "body_roll": 59,
    "body_pitch": 61,
    "gaze_x": 54,
    "gaze_y": 58,
    "eye_smile_left": 78,
    "eye_smile_right": 78,
    "mouth_smile": 84
  }
}
```

这些候选同时服务两个目的：

- prompt 中作为代表性动作风格样本，帮助 LLM 理解语义轴如何组合。
- 运行时作为 fallback pose 库，在 LLM 生成结果不可用时直接转成 `engine.motion_intent.v3`。

fallback pose 不代表旧素材选择器。它是语义轴兜底。

## Normalize / Repair 规则

适配器收到当前路线的 motion 后先执行 normalize / repair，而不是立即 fallback。路线只决定 motion 从哪里来，修复规则完全相同。

### 可修复错误

这些情况修复后仍可使用 LLM 生成结果：

- `duration_hint_ms` 缺失：使用默认时长 `1000ms`。
- `duration_hint_ms` 不是数字但可转数字：转成整数。
- `duration_hint_ms` 太短或太长：夹到允许范围。
- 轴值是字符串数字：转成数字。
- 已知轴值越界：按该轴 `SemanticAxisProfile.value_range` clamp。
- 少量未知轴：丢弃未知轴，保留合法轴。
- 单个 axis id 为空、值不可转数字、或对应 axis 不在当前 profile 中，只丢弃该轴，不影响其他轴。
- `emotion_label` 缺失：可用 `fallback_pose_id` 对应示例的 emotion 或 `neutral` 补齐。

### 不兼容的输入

新的自动链路不兼容旧 axis payload：

```json
{
  "axes": {
    "head_yaw": { "value": 62 }
  }
}
```

这种结构应被视为无效轴并触发 fallback，而不是被兼容修复。新契约只接受：

```json
{
  "axes": {
    "head_yaw": 62
  }
}
```

原因：嵌套 `{ "value": number }` 平白增加 LLM 输出复杂度，也会让 prompt 和测试同时维护两套形状。改完后新的格式就是唯一格式。

### 有效动作判定

有效动作不按 idle / expressive 区分最低轴数，因为 idle 不属于 LLM 本轮生成职责。

LLM 输出修复后应满足：

- 至少保留一个可见动作骨架：头部、身体、视线三类中至少覆盖两类。
- 明确情绪或明确姿态时，应同时包含头部或身体骨架，以及至少一类表情/眼部细节。
- 如果修复后只剩 1 到 2 个合法轴，通常视为动作表达不足，进入 fallback。
- 如果只剩嘴角、眉毛等弱表情细节，且缺少头部/身体/视线骨架，进入 fallback。
- 如果合法轴数量充足但部分轴越界或未知，保留修复后的 LLM 结果。

轴范围完全以 `SemanticAxisProfile.value_range` 为准。实现和 prompt 都不要假设所有轴一定是 `0..100`。

## 不可修复错误

这些情况使用 fallback pose：

- motion JSON 结构无法解析。
- `axes` 缺失、为空，或修复后动作表达不足。
- `axes` 使用旧嵌套 `{ "value": number }` 格式。
- `profile_id` / `model_id` / `profile_revision` 与当前模型身份冲突。
- `fallback_pose_id` 之外的字段足以说明动作意图失败。
- LLM 输出了 `choice`、`motion_id`、catalog motion 或旧播放文件引用。

## Fallback 选择

fallback 顺序：

```text
LLM axes 修复后动作表达足够
  -> 使用 LLM 生成结果
否则查 fallback_pose_id
  -> 命中则使用对应语义 pose 示例
否则
  -> 使用默认 neutral fallback pose
```

fallback pose 生成的最终 payload 仍是 flat axes 的 `engine.motion_intent.v3`：

```json
{
  "schema_version": "engine.motion_intent.v3",
  "profile_id": "...",
  "profile_revision": 1,
  "model_id": "...",
  "emotion_label": "happy",
  "duration_hint_ms": 1000,
  "axes": {
    "head_pitch": 62,
    "mouth_smile": 84
  },
  "summary": {
    "axis_count": 2,
    "fallback_pose_id": "happy_smile",
    "fallback_used": true
  }
}
```

## 协议边界

前端协议不需要新增新的 motion 类型。后端继续广播：

```text
type: engine.motion_intent
payload.intent.schema_version: engine.motion_intent.v3
```

`engine.motion_intent.v3.axes` 的目标形状是 flat number：

```json
{
  "axes": {
    "head_yaw": 54,
    "head_pitch": 62
  }
}
```

可以在 `summary` 或 diagnostics 中记录来源：

```json
{
  "summary": {
    "axis_count": 8,
    "fallback_pose_id": "happy_smile",
    "fallback_used": true,
    "repair_warnings": [
      "duration_hint_ms_defaulted",
      "unknown_axis_dropped:tail_swing"
    ]
  }
}
```

这些诊断字段只用于调试和调参，不应成为前端播放必需字段。

## 与旧播放能力的关系

当前设计不是删除所有旧播放能力，而是从大模型自动生成动作链路里剔除它们。旧资源可以继续服务动作实验室、手动调试、模型扫描和 fallback pose 抽取，但不能作为自动链路的播放目标。

继续允许存在的能力：

- 动作实验室中对旧 motion / expression / catalog 的分析、预览和实验。
- 手动调试入口中对旧资源的播放或检查。
- Live2D SDK 正常加载模型资源所需的 motion / expression 文件支持。

自动生成链路中必须移除的能力：

- prompt 注入 motion3 catalog。
- prompt 注入 exp3 表情模板。
- prompt 注入旧播放文件分析结果作为可选动作。
- LLM 输出 `choice`。
- LLM 输出 `motion_id`。
- 后端把自动链路结果转成 `engine.catalog_motion.v1`。
- fallback 走旧 motion / expression 播放。

理由：

- 固定 motion3 / expression 模板会把系统带回素材选择器，而不是语义参数驱动。
- 自动链路混入旧资源后，LLM 会倾向选择素材名，而不是理解语义轴。
- 语义 fallback pose 与主链路同构，仍走 `engine.motion_intent.v3 -> parameter_plan`，更容易调试和演进。

## 已确认设计决策

- 默认 duration 统一使用 `1000ms`。
- 每个轴的范围完全以 `SemanticAxisProfile.value_range` 为准。
- `axes` 唯一合法输入形态是 flat number。
- `fallback_pose_id` 是必填字段。
- fallback pose 候选来源优先级为：用户手调结果 -> `Expressions/*.exp3.json` 显式参数抽取 -> 当前 `SemanticAxisProfile.parameter_bindings` 可映射参数抽取；三层都不可用时才使用默认 neutral pose。
- `fallback_pose_id` 在 middleware-first 中放入 `plugin_hints.ag99live_motion`。
- `fallback_pose_id` 在 inline-first 中放入 `<@anim>.intent`。
- `idle` 归系统本底，不作为 LLM 本轮动作输出 mode。
- `choice` 从大模型动作输出契约中删除。
