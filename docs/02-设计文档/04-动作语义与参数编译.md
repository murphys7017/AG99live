# 动作语义与参数编译

## 动作输入

`ag99live.motion` 使用 `engine.motion_intent.v4` 描述动作意图。输入必须有非空 `intent_tags`，参数动作统一使用 `motion_steps`：

| 形态 | 用途 |
| --- | --- |
| `motion_steps` | 1–4 个按顺序发生的稀疏语义姿态事件；单一姿态也使用 1 个 step。 |
| `motion_resource_id` | 已公开且可预检的完整模型动作资源。 |

参数动作可选 `duration_hint_ms` 和 `expression_resource_id`。完整动作资源不能和参数计划的时长或曲线字段混用。运行时不接受 `axis_levels` 或根级 `axis_values`。

```json
{
  "intent_tags": ["认真解释", "看向用户"],
  "motion_steps": [
    {"axis_values": {"head_yaw": 66.0, "body_yaw": 65.0}, "duration_weight": 1},
    {"axis_values": {"head_yaw": 75.0, "gaze_x": 65.0}, "duration_weight": 2},
    {"axis_values": {"head_yaw": 50.0}, "duration_weight": 1}
  ]
}
```

## 稀疏序列语义

`motion_steps` 不是重复完整姿态：

1. 每个 step 有非空 `axis_values` 和 `duration_weight`（`1..3`）。
2. 一个轴只从首次声明的 step 开始由该序列控制。
3. 已声明轴在后续 step 省略时保持上一目标。
4. 显式写入该轴的 `neutral` 值表示回到语义中性。
5. 所有 step 的已声明轴并集构成该序列的受控轴集合。

Adapter、Prompt 样本、Motion Lab 和 ModelEngine 都使用这一种解释。没有补轴、隐式中性值或第二条序列规则。

## Profile 与连续值

Provider 直接输出语义轴在 `value_range` 内的具体数值，不输出离散等级。当前 `SemanticAxisProfile` 决定哪些轴可用，以及每个值如何映射：

- `value_range` 是语义值的硬边界。
- `neutral` 是语义中性值。
- `soft_range`、`strong_range`、`extreme_range` 提供强度参考与校验信息。
- 参数绑定、轴角色和关系图把语义值映射到真实 Live2D 参数。

同一动作语义可以在不同模型上得到不同但可控的参数计划。更换模型时应校准 profile，不应把参数 ID 暴露给大模型。历史 `-4..4` 数据只在训练导出时根据轴范围转换。

## 编译与计划

ModelEngine 依次验证输入、解析 profile、应用关系图、安排时序、绑定参数并生成 `engine.parameter_plan.v3`。计划中的每项参数包含 `axis_id`、`parameter_id`、`activation_at_ms`、目标值、来源、可选 keyframe、语音调制和动态限制。

参数来源可以是语义轴、关系图、speech pose、expression、连续性或人工调校。来源和诊断被保留，使 Motion Lab 能追溯模型输出、编译约束和最终表现之间的因果关系。

## 关系图和资源

关系图处理头身跟随、有限反向平衡和模型范围约束。它只在 ModelEngine 中解释，Adapter 和 WebSDK 不各自重算。`motion_resource_id` 与 expression 也必须经过 ModelEngine 预检和 PlaybackTimeline，不能绕过运行所有权。

## 拒绝原则

未知轴、非有限数值、越过 `value_range`、空 step、形态冲突、无可用 profile、无效资源和错误版本都会明确失败。系统不自动改名、补轴、补默认姿态或把异常转换为看似成功的播放。

## 验收

真实运行时，应该能从 Motion Lab 或日志回答：输入是什么、为何接受或拒绝、具体轴值如何经过 profile 和关系图、哪个参数何时激活、计划是否开始执行以及最终如何结算。
