# 动作语义与参数编译

## 动作输入

`ag99live.motion` 使用 `engine.motion_intent.v4` 描述动作意图。输入必须有非空 `intent_tags`，并且只能选择一种执行形态：

| 形态 | 用途 |
| --- | --- |
| `axis_levels` | 一次语义姿态。 |
| `motion_steps` | 2 至 4 个按顺序发生的稀疏语义姿态事件。 |
| `motion_resource_id` | 已公开且可预检的完整模型动作资源。 |

参数姿态与序列可选 `duration_hint_ms` 和 `expression_resource_id`。完整动作资源不能和参数计划的时长或曲线字段混用。

```json
{
  "intent_tags": ["认真解释", "看向用户"],
  "motion_steps": [
    {"axis_levels": {"head_yaw": 2, "body_yaw": 1}, "duration_weight": 1},
    {"axis_levels": {"head_yaw": 3, "gaze_x": 2}, "duration_weight": 2},
    {"axis_levels": {"head_yaw": 0}, "duration_weight": 1}
  ]
}
```

## 稀疏序列语义

`motion_steps` 不是重复完整姿态：

1. 每个 step 有非空 `axis_levels` 和 `duration_weight`（`1..3`）。
2. 一个轴只从首次声明的 step 开始由该序列控制。
3. 已声明轴在后续 step 省略时保持上一目标。
4. 显式 `0` 表示该轴回到语义中性。
5. 所有 step 的已声明轴并集构成该序列的受控轴集合。

Adapter、Prompt 样本、Motion Lab 和 ModelEngine 都使用这一种解释。没有补轴、隐式中性值或第二条序列规则。

## Profile 与九级映射

主模型只输出语义轴和 `-4..4` 的整数等级。当前 `SemanticAxisProfile` 决定哪些轴可用，以及每个等级如何映射：

- `value_range`、`soft_range`、`strong_range`、`extreme_range` 限定表现范围。
- `level_anchors` 固定九个等级的模型级锚点。
- `max_velocity`、`max_acceleration` 和响应策略约束表现层追赶目标。
- 参数绑定、轴角色和关系图把语义映射到真实 Live2D 参数。

同一动作语义可以在不同模型上得到不同但可控的参数计划。更换模型时应校准 profile，不应把参数 ID 暴露给大模型。

## 编译与计划

ModelEngine 依次验证输入、解析 profile、采样、应用关系图、安排时序、绑定参数并生成 `engine.parameter_plan.v3`。计划中的每项参数包含 `axis_id`、`parameter_id`、`activation_at_ms`、目标值、来源、可选 keyframe、语音调制和动态限制。

参数来源可以是语义轴、关系图、speech pose、expression、连续性或人工调校。来源和诊断被保留，使 Motion Lab 能追溯模型输出、编译约束和最终表现之间的因果关系。

## 关系图和资源

关系图处理头身跟随、有限反向平衡和模型范围约束。它只在 ModelEngine 中解释，Adapter 和 WebSDK 不各自重算。`motion_resource_id` 与 expression 也必须经过 ModelEngine 预检和 PlaybackTimeline，不能绕过运行所有权。

## 拒绝原则

未知轴、非整数等级、空 step、形态冲突、无可用 profile、无效资源和错误版本都会明确失败。系统不自动改名、补轴、补默认姿态或把异常转换为看似成功的播放。

## 验收

真实运行时，应该能从 Motion Lab 或日志回答：输入是什么、为何接受或拒绝、等级采样为何值、关系图如何影响结果、哪个参数何时激活、计划是否开始执行以及最终如何结算。
