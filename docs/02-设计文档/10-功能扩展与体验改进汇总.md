# 功能扩展与体验改进汇总

本文是 AG99live 与 AG99 后续体验工作的统一分类入口，综合 N.E.K.O 功能方向、已有能力审计，以及用户对 AG99 现有能力的补充说明。它用于决定“新增什么、优化什么、哪些已有基础要重新组织”，不代表其中所有项目都已完成源码和运行验收。

## 目标

AG99live 的 Live2D 核心和 C++ 性能优化已形成基础。后续重点从“继续增加底层能力”转向让角色更容易使用、更能理解用户状态，并在说话之外也保持自然的存在感。AG99 继续拥有会话、主动对话、记忆和 Provider 等宿主能力；AG99live 负责桌宠状态、Live2D 表现及桌面体验。

## 1. 需要新增的功能

| 功能 | 期望体验 | 边界与设计原则 | 建议顺序 |
| --- | --- | --- | --- |
| 桌面场景事实接入 AG99 | 将“用户回来”“触摸宠物”“桌面忙/闲”等少量、有意义的事实送入 AG99 现有 Observation Runtime | 当前协议和 Adapter→AG99 Observation 链路均不存在；需新增受控协议消息及 Adapter sensor 调用，不发每帧或鼠标轨迹 | 先做边界设计 |
| 本地开口时机/输出准入 | 播放中、用户正在操作、静音或不适合打断时，本地可立即允许、短暂延后或抑制主动语音 | 只负责“现在是否适合呈现”，不判断“说什么”或复制 AG99 主动策略；当前没有完整 owner/实现 | 先做边界设计 |
| 触摸与桌宠互动 | 点击、悬停、轻抚、拖动等行为可以触发不同的本地动作、表情或视线反馈，让用户不必每次先发消息 | 先核实现有窗口交互和模型动作能力，再补齐缺少的语义反馈；默认本地响应，可配置、可打断，不因高频交互调用大模型 | 第一批 |
| 场景模式 | 用户可以切换聊天、工作/专注、安静、观看/游戏等模式，角色表现、输入和打扰策略随场景调整 | 用户可见模式是新增产品层；桌面事实协议和本地准入需要先明确；AG99 仍负责语义主动决策 | 后续批次 |

新增功能优先选择能够复用本地状态、动作、表情和既有协议的能力。暂不以增加高频大模型调用来制造“活着”的感觉。

## 2. 需要优化的已有功能

| 能力 | 现状 | 优化重点 | 责任边界 |
| --- | --- | --- | --- |
| 主动对话 | AG99 已有主动对话策略和输出路径；AG99live 通过 `send_by_session()` 接收主动输出 | 检查语义策略与用户控制；优化桌面事实输入、输出准入、打断和状态恢复。目前场景事实输入与本地开口准入尚未接通 | AG99 决定是否表达及表达内容；AG99live 负责本地及时准入和角色表现 |
| 记忆 | AG99 已有记忆模块，当前体验存在由多种原因造成的混乱 | 先定位问题来源：记忆类型和对话历史边界、写入来源、召回时机、重复/过期/冲突信息，以及用户查看和修正路径；确认后再改已有链路 | 沿用 AG99 记忆能力，不在 AG99live 新建轻量关系记忆或平行事实源 |
| 已实现但难发现、难启用或反馈弱的能力 | 能力分布在 AG99 配置、Web 控制页、桌面设置、创作者工具和 Native Runtime | 解释默认状态和依赖，标明基础/高级/实验用途；为断连、配置错误和设备失败提供可理解原因及恢复入口 | 优先复用现有设置 broker、runtime snapshot 和诊断路径；不足时只补最小链路 |

主动对话和记忆的优化应先审计现状、定位具体问题，再决定修改。不能仅凭功能已经存在就推断触发、记忆质量或管理入口当前有缺陷。

## 3. 有一定基础，需要重新组织设计

| 主题 | 已有基础 | 需要重新组织的内容 | 目标 |
| --- | --- | --- | --- |
| 角色状态模型 | 已有待机、呼吸、眨眼、鼠标凝视、思考随动、对话/播放/打断等局部机制 | 统一 idle、attention、thinking/waiting、speaking、interrupted、恢复待机和异常等状态的触发、优先级、结束条件及动作映射 | 让各项局部能力组合成连续角色表现；本地高频状态不调用大模型 |
| 能力入口与状态展示 | 有桌面设置、AG99 Web 配置、诊断、History、Action Lab、Profile Editor 和设备设置 | 按普通用户、创作者/高级用户分层；聚合已启用、待配置、运行中、不可用、失败和恢复等状态 | 用户能快速知道角色当前能做什么、问题在哪里、下一步怎么操作 |
| 角色表现配置 | 有模型 Profile、动作目录、语音设置、Motion Lab、Action Lab 和 Profile Editor | 将分散的角色身份、模型引用、语音、情绪/动作映射、待机和场景设置组织成可复用的角色预设；导入导出前先明确资源引用和授权边界 | 换模型或分享配置时能够复用“角色如何说、看、动和待机”的体验 |
| 能力成熟度标记 | 源码中同时包含默认可用、需配置、实验性、创作者工具和依赖真实设备的功能 | 在界面和文档中区分已默认可用、需要配置、实验性、仅开发工具、链路待核和现场待验收 | 不让“源码有实现”被误解为“开箱即用且已验收” |

## 排除项与复用原则

- **直播**：Bilibili 弹幕客户端和弹幕合批输入实际在 AG99live 桌面侧，当前通过普通文本输入送入 AG99；它不是 AG99 已有的 Bilibili 接入。当前暂不扩大直播互动编排范围，是否把现有输入作为产品卖点仍待确认。
- **音乐与节目单**暂不作为 AG99live 新增项；复用 AG99 现有能力，不另做歌曲、动作和节目单管理系统。
- **主动对话和记忆**均沿用 AG99 现有模块；AG99live 需要补齐尚不存在的桌面事实输入与本地开口准入，再改善状态反馈和角色表现衔接。
- 不新增第二套 PluginManager、主动对话调度器、Provider 管理器、记忆事实源或播放时钟。
- 屏幕/窗口观察保持单独授权，不因场景切换或主动对话自动开启。

## 建议推进顺序

1. **先组织基础状态**：梳理 idle、凝视、输入、生成、播放、打断和异常的真实 owner 与信号，形成最小角色状态模型，并核实当前能力状态可见性。
2. **优化 AG99 既有链路**：分别审查主动对话和记忆，找到具体现象与根因；先完成一次主动输出到 Live2D 状态收口的纵向验证，再处理记忆链路中的首个明确问题。
3. **加入桌宠互动**：实现一个范围小的触摸/悬停互动试点，确认本地表现优先、可打断且不触发额外 LLM 请求。
4. **形成场景模式**：在前面设置与状态边界清楚后，选择聊天、工作/专注、安静等最有用的场景，组合已有能力并现场验收。
5. **整理角色表现预设**：待模型 profile 和场景行为边界稳定后，再将分散配置组织为可复用预设。

## 验收原则

- 角色无对话时有稳定自然的本地待机；用户互动后能反馈注意、思考、说话、打断和恢复。
- 场景切换不会重复创建 AG99 的主动策略、Provider 或播放链路。
- 每项能力的状态和依赖对用户可见；失败信息能指向具体恢复动作。
- 主动对话和记忆的修改以 AG99 现有模块为基础，并通过真实联调验证。
- 高频鼠标、凝视、Physics 和触摸信号不直接形成高频大模型请求。
- Native 与 TypeScript 桌面端各自支持的能力要按实际实现标记，并经真实运行验收后再称为可用。
