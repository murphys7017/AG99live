# 统一时钟引擎设计

> 文档状态：当前实现规格。正式回复通过原子 `output.segment.v3` 进入
> `TurnPlaybackSessionStore`，再由唯一 `PlaybackTimelineRuntime` 协调字幕、音频、
> 动作和口型。本文不保留迁移过程或旧播放链路。

## 1. 目标

统一时钟链路解决四个问题：

1. 同一回复段的字幕、音频、动作和口型使用同一 `turn_id + message_id` 身份。
2. 有音频时只使用本段 `HTMLAudioElement` 的真实播放时钟。
3. 所有 sink 的 started、terminal 和中断由同一个 Timeline 生命周期解释。
4. 缺少协议事实、时钟、sink 或 wiring 时显式失败，不以 fallback 掩盖错误。

非目标：

- Timeline 不决定动作语义和轴值。
- ModelEngine 不播放音频，也不直接写 SessionStore。
- Live2D WebSDK 不读取 turn、segment 或后端协议。
- Lip sync 不创建独立 WAV 时钟。
- Performance curve 不创建第二条播放链路。

## 2. 当前主链路

```text
output.segment.v3
  -> Inbound 严格解析全部 slots
  -> SessionStore.commitOutputSegment()
  -> TurnPlaybackOrchestrator 生成一个 SegmentJob
  -> PlaybackTimelineRuntime.startSegmentJob()
  -> audio / deferred subtitle / motion / lip-sync sinks
  -> segment-bound audio clock 或 explicit motion-only synthetic clock
  -> ModelEngine parameter plan
  -> Live2D WebSDK 逐帧执行
  -> Timeline terminal
  -> SessionStore projection
  -> control.playback_finished
```

正式链路不存在晚到 audio/motion patch，也不等待 `synth_finished` 才起播已经完整提交的段。

## 3. 组合根与实例所有权

`frontend/src/app/usePetDesktopRuntime.ts` 是运行时组合根，直接创建并持有：

- 一个 `TurnPlaybackSessionStore`。
- 一个 `AdapterConnection`。
- 一个 `PlaybackTimelineRuntime`。
- 一个 `BrowserAudioTimelineSink`。
- 一个 `ModelEngine` 和 motion player。
- 一个 `PlaybackCompletionCoordinator`。

装配顺序：

```text
App 创建 Adapter
  -> Adapter 提供 immutable Timeline execution ports
  -> App 创建 PlaybackTimelineRuntime
  -> App 创建 BrowserAudioTimelineSink
  -> App 将同一个 Runtime 与 BrowserAudioSink attach 给 Adapter
  -> Orchestrator、AudioRuntime、ModelEngine integration 共用该 Runtime
```

约束：

- Adapter 不接收 Timeline factory，也不创建 Timeline 实例。
- Adapter 不创建 BrowserAudioSink，只持有 attach 后的播放端口。
- attach 只能执行一次；未 attach 或重复 attach 都是 wiring 错误。
- 运行中不存在 `configureSegmentExecution` 或第二套 timeline facade。
- `PlaybackTimelineRuntime` 的 registry 只按 `turn_id + message_id` 定位段。

## 4. 模块职责

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| Inbound runtime | 协议解析、slot 校验、原子提交 | 播放和补齐缺失事实 |
| SessionStore | 持久化 turn/segment 事实 | 驱动 AudioElement 或 Live2D |
| Orchestrator | 观察完整段并生成 SegmentJob | 播放媒体、等待分片、维护第二份 readiness |
| PlaybackTimelineRuntime | segment registry、sink 注册/启动/终态、时钟、失败传播 | 解释动作轴语义 |
| Adapter audio runtime | pending audio queue、UI 音频状态、Timeline 适配 | 创建 Timeline、写 audio/motion lifecycle 事实 |
| ModelEngine | 动作校验、关系图、timing、parameter plan | 播放音频、直接写 SessionStore |
| Live2D lip-sync boundary | WebAudio RMS、嘴部参数写入与清理 | 创建第二音频时钟 |
| Live2D WebSDK | 逐帧曲线、动力学、冲突解析和参数写入 | turn/segment 编排 |
| CompletionCoordinator | settled 判断、playback ACK、轮次完成 | motion 记录和 sink 生命周期 |

## 5. SegmentJob 与释放语义

Orchestrator 只调用：

```text
timelineRuntime.startSegmentJob({
  turnId,
  messageId,
  text,
  audio,
  motion
})
```

Timeline segment executor 独占 text/audio/motion release 写入权：

- `audio=present`：先启动 audio sink，canonical text 作为 deferred subtitle 保留。
- `audio=absent`：文本可立即释放；有 motion 时创建 explicit motion-only timeline。
- `audio=failed`：拒绝待显示字幕和已声明 motion，不转换为 text-only 或 motion-only。
- queue item 缺失或身份不匹配：segment 失败，不从其它 pending item 猜测。

`absent` 是后端协议事实，不能由超时、消息没到或播放失败推导。

## 6. 时钟模型

### 6.1 有音频

每次 audio sink 启动会创建一个 AudioElement 和只绑定该实例的 clock：

```text
currentTime
duration
playbackRate
playing / paused / ended
```

AudioElement 的 `playing` 事件携带该 clock 进入 Timeline。Timeline 不查询模块级
active audio element，也不允许其它 segment 借用该 clock。

`loadedmetadata` 只提供准备阶段的 duration，不代表声音已经开始。只有 `playing`
可以建立 audio started 事实并唤醒字幕、口型和已准备动作。

Timeline 在 audio sink start 后持有 3000ms 启动期限。期间 motion 可以保持 pending，但不得由 ModelEngine 的独立计时器提前失败；到期时 Timeline 统一停止 sink 并失败 audio、deferred subtitle 和 required motion。

### 6.2 明确无音频

只有 `audio.state=absent` 且存在 motion 时，Timeline 才创建 synthetic
motion-only clock。它只为无音频动作提供本地时间基，不模拟音频播放。

### 6.3 音频不可用

有音频的段若在 started 时拿不到真实 clock，audio sink 和 segment 失败。禁止：

- 安装永远返回 playing 的 unavailable clock。
- 使用 SessionStore 时长估计代替真实 clock。
- 从全局 active audio element 反查 clock。
- 把失败段重解释为 motion-only。

## 7. Audio、Subtitle 与 Lip Sync

普通音频段的顺序：

1. Timeline 注册并启动 required audio sink。
2. Audio metadata 回报 duration。
3. ModelEngine 预编译正式 semantic intent，或内部 `speech_only` request。
4. Audio `playing` 携带 segment-bound clock。
5. Timeline 投影 audio started，并释放 deferred canonical subtitle。
6. Timeline 在同一 AudioElement 上启动 lip-sync WebAudio analyser。
7. Timeline 唤醒已经准备的 required motion sink。
8. audio、lip_sync 和 motion 分别回报 terminal。

字幕是 audio-backed canonical text，不是第二条普通文本消息。音频起播前失败时，待显示字幕也失败。

Lip sync 是 Timeline 内的 optional sink：

- 正常路径使用同一 AudioElement 的真实 RMS。
- 主路径失败必须记录明确日志和 `lip_sync failed` terminal。
- 已定义的有界随机开合只是一种嘴部视觉降级，持续到音频结束；不得驱动 speech energy。
- lip sync 失败不伪装成成功，也不阻断已经正常播放的音频。

## 8. Motion 与 Speech-Only

正式 motion slot 使用 `engine.motion_intent.v4`。ModelEngine 在 metadata 阶段使用本段 duration
预编译，在 audio `playing` 后使用最新 clock snapshot 启动。

当正式 motion 为 `absent` 且模型支持 voice-following 时，ModelEngine 可以创建内部：

```text
SpeechOnlyMotionRequest {
  kind: speech_only
  profileId
  profileRevision
  modelId
}
```

该 request 只存在于 ModelEngine 内部，在编译边界适配为 parameter plan；它不是
`engine.motion_intent.v3/v4` 传输 payload，也不能覆盖正式 motion 的失败。

动作开始必须同步返回非空 `runId`。ModelEngine 只向 Timeline 报告 rejected、started 和
terminal；`sessionProjection` 是 audio/motion lifecycle 写入 SessionStore 的唯一出口。

catalog motion 只有 WebSDK 在资源加载后获得有效 Cubism handle 才能报告 started。`accepted`
不是 started；其启动和终态 watchdog 属于 motion player，terminal 仍由 Timeline 解释。

## 9. Performance Curve

后端只在 motion payload 内附加 `performance_curve_hint`。前端不接收独立 curve patch，
也不创建 PerformanceCurveSink。

ModelEngine 使用 audio duration 和当前剩余时长求解 parameter plan 的进入、保持和退出 timing。
动作在 audio `playing` 后立即启动，视觉入场延迟完全由计划曲线表达，不再叠加固定 90ms/260ms 定时器。

启用曲线生成时必须显式配置独立 `performance_curve_provider_id`。配置无效属于启动配置错误，
不得复用当前会话聊天 Provider。曲线任务在原子段关闭前未 ready 时只记录 skipped 诊断，
不补发 patch，也不改变原 motion slot 的协议事实。

## 10. 终态与写入权

| 事实 | 唯一写入者 |
| --- | --- |
| 原子 segment、backend turn/synth 状态 | Inbound protocol runtime |
| segment ready | TurnPlaybackOrchestrator |
| text/audio/motion released | Timeline segment executor |
| audio duration/started/terminal | Timeline sessionProjection |
| motion started/completed/failed | Timeline sessionProjection |
| lip-sync terminal | PlaybackTimelineRuntime / PlaybackTimelineEngine |
| settling、playback ACK、completed | PlaybackCompletionCoordinator |

Sink 首次进入 `completed / failed / interrupted / absent` 后终态稳定，迟到 cleanup 不得覆盖真实失败。
未关闭 timeline 上缺少 required sink 或 lifecycle wiring 时必须让对应段失败；已关闭 timeline 的迟到事件
只保留诊断，不重新创建 segment 或 timeline。

## 11. 中断与销毁

- 中断必须携带明确 `turn_id + message_id`，ModelEngine 只停止匹配的 active run。
- 新输入不会替换或中断旧 timeline；它使用新的 `turn_id` 直接提交 AstrBot，由官方队列调度。
- 前端不维护输入队列；每条输入完成自身附件准备后直接发送，调度顺序由 AstrBot 负责。
- `control.interrupt` 只由用户显式中断操作发送，不得作为 `sendText` 的前置保护或播放收口手段。
- audio stop 同时清理 AudioElement、WebAudio graph、deferred subtitle 和仍 open 的 required sinks。
- App scope dispose 负责断开 Adapter、停止 Timeline 和清理 watchers。
- Live2D 模型替换先取消旧 load generation，再释放 Cubism 资源；旧异步回调不得触碰新实例。

## 12. 严格失败规则

| 错误 | 处理 |
| --- | --- |
| `output.segment.v3` 非法 | 拒绝整段，零 Store/queue 副作用 |
| 重复 segment | 拒绝，不覆盖旧段 |
| queue identity 不匹配 | segment failed |
| audio present 但真实 clock 缺失 | audio、字幕和 segment failed |
| audio failed | 字幕与 motion failed，不转 absent |
| audio start timeout | audio、字幕、required motion 与 segment failed |
| motion 编译或启动失败 | motion failed，不生成默认 pose |
| Timeline/required sink 缺失 | 对应段 failed |
| terminal 重复写入 | 保持首个终态并记录诊断 |
| v4 motion 非法 | 显式失败，不降级到 v3 |

官方 AstrBot `<@anim>` 是注入函数不存在时的独立 v3 兼容传输入口，不是 v4 主链路失败后的 fallback。

## 14. 验证与剩余风险

当前自动验证覆盖 Timeline 状态机、audio sink、ModelEngine 编译、协议提交、类型检查和 Web 构建。
仍需真实 AstrBot + Provider + TTS + Electron + Live2D 端到端验证：

1. WAV 起播与字幕首次显示是否来自同一个 `playing` 事实。
2. 口型是否绑定当前 AudioElement 并在结束/中断后清零。
3. 语义动作和 speech-only 动作是否使用同一 segment clock。
4. audio failed、快速 interrupt、模型替换时所有终态是否一致。
5. hybrid 多 segment 是否严格隔离 `message_id`、clock 和 motion run。
