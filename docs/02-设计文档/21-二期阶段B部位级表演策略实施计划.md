# 二期阶段 B 部位级表演策略当前基线

## 1. 文档目的

本文档记录二期阶段 B 在当前源码中的实现边界、模块职责和剩余工作。阶段 B 的源码收口已经完成，
本文不再记录历史实施批次、提交信息或回滚过程，也不重新定义项目架构。

阶段 B 的核心结果是：语义姿态、sequence、SpeechPose、gaze、face、hesitation、residual 和主动动力学
都沿同一条 ModelEngine 编译链路进入参数计划，再由 AG99 Live2D Runtime 完成一次主动参数融合和表现响应。
后续修改只能在这条链路内进行，不能重新增加并行的时间线、播放器、动作编排器或参数融合器。

## 2. 当前唯一主链路

```text
engine.motion_intent.v4
-> compileSemanticMotion
-> CompiledSemanticMotion
-> compilePerformanceSchedule
-> ModelParameter compile stages
-> parameterTrackGraphCompiler
-> engine.parameter_plan.v3
-> PlaybackTimeline
-> AG99 Live2D Runtime / ActiveParameterRuntime
   -> SpeechSignalRuntime
   -> ActiveParameterMixer
   -> ParameterPresentation
-> LAppModel active parameter write
-> Official Cubism Physics / model.update / draw
```

各层只拥有自己的事实：

| 层 | 当前职责 | 明确不负责 |
| --- | --- | --- |
| Persona / LLM | 生成可见文本和九级语义动作意图 | 生成 Live2D 最终参数、逐帧数组或 Physics 参数 |
| Adapter | 校验动作 effect、关联身份、聚合原子输出段 | 编译最终模型参数或维护前端播放状态 |
| PerformanceSchedule | 统一 phrase、step、部位事件、停顿、残留和释放时序 | 播放媒体、逐帧写模型参数或融合主动来源 |
| Parameter Track Compiler | 将 Schedule 事件投影成 V3 keyframes / modulation | 重新计算文本时间或融合参数来源 |
| PlaybackTimeline | 管理 Segment 的音频时钟和 required sink 生命周期 | 解释语义动作或生成参数目标 |
| ActiveParameterMixer | 以 Cubism base snapshot 为基准融合 direct plan（含 SpeechPose modulation）与口型 | 判断文本语义、决定事件时间或计算 Physics |
| ParameterPresentation | 对融合后的非口型目标执行一次 bounded / spring 响应 | 再次融合来源或处理 Physics 参数 |
| SpeechSignalRuntime | 从当前音频生成 RMS、voiced、attack/release 和活跃度信号 | 决定语义方向或直接替代口型协议 |
| Cubism Physics | 根据主动参数计算头发、衣服和饰品的被动响应 | 参与语义编排、主动参数平滑或 Mixer 融合 |

## 3. `PerformanceSchedule` 当前内容

源码位置：`frontend/src/model-engine/compiler/performanceSchedule.ts`。

Schedule 是 ModelEngine 编译期唯一的表演时间事实源，当前保存：

- canonical assistant text 的 phrase、边界类型、权重和 emphasis。
- sequence step 的 `durationWeight`、起止时间和 estimated alignment。
- semantic transition 与每个部位的 timing 结果。
- SpeechPose 的 start、phrase、release 事件。
- gaze、face 和 hesitation 的诊断事件。
- 每条轨道的 `requiredOwnedUntilMs`、residual、压缩结果和释放决策。
- 事件到参数 keyframe 或 speech modulation 节点的来源映射。

V4 没有 phrase identity 或 text span，因此 phrase 与 sequence step 只能记录估算对应，不能描述成精确的
“第二句话对应第二个动作”。如果后续真实数据证明这种近似不足，必须先单独评估协议扩展，不能在前端伪造 ID。

## 4. 部位策略当前状态

### 4.1 gaze

gaze 已通过共享 Schedule 生成专用事件：

- `gaze_lead`：单姿态或 sequence 起始时先进入有限比例目标。
- `gaze_dwell`：短暂起势后进入完整视线目标。
- `gaze_transfer`：sequence 在下一个 step 前转移，长句 pose 可在 phrase 边界进行一次有界转移。
- `gaze_release`：只记录 Direct Plan 的释放时刻，不生成 neutral keyframe。

最终回收由同一份 plan blend 混回当帧 Cubism base，不先回 Profile neutral 再跳 Idle Motion。

### 4.2 face

进入 Direct Plan 且偏离中性值的 `eye / brow / mouth / face` 轴使用 face 生命周期：

```text
face_enter
-> 可选 face_settle
-> face_transfer
-> dynamic residual
-> face_release
-> plan blend-out 回到当帧 base
```

pose 与 sequence 共用同一参数轨道投影入口。四步 sequence 已占满 V3 keyframe 预算时，不追加 settle，
也不删除主模型给出的语义目标。`mouth_open` 的实际口型所有权仍属于 runtime，Expression 资源冲突继续
由现有资源策略显式拒绝。

### 4.3 hesitation 与 semantic reversal

全局 hesitation 只从以下信息确定性派生：

- phrase 结尾的省略号或破折号。
- 连续软边界或明显转折词前的 phrase 边界。
- 现有 `intentTags` 中的思考、犹豫、迟疑和停顿信号。

编译器最多选择一个最强合法窗口，并生成 `hesitation_hold / hesitation_resume`。semantic、gaze、face
和 SpeechPose 使用同一个累计 hold，不创建私有时钟或额外参数目标。

semantic 方向换向不是全局 hesitation 的候选来源。相邻 step 本来发生换向时，只在对应 semantic axis
轨道内增加短暂准备保持，并记录 `semantic_reversal_preparation`；其他轴不受影响。

候选窗口不足时只记录明确的未采用原因。已经选中的必需事件如果时间、引用或顺序非法，则显式编译失败，
不通过压缩、截断或 fallback 伪造结果。

### 4.4 dynamic residual

residual 表示某条轨道在最后目标上需要保留的最小尾部时间，不是第二段动画。它由 Schedule 统一读取：

- semantic group 的基础响应策略。
- 最后 phrase 的边界、标点和 emphasis。
- hesitation 是否存在。
- 最后一次 semantic transition 是否换向。
- 当前 plan 的 blend-out 和最大时长预算。

sequence graph 收集各轨道的 `requiredOwnedUntilMs`，取最晚需求作为唯一共享 release 和 graph duration。
任何尾部扩展都必须留在 V3 合法时长内；无法容纳的必需事件显式失败，不回退到固定 residual。

### 4.5 主动动力学与语音随动

B6-1 复用 `mapSemanticBindingDynamics()` 和 `ParameterPresentation` 的既有响应结构：

- head / gaze 使用更快的响应，允许有限欠阻尼和小幅 overshoot。
- body / torso / shoulder 使用更低响应频率和更高阻尼，配合已有轨道偏移形成后跟。
- eye / brow / face 使用快速但更受控的 spring。
- 未识别的自定义部位继续使用原有 bounded 响应。

B7 在已有职责内收口说话随动和相邻音频段接管：

- 普通讲话优先使用 yaw / roll 主导随动，头身共享确定性方向种子。
- semantic strength、`emotion_label` 和 `intent_tags` 共同选择已有 gesture family 和 preset，避免讲话时
  固定退化为单一的点头。
- 当前 audio 结束且只剩 Direct Plan residual 时，相邻 audio-backed segment 可以原子接管相同参数的
  表现状态；motion-only 仍必须完整执行。

语音能量只调制已有 SpeechPose modulation 的活跃度和 emphasis，不决定左右、上下或语义方向。口型继续
使用当前音频的即时路径；口型不可用不能阻止头身说话随动。Cubism Physics 不进入上述主动动力学路径。

## 5. 语音提示与可选表演曲线

`speech_cues` 是 provider-neutral 的短语级提示，沿 `output.segment.v4.speech` 传递到 Schedule。它们只
影响已有的 phrase emphasis 或 hesitation 候选，不生成新的动作类型、播放器或参数来源；canonical text
仍独立用于字幕、聊天记录和普通 TTS。

当前支持的提示方向包括 `breath`、`sigh`、`laugh`、`chuckle`、`hesitate` 和 `emphasis`。提示只提供
粗粒度 phrase 定位，真实发生时间仍由 PlaybackTimeline 的音频时钟决定。

可选 `performance_curve_hint` 只属于 `motion.payload`。它可以在 TTS 期间并行请求，也可以因未及时完成、
Provider 失败或配置关闭而跳过。它绝不能阻塞 TTS、`output.segment.v4`、基础动作或音频播放，也不能在
Segment 出站后通过独立 patch 修改已提交动作。

## 6. 参数轨道与运行时执行

`parameterTrackGraphCompiler.ts` 只负责把 Schedule 事件投影成 `engine.parameter_plan.v3`：

```text
semantic -> compileSemanticTrackTiming + buildSemanticTrack
gaze / face -> 专用事件编译 + buildStagedPartParameterTrack
speech -> 现有 SpeechPose modulation
```

当前统一使用 `PerformancePartTrackTiming`：

```text
PerformancePartTrackTiming
  events                 全部诊断事件，包括 release
  parameterEvents        可投影为 keyframe 的事件
  requiredOwnedUntilMs
  staggered
  residual
  compressed
  strategy: semantic | gaze | face
```

release 事件只进入诊断，不投影成 neutral keyframe。V3 每个参数允许 2-4 个 keyframe，第一点必须是
`at_ms=0 / transition_ms=0`；四步 sequence 已占满预算时，装饰事件必须在编译前按规则省略，不能先生成
超额轨道再 catch-and-retry。

进入 AG99 Runtime 后，主动来源只走一次融合：

```text
base snapshot + direct plan（含 SpeechPose modulation）+ lip-sync
-> ActiveParameterMixer
-> final non-lip target
-> ParameterPresentation 一次响应
-> 唯一主动参数帧写入
-> Cubism Physics
```

WebSDK 不重新解释 semantic group，不创建第二次平滑，也不处理文本或 hesitation。官方 Cubism `Framework`
和 `Core` 保持原始 SDK 职责，不承载 AG99 表演业务。

## 8. 当前剩余工作

这些是二期源码收口后的深化方向，不是阶段 B 主链路缺失：

1. 用真实 TTS、Electron 和 Live2D 观察 head、gaze、face、body 的起势、保持、换向和收势，确认当前
   response profile 是否需要有限数值调校。
2. 观察连续 Turn 的动作是否仍过于重复，再决定是否需要扩展动作族评价；不先增加强制运行时多样性控制器。
3. 按 Physics setting 分析输入、粒子链、输出、速度和衰减，形成模型级诊断与 profile；Physics 仍不进入
   Performance Director 或 ActiveParameterMixer。
4. 在动作观感基础稳定后建设 Motion Lab 评价入口、播放完成点赞、问题分类、sequence 对比和训练样本筛选。
5. 为 VTS 原始录制补充语义标注、审核和训练导出；小模型尚未接入正式运行链路。
6. 只有真实数据证明 estimated alignment 不够时，才评估 phrase identity 或 text span 协议扩展。

## 9. 诊断与失败规则

Schedule trace 至少能够定位：

- 每个部位事件来自哪个 axis、phrase 或 semantic step。
- transition、hold、residual 和共享 release 的时间。
- 事件投影到哪个参数节点或 speech modulation 点。
- 哪个可选事件因 keyframe 预算或合法窗口被省略。
- 必需事件为何编译失败。

以下情况必须显式失败：

- 时间不是有限数、小于零或顺序逆转。
- 事件引用不存在的 axis、step、phrase 或 parameter。
- 必需轨道超出 V3 keyframe 上限或最大合法时长。
- Expression 资源与 Direct Plan 重复控制参数。
- 同一 parameter 被不允许的重复轨道或 modulation 占有。

没有 hesitation 信号、候选窗口不足、可选 settle 未创建、performance curve 未及时完成和 Motion Lab
观察写入失败，都不能改写当前回复、动作或协议事实。不得用默认动作、旧 schema、第二套播放器或 catch
后的通用轨道掩盖正式路径失败。
