# 二期阶段 B 部位级表演策略实施计划

## 1. 文档目的

本文档是二期阶段 B 的唯一详细实施计划。它不重新定义项目架构，而是基于当前源码说明：

- 现在已经具备哪些表演编排能力。
- face、hesitation、dynamic residual 和头身视线协作当前已经做到什么，以及下一批还缺什么。
- 每一批应该修改、删除和保留哪些代码。
- 如何不修改当前对外协议，不创建第二套时钟、播放器、参数融合器或 fallback。
- 每批的完成标准、最小验证和回滚边界。

阶段 B 的目标不是继续增加动作模块，而是让已有的语义姿态、sequence、SpeechPose、视线、面部和收势共享同一份 `PerformanceSchedule` 与参数轨道。

## 2. 当前源码事实

### 2.1 已存在的唯一主链路

```text
engine.motion_intent.v4
-> compileSemanticMotion
-> CompiledSemanticMotion
-> compilePerformanceSchedule
-> ModelParameter compile stages
-> parameterTrackGraphCompiler
-> engine.parameter_plan.v3
-> PlaybackTimeline
-> AG99 Live2D Runtime / ParameterPresentation
-> ActiveParameterMixer
-> LAppModel active parameter write
-> Official Cubism Physics / model.update / draw
```

当前边界是合理的，阶段 B 必须在这条链路内继续完成，不得旁路新建表演运行时。

### 2.2 `PerformanceSchedule` 已有能力

`frontend/src/model-engine/compiler/performanceSchedule.ts` 已经统一保存：

- 助手文本分片后的 phrase、边界强度、权重和 emphasis。
- sequence step 的 `durationWeight`、起止时间和比例。
- phrase 与 semantic step 之间的估算时间重叠关系。
- semantic transition、SpeechPose start/phrase/release 和 gaze 事件。
- 事件到最终 keyframe 或 speech modulation 节点的诊断映射。

因此，后续不应再建 `FaceTimeline`、`HesitationTimeline` 或部位私有时钟。

### 2.3 gaze 已验证专用策略接入方式

gaze 已经不再使用通用 semantic-group 时间常量，而是通过同一份 Schedule 生成：

- `gaze_lead`：先进入有限比例的视线目标。
- `gaze_dwell`：短暂起势后进入完整目标。
- `gaze_transfer`：sequence 在下一个 step 前转移，长句 pose 可在 phrase 边界做一次有界转移。
- `gaze_release`：只记录 Direct Plan 开始释放所有权的时刻。

最终收回依然由现有 plan blend 混回当帧 Cubism base，不会先回 Profile neutral 再跳到 Idle Motion。

### 2.4 SpeechPose 已是非周期 phrase 手势

`speechPoseStage.ts` 已经不是单一正弦摆动：

- 按 phrase 生成非周期手势点。
- 根据 preset 选择头部和身体通道。
- 根据 Turn/Message 身份做可重现取样。
- 头部与身体使用不同的起势比例、transition 和 `follow_delay_ms`。
- 通常优先选择 roll/yaw，pitch 主要保留给强调。

阶段 B 不应推翻 SpeechPose，而应让其与 face、hesitation 和 semantic track 共享更完整的编排信息。

### 2.5 运行时职责不需要重新划分

- ParameterPresentation 求值已编译的轨道。
- ActiveParameterMixer 是唯一主动参数融合入口。
- Cubism Physics 在主动参数写入后计算头发、衣服和饰品的被动响应。
- 官方 Cubism Framework/Core 不理解 Turn、文本、语义轴、phrase 或表演事件。

## 3. 已确认的缺口

### 3.1 face 仍然只是通用轨道

`eye / brow / mouth / face` 目前共用一组固定常量：

```text
transitionOffsetMs = 25
transitionMs       = 80
preferredHoldMs    = 45
residualMs         = 40
```

它只表达“这类轴稍后变化”，没有表达：

- 面部先轻微起势、再进入完整表情。
- 表情在句尾的有限停留。
- sequence 转折中的面部转换。
- 疑问、感叹、省略和普通句号的不同收势。

对 pose 来说，除 gaze 外的语义参数也没有独立 keyframe 轨道，主要依赖整个 plan 的 blend-in/out。

### 3.2 hesitation 没有正式事件

当前 trace 中没有 hesitation 类型。逗号、省略号、破折号、转折 phrase 和“思考/犹豫”类 intent tag 不会形成可解释的停顿事件。

结果是参数从一个目标干净地进入下一个目标，缺少“保持 -> 考虑 -> 继续或换向”的中间结构。

### 3.3 residual 已由共享 Schedule 动态决定（B4 已完成）

`resolveTrackTimingPolicy()` 不再拥有固定 residual。semantic、gaze 和 face 统一读取句尾标点、
phrase boundary、emphasis、hesitation、最终 semantic transition 是否换向以及合法尾部预算，
在各部位基础响应时长上生成有界 residual request。`engine.parameter_plan.v3` 只有一套全局 blend，
因此 sequence graph 取所有轨道最晚的最小占有时间作为唯一真实 release；单 pose 只使用原有 release
前能够容纳的 residual。两者都不创建第二段动画，也不伪造部位独立释放。

### 3.4 部位协作只有局部常量

当前已有：

- gaze 在 sequence step 前约 80 ms 转移。
- semantic head 无额外延迟。
- semantic body 默认延迟 110 ms。
- SpeechPose body 使用 Voice Following Profile 中的 `follow_delay_ms`。

但这些关系仍分散在 gaze、通用 semantic policy 和 Voice Following Profile 中。它们还没有共同响应“这是起势、转折、强调、犹豫还是收势”。

### 3.5 当前类型与轨道投影已收口为多部位策略

`parameterTrackGraphCompiler.ts` 当前是：

```text
semantic -> compileSemanticTrackTiming + buildSemanticTrack
gaze / face -> 专用事件编译 + buildStagedPartParameterTrack
```

pose 路径则在 `parameterTrackGraphStage.ts` 中使用 `attachPosePartTracks()` 统一处理 gaze 和 face。

hesitation 后续仍必须复用这套部位轨道结果，不能另加 `attachPoseFaceTracks()`、`attachHesitationTracks()`
或更多 timing map，把策略重新拆成重复实现。

### 3.6 V3 参数轨道有四点上限

`engine.parameter_plan.v3` 的每参数 keyframe 数量为 2-4，第一点必须是 `at_ms=0 / transition_ms=0`。

这意味着：

- 四步 sequence 已经占满四个语义目标。
- 不能为了 face settle、hesitation 或 release 盲目追加第五点。
- release 不应变成回 neutral 关键帧，应继续由 plan blend 完成。
- 可选装饰事件必须在事件编译前按明确优先级决定是否生成，不得先生成超额轨道再 catch-and-retry 或降级为通用轨道。

## 4. 目标内部模型

### 4.1 不增加新的对外协议

首批继续使用：

- `engine.motion_intent.v4`
- `engine.parameter_plan.v3`
- 现有 `SemanticParameterPlanEntry.keyframes`
- 现有 `PerformanceSchedule` 内部 trace

不在首批增加 phrase ID、hesitation 协议字段、逐帧参数数组或新的 WebSocket 消息类型。

### 4.2 Schedule 仍然是唯一时间事实源

Schedule 内部事件扩展为三类：

```text
semantic events
  semantic_transition

part strategy events
  gaze_lead / gaze_dwell / gaze_transfer / gaze_release
  face_enter / face_settle / face_transfer / face_release

speech and discourse events
  speech_start / speech_phrase / speech_release
  hesitation_hold / hesitation_resume
```

事件只描述时间、来源和所有权结构，不保存最终逐帧参数值。

### 4.3 统一轨道编译结果

当前 `PerformanceSemanticTrackTiming` 和 `PerformanceGazeTrackTiming` 具有重复字段。实施时应收口为一个内部结果：

```text
PerformancePartTrackTiming
  events                 全部诊断事件，包含 release
  parameterEvents        只包含需投影为 keyframe 的事件
  requiredOwnedUntilMs
  staggered
  residual
  compressed
  strategy: semantic | gaze | face
```

不同策略仍可以使用不同的事件生成函数，但 sequence compiler 只管理一个 timing map 和一个轨道投影入口。`gaze_release`、`face_release` 等所有权事件进入 `events`，但不进入 `parameterEvents`，因此不会被错误投影成 neutral keyframe。

### 4.4 face 的实际表达

face 不复制 Expression 资源，也不接管口型。它只处理已经绑定到 Direct Plan 的 `eye / brow / mouth / face` 语义参数。

目标生命周期：

```text
plan blend-in
-> face_enter（轻量起势）
-> face_settle（完整表情）
-> face_transfer（sequence 语义变化）
-> 动态 residual（可选）
-> face_release（开始释放 plan ownership）
-> plan blend-out 回到当帧 base
```

约束：

- pose 只在确实需要起势/稳定差异时生成两点或三点轨道。
- sequence 优先保留主模型生成的语义 step。有空余 keyframe 预算时才增加 settle，不删除语义目标。
- `face_release` 是诊断事件，不是 neutral keyframe。
- Expression 资源与 Direct Plan 的参数冲突仍由现有 `resourcePolicyStage` 拒绝，不新增覆盖或混合规则。

### 4.5 hesitation 的实际表达

首批 hesitation 从已有信息确定性派生，不改 LLM 协议：

- phrase 结尾的 `… / ... / —`。
- 连续软边界或明显转折词前的 phrase 边界。
- 已有 `intentTags` 中的思考、犹豫、迟疑类信号。
- sequence 相邻 step 的目标方向变化。

首批只生成：

- `hesitation_hold`：在当前目标上短暂保持。
- `hesitation_resume`：恢复原定的下一个 semantic transition。

它不凭空生成新的语义方向。“反转”只在相邻 semantic step 本来就发生换向时表现为“先保持，再换向”。如果未来要让 Director 生成额外中间姿态，需要单独证明所有权和 keyframe 预算，不在首批偷渡。

### 4.6 dynamic residual 的实际表达

residual 表示某条轨道在最后目标上需要保留的最小尾部时间，不是第二段动画。V3 仍只有一个全局
blend-out，最终 release 由 sequence graph 在收集全部轨道需求后统一确定。

动态计算输入：

- semantic group 的基础响应速度。
- 最后一个 phrase 的 boundary 与标点。
- 最后一个 phrase 的 emphasis。
- 是否存在 hesitation。
- 最后一次 semantic transition 是继续同向还是换向。
- 当前 plan 的 blend-out 和最大时长上限。

预期规则：

- 普通陈述句使用短 residual。
- 问句允许 gaze/face 有限保留。
- 感叹或强调快速到位，但不长时占有。
- 省略和 hesitation 可延长保持，但必须有上限。
- body 可以提出比 head/face 更晚的最小占有需求；如果它成为最长需求，会推迟整份 plan 的共享 release，
  而不是让 body 与 face 在 V3 中分别释放。

动态 residual 函数必须事先读取合法尾部预算，并直接返回预算内的确定性结果；这是正常范围策略，不是失败后 fallback。如果已被选为必需的事件仍无法在 `MAX_MOTION_DURATION_MS` 与 keyframe 顺序内表达，应在编译期返回精确错误，不回退到固定 residual。

### 4.7 头、身体、视线和面部的协作

协作分为时间关系和数值关系，两者不应混在一起：

- 时间关系由 `PerformanceSchedule` 所有：gaze 可领先，head 是主动起势，face 稍后进入，body 延迟跟随。
- 数值关系由已有 semantic axis relation graph 与 Profile 所有：头身同向、反向平衡、比例和边界不在 Schedule 里硬编码。
- SpeechPose 仍只生成说话期间的有界 modulation，不改写 semantic target。
- ActiveParameterMixer 仍只融合已生成的 contribution，不根据句型临时改时间或目标。

有限反向平衡只能使用 Profile 明确允许的 relation rule。如果当前 relation graph 无法表达，先记录为独立 Profile 能力缺口，不在 Director 中偷加一套值融合。

## 5. 分批实施顺序

### 批次 B1：收口轨道策略结果（已完成）

目标：在增加 face 前，删除当前只适合“gaze 与其他”的双路管理。

主要修改：

- 在 `performanceSchedule.ts` 中统一 semantic/gaze 共有 timing 结果结构。
- 在 `parameterTrackGraphCompiler.ts` 中将 `timingsByAxis` 和 `gazeTimingsByAxis` 收口为一个按 axis 缓存的结果。
- 将 sequence 轨道编译改为“解析策略 -> 编译事件 -> 投影参数点”的单一流程。
- 保留 gaze 当前可见行为与错误语义，不在这一批改动观感常量。

应删除或迁移：

- sequence compiler 中两个平行 timing map。
- 只为返回类型差异而存在的重复计数与类型断言。

完成标准：

- gaze pose 和 sequence 编译结果与当前一致。
- 不新增协议版本。
- 不新增 stage、Timeline 或运行时控制器。

当前实现结果：

- semantic 与 gaze 统一返回 `PerformancePartTrackTiming`。
- `events` 保留全部诊断事件，`parameterEvents` 只保留可投影成 keyframe 的事件；release 不会被错误投影成回中点。
- sequence compiler 只保留一个 axis timing map 与 `buildScheduledParameterTrack()` 投影入口。
- 旧的 `PerformanceSemanticTrackTiming`、`PerformanceGazeTrackTiming`、双 timing map 和类型断言已删除。
- 统一边界会拒绝同 axis 策略不一致，以及可投影事件数与参数节点数不一致。
- gaze pose/sequence 的事件生成、目标比例、尾部扩展和 plan blend release 行为未改变。

建议提交：

```text
refactor: unify performance part track compilation
```

### 批次 B2：face 生命周期（已完成）

目标：让 face 从固定 semantic-group 常量进入共享 Schedule 的专用策略。

主要修改：

- 在 `performanceSchedule.ts` 中增加 face event 编译。
- 修改已有 pose 轨道附加函数，使其处理 gaze 和 face，而不是新增平行 `attachPoseFaceTracks()` stage。
- 在 sequence track graph 中将 face 事件投影为现有 V3 keyframes。
- 使用现有 plan blend 完成 release，不写 neutral 回中点。
- 扩展 `PerformanceTimingEventTrace` 的内部事件类型，并在 trace 版本确实发生含义变化时升级内部 trace 版本。

应删除或迁移：

- `resolveTrackTimingPolicy()` 中 `eye / brow / mouth / face` 的固定 residual 所有权。
- `attachPoseGazeTracks()` 的 gaze-only 命名和只支持单部位的分支结构。

完成标准：

- pose 面部表情能观察到起势、稳定和释放。
- sequence 面部转换不删除任何 LLM 语义 step。
- 四点上限在事件生成前就已决定，不使用失败后降级。
- Expression 资源参数冲突仍显式拒绝。

当前实现结果：

- face 与 gaze 共用 `PerformancePartTrackTiming`、共享 finalizer、单 axis timing map 和单参数投影入口。
- pose 与 sequence 均由现有 `ParameterTrackGraphStage` / sequence graph 编译器投影，不新增 face Stage。
- `face_enter` 只在存在 `face_settle` 时使用 68% 目标；settle 在 45ms 开始并用 75ms 过渡到完整目标。
- sequence 的 `face_transfer` 在对应 semantic step 开始后 25ms 进入，四步上限已满时省略 settle 并完整保留四个 LLM 目标。
- `face_release` 只进入 trace，不进入 `parameterEvents`，并在 sequence graph 最终化时与唯一全局 plan blend 起点对齐。
- `resolveTrackTimingPolicy()` 已删除 `eye / brow / mouth / face` 的固定策略分支，旧 gaze-only pose 命名和投影函数已删除。
- 内部 trace 在 B2 升级为 `performance_schedule_trace.v3`；外部 `engine.motion_intent.v4` 与 `engine.parameter_plan.v3` 不变。
- `mouth_open` 的 runtime 所有权和 Expression 参数冲突拒绝规则保持不变。

建议提交：

```text
feat: schedule face performance lifecycle
```

### 批次 B3：hesitation 与停顿

目标：将已有 phrase 与 intent tag 中的犹豫信号转换为正式时间事件。

主要修改：

- 扩展 `compilePerformanceSchedule()` 的内部输入，读取已有 `intentTags` 和必要的语义摘要；不改对外 intent 协议。
- 从 phrase boundary、标点和相邻 sequence step 中编译 `hesitation_hold/resume`。
- 让 semantic、face、gaze 事件在同一 Schedule 中消费 hesitation 产生的窗口。
- SpeechPose phrase 点在 hesitation 窗口中降低变化速度或保持，但不新增第二条说话轨道。

不做：

- 不凭空添加新的正负语义目标。
- 不根据音量直接决定左右方向。
- 不为无犹豫信号的句子随机插入停顿。

完成标准：

- 省略、思考和转折句能从 trace 中解释“何时保持，何时继续”。
- 没有 hesitation 信号时不生成事件，不视为错误。
- 有信号但达不到最小合法 hold 窗口时，在事件生成前记录 `hesitation_not_scheduled:insufficient_window`，不生成一个随后需要修补的非法事件。
- 已经被选中并注册的 hesitation 事件如果时间、引用或顺序非法，则显式编译失败。

当前实现结果：

- `compilePerformanceSchedule()` 直接读取现有 `intentTags` 与 sequence 语义轴结果，不扩展外部动作协议。
- 省略号、破折号、转折、连续软边界、犹豫类标签和真实方向反转会形成候选；只选择一个最强合法窗口。
- `hesitation_hold / hesitation_resume` 只表达编排时间，不生成额外参数 keyframe 或随机目标。
- semantic、gaze、face 和 SpeechPose 对窗口后的事件累计应用同一绝对 hold；SpeechPose 无法在 release
  前容纳完整窗口时显式编译失败，不再按局部活动区间缩放或截断。
- 不足的候选窗口写入 `hesitation_not_scheduled:insufficient_window`，不会在失败后降级为其他动作。
- 当前内部 trace 为 `performance_schedule_trace.v7`，Motion Lab 可显示 hesitation、speech cue 映射、residual 原因和共享 release decision；外部 V4/V3 协议不变。

建议提交：

```text
feat: compile hesitation performance events
```

### 批次 B4：dynamic residual 与部位时序协作（已完成）

目标：删除固定 residual 所有权，并让 gaze/head/face/body 围绕同一类表演事件保持有界的先后关系。

当前实现结果：

- residual 统一读取句尾、emphasis、hesitation、最终换向和尾部预算；semantic group 常量只保留为部位基础响应参考，不再直接拥有最终决策。
- 每条轨道通过 `requiredOwnedUntilMs` 提交最小占有需求，sequence graph 取最大值确定唯一共享 release
  与 graph duration；任何扩展都受 `MAX_MOTION_DURATION_MS - blendOutMs` 约束，单 pose 不越权改写 plan timing。
- gaze/head/face/body 仍使用各自必要的起势偏移，但全部在同一 `PerformanceSchedule` 中生成、登记并追踪，不建立部位私有时钟。
- Voice Following Profile 继续拥有 speech modulation 的 `follow_delay_ms`；Schedule 不覆盖模型级配置。
- 无法容纳 semantic transition 与 blend-out 的输入会明确编译失败，不截断、不回退到固定 residual。
- 当前内部 trace 为 `performance_schedule_trace.v7`，所有 gaze/face release 与最终全局 blend 起点一致；
  外部 `engine.motion_intent.v4` 与 `engine.parameter_plan.v3` 不变。

完成标准：

- 普通陈述、问句、强调和犹豫句具有可解释的不同收势。
- 头、身体、视线和面部的时间关系能从同一 Schedule trace 中还原。
- 任何 plan 尾部扩展都有事件来源，不再只有一个 semantic-group 常量。
- 释放后最终值仍等于当帧 Cubism base，不出现先回一点再跳 Idle 的现象。

建议提交：

```text
feat: derive performance residual and part timing
```

这一批位于 B4 之后、语音能量耦合之前。它先把上游模型生成的少量语音表演提示规范化，
再交给现有 `PerformanceSchedule`；不直接改变 TTS Provider，也不创建新的动作控制路径。

当前进度：AstrBot 侧的结构化输出、规范化、结果 Hook 和旧 MiniMax 标签链路清理已经完成；
AG99 侧已完成结果 Hook 接收、Adapter 交接、`output.segment.v4` speech slot、前端 SessionStore
保留、ModelEngine 编译上下文传递和 PerformanceSchedule 映射。

  `chuckle`、`hesitate` 和 `emphasis`。
- 在模型结果完成后校验并规范化提示；`canonical_text` 继续作为字幕、聊天记录和普通 TTS 文本。
- 通过 `output.segment.v4.speech` 交给 AG99，禁止 AG99 重新解析 Provider 语法，也禁止把提示塞入 motion payload。
- 将提示映射到现有的 hesitation、speech phrase、face 或 speech modulation 事件，不增加新的
  Stage、时钟、播放器、Mixer source 或参数写入路径。
- `OnTTSStateChangedEvent` 继续只报告 TTS 生命周期，不承担文本转换或表演提示修改。

第一版只提供粗粒度的 phrase 定位，不生成精确音频时间，也不让提示决定语义动作方向。真实时间
仍由 PlaybackTimeline 的音频时钟决定。若跨进程传递需要扩展 `output.segment`，必须增加明确的
语音字段并同步维护协议契约，不能通过未声明的 metadata 绕过协议；协议变更应与本批次独立审阅。

完成标准：

- 没有语音提示时，现有 B1-B4 行为完全不变。
- 有语音提示时，output segment、SessionStore 和 PerformanceSchedule trace 能保留提示来源、
  source phrase、内部 phrase 映射和未采用原因。
- 字幕、聊天记录和普通 TTS 文本中不出现内部提示。
- 不新增第二套 Timeline、播放器、参数融合器或 Provider 专用语法解析器。

建议提交：

```text
feat: add provider-neutral speech cues to performance schedule
```

当前实现结果：

- `speech_cues` 沿现有 SegmentJob、PlaybackTimeline motion context 和 ModelEngine CompileOptions 传递，
  prepared-motion cache identity 同时包含 cue 序列。
- canonical text 先按标点形成 source phrase，再按现有 18 个有效字符规则切成内部 phrase；一个 cue
  可以稳定映射到同一 source phrase 下的全部内部 phrase，不直接使用内部数组下标。
- `emphasis / laugh / chuckle` 只调整现有 phrase emphasis，并由 SpeechPose 消费；
  `hesitate / breath / sigh` 只参与现有最强合法 hesitation 候选选择。
- hesitation 类 cue 的 `before / after` 使用目标 source phrase 的前后边界；开头、结尾或时长不足的
  候选通过统一合法窗口筛选记录为未采用，不新增前置等待、尾部动画或 fallback。
- 无 canonical text 时不消费 cue；没有 cue 时 B1-B4 的 phrase、事件和参数轨道行为保持不变。
- 内部 trace 为 `performance_schedule_trace.v7`；外部 `output.segment.v4`、`engine.motion_intent.v4`
  和 `engine.parameter_plan.v3` 不变。

### 批次 B5：语音能量有界耦合

这一批只在 B5-pre 和 B1-B4 稳定后开始。

目标：使用 SpeechSignalRuntime 已有的 energy、voiced、attack/release 和 emphasis slope 影响活跃度，而不改变语义方向。

原则：

- 音频只调制速度、局部幅度和 emphasis，不决定左右/上下目标。
- 静音和停顿让轨道保持或降低活跃度，不触发随机回中。
- 不向模型参数直接写入每帧随机数。
- 不改 Physics 输出参数。

建议提交：

```text
feat: couple speech energy to performance activity
```

## 7. 诊断与失败语义

### 7.1 必须可观测的事实

Schedule trace 至少应能回答：

- 每个 face/gaze/hesitation 事件由哪个 axis、phrase 或 semantic step 产生。
- 事件何时开始，transition、hold 和 residual 各有多长。
- 轨道是否因时间窗口较短而在编译前按规则压缩。
- 哪个事件投影成了哪个 parameter keyframe 或 speech modulation 点。
- plan 为什么扩展尾部，扩展了多少。
- 哪个可选事件因四点合法预算而在编译前未被选中。

### 7.2 失败优先

以下情况必须编译失败，不得 fallback：

- 事件时间非有限数、小于零或顺序逆转。
- 事件引用不存在的 axis、step、phrase 或 parameter。
- 必需轨道超出 V3 keyframe 上限。
- 已选中的必需事件或 residual 仍使 plan 超出最大合法时长。
- Expression 资源与 Direct Plan 重复控制参数。
- 同一 parameter 被重复轨道或 modulation 占有。

“输入中没有 hesitation 信号”、“候选 hesitation 达不到最小时间窗口”、“某个可选 settle 事件在预算选择前未被创建”不是失败；它们必须是策略的确定性且可诊断结果，而不是 catch 异常后的兼容分支。

## 8. 最小验证策略

自动验证只做最基础输入输出检查，不用大量模拟测试代替真实表演验收。

每批必做：

1. 源码调用链复核，确认无新的所有权重复。
2. `npm run typecheck:renderer`。
3. `git diff --check`。
4. 最少一个 pose 与一个 sequence 边界输入输出 smoke；只有在当前已有公开边界可直接驱动时才保留。
5. 检查 trace 中的事件、参数节点和 plan duration 是否一致。

用户实际验收：

- AstrBot 真实回复。
- 真实 TTS 音频。
- Electron PlaybackTimeline。
- Motion Lab 历史和回放。
- Live2D 可见起势、停顿、换向、收势和 Physics 被动响应。

实时验收不可用时，必须明确记录证据缺口，不用更多 mock、fallback 或兼容代码补偿。

## 11. 预期结果

B1-B4 完成后，一次回复应呈现为：

```text
视线有限领先
-> 头部起势
-> 面部表情稍后进入并稳定
-> 身体延迟跟随
-> phrase 之间保持或转换重心
-> 犹豫/转折处先短暂保持，再继续或换向
-> 句尾按句型保留有界 residual
-> 通过同一 plan blend 释放到当帧 Cubism base
-> Cubism Physics 继续产生头发、衣服和饰品的被动残留
```

这个结果的核心不是“动得更大”，而是“不同部位在同一段话里有先后、保持、转折和收势”，同时保持当前单一时钟、单一轨道编译、单一参数融合和显式失败的架构边界。
