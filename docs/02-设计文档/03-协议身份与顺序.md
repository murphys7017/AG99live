# 协议身份与顺序

## 身份模型

AG99live 将采集、对话、逻辑消息、播放段和动作运行分开标识。它们不能互相替代。

| 标识 | 含义 | 主要拥有者 |
| --- | --- | --- |
| `capture_turn_id` | 持续麦克风采集会话的根身份 | 前端采集与 Adapter STT ingress |
| `turn_id` | 一次正式对话及其播放范围 | Adapter 与前端 SessionStore |
| `stream_id` | 一段音频流的边界 | 音频输入协议 |
| `message_id` | Turn 内的一条逻辑 AG99 消息 | Adapter 输出段聚合 |
| `sequence` | 同一 Turn 中逻辑消息的播放顺序 | `output.segment`（Payload Schema `output.segment.v5`）与 Orchestrator |
| `segment_id` | 前端播放任务的局部身份 | PlaybackTimeline |
| `run_id` | 一次实际动作或资源运行 | ModelEngine / Live2D runtime |

## 采集与正式 Turn

PTT 结束的采集根可以直接形成正式 `turn_id`。持续收音则不同：根 ID 仅标识采集连续性，每个 VAD 语音段被 Adapter 派生为 `<capture_turn_id>:vad:<n>`。子 Turn 才能拥有 AG99 event、输出段、Timeline 和取消语义。

这样新语音可以只中断同一个采集会话下的在飞子 Turn，同时保留持续麦克风运行。

## 消息顺序

`message_id` 标识“哪条逻辑消息”；`sequence` 标识“这条消息在该 Turn 中何时播放”。Adapter 在一条逻辑消息可确认时立即提交原子段。前端按 `sequence` 安排播放，即使消息的后端完成时刻不同。

`control.synth_finished` 说明后端已没有待发送段，不是段播放的触发条件。前端只在对应段已经稳定结算后发送播放完成通知。

## 不变量

- 不用 capture 根 ID 复用多个正式 VAD Turn。
- 不把 `message_id` 当作前端动作 `run_id`。
- 不因晚到段、重复段或已取消 Turn 重开播放。
- 不用全局可变“当前 Turn”推断段归属。
- 不通过别名或兼容映射掩盖身份不一致。

身份边界保证音频、动作、完成回执和取消能在多段与多输入来源下保持可追溯。
