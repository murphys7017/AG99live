# 当前动作与播放问题清单

本文只记录当前未完成的工作。已修复的历史问题不在仓库中保留；稳定边界以架构文档和当前代码为准。

## 1. 当前主链路

```text
Persona Effect / official <@anim> wrapper
-> engine.motion_intent.v4
-> output.segment.v3
-> SessionStore 原子提交
-> PlaybackTimeline 统一时钟与 sink 终态
-> ModelEngine 语义轴、关系图和参数编译
-> ParameterPresentation
-> Cubism Motion / Expression / Physics
```

音频、字幕、口型和动作只能从同一个 segment 和 Timeline 建立生命周期。正式动作编译失败是显式 motion sink failure，不转换为 speech-only 或默认姿态。

## 2. 必须进行的真实链路验证

自动化输入输出检查不能证明播放链路正确。需要在同一次 AstrBot + Provider + TTS + Electron + Live2D 会话中确认：

- `server_info` manifest 握手通过，`live2d_scan.v2` 模型同步成功。
- 文本、单段 WAV、预开口、真实口型、动作和终态只各执行一次。
- 长音频、暂停恢复和音频结束后的动作尾部连续，没有时钟跳变。
- 中断、TTS 失败和非法 motion 都进入明确失败终态，没有 fallback。
- speech-only 与 semantic motion + speech 均经过同一 SemanticAxisProfile 参数绑定。

## 3. 说话表演质量

当前 `SpeechPoseStage` 已经并入统一参数编译链，但手势仍主要来自少量固定模板。下一步需要：

- roll/yaw 使用非周期的偏移、停留和回收片段。
- pitch 只在确认、重音和句尾等语义位置触发稀疏点头。
- 身体延迟跟随头部，幅度更小，允许短时保持或有限反向平衡。
- 变化检测同时观察 yaw、roll、pitch 和主要身体轴，避免连续使用同一动作族。

## 4. Cubism Physics 诊断

物理组件已在参数计划之后执行，普通参数平滑不直接写入头发、衣物和饰品输出。尚未完成的是真实模型观测：

- 记录语义头身输入、Physics 级联中间参数和末端输出的实际幅度。
- 确认衰减发生在语义输入、模型级联还是末端绑定，再调整 profile 或 Physics。
- 在 60 FPS 目标下观察真实帧时间和 180 Hz 显示器环境，不新增随机物理摆动。

## 5. Motion Lab 数据闭环

- 历史 sequence 需要保留和编辑 v4 `motion_steps`，不压平为单姿态。
- 参考样本只保留紧邻的用户输入和 assistant 输出，不保存 system prompt、工具调用或完整协议载荷。
- 继续记录原始等级、采样值、关系派生值、约束值、参数计划和终态，保持可归因性。

## 6. AstrBot 输出分段边界

如果同一句回复在 AstrBot 中被拆成多个 TTS 逻辑段，前端会顺序播放多个独立 WAV，段间可能产生停顿。AG99live 不在 Adapter 或前端合并音频；正确边界是 AstrBot 输出策略为一个逻辑回复生成一个 WAV，而 `immediate_reply` 和 `final_reply` 等真实业务段仍独立。

## 7. 当前顺序

1. 完成 `live2d_scan.v2` 和 manifest 握手的真实重启验证。
2. 完成语音、口型、动作尾部和失败终态的端到端实测。
3. 升级说话手势生成器，减少周期点头。
4. 补充 Physics 输入/输出诊断后再调整物理表现。
5. 完成 Motion Lab sequence 编辑与筛选工作台。
