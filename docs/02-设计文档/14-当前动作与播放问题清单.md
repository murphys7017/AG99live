# 二期动作与播放优化清单

本文记录一期主链路完成后，进入二期的动作表现优化问题。它们用于提高自然度、可解释性和数据能力，不表示一期实现未完成。产品阶段边界以 [一期完成边界与二期入口](../01-架构与结构/06-一期完成边界与二期入口.md) 为准。

详细处理顺序见 [动作表现优化实施方案](./15-动作表现优化实施方案.md)。

## 1. 当前稳定边界

当前正式链路是：

```text
Persona Effect / official <@anim> wrapper
-> engine.motion_intent.v4
-> output.segment.v3
-> SessionStore 原子提交协议槽位
-> PlaybackTimeline 统一时钟与 required sink 生命周期
-> ModelEngine semantic + model_parameter 两阶段编译
-> engine.parameter_plan.v3
-> ParameterPresentation direct-plan 逐帧贡献
+ Cubism Motion / Expression / drag / breath base snapshot
+ lip-sync contribution
-> Parameter Mixer 唯一主动参数融合与最终裁剪
-> Cubism Physics
-> model update / draw
```

以下边界已经由当前源码建立：

- 大模型输出 `-4..4` 九级语义等级，不直接生成 Live2D 参数值。
- 主模型在同一次回复中同时生成 assistant text 和唯一 `ag99live.motion` effect；
  TTS 不是语义动作参数来源。
- `axis_levels` 与 `motion_steps` 只能二选一；正式动作协议统一为
  `engine.motion_intent.v4`。
- `motion_steps` 在语音生成前已经确定；ModelEngine 只在拿到真实音频时长后，
  按 `duration_weight` 将语义步骤展开到同一 Timeline，当前没有句子或文本 span 绑定。
- optional performance curve 只能附加整段 entry/hold/exit/emphasis/energy timing hint，
  不生成语义轴，也不阻塞 TTS 或 segment 出站。
- 九级采样、强度范围、语义轴关系和参数绑定都在前端 ModelEngine 完成。
- Motion Lab 保存 `CompiledSemanticMotion`，pose 与 sequence 都能保真重放和投影回 Prompt。
- Motion Lab 样本从原始事件库读取同 Turn 的用户输入和目标 segment canonical assistant text。
- 人工参考样本按当前用户输入做确定性相关性选择，实际进入 Prompt 的投影结果会被记录。
- `ParameterPresentation` 只产生 direct-plan 当前帧贡献；Parameter Mixer 将其与 lip-sync 按稳定规则
  组合并一次裁剪，`LAppModel` 在 Cubism Physics 前执行唯一主动参数写入。
- SegmentJob 的 canonical assistant text 已沿 motion context、scheduler 和 compile options 进入
  `SpeechPoseStage`；speech-only 从同一个 SessionStore getter 取得同一段文本。
- `SpeechPoseStage` 已删除整段固定控制点模板，按强弱标点、有效字符长度和真实音频时长生成
  可复现的非周期调制轨道；头部和身体使用不同的事件密度、起势与过渡速度。
- `SpeechSignalRuntime` 已取消静音增益地板，使用 voiced/unvoiced 滞回让持续静音收敛到零，
  并用正能量斜率生成短促强调增益；RMS 不选择动作方向。
- `parameterTrackGraphCompiler` 已统一 sequence keyframes、SpeechPose modulation、部位错峰、hold、
  release 和 residual，继续输出 `engine.parameter_plan.v3`，不新增运行时播放器。
- Physics input 和语义姿态绑定参数不受末端物理倍率放大。
- `motion.absent` 与 `motion.failed` 已分离。应有动作但 effect 或 payload 缺失时明确失败，
  speech-only 不替代正式动作。
- SessionStore 负责协议槽位与稳定投影，PlaybackTimeline 负责实时 required sink。
  下一段和 `playback_finished` 都会等待开放 Timeline 收口。

二期主要优化方向已经不是消息能否到达或不同部位是否共享时间轨道，而是 LLM sequence 与 phrase
如何建立明确的语义对应，以及主动动力学和模型物理如何继续调校。

## 2. 二期优化问题

### 2.1 语义 sequence 与 phrase 仍缺少明确身份绑定

源码：

- `astrbot_plugin_ag99live_adapter/middleware/interaction_motion/prompt_builder.py`
- `astrbot_plugin_ag99live_adapter/middleware/interaction_motion/prompt_references.py`
- `astrbot_plugin_ag99live_adapter/prompts/motion_selector_examples.py`
- `frontend/src/model-engine/compiler/compileSemanticMotion.ts`
- `frontend/src/model-engine/compiler/stages/speechPoseStage.ts`

Prompt 已允许普通解释、疑问和惊讶回复使用自然 `motion_steps`，并明确禁止按逐词或语音节奏拆步。
这条边界是正确的：LLM sequence 表达整句话的语义姿态变化，SpeechPoseStage 表达持续说话表现。

当前参数时间轨道图已经把语义步骤、SpeechPose modulation 和部位延迟编译成同一份参数计划；
ParameterMixer 继续只负责同一帧内的 base snapshot、direct plan 和 lip-sync 贡献组合。

仍缺少的是 sequence step 与 phrase 的明确语义身份：

```text
semantic motion_steps
+ phrase-level speech gesture
+ realtime pause/emphasis energy
-> one parameter track graph（已完成时间编排）
```

当前只能根据 `duration_weight` 和 phrase 权重在同一时长内近似分布，仍不能显式表达哪个语义步骤
对应哪个 phrase。这个问题需要未来协议提供 phrase identity 或 text span，不能由轨道图猜测文本语义。

### 2.2 V4 sequence 不能表达稀疏的控制权变化

源码：

- `astrbot_plugin_ag99live_adapter/motion/motion_intent.py`
- `normalize_motion_steps()`
- `frontend/src/model-engine/compiler/compileSemanticMotion.ts`
- `frontend/src/model-engine/compiler/compileModelParameterPlan.ts`

当前 `motion_steps`：

- 只能有 2 到 4 步。
- 每一步必须使用完全相同的轴集合。
- 每步只有 `duration_weight=1..3`。
- 没有 hold、release、inherit 或步骤语义。

这个限制保证每个参数都能生成闭合 keyframe，适合当前 V4，但难以表达“先转头、再移视线、
最后增加笑容”这种逐步取得和释放控制权的动作。该问题不应在 V4 内继续增加隐式解释；
真正需要时应由新的协议版本显式定义稀疏步骤语义。

### 2.3 已部分修复：主动参数动力学过于干净

源码：

- `frontend/src/live2d/WebSDK/src/parameterpresentation.ts`
- `advanceParameterDynamics()`
- `resolveTrajectoryEnvelope()`

`engine.parameter_plan.v3` 已为每个参数显式携带 response policy。ModelEngine 根据
`SemanticAxisProfile.semantic_group` 为头部和身体编译 spring 响应，其余参数继续使用 bounded 响应；
WebSDK 不再根据轴名称猜测部位。

第一批已经完成：

- 头部使用较快、轻微欠阻尼的响应，允许短促且受速度/加速度限制的过冲。
- 身体使用更低频率和更高阻尼，启动、反转与收势都慢于头部。
- gaze、face 和其它参数仍使用原有精确制动。
- mouth lip-sync 不经过该主动姿态动力学。
- Cubism Physics 输出不进入 ParameterPresentation。

二期继续调校的部分：

- 头部过冲幅度和稳定时间是否匹配实际模型观感。
- 身体跟随速度是否需要按模型进一步降低。
- sequence 高频反转时是否需要额外的显式 hesitation 节点。
- gaze 和 face 是否应在后续批次获得独立响应策略。

这里继续通过主动参数动力学调校，不能通过随机写头发参数或放大 Physics 代替。

### 2.4 Cubism Physics 缺少 setting 级诊断与调校

源码：

- `frontend/src/live2d/WebSDK/Framework/src/physics/cubismphysics.ts`
- `setTerminalOutputResponseScale()`
- `updateOutputParameterValue()`
- `frontend/src/live2d/WebSDK/src/lappmodel.ts`
- `frontend/src/live2d-renderer/settings.ts`

当前 `physicsResponseScale` 只放大末端 Physics 输出，并排除 Physics input 和
SemanticAxisProfile 已绑定的主动姿态参数。这个范围隔离是正确的。

仍缺少：

- 每个 Physics setting 的输入、粒子链和末端输出关系。
- 头发、衣服和饰品的独立倍率。
- setting 级 Mobility、Delay、Acceleration、Radius 调校。
- 输入幅度、输出幅度、clamp 和响应时间的低频诊断。

全局倍率只能验证“输出变大”，不能判断速度、残留和模型绑定是否自然。

### 2.5 Motion Lab 仍缺少 sequence 编辑和多轮多样性反馈

源码：

- `frontend/src/components/MotionTuningPanel.vue`
- `frontend/src/playback-integrations/useMotionPlaybackRecorder.ts`
- `astrbot_plugin_ag99live_adapter/runtime/motion_state/tuning_store.py`
- `astrbot_plugin_ag99live_adapter/middleware/interaction_motion/prompt_context.py`
- `astrbot_plugin_ag99live_adapter/middleware/interaction_motion/scheduling.py`

当前已完成 sequence 保真保存/重放、对话上下文绑定、相关样本选择和 canonical text 关联。
仍存在两个产品缺口：

1. sequence 样本可以查看、播放、保存和作为 Prompt 参考，但 UI 不能逐 step 调整
   `axis_levels` 与 `duration_weight`。
2. Prompt 只携带上一动作关键轴和本轮相关人工样本，没有最近数轮动作族分布，
   仍可能连续选择同一种头部动作。

训练数据导出属于后续小模型计划，不应阻塞当前动作表现优化。

## 3. 二期优先级

```text
P1  gaze / face / hesitation 等部位级主动动力学
P1  sequence step 与 phrase identity 的显式绑定设计
P2  Physics setting 诊断和模型级调校
P2  Motion Lab sequence 编辑与最近动作多样性反馈
P3  稀疏 sequence 新协议和训练数据导出
```

Parameter Mixer 集中化、segment 文本透传、非周期 SpeechPose 和 RMS 静音/重音基础调制均已完成，
参数时间轨道图也已经接管 sequence、phrase modulation 和头身错峰，不再作为待处理项。下一阶段仍不接管
或重新生成 LLM 已输出的 `axis_levels` / `motion_steps`。

继续单独放大九级锚点、全局动作强度或 Physics 倍率，只会让现有运动更大，不能解决语义步骤与
说话窗口的对应关系和部位时间关系问题。
