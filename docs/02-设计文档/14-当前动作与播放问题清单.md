# 当前动作与播放问题清单

本文只记录当前源码仍存在的问题。已经落地的能力作为边界说明，不再以“待迁移”或历史修复项重复出现。

详细处理顺序见 [动作表现优化实施方案](./15-动作表现优化实施方案.md)。

## 1. 当前稳定边界

当前正式链路是：

```text
Persona Effect / official <@anim> wrapper
-> engine.motion_intent.v4
-> output.segment.v3
-> SessionStore 原子提交协议槽位
-> PlaybackTimeline 统一时钟与 required sink 生命周期
-> ModelEngine semantic + model_parameter 两阶段编译
-> engine.parameter_plan.v2
-> ParameterPresentation 主动参数逐帧解算
-> Cubism Motion / Expression / Physics
```

以下边界已经由当前源码建立：

- 大模型输出 `-4..4` 九级语义等级，不直接生成 Live2D 参数值。
- `axis_levels` 与 `motion_steps` 只能二选一；正式动作协议统一为
  `engine.motion_intent.v4`。
- 九级采样、强度范围、语义轴关系和参数绑定都在前端 ModelEngine 完成。
- Motion Lab 保存 `CompiledSemanticMotion`，pose 与 sequence 都能保真重放和投影回 Prompt。
- Motion Lab 样本从原始事件库读取同 Turn 的用户输入和目标 segment canonical assistant text。
- 人工参考样本按当前用户输入做确定性相关性选择，实际进入 Prompt 的投影结果会被记录。
- `ParameterPresentation` 在 Cubism Physics 之前驱动主动参数；Physics input 和语义姿态绑定参数
  不受末端物理倍率放大。
- `motion.absent` 与 `motion.failed` 已分离。应有动作但 effect 或 payload 缺失时明确失败，
  speech-only 不替代正式动作。
- SessionStore 负责协议槽位与稳定投影，PlaybackTimeline 负责实时 required sink。
  下一段和 `playback_finished` 都会等待开放 Timeline 收口。

当前主要缺口已经不是消息能否到达，而是说话动作是否具有语句结构、不同部位的时间关系、
自然的主动动力学和可调的模型物理表现。

## 2. 仍存在的问题

### 2.1 说话随动仍由四套固定模板主导

源码：

- `frontend/src/model-engine/compiler/stages/speechPoseStage.ts`
- `GESTURE_TEMPLATES`
- `PRESET_CHANNELS`
- `buildGestureTrack()`
- `selectGestureChannels()`

当前只有：

```text
calm_explain
lively_chat
gentle_support
emphatic
```

每个 preset 都是固定归一化控制点，随后按整段音频时长拉伸。种子只改变整体方向和少量选择，
不能根据句子数量、转折、疑问句尾或真实停顿生成新的手势事件。

直接后果：

- 短句和长句动作结构相同，只是速度不同。
- 同一 preset 的头部和身体沿相似曲线运动。
- 长语音仍只有少量方向切换。
- 多轮对话容易重复左右摆动或点头。

Timeline 的 SegmentJob 已拥有 canonical assistant text，但当前
`PlaybackTimelineMotionContext` 和 ModelEngine compile context 没有该文本。
SpeechPoseStage 因此无法按句子规划动作。

### 2.2 RMS 只控制幅度，没有形成停顿和重音事件

源码：

- `frontend/src/live2d/lipSyncTimelineSink.ts`
- `frontend/src/live2d/WebSDK/src/lappmodel.ts`
- `updateSpeechAudioEnvelope()`
- `resolveSpeechAudioGain()`
- `resolveSemanticBindingFrameTarget()`

WebAudio analyser 当前输出 mouth value 和 speech energy。speech energy 经过 attack/release 后，
只缩放 `speech_gesture_track` 幅度，不改变：

- 控制点数量。
- 当前保持位置。
- 动作方向。
- 重音触发。
- 句尾收势。

头部和身体增益还有固定下限，静音时既不会稳定保持当前重心，也不会产生明确的暂停状态。
这会让说话随动持续运动，却缺少真人讲话的“停一下、强调一下、再继续”。

### 2.3 语义 sequence 与说话节奏仍是两套独立计划

源码：

- `astrbot_plugin_ag99live_adapter/middleware/interaction_motion.py`
- `astrbot_plugin_ag99live_adapter/prompts/motion_selector_examples.py`
- `frontend/src/model-engine/compiler/compileSemanticMotion.ts`
- `frontend/src/model-engine/compiler/stages/speechPoseStage.ts`

Prompt 已允许普通解释、疑问和惊讶回复使用自然 `motion_steps`，并明确禁止按逐词或语音节奏拆步。
这条边界是正确的：LLM sequence 表达整句话的语义姿态变化，SpeechPoseStage 表达持续说话表现。

当前缺少统一组合层：

```text
semantic motion_steps
+ phrase-level speech gesture
+ realtime pause/emphasis energy
-> one parameter track graph
```

因此语义 sequence 和说话轨迹只能在现有 binding/presentation 阶段叠加，不能显式表达
哪个动作先发生、谁应保持、谁应在句尾回收。

### 2.4 V4 sequence 不能表达稀疏的控制权变化

源码：

- `astrbot_plugin_ag99live_adapter/motion/motion_intent.py`
- `normalize_motion_steps()`
- `frontend/src/model-engine/compiler/compileSemanticMotion.ts`
- `frontend/src/model-engine/compiler/compileModelParameterPlan.ts`

当前 `motion_steps`：

- 只能有 2 到 4 步。
- 每一步必须使用完全相同的轴集合。
- 每步只有 `duration_weight=1..3`。
- 没有 hold、release、inherit 或步骤语义。

这个限制保证每个参数都能生成闭合 keyframe，适合当前 V4，但难以表达“先转头、再移视线、
最后增加笑容”这种逐步取得和释放控制权的动作。该问题不应在 V4 内继续增加隐式解释；
真正需要时应由新的协议版本显式定义稀疏步骤语义。

### 2.5 语义轴关系图只计算静态值

源码：

- `frontend/src/types/semantic-axis-profile.ts`
- `frontend/src/model-engine/compiler/stages/couplingStage.ts`
- `frontend/src/model-engine/compiler/stages/semanticAxisRelationGraphStage.ts`
- `frontend/src/model-engine/compiler/stages/modelParameterBindingStage.ts`

`ag99.semantic_axis_relation_graph.v1` 当前支持：

```text
derive
bounded_ratio
```

它能派生身体轴并限制头身比例，但每次只计算一个姿态或一个 sequence step 的静态值。
它不能表达：

- 视线先动、头部后跟。
- 头部先启动、身体延迟跟随。
- 头停后身体继续少量移动。
- 方向反转时的有限反向平衡。
- 不同部位的 hold、release 和 residual。

当前系统已有“语义值图”，尚未形成“参数时间轨道图”。

### 2.6 主动参数动力学过于干净

源码：

- `frontend/src/live2d/WebSDK/src/parameterpresentation.ts`
- `advanceParameterDynamics()`
- `resolveTrajectoryEnvelope()`

当前解算用最大速度和最大加速度追踪目标，越过目标时直接落到目标并清零速度。
这保证了稳定、帧率无关和无失控过冲，但所有部位容易呈现同一种精确制动：

- 头和身体只有速度数值差异，重量感不足。
- 方向反转没有迟疑和惯性阶段。
- 到达目标后缺少受控的少量残留。
- 收势容易显得“很干净”，与 Live2D 角色需要的夸张感不一致。

这里应改主动参数动力学，不能通过随机写头发参数或放大 Physics 代替。

### 2.7 Cubism Physics 缺少 setting 级诊断与调校

源码：

- `frontend/src/live2d/WebSDK/Framework/src/physics/cubismphysics.ts`
- `setTerminalOutputResponseScale()`
- `updateOutputParameterValue()`
- `frontend/src/live2d/WebSDK/src/lappmodel.ts`
- `frontend/src/live2d-renderer/settings.ts`

当前 `physicsResponseScale` 只放大末端 Physics 输出，并排除 Physics input 和
SemanticAxisProfile 已绑定的主动姿态参数。这个范围隔离是正确的。

仍缺少：

- 每个 Physics setting 的输入、粒子链和末端输出关系。
- 头发、衣服和饰品的独立倍率。
- setting 级 Mobility、Delay、Acceleration、Radius 调校。
- 输入幅度、输出幅度、clamp 和响应时间的低频诊断。

全局倍率只能验证“输出变大”，不能判断速度、残留和模型绑定是否自然。

### 2.8 Motion Lab 仍缺少 sequence 编辑和多轮多样性反馈

源码：

- `frontend/src/components/MotionTuningPanel.vue`
- `frontend/src/playback-integrations/useMotionPlaybackRecorder.ts`
- `astrbot_plugin_ag99live_adapter/runtime/motion_state/tuning_store.py`
- `astrbot_plugin_ag99live_adapter/middleware/interaction_motion.py`

当前已完成 sequence 保真保存/重放、对话上下文绑定、相关样本选择和 canonical text 关联。
仍存在两个产品缺口：

1. sequence 样本可以查看、播放、保存和作为 Prompt 参考，但 UI 不能逐 step 调整
   `axis_levels` 与 `duration_weight`。
2. Prompt 只携带上一动作关键轴和本轮相关人工样本，没有最近数轮动作族分布，
   仍可能连续选择同一种头部动作。

训练数据导出属于后续小模型计划，不应阻塞当前动作表现优化。

## 3. 必须进行的真实验证

以下内容不能由静态检查或基础输入输出 smoke 证明：

- Mk6 九级锚点在实际窗口尺寸下是否形成清晰差异。
- 语义 sequence 与 speech gesture 叠加后是否 clipping 或长时间贴边。
- 长短句、真实停顿、重音、暂停恢复和动作尾部是否连续。
- 30、60、120 FPS 时间输入下主动参数轨迹是否近似一致。
- 180 Hz 显示器环境下实际 RAF delta、Physics 稳定性和 GPU 占用。
- 每组头发、衣服和饰品对 Physics 输入的真实响应。
- Motion Lab 保存、复播、Prompt 引用和最终生成是否在同一真实会话闭环。

## 4. 当前优先级

```text
P0  segment 文本上下文 + 非周期说话手势规划
P0  停顿/重音能量事件与语义轨道组合
P1  参数时间关系图和部位级主动动力学
P2  Physics setting 诊断和模型级调校
P2  Motion Lab sequence 编辑与最近动作多样性反馈
P3  稀疏 sequence 新协议和训练数据导出
```

继续单独放大九级锚点、全局动作强度或 Physics 倍率，只会让现有模板运动得更大，
不能解决时间结构和部位关系问题。
