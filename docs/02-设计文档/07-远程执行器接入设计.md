# 远程执行器接入设计

## 目标

AG99live 支持把用户的任务委托给一台或多台用户电脑上的远程执行器完成。AstrBot 侧负责理解用户意图、组织任务级命令、注入执行器上下文、接收执行结果并通过桌宠展示过程；远程执行器连接层负责连接 Codex app-server 或其他 executor，把任务交给本机 agent 细分步骤并执行。

当前已接入的 Windows 操作路径是：AG99live Adapter 连接配置中的 Codex app-server WebSocket，查询并注入 `computer-use:computer-use` skill，再把用户任务作为 app-server turn 输入发送给 Codex。Windows 桌面观察、点击、输入等底层动作由 app-server / Computer Use 执行，Adapter 不直接操作鼠标键盘。

这条能力的核心不是让 AstrBot 直接控制鼠标、浏览器或文件系统，而是建立一条稳定的任务委托链路：

```text
用户 / 桌宠
  -> AG99live AstrBot Adapter
    -> AstrBot Core
      -> remote operator task
        -> Codex app-server / OpenCode
          -> Computer Use / OpenCode CLI
```

## 当前闭环

- AG99live Adapter 从配置读取远程电脑条目、后端类型、endpoint、默认电脑和执行档位。
- Adapter probe endpoint，只向 prompt 注入在线电脑和默认路由。
- AstrBot Core 对桌面/电脑/软件操作请求产出任务级 JSON，而不是直接调用 shell/browser/CUA 工具。
- `backend=codex_app_server` 时，Adapter 连接 Codex app-server WebSocket，查找并使用 `computer-use:computer-use` skill。
- `backend=opencode` 时，Adapter 按配置的 `model / variant / workdir` 执行代码、文件、命令、日志类任务。
- 执行结果以 `remote_operator_result` 来源重新进入 AstrBot 事件，避免结果再次触发远程执行器。

## 边界

- 不让 Adapter 自己实现通用 Windows 桌面应用自动化；Windows 桌面动作必须经由 Codex app-server / Computer Use 等外部 executor。
- 不让 AstrBot 主模型逐步调用 `click/type/read_file` 这类底层操作工具。
- 不把 OpenCode CLI、Codex CLI 或 Codex app-server 直接嵌入 AG99live 前端。
- 不让桌宠前端成为本机高权限执行主体。
- 当前前端不提供专用远程执行器任务页；结果通过 AstrBot 输出链路回到桌宠。

## 归属边界

### AG99live Adapter

Adapter 是远程执行器接入中枢，拥有两条连接：

```text
桌宠 WebSocket: AG99live frontend <-> AG99live Adapter
Executor connection: Codex app-server / OpenCode <-> AG99live Adapter
```

Adapter 负责：

- 维护配置中的电脑条目、endpoint 探测状态、默认电脑和当前执行状态。
- 在 prompt 阶段注入远程执行器上下文。
- 在结果阶段收集最终执行结果，并作为系统级输入回灌 AstrBot。
- 把任务结果关联到 AstrBot turn / message / frontend turn。

Adapter 不负责：

- 自己拆解本机执行步骤。
- 直接执行 OpenCode/Codex/浏览器/桌面工具。
- 决定所有底层操作细节。

### 多电脑路由

Adapter 维护配置驱动的远程电脑注册表。每个条目包含稳定 key、用户可读名称、后端类型、endpoint 和固定执行参数；电脑名称注册由配置完成，不要求 app-server 自己上报。

路由规则：

- 如果任务明确指定 `target.computer_name` 或 `target.computer_id`，Adapter 只投递到对应电脑。
- 如果任务没有指定电脑，Adapter 投递到默认电脑。
- 如果默认电脑不在线，Adapter 应返回可恢复错误，并把在线电脑列表反馈给 AstrBot，让 Core 询问用户或改派。
- 如果多台电脑重名，`computer_id` 是最终路由依据，`computer_name` 只用于 prompt 和用户可见展示。
- 同一 `task_id` 在同一时间只能绑定一台电脑，避免执行事件串线。

### AstrBot Core

AstrBot Core 负责把对话意图提升为任务级委托：

- 是否需要使用远程执行器。
- 要委托给哪个执行器能力。
- 目标软件、任务目标、输入上下文和成功标准。
- 本轮任务的权限约束和用户可见说明。

Core 不应该直接承担本机执行细节。它输出的是任务级命令，例如：

```json
{
  "computer": "work",
  "profile": "simple",
  "prompt": "打开 Edge，搜索 OpenCode CLI usage，并总结关键结论。"
}
```

## 当前实现

- `_conf_schema.json` 中的 `remote_operator_computer_entries` 配置 computer key、用户可读名称、后端类型、endpoint 和固定执行参数。
- `RemoteOperatorRuntime.refresh_online_status()` 会 probe 每台电脑 endpoint，并把在线电脑写入 remote operator prompt registry。
- `AG99liveRemoteOperatorPromptContributor` 只在存在在线电脑时注入远程执行器能力说明。
- 对“操作电脑/桌面/软件”类请求，remote operator middleware 会覆盖核心执行 prompt，要求核心只输出 `{"computer","profile","prompt"}` 三字段 JSON。
- `RemoteOperatorRuntime.execute()` 根据 computer 和 profile 选择后端、endpoint、model、effort 或 OpenCode 固定参数。
- Codex app-server 后端会在 turn 输入中插入 `computer-use:computer-use` skill，因此 Windows 桌面操作由 Codex app-server 和 Computer Use 完成。
- OpenCode 后端按配置执行代码、文件、命令、日志类任务，模型和工作目录不由聊天模型决定。
- 执行结果会作为 `remote_operator_result` 来源重新进入 AstrBot 事件，并带上 computer、profile、success/error 等 metadata，避免再次触发远程执行器递归。

## Prompt 注入目标

Adapter 的 prompt contributor 注入的内容应包括：

- 当前是否有远程执行器在线。
- 在线电脑列表、默认电脑、每台电脑的后端类型和执行档位。
- 每个能力的适用范围和限制。
- 当前任务是否允许自动委托。
- 如何构造任务级命令，以及未指定电脑时会使用默认电脑。

Prompt 注入不应该鼓励模型输出底层操作步骤，例如坐标点击、具体 UIA selector 或 shell 命令细节。模型只需要给执行器明确任务、目标、约束和成功标准。

执行结果不能破坏现有文本、音频、动作同步链路。当前结果作为系统级输入重新进入 AstrBot，而不是混进 `engine.motion_*` 协议。

## 当前能力范围

- Codex app-server 后端用于 Windows 桌面、应用、浏览器和 Computer Use 任务。
- OpenCode 后端用于代码、文件、命令、日志和项目开发任务。
- Adapter 只接收最终执行结果并回灌 AstrBot；细粒度进度、确认 UI、取消入口和 artifact 展示不属于当前前端主链路。
- 当前开发测试阶段权限审批由后端配置和外部 executor 控制；AG99live 前端不持有额外本机执行权限。

## 安全原则

- 默认最小权限。
- 写文件、运行命令、发送消息、下载、删除、桌面输入必须可配置确认策略。
- 每个任务必须有日志和任务 ID。
- Codex app-server、OpenCode CLI 或 Codex CLI 不应裸跑在无限权限环境中，外层必须有 policy / approval / audit。

## 当前判断

最重要的边界是：Adapter 是中枢，Codex app-server / OpenCode 是连接层，Computer Use / OpenCode CLI 是执行者，AstrBot 给任务级命令，桌宠负责可见交互。
