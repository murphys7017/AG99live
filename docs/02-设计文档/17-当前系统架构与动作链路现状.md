# 当前系统架构与动作链路现状

本文记录当前源码已经形成的真实系统，不记录已经废弃的历史方案，也不把后续计划写成当前能力。
后续涉及动作生成、TTS、播放同步、ModelEngine、ParameterMixer 或 Live2D WebSDK 的审阅，先以本文的
权责边界为准，再查看对应的专项设计文档。

## 1. 项目定位

AG99live 不是一个单独的“动作播放器”，也不是一个再次实现 AstrBot 对话队列的运行时。它的核心职责是：

```text
AstrBot 负责对话与主模型调用
-> AG99live Adapter 负责动作协议、输出段和前后端交接
-> 前端 Timeline 负责统一播放时钟
-> ModelEngine 负责语义动作编译和模型参数计划
-> ParameterMixer 负责逐帧主动参数融合
-> Live2D WebSDK 负责模型写入、Physics 求解和渲染
```

系统最基本的用户体验是：用户发送一条消息，系统生成一段回复，同时准备语音和 Live2D 表演，前端以同一
个输出段完成字幕、音频、口型和动作的播放。

## 2. 当前模块边界

### 2.1 AstrBot 与 AG99live Adapter

AstrBot 及其运行时负责：

- 接收用户消息并管理对话上下文。
- 调用主模型生成回复文本。
- 调用 TTS 生成音频。
- 管理 AstrBot 自身的输入、事件和输出生命周期。

AG99live Adapter 负责：

- 向主模型提供 Live2D 能力、语义轴定义、资源候选和动作示例。
- 接收主模型的 `ag99live.motion` effect 或官方 `<@anim>` 兼容输出。
- 校验并规范化 `engine.motion_intent.v4`。
- 为一个逻辑输出段关联 `turn_id`、`message_id` 和 TTS 生命周期身份。
- 将文本、音频、动作和失败事实组装为一个 `output.segment.v3`。
- 提供可选的 performance curve 请求，但不得让它阻塞 TTS 或基础动作出站。

Adapter 不负责：

- 重新实现 AstrBot 的对话队列。
- 重新实现 TTS 文本转换或音频生成。
- 把 TTS 或 performance curve 当成语义动作来源。
- 生成 Live2D 具体参数值。
- 直接逐帧写入 Live2D 模型。

### 2.2 协议、SessionStore 与 PlaybackTimeline

协议层负责描述事实和身份，不负责推断缺失事实。

- `SessionStore` 保存 `output.segment.v3` 的 text、audio、motion 槽位和稳定投影。
- `PlaybackTimeline` 管理 required sink、音频时钟、动作时钟和终态。
- `turn_id` 表示对话轮次。
- `message_id` 表示逻辑输出段。
- `tts_request_id` 表示一次独立的 TTS 生成生命周期。
- 前端播放完成后，使用对应的 `turn_id` 收口播放生命周期。

SessionStore 中槽位已经 settled，不等于前端播放已经结束。只要 required Timeline 仍开放，就不能启动下一段
的播放，也不能发送 `control.playback_finished`。

### 2.3 ModelEngine

ModelEngine 是前端动作编译边界，分为两个阶段：

```text
engine.motion_intent.v4
-> semantic compile
-> CompiledSemanticMotion
-> model_parameter compile
-> engine.parameter_plan.v3
```

第一阶段负责：

- 校验九级 `axis_levels`。
- 根据模型的 semantic profile 将等级转换为实际语义轴值。
- 应用确定性采样、锚点、扰动和关系图约束。
- 编译 `axis_levels` 或 `motion_steps` 为 `CompiledSemanticMotion`。

第二阶段负责：

- 将编译后的语义轴值绑定到当前 Live2D 模型的可写参数。
- 生成 `engine.parameter_plan.v3`。
- 生成 ParameterPresentation 所需的轨迹、过渡和说话随动调制信息。
- 在绑定、时长、参数集合和约束不满足时明确失败。

ModelEngine 不负责生成新的对话语义，也不应从文本重新决定主动作方向。

### 2.4 ParameterPresentation、ParameterMixer 与 WebSDK

`ParameterPresentation` 是主动参数计划的逐帧表现层。它根据统一 Timeline 时钟计算 direct plan 当前帧的贡献，
包括语义动作过渡和 SpeechPose 的补充调制。

`ParameterMixer` 是逐帧融合层，不是动作规划器。它接收：

```text
Cubism Motion / Expression / drag / breath base snapshot
+ direct-plan contribution
+ lip-sync contribution
-> ResolvedParameterFrame
```

它负责统一优先级、权重、冲突处理和最终运行时范围裁剪，`LAppModel` 只能应用这一份最终帧。

`LAppModel` 在主动参数写入完成后调用 Cubism Physics，再更新模型和绘制画面。

### 2.5 Cubism Physics

Cubism Physics 负责头发、衣服、饰品等被动参数的解算。它不属于语义动作计划，也不属于 ParameterMixer 的
主动参数融合。

当前系统已经明确：

- Physics input 和已绑定的语义姿态参数不能被末端 Physics 倍率重复放大。
- 主动参数的逐帧平滑不能替代 Physics 的动力学解算。
- 不允许把 `Phy*` 等 Physics 输出参数写入语义动作计划。
- Physics 的更细粒度诊断和模型级调校仍属于后续工作。

## 3. 真实端到端时序

### 3.1 后端生成阶段

```text
用户输入
  -> AstrBot 接收并进入自身对话/事件链路
  -> 主模型一次生成 assistant text
     + 唯一 ag99live.motion effect
  -> Adapter 校验 effect arguments
  -> 生成或登记逻辑输出段身份
  -> TTS 开始生成音频
  -> TTS generating 时，可选 performance curve 并行请求
  -> TTS succeeded / failed
  -> output.segment.v3 原子出站
```

这里的关键事实是：动作语义已经在 TTS 之前由主模型产生。TTS 只会提供音频和最终时长，不会重新生成
`axis_levels` 或 `motion_steps`。

### 3.2 前端接收与编译阶段

```text
output.segment.v3
  -> SessionStore 写入 text/audio/motion 槽位
  -> PlaybackTimeline 创建 segment job
  -> 释放字幕、音频和动作 sink
  -> 音频元素提供真实 duration
  -> canonical assistant text 进入 motion compile context
  -> ModelEngine 编译 semantic motion
  -> SpeechPose 按 phrase 生成补充 modulation track
  -> ModelEngine 编译 model parameter plan
  -> 动作计划等待统一 Timeline 时钟起播
```

`motion_steps` 的当前时间映射方式是：所有步骤共享同一段音频时长，根据 `duration_weight` 分配相对时长。
当前协议没有 `phrase_index`、文本 span 或声学停顿绑定，因此不能声称它已经实现了逐句精准动作同步。

### 3.3 逐帧表现阶段

```text
统一 Timeline delta
  -> ParameterPresentation 计算 direct-plan 当前贡献
  -> SpeechSignalRuntime 用滞回阈值更新静音状态与短重音 envelope
  -> speech energy 有界调制 SpeechPose track，lip-sync 生成口型贡献
  -> ParameterMixer 融合 base、direct plan 和 lip-sync
  -> LAppModel 写入唯一 ResolvedParameterFrame
  -> Cubism Physics.evaluate()
  -> model.update()
  -> draw
```

SpeechPose 当前属于 direct plan 内的补充说话手势。它读取 canonical assistant text 和真实音频时长，
但不能被当成 LLM 主动作的替代，也不能在主动作失败时悄悄伪造正式动作成功。

## 4. 动作数据从哪里来

| 数据 | 来源 | 当前作用 |
| --- | --- | --- |
| `intent_tags` | 主模型 | 描述语气、姿态和表演场景 |
| `axis_levels` | 主模型 | 单一语义姿态的九级方向强度 |
| `motion_steps` | 主模型 | 2-4 个语义姿态步骤及相对时长 |
| semantic axis 实际值 | ModelEngine | 根据 profile、锚点、扰动和关系图得到 |
| model parameter plan | ModelEngine | 将语义轴绑定为模型可写参数轨迹 |
| speech-following modulation | ModelEngine SpeechPoseStage | 按 phrase 在语义动作周围生成确定性非周期随动 |
| mouth / speech energy | 音频分析与 `SpeechSignalRuntime` | 口型、静音收敛和短重音增益 |
| performance curve hint | 可选独立小模型 | 整段 timing/energy 提示，不生成动作轴 |
| hair / cloth / accessory physics | Cubism Physics | 被动物理表现 |
| final parameter frame | ParameterMixer | 统一融合后的唯一写入结果 |

因此需要区分两种“动作参数”：

1. **语义动作参数**：主模型输出的 `axis_levels` / `motion_steps`。
2. **模型驱动参数**：ModelEngine 编译后实际写入 Live2D 参数的数值和轨迹。

## 5. 当前已完成的基础能力

- 主模型文本和动作 effect 在同一回复内生成，避免语义与文本分离。
- `engine.motion_intent.v4` 支持九级语义轴、单姿态和 2-4 步 sequence。
- Adapter 对动作结构、轴、资源和模型能力进行校验。
- ModelEngine 已完成语义编译与模型参数编译两阶段边界。
- `duration_weight` 已用于将 sequence 展开到真实音频 Timeline。
- canonical assistant text 已按 segment 身份进入 ModelEngine；speech-only 读取同一 SessionStore 文本事实。
- SpeechPose 已删除整段固定模板，按标点、长度、音频时长和 channel 生成确定性非周期调制轨道。
- SpeechSignalRuntime 已删除静音增益地板，并实现 voiced/unvoiced 滞回与正能量斜率强调。
- `output.segment.v3` 统一承载文本、音频和动作事实。
- SessionStore 与 PlaybackTimeline 已分离协议槽位和实时播放状态。
- ParameterMixer 已成为主动参数的唯一逐帧融合入口。
- Cubism Physics 已与语义参数计划和主动参数平滑隔离。
- Motion Lab 已能保存编译结构、上下文和播放结果，用于参考和复盘。

## 6. 当前仍未完成的问题

### 6.1 主动作与语句结构没有精确绑定

LLM 可以生成 `motion_steps`，但当前只提供 `duration_weight`，没有文本 span 或 phrase identity。
因此步骤与语句的对应关系只能近似表达，不能保证某个动作一定落在某个句子或重音位置。

### 6.2 语义 sequence 与 phrase modulation 尚未统一编排

SpeechPose 已拥有 phrase 级非周期结构，RMS 也能让静音收敛并触发短强调；但它们仍作为补充 modulation
附着在按 `duration_weight` 展开的语义 sequence 上。当前还没有统一轨道图表达哪个语义步骤对应哪个
phrase、哪个部位应先动、保持或延迟回收。

### 6.3 参数关系图仍偏静态

语义轴关系图目前主要解决同一时刻的派生和比例约束，还没有统一表达头部先动、身体延迟、视线先行、
hold、release 和 residual 的时间轨道。

### 6.4 主动参数动力学与 Physics 调校仍需真实模型验证

主动参数当前强调稳定、帧率无关和受控收势，表现仍可能过于干净。Physics 还缺少 setting 级输入、粒子链、
输出和响应时间诊断。

## 7. 当前明确不做的事情

- 不让文本分句器接管主模型的语义动作生成。
- 不让 TTS 或 performance curve 生成第二套语义动作。
- 不新增第二个播放时钟或独立动作播放器。
- 不在 Adapter 里重复实现 AstrBot 的队列、TTS 或对话状态机。
- 不用 speech-only、默认姿态或 fallback 掩盖正式动作失败。
- 不在 V4 中通过隐式规则猜测稀疏步骤含义；需要精确绑定时再设计新协议。
- 不把 Physics 输出参数交给主动参数平滑或 ParameterMixer。
