# 动作参数处理与轴关系图

本文定义动作意图从模型输出到 Live2D 参数计划的唯一处理方式。它描述当前契约和所有权，不记录迁移过程、修复批次或已经删除的方案。

## 1. 目标

动作系统要把大模型擅长的语义判断转换成可校验、可复现、可解释的 Live2D 表现：

```text
主模型回复文本 + ag99live.motion
  -> Adapter 严格结构校验
  -> engine.motion_intent.v4
  -> ModelEngine 动作参数处理电路
  -> engine.parameter_plan.v3 / typed motion resource
  -> PlaybackTimeline
  -> Live2D WebSDK 逐帧执行
```

设计原则：

- 大模型决定语义方向和九级强度，不直接生成 Live2D 参数值。
- Adapter 只验证和运输，不修复语义，不补默认姿态。
- ModelEngine 是动作值转换、派生和约束的唯一所有者。
- Live2D WebSDK 只执行已经编译完成的计划，并负责逐帧表现与物理响应。
- 无效输入进入 feedback，不改写成一个看似成功的动作。

## 2. 输入契约

Persona Effect 名称为 `ag99live.motion`。主模型必须提供：

```json
{
  "intent_tags": ["认真解释", "看向用户"],
  "axis_levels": {
    "head_yaw": 3,
    "body_yaw": 2,
    "gaze_x": 3
  }
}
```

可选字段：

- `duration_hint_ms`
- `motion_steps`
- `expression_resource_id`
- `motion_resource_id`

`axis_levels` 只接受 `-4..4` 整数：

| 等级 | 语义 |
| --- | --- |
| `-4` | 负方向极强、短时夸张 |
| `-3` | 负方向清晰可见 |
| `-2` | 负方向克制表达 |
| `-1` | 负方向细节或过渡 |
| `0` | 明确回到中性 |
| `1` | 正方向细节或过渡 |
| `2` | 正方向克制表达 |
| `3` | 正方向清晰可见 |
| `4` | 正方向极强、短时夸张 |

省略轴表示本轮不控制该轴；显式 `0` 表示本轮要求该轴回到中性。普通主要姿态轴优先使用 `±3`，避免 Live2D 小动作不可见；`±4` 只用于明确的夸张表演。

## 3. 严格校验与 Feedback

Adapter 在生成 `engine.motion_intent.v4` 前只做协议与当前模型能力校验：

1. `intent_tags` 必须是非空语义标签集合。
2. `axis_levels` 的轴必须由当前 `SemanticAxisProfile` 暴露。
3. 每个等级必须是 `-4..4` 整数，不接受数字文本和连续值。
4. `axis_levels` 不能为空；全中性输入由 ModelEngine 在采样后按当前 profile neutral 严格判定。
5. typed resource 必须命中当前模型 catalog，且 expression 与 motion 不能同时选择。
6. `motion_steps` 中的每一步必须独立满足同一契约。
7. 任一必需字段非法时拒绝整个 effect，不保留其中看似可用的部分。

失败结果进入结构化 Motion Feedback，至少包含：

- `turn_id`
- `message_id`
- 原始 effect arguments
- 稳定的 failure reason
- 当前 profile id/revision

Feedback 只用于诊断、动作实验室记录和后续人工分析。它不会自动重试模型，也不会生成默认动作。

## 4. ModelEngine 参数处理电路

当前 compiler registry 的顺序是：

```text
IntentValidator                 order 10
-> AxisResolver                order 20
-> IntensityStage              order 30
-> SemanticAxisRelationGraph   order 40
-> ModeResolverStage           order 45
-> TimingStage                 order 46
-> CompiledSemanticMotion
-> SpeechPoseStage             order 60
-> ModelParameterBindingStage order 80
-> ResourcePolicyStage         order 90
```

各阶段只能处理自己的数据：

| 阶段 | 唯一职责 |
| --- | --- |
| `IntentValidator` | 校验 schema、模型、profile revision 和输入模式 |
| `AxisResolver` | 根据 profile 锚点把等级转换为实际语义轴值 |
| `IntensityStage` | 应用用户配置的整体与单轴强度 |
| `SemanticAxisRelationGraph` | 唯一执行派生、轴范围和轴间比例约束 |
| `ModeResolverStage` | 根据有效动作量确定 idle/expressive |
| `TimingStage` | 解析 duration hint、音频时钟和动作自身 timing |
| `SpeechPoseStage` | 在关系图收口后的语义轴结果上，根据 voice-following profile 生成确定性说话手势轨迹，不直接创建模型参数 |
| `ModelParameterBindingStage` | 将语义姿态和说话手势统一映射到 Live2D 参数，集中决定范围、权重和动力学 |
| `ResourcePolicyStage` | 校验 typed resource 的类型、可播放性和参数所有权 |

核心 stage 不能在运行时移除或禁用；extension 必须通过 registry 挂载，不能绕过 compile pipeline 修改计划。

## 5. 九级锚点与确定性采样

每个模型的 `SemanticAxisProfile` 为每个轴保存：

- `neutral`
- `soft_range`
- `strong_range`
- `extreme_range`
- `level_anchors`
- `value_range`

等级转换使用当前 profile 的锚点，并在该等级的合法区间内加入有界扰动。扰动必须可复现：

```text
segment_seed = turn_id + message_id + profile.source_hash + transform_version
axis_seed = segment_seed + axis_id
actual_value = level_interval_sample(shared_random, axis_random)
```

这样可以同时满足：

- 同一 segment 重放时得到相同动作。
- 不同回复不会机械地落在同一个锚点。
- 头部和身体分别使用自己的标定范围。
- Motion Lab 可以比较原始等级与实际值。

等级采样只能发生在对应区间内，不能跨级。采样完成后，`IntensityStage` 可以根据用户设置缩放相对中性点的偏移，因此最终候选值可以跨过原等级区间；它不能绕过随后由关系图统一执行的 `value_range` 和头身比例约束。

默认 profile 面向 Live2D 虚拟主播的可读性标定：一级动作已经需要在正常观看尺寸下可见，三级应形成明确姿态，四级可接近模型标定边界但不能越过真实参数范围。头部 yaw 的默认四级范围约为模型可用幅度的 96%，pitch/roll 约为 84%；身体 yaw/roll 约为 92%，身体 pitch 约为 84%。模型自己的 calibration 仍是最终硬边界，不能通过全局倍率扩大。

## 6. 轴关系图

关系图是 `SemanticAxisProfile` 的一部分。它描述轴之间的计算关系，不是 UI 图表，也不是运行时随机规则。

当前节点数据包括：

- axis id、role 和 neutral
- value range 与九级锚点
- Live2D parameter bindings
- 当前输入值及其来源

当前边包括：

- derive：从源轴生成派生候选。
- bounded ratio：限制目标轴相对源轴的最大偏移。
- same direction：通常同向跟随。
- opposite direction：允许反向平衡，但使用更严格的幅度上限。

头身关系的目标不是强制同向，而是阻止视觉上不可能的组合：

- 头部和身体可以同向。
- 头部和身体可以有限反向。
- 身体扭转通常小于头部扭转。
- 关系图只约束超出模型标定范围的组合，不改写本来就在合法范围内的表达。

关系图在强度处理后、模式和时序解析前执行一次，并从显式轴值重建派生轴。说话手势是运行时偏移轨道，不参与语义姿态派生，但必须与语义姿态共用 `SemanticAxisProfile` 的参数绑定、范围和动力学。Adapter、参数绑定阶段和 WebSDK 不得重复实现同类头身约束。

## 7. 资源层

`axis_levels`、expression resource 和 motion resource 的职责不同：

| 层 | 行为 |
| --- | --- |
| 语义轴 | 形成参数姿态计划 |
| expression resource | 无参数冲突时与姿态计划叠加 |
| motion resource | 作为完整动作替代普通参数计划 |

资源候选只来自当前模型 catalog 中明确暴露的条目。LLM 不接触文件路径、group/index 或底层参数 ID。

`ResourcePolicyStage` 必须在播放前完成：

- 类型和资源身份校验。
- expression 参数所有权冲突检测。
- motion 可播放性和运行时定位校验。
- 选择唯一执行策略。

资源无效或冲突时，本段动作失败；不能清除资源字段后继续播放轴计划。

## 8. 说话随动与逐帧表现

说话随动不是固定正弦摆动，也不是口型的替代物。

ModelEngine 的 `SpeechPoseStage` 根据：

- `turn_id + message_id`
- `ag99.voice_following_profile.v3`
- 音频时长
- 语义动作上下文

生成确定性的 `speech_gesture_track`。轨迹由若干控制点组成，表达保持、起势、重心变化和收势；音频能量只调节活跃程度，不决定左右方向。

说话轨道按 Live2D 表演可读性标定，而不是按真人头部的绝对角度缩小：横向歪头和转头是普通讲话的主要可见动作，pitch 主要承担重音；活泼与强调 preset 必须包含延迟的身体跟随。头部先启动、身体后启动并使用独立音频包络，避免头身完全同步，同时保证正常语音能量下动作不会被连续比例缩放到不可见。

`voice_following_profile.v3` 只携带 channel、`semantic_axis_id`、layer、`amplitude_ratio` 和跟随延迟。`amplitude_ratio` 是相对于 semantic axis `max_speech_offset` 的有效比例，不再拆分 amplitude 与 weight。无论该轴是否同时被 LLM 姿态控制，最终参数都只能由 `ModelParameterBindingStage` 根据 `SemanticAxisProfile` 建立；speech-only 计划使用同一轴的 neutral 作为静态目标，再叠加说话轨迹。

编译前必须确认 `semantic_axis_id` 存在并具有有效 parameter bindings。映射缺失属于模型能力配置错误，动作编译应明确失败，不能改用扫描范围直接生成参数，也不能静默选择其他轴。

Live2D WebSDK 逐帧消费：

- parameter plan
- speech gesture track
- 真实音频 RMS 提供的 speech energy
- lip-sync mouth value

ModelEngine 的 `parameterTrackGraphCompiler` 现在是 sequence 时间关系的唯一编译所有者。它接收每个语义步骤已经绑定好的模型参数和唯一 SpeechPose 轨迹，在编译期形成每参数闭合轨道：gaze 可在语义步骤前少量起势，head 使用步骤基准时间，body 延迟跟随；每条轨道独立计算 transition、hold 和末段 residual。语义调度保留已有音频或动作总时长，过短的权重窗口只压缩本轨道的 transition 与 hold；只有最后一次过渡、residual 和既有 blend-out 确实超出总时长时才扩展尾部。不再根据最大速度/加速度重复计算一套 rest-to-rest 预算，也不再让所有部位共享同一个 transition。

轨道图继续输出 `engine.parameter_plan.v3` 的 `keyframes` 与 `modulation`，不跨 WebSocket，也不建立运行时图引擎。序列关键帧和说话手势在 WebSDK 中统一转换为 `ParameterPresentationTrackPoint`，区间过渡只由 `ParameterPresentation` 解析；静态目标与轨迹目标随后进入同一个 `ParameterPresentationNode`。节点统一持有实际模型参数的初始值、中性值、最小/最大值、最大速度、最大加速度和当前动力学状态。它只计算 direct plan source 的当前参数贡献，不再直接决定跨来源组合或写入模型。

所有主动 source 的当前贡献由 WebSDK 的 `Parameter Mixer` 在 Cubism Physics 前统一解析。它从 Cubism Motion、Expression、drag 与 breath 形成的 base parameter snapshot 开始，按稳定优先级逐项以权重向 direct plan 与 lip-sync 提供的绝对目标值插值，并对最终值执行一次运行时范围裁剪。`LAppModel` 只能应用这个唯一的 `ResolvedParameterFrame`。

当前求值顺序为：

```text
parameter plan / speech gesture target
  -> ParameterPresentation source 轨迹与动力学
  -> Parameter Mixer（base snapshot + source contributions）
  -> 最终模型参数范围裁剪
  -> 唯一主动参数写入
  -> Cubism Physics
```

说话随动只负责生成轨迹控制点，不维护第二套范围或平滑器。音频能量只经过独立的 attack/release 包络去噪，不再进行额外曲线整形。计划收势时，表现节点生成降低 Direct Plan 所有权的 contribution，并由 Parameter Mixer 逐帧混合到当前后台 Motion/Expression base value；权重归零的最终帧严格等于后台值，随后才释放计划。Profile 的中性值只用于语义回中和动作内部计算，不作为图层释放目标。`Phy*` 等物理输出参数不进入语义参数计划或参数融合器；Profile 生成、加载和保存都必须拒绝 `physics/marker` 参数绑定，由 Cubism Physics 在驱动参数写入后独立求解。

口型和说话手势可以共享同一音频来源，但它们是两个独立 sink。口型失败必须记录真实失败；不能把说话手势当成口型成功。

## 9. 时间所有权

ModelEngine 只消费 PlaybackTimeline 提供的 segment-scoped clock context：

- 有音频时使用真实 `HTMLAudioElement` 时钟。
- 明确无音频的 motion-only segment 使用自己的 synthetic clock。
- 声明有音频但时钟不可用时，本段失败，不能改成 motion-only。
- performance curve 是可选 timing hint；未及时完成或无法应用时记录 skipped，原动作按自身合法 timing 播放。

字幕、音频、动作和口型共享 `turn_id + message_id`，不存在第二套动作播放时钟。

## 10. 可观测数据

Motion Lab 当前按同一 segment 关联保存：

- 原始 `intent_tags`、`axis_levels`、`motion_steps` 和 typed resource。
- 等级区间和确定性采样结果。
- intensity 后的 controlled values。
- 关系图派生值。
- relation graph 每条边的 evaluation 和 adjustment。
- 最终 constrained axes。
- `engine.parameter_plan.v3` 或 resource execution plan。
- run id、Timeline clock、started/terminal outcome。
- 同 Turn 用户输入与目标 segment 的 canonical assistant text。
- `CompiledSemanticMotion` 的 pose 或完整 sequence 结构。

所有转换都必须保留来源。只保存最终参数会失去模型输出、引擎约束与运行表现之间的因果关系。
已保存样本会按当前 profile 投影为 pose `axis_levels` 或完整 `motion_steps`，再依据本轮用户文本、
标签和动作族选择 1-3 个参考进入 Prompt；不得把 sequence 压平。

## 11. 运行验收

真实对话链路应能从日志和 Motion Lab 逐段回答：

1. 主模型输出了什么 effect arguments。
2. Adapter 为什么接受或拒绝。
3. 九级等级被采样成什么值。
4. 哪些值由关系图派生。
5. 哪条关系边约束了哪个轴。
6. 最终生成了什么参数计划或资源计划。
7. Timeline 使用了哪个音频时钟并在何时启动动作。
8. WebSDK 是否实际开始写参数并报告终态。

自动检查只保留协议边界的基础输入输出 smoke，不作为端到端动作正确性的证明。

## 12. 禁止事项

- 不允许 Adapter 进行姿态 repair、expressive floor 或头身约束。
- 不允许无效 axes 生成默认动作。
- 不允许 ModelEngine 之外的模块再次解释语义等级。
- 不允许 WebSDK 猜测参数 ID 或补齐缺失计划字段。
- 不允许 expression/motion 资源绕过 ModelEngine 和 PlaybackTimeline。
- 不允许 performance curve 建立独立播放链或阻塞 TTS。
- 不允许把兼容 `<@anim>` 当成 Persona Effect 失败后的替代入口。
