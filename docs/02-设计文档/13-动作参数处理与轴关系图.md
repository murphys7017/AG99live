# 动作参数处理与轴关系图

本文定义动作意图从模型输出到 Live2D 参数计划的唯一处理方式。它描述当前契约和所有权，不记录迁移过程、修复批次或已经删除的方案。

## 1. 目标

动作系统要把大模型擅长的语义判断转换成可校验、可复现、可解释的 Live2D 表现：

```text
主模型回复文本 + ag99live.motion
  -> Adapter 严格结构校验
  -> engine.motion_intent.v4
  -> ModelEngine 动作参数处理电路
  -> engine.parameter_plan.v2 / typed motion resource
  -> PlaybackTimeline
  -> Live2D WebSDK 逐帧执行
```

设计原则：

- 大模型决定语义方向和九级强度，不直接生成 Live2D 参数值。
- Adapter 只验证和运输，不修复语义，不补默认姿态。
- ModelEngine 是动作值转换、派生和约束的唯一所有者。
- Live2D WebSDK 只执行已经编译完成的计划，并负责逐帧表现与物理响应。
- 无效输入进入 feedback，不改写成一个看似成功的动作。

## 2. 输入契约

Persona Effect 名称为 `ag99live.motion`。主模型必须提供：

```json
{
  "intent_tags": ["认真解释", "看向用户"],
  "axis_levels": {
    "head_yaw": 3,
    "body_yaw": 2,
    "gaze_x": 3
  }
}
```

可选字段：

- `duration_hint_ms`
- `motion_steps`
- `expression_resource_id`
- `motion_resource_id`

`axis_levels` 只接受 `-4..4` 整数：

| 等级 | 语义 |
| --- | --- |
| `-4` | 负方向极强、短时夸张 |
| `-3` | 负方向清晰可见 |
| `-2` | 负方向克制表达 |
| `-1` | 负方向细节或过渡 |
| `0` | 明确回到中性 |
| `1` | 正方向细节或过渡 |
| `2` | 正方向克制表达 |
| `3` | 正方向清晰可见 |
| `4` | 正方向极强、短时夸张 |

省略轴表示本轮不控制该轴；显式 `0` 表示本轮要求该轴回到中性。普通主要姿态轴优先使用 `±3`，避免 Live2D 小动作不可见；`±4` 只用于明确的夸张表演。

## 3. 严格校验与 Feedback

Adapter 在生成 `engine.motion_intent.v4` 前只做协议与当前模型能力校验：

1. `intent_tags` 必须是非空语义标签集合。
2. `axis_levels` 的轴必须由当前 `SemanticAxisProfile` 暴露。
3. 每个等级必须是 `-4..4` 整数，不接受数字文本和连续值。
4. `axis_levels` 不能为空；全中性输入由 ModelEngine 在采样后按当前 profile neutral 严格判定。
5. typed resource 必须命中当前模型 catalog，且 expression 与 motion 不能同时选择。
6. `motion_steps` 中的每一步必须独立满足同一契约。
7. 任一必需字段非法时拒绝整个 effect，不保留其中看似可用的部分。

失败结果进入结构化 Motion Feedback，至少包含：

- `turn_id`
- `message_id`
- 原始 effect arguments
- 稳定的 failure reason
- 当前 profile id/revision

Feedback 只用于诊断、动作实验室记录和后续人工分析。它不会自动重试模型，也不会生成默认动作。

## 4. ModelEngine 参数处理电路

当前 compiler registry 的顺序是：

```text
IntentValidator                 order 10
-> AxisResolver                order 20
-> IntensityStage              order 30
-> CouplingStage               order 40
-> ModeResolverStage           order 45
-> TimingStage                 order 46
-> SemanticAxisRelationGraph   order 50
-> CompiledSemanticMotion
-> SpeechPoseStage             order 60
-> PlanBuilder                 order 80
-> ResourcePolicyStage         order 90
```

各阶段只能处理自己的数据：

| 阶段 | 唯一职责 |
| --- | --- |
| `IntentValidator` | 校验 schema、模型、profile revision 和输入模式 |
| `AxisResolver` | 根据 profile 锚点把等级转换为实际语义轴值 |
| `IntensityStage` | 应用用户配置的整体与单轴强度 |
| `CouplingStage` | 根据显式 coupling 产生派生候选值 |
| `ModeResolverStage` | 根据有效动作量确定 idle/expressive |
| `TimingStage` | 解析 duration hint、音频时钟和动作自身 timing |
| `SpeechPoseStage` | 根据 voice-following profile 生成确定性的说话手势轨迹 |
| `SemanticAxisRelationGraph` | 统一执行轴范围、派生关系和轴间比例约束 |
| `PlanBuilder` | 将最终语义轴映射到 Live2D 参数计划 |
| `ResourcePolicyStage` | 校验 typed resource 的类型、可播放性和参数所有权 |

核心 stage 不能在运行时移除或禁用；extension 必须通过 registry 挂载，不能绕过 compile pipeline 修改计划。

## 5. 九级锚点与确定性采样

每个模型的 `SemanticAxisProfile` 为每个轴保存：

- `neutral`
- `soft_range`
- `strong_range`
- `extreme_range`
- `level_anchors`
- `value_range`

等级转换使用当前 profile 的锚点，并在该等级的合法区间内加入有界扰动。扰动必须可复现：

```text
segment_seed = turn_id + message_id + profile.source_hash + transform_version
axis_seed = segment_seed + axis_id
actual_value = level_interval_sample(shared_random, axis_random)
```

这样可以同时满足：

- 同一 segment 重放时得到相同动作。
- 不同回复不会机械地落在同一个锚点。
- 头部和身体分别使用自己的标定范围。
- Motion Lab 可以比较原始等级与实际值。

采样只能发生在等级对应区间内，不能跨级，也不能绕过 `value_range`。

## 6. 轴关系图

关系图是 `SemanticAxisProfile` 的一部分。它描述轴之间的计算关系，不是 UI 图表，也不是运行时随机规则。

当前节点数据包括：

- axis id、role 和 neutral
- value range 与九级锚点
- Live2D parameter bindings
- 当前输入值及其来源

当前边包括：

- coupling：从源轴生成派生候选。
- bounded ratio：限制目标轴相对源轴的最大偏移。
- same direction：通常同向跟随。
- opposite direction：允许反向平衡，但使用更严格的幅度上限。

头身关系的目标不是强制同向，而是阻止视觉上不可能的组合：

- 头部和身体可以同向。
- 头部和身体可以有限反向。
- 身体扭转通常小于头部扭转。
- 关系图只约束超出模型标定范围的组合，不改写本来就在合法范围内的表达。

关系图必须在所有候选值产生之后、参数映射之前执行一次。Adapter、PlanBuilder 和 WebSDK 不得重复实现同类头身约束。

## 7. 资源层

`axis_levels`、expression resource 和 motion resource 的职责不同：

| 层 | 行为 |
| --- | --- |
| 语义轴 | 形成参数姿态计划 |
| expression resource | 无参数冲突时与姿态计划叠加 |
| motion resource | 作为完整动作替代普通参数计划 |

资源候选只来自当前模型 catalog 中明确暴露的条目。LLM 不接触文件路径、group/index 或底层参数 ID。

`ResourcePolicyStage` 必须在播放前完成：

- 类型和资源身份校验。
- expression 参数所有权冲突检测。
- motion 可播放性和运行时定位校验。
- 选择唯一执行策略。

资源无效或冲突时，本段动作失败；不能清除资源字段后继续播放轴计划。

## 8. 说话随动与逐帧表现

说话随动不是固定正弦摆动，也不是口型的替代物。

ModelEngine 的 `SpeechPoseStage` 根据：

- `turn_id + message_id`
- `ag99.voice_following_profile.v2`
- 音频时长
- 语义动作上下文

生成确定性的 `speech_gesture_track`。轨迹由若干控制点组成，表达保持、起势、重心变化和收势；音频能量只调节活跃程度，不决定左右方向。

Live2D WebSDK 逐帧消费：

- parameter plan
- speech gesture track
- 真实音频 RMS 提供的 speech energy
- lip-sync mouth value

序列关键帧和说话手势统一转换为 `ParameterPresentationTrackPoint`，区间过渡只由 `ParameterPresentation` 解析；静态目标与轨迹目标随后进入同一个 `ParameterPresentationNode`。节点统一持有实际模型参数的初始值、中性值、最小/最大值、最大速度、最大加速度和当前动力学状态，并按以下顺序求值：

```text
parameter plan / speech gesture target
  -> 进入、保持、退出轨迹
  -> 模型参数范围约束
  -> 单一速度/加速度解算
  -> Cubism 参数写入
  -> Cubism Physics
```

说话随动只负责生成轨迹控制点，不维护第二套范围或平滑器。音频能量只经过独立的 attack/release 包络去噪，不再进行额外曲线整形。计划到达声明时长后，表现节点继续完成回中动力学，只有全部参数到达中性且速度归零才结束计划。`Phy*` 等物理输出参数不进入语义参数计划；Profile 生成、加载和保存都必须拒绝 `physics/marker` 参数绑定，由 Cubism Physics 在驱动参数写入后独立求解。
- 模型物理、惯性和参数混合规则

口型和说话手势可以共享同一音频来源，但它们是两个独立 sink。口型失败必须记录真实失败；不能把说话手势当成口型成功。

## 9. 时间所有权

ModelEngine 只消费 PlaybackTimeline 提供的 segment-scoped clock context：

- 有音频时使用真实 `HTMLAudioElement` 时钟。
- 明确无音频的 motion-only segment 使用自己的 synthetic clock。
- 声明有音频但时钟不可用时，本段失败，不能改成 motion-only。
- performance curve 是可选 timing hint；未及时完成或无法应用时记录 skipped，原动作按自身合法 timing 播放。

字幕、音频、动作和口型共享 `turn_id + message_id`，不存在第二套动作播放时钟。

## 10. 可观测数据

Motion Lab 应按同一 segment 关联保存：

- 原始 `intent_tags`、`axis_levels`、`motion_steps` 和 typed resource。
- 等级区间和确定性采样结果。
- intensity 后的 controlled values。
- coupling 派生值。
- relation graph 每条边的 evaluation 和 adjustment。
- 最终 constrained axes。
- `engine.parameter_plan.v2` 或 resource execution plan。
- run id、Timeline clock、started/terminal outcome。

所有转换都必须保留来源。只保存最终参数会失去模型输出、引擎约束与运行表现之间的因果关系。

## 11. 运行验收

真实对话链路应能从日志和 Motion Lab 逐段回答：

1. 主模型输出了什么 effect arguments。
2. Adapter 为什么接受或拒绝。
3. 九级等级被采样成什么值。
4. 哪些值由 coupling 派生。
5. 哪条关系边约束了哪个轴。
6. 最终生成了什么参数计划或资源计划。
7. Timeline 使用了哪个音频时钟并在何时启动动作。
8. WebSDK 是否实际开始写参数并报告终态。

自动检查只保留协议边界的基础输入输出 smoke，不作为端到端动作正确性的证明。

## 12. 禁止事项

- 不允许 Adapter 进行姿态 repair、expressive floor 或头身约束。
- 不允许无效 axes 生成默认动作。
- 不允许 ModelEngine 之外的模块再次解释语义等级。
- 不允许 WebSDK 猜测参数 ID 或补齐缺失计划字段。
- 不允许 expression/motion 资源绕过 ModelEngine 和 PlaybackTimeline。
- 不允许 performance curve 建立独立播放链或阻塞 TTS。
- 不允许把兼容 `<@anim>` 当成 Persona Effect 失败后的替代入口。
