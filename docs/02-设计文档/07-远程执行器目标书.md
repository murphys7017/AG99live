# 远程执行器目标书

## 目标

AG99live 后续要支持把用户的任务委托给一台或多台用户电脑上的远程执行器完成。AstrBot 侧负责理解用户意图、组织任务级命令、注入执行器上下文、接收执行结果并通过桌宠展示过程；本机 Local Bridge / SDK 负责连接 Codex CLI app-server 或其他 executor，把任务交给本机 agent 细分步骤并执行。后续可继续接入 OpenCode CLI、浏览器控制、文件/命令行工具或 Windows 桌面工具。

这条能力的核心不是让 AstrBot 直接控制鼠标、浏览器或文件系统，而是建立一条稳定的任务委托链路：

```text
用户 / 桌宠
  -> AG99live AstrBot Adapter
    -> AstrBot Core
      -> remote operator task
        -> Local Bridge / SDK
          -> Codex CLI app-server / OpenCode CLI / Browser / Shell / FS / Desktop tools
```

## 成功标准

- AG99live Adapter 能识别当前是否存在可用远程执行器，并在 prompt 阶段注入能力、状态、权限约束和使用方式。
- AstrBot Core 能产出任务级命令，而不是底层操作命令。
- Local Bridge / SDK 能接收任务级命令，并转交给指定电脑上的 Codex CLI app-server 或其他 executor 执行。
- Adapter 能维护多台电脑的在线状态、能力列表和默认路由；用户未指明电脑时走默认电脑。
- Adapter 能接收 SDK 的进度、确认请求、截图/日志等 artifact 和最终结果。
- 桌宠前端能展示执行过程、确认请求、取消入口和最终结果。
- 整条链路保留权限边界、审计日志、任务 ID 和可追踪状态。

## 非目标

- 不在第一阶段实现通用 Windows 桌面应用自动化。
- 不让 AstrBot 主模型逐步调用 `click/type/read_file` 这类底层操作工具。
- 不把 OpenCode CLI、Codex CLI 或 Codex app-server 直接嵌入 AG99live 前端。
- 不让桌宠前端成为本机高权限执行主体。
- 不承诺自动完成所有桌面软件任务；第一阶段只验证任务委托闭环。

## 归属边界

### AG99live Adapter

Adapter 是远程执行器接入中枢，拥有两条连接：

```text
桌宠 WebSocket: AG99live frontend <-> AG99live Adapter
SDK WebSocket: Local Bridge / SDK <-> AG99live Adapter
```

Adapter 负责：

- 维护多台 SDK/电脑连接、心跳、能力上报、默认电脑和当前执行状态。
- 在 prompt 阶段注入远程执行器上下文。
- 在结果阶段收集执行器事件，并转换为前端可展示的 `client_objects` 或后续专用协议消息。
- 将用户确认、取消、继续等操作转发给 SDK。
- 把任务结果关联到 AstrBot turn / message / frontend turn。

Adapter 不负责：

- 自己拆解本机执行步骤。
- 直接执行 OpenCode/Codex/浏览器/桌面工具。
- 决定所有底层操作细节。

### 多电脑路由

Adapter 维护一个远程电脑注册表。每个 Local Bridge / SDK 连接后都要上报稳定的 `computer_id`、用户可读的 `computer_name`、能力列表和 executor 状态。

示例：

```json
{
  "type": "operator.hello",
  "computer_id": "pc_home_001",
  "computer_name": "home-desktop",
  "is_default": true,
  "executors": [
    {
      "kind": "codex_app_server",
      "status": "online",
      "endpoint": "local"
    }
  ],
  "capabilities": ["codex", "workspace", "shell_readonly", "browser_preview"]
}
```

路由规则：

- 如果任务明确指定 `target.computer_name` 或 `target.computer_id`，Adapter 只投递到对应电脑。
- 如果任务没有指定电脑，Adapter 投递到默认电脑。
- 如果默认电脑不在线，Adapter 应返回可恢复错误，并把在线电脑列表反馈给 AstrBot，让 Core 询问用户或改派。
- 如果多台电脑重名，`computer_id` 是最终路由依据，`computer_name` 只用于 prompt 和用户可见展示。
- 同一 `task_id` 在同一时间只能绑定一台电脑，避免执行事件串线。

### AstrBot Core

AstrBot Core 负责把对话意图提升为任务级委托：

- 是否需要使用远程执行器。
- 要委托给哪个执行器能力。
- 目标软件、任务目标、输入上下文和成功标准。
- 本轮任务的权限约束和用户可见说明。

Core 不应该直接承担本机执行细节。它输出的是任务级命令，例如：

```json
{
  "type": "operator.task",
  "task_id": "task_001",
  "target": {
    "kind": "browser",
    "computer_name": "home-desktop",
    "app": "edge"
  },
  "objective": "打开浏览器，搜索指定资料，并总结关键结论。",
  "inputs": {
    "query": "OpenCode CLI usage"
  },
  "success_criteria": [
    "打开目标浏览器",
    "找到相关资料",
    "返回摘要和来源"
  ],
  "constraints": {
    "allow_file_write": false,
    "allow_shell": false,
    "require_confirmation": false,
    "timeout_seconds": 180
  },
  "reporting": {
    "progress": true,
    "artifacts": ["screenshot", "log"],
    "final_summary": true
  }
}
```

### Local Bridge / SDK

Local Bridge / SDK 是用户电脑上的连接层。它负责：

- 接收任务级命令。
- 连接本机 Codex CLI app-server，并把任务转成 app-server 可执行的 prompt / turn。
- 可选连接 OpenCode CLI、Playwright/CDP、shell、文件工具和后续 Windows 桌面工具。
- 管理本机权限、确认、取消、超时和日志。
- 回传进度事件、artifact、错误和最终结果。

Codex CLI app-server 或 OpenCode CLI 才是具体的本机 agent executor。AstrBot 不需要知道 executor 内部每一步具体怎样做。

## 推荐任务协议

第一版任务协议固定以下字段：

| 字段 | 说明 |
|---|---|
| `task_id` | 任务唯一 ID，由 Adapter 或 Core 分配 |
| `target` | 目标对象，例如 browser、workspace、app、desktop |
| `target.computer_name` | 可选，用户可读电脑名称；未指定时走默认电脑 |
| `target.computer_id` | 可选，稳定电脑 ID；存在时优先于 `computer_name` |
| `objective` | 自然语言任务目标 |
| `inputs` | 查询词、文件路径、用户补充文本等结构化输入 |
| `success_criteria` | 完成条件，供 SDK 自检 |
| `constraints` | 权限、超时、确认、允许目录、允许应用 |
| `context` | 可选上下文，例如当前会话摘要、截图说明 |
| `reporting` | 进度、截图、日志、最终摘要要求 |

任务级命令应该比普通自然语言更具体，但不能细到坐标级动作。合理粒度是：

- 打开哪个软件。
- 做什么任务。
- 使用哪些输入。
- 什么算完成。
- 哪些操作允许或需要确认。

## 推荐事件协议

SDK 向 Adapter 回传事件流：

```json
{"type": "operator.started", "task_id": "task_001"}
```

```json
{
  "type": "operator.progress",
  "task_id": "task_001",
  "message": "正在打开浏览器"
}
```

```json
{
  "type": "operator.approval_required",
  "task_id": "task_001",
  "approval_id": "approval_001",
  "message": "需要运行 OpenCode CLI 读取工作区文件。",
  "risk": "medium"
}
```

```json
{
  "type": "operator.artifact",
  "task_id": "task_001",
  "artifact": {
    "type": "screenshot",
    "id": "shot_001",
    "mime_type": "image/png"
  }
}
```

```json
{
  "type": "operator.completed",
  "task_id": "task_001",
  "summary": "已完成资料检索并返回摘要。",
  "evidence": ["已打开浏览器并读取目标页面。"]
}
```

失败和取消也必须是显式事件：

```json
{
  "type": "operator.failed",
  "task_id": "task_001",
  "error": "browser_navigation_timeout",
  "message": "浏览器页面加载超时。"
}
```

```json
{"type": "operator.cancelled", "task_id": "task_001"}
```

## Prompt 注入目标

Adapter 的 prompt contributor 注入的内容应包括：

- 当前是否有 SDK 在线。
- 在线电脑列表、默认电脑和每台电脑的能力列表，例如 `codex`, `opencode`, `browser`, `workspace`, `desktop_preview`。
- 每个能力的适用范围和限制。
- 当前任务是否允许自动委托。
- 哪些操作需要用户确认。
- 如何构造任务级命令，以及未指定电脑时会使用默认电脑。

Prompt 注入不应该鼓励模型输出底层操作步骤，例如坐标点击、具体 UIA selector 或 shell 命令细节。模型只需要给 SDK 明确任务、目标、约束和成功标准。

## 结果获取目标

Adapter 的结果阶段负责把 SDK 事件接入当前 turn：

- `operator.progress` 显示为过程状态。
- `operator.approval_required` 显示为确认 UI。
- `operator.artifact` 显示为截图、日志或文件附件。
- `operator.completed` 汇入最终回复或作为可见执行结果。
- `operator.failed` 显示失败原因，并允许 AstrBot 决定是否重试、换能力或向用户说明。

结果展示不能破坏现有文本、音频、动作同步链路。远程执行器事件应作为独立 client object 或独立系统消息接入，而不是混进 `engine.motion_*` 协议。

## 第一阶段范围

第一阶段只做最小闭环：

1. Local Bridge / SDK 连接 Adapter，上报电脑名称、默认标记和能力。
2. Adapter prompt 注入远程执行器状态、在线电脑列表和默认电脑。
3. AstrBot 能产出任务级命令。
4. SDK 连接本机 Codex CLI app-server，完成一个只读代码/文件任务。
5. SDK 回传进度、日志和最终摘要。
6. Adapter 把事件展示给桌宠。

浏览器控制可以作为第二个样板能力：

- 打开浏览器。
- 访问 URL 或搜索关键词。
- 截图。
- 读取页面文本。
- 返回摘要和来源。

## 后续阶段

### 第二阶段：浏览器执行器

- Playwright 或 CDP 控制 Edge/Chrome。
- 支持公开网页检索、截图、读取 DOM 文本。
- 登录态、下载、表单提交默认需要确认。

### 第三阶段：工作区执行器

- OpenCode CLI / Codex CLI 作为代码任务执行者。
- Codex CLI app-server 作为优先 executor；OpenCode CLI 作为可选 executor。
- 支持读文件、搜索、运行测试、给出修复建议。
- 写文件和破坏性命令必须确认。

### 第四阶段：Windows 桌面执行器

- Win32 / UI Automation / 截图 / OCR / 键鼠输入组合。
- 先适配少量高频软件。
- 所有桌面点击、输入、发送、删除类动作默认需要确认。

## 安全原则

- 默认最小权限。
- 写文件、运行命令、发送消息、下载、删除、桌面输入必须可配置确认策略。
- SDK 需要本机侧取消能力。
- 每个任务必须有日志和任务 ID。
- artifact 不应无限制上传；截图、日志和文件都要受大小与敏感信息策略约束。
- Codex app-server、OpenCode CLI 或 Codex CLI 不应裸跑在无限权限环境中，外层必须有 policy / approval / audit。

## 当前判断

这条路线实现难度可控，因为 AG99live Adapter 已经具备 prompt contributor、result contributor 和桌宠 WebSocket 基础。新增能力主要是：

- 增加一条 SDK WebSocket。
- 增加远程执行器 prompt 上下文。
- 增加多电脑注册、默认电脑和按名称路由。
- 定义任务协议和事件协议。
- 编写 Local Bridge / SDK，先接 Codex CLI app-server，再把 OpenCode CLI 作为可选 executor。

最重要的边界是：Adapter 是中枢，Local Bridge / SDK 是连接层，Codex app-server / OpenCode CLI 是执行者，AstrBot 给任务级命令，桌宠负责可见交互。
