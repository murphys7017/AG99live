# 远程执行器目标书

## 目标

AG99live 支持把用户的任务委托给一台或多台用户电脑上的远程执行器完成。AstrBot 侧负责理解用户意图、组织任务级命令、注入执行器上下文、接收执行结果并通过桌宠展示过程；远程执行器连接层负责连接 Codex app-server 或其他 executor，把任务交给本机 agent 细分步骤并执行。

当前已接入的 Windows 操作路径是：AG99live Adapter 连接配置中的 Codex app-server WebSocket，查询并注入 `computer-use:computer-use` skill，再把用户任务作为 app-server turn 输入发送给 Codex。Windows 桌面观察、点击、输入等底层动作由 app-server / Computer Use 执行，Adapter 不直接操作鼠标键盘。

这条能力的核心不是让 AstrBot 直接控制鼠标、浏览器或文件系统，而是建立一条稳定的任务委托链路：

```text
用户 / 桌宠
  -> AG99live AstrBot Adapter
    -> AstrBot Core
      -> remote operator task
        -> Codex app-server / Local Bridge / SDK
          -> Computer Use / OpenCode CLI / Browser / Shell / FS / Desktop tools
```

## 成功标准

- AG99live Adapter 能识别当前是否存在可用远程执行器，并在 prompt 阶段注入能力、状态、权限约束和使用方式。
- AstrBot Core 能产出任务级命令，而不是底层操作命令。
- Codex app-server / Local Bridge / SDK 能接收任务级命令，并转交给指定电脑上的 executor 执行。
- Adapter 能维护多台电脑的在线状态、能力列表和默认路由；用户未指明电脑时走默认电脑。
- Adapter 能接收 SDK 的进度、确认请求、截图/日志等 artifact 和最终结果。
- 桌宠前端能展示执行过程、确认请求、取消入口和最终结果。
- 整条链路保留权限边界、审计日志、任务 ID 和可追踪状态。

## 非目标

- 不让 Adapter 自己实现通用 Windows 桌面应用自动化；Windows 桌面动作必须经由 Codex app-server / Computer Use 等外部 executor。
- 不让 AstrBot 主模型逐步调用 `click/type/read_file` 这类底层操作工具。
- 不把 OpenCode CLI、Codex CLI 或 Codex app-server 直接嵌入 AG99live 前端。
- 不让桌宠前端成为本机高权限执行主体。
- 不承诺自动完成所有桌面软件任务；第一阶段只验证任务委托闭环。

## 归属边界

### AG99live Adapter

Adapter 是远程执行器接入中枢，拥有两条连接：

```text
桌宠 WebSocket: AG99live frontend <-> AG99live Adapter
SDK WebSocket: Codex app-server / Local Bridge / SDK <-> AG99live Adapter
```

Adapter 负责：

- 维护多台 SDK/电脑连接、心跳、能力上报、默认电脑和当前执行状态。
- 在 prompt 阶段注入远程执行器上下文。
- 在结果阶段收集执行器事件，并转换为前端可展示的 `client_objects` 或后续专用协议消息。
- 将用户确认、取消、继续等操作转发给 SDK。
- 把任务结果关联到 AstrBot turn / message / frontend turn。

Adapter 不负责：

- 自己拆解本机执行步骤。
- 直接执行 OpenCode/Codex/浏览器/桌面工具。
- 决定所有底层操作细节。

### 多电脑路由

Adapter 维护一个远程电脑注册表。每个 Local Bridge / SDK 连接后都要上报稳定的 `computer_id`、用户可读的 `computer_name`、能力列表和 executor 状态。

示例：

```json
{
  "type": "operator.hello",
  "computer_id": "pc_home_001",
  "computer_name": "home-desktop",
  "is_default": true,
  "executors": [
    {
      "kind": "codex_app_server",
      "status": "online",
      "endpoint": "local"
    }
  ],
  "capabilities": ["codex", "workspace", "shell_readonly", "browser_preview"]
}
```

路由规则：

- 如果任务明确指定 `target.computer_name` 或 `target.computer_id`，Adapter 只投递到对应电脑。
- 如果任务没有指定电脑，Adapter 投递到默认电脑。
- 如果默认电脑不在线，Adapter 应返回可恢复错误，并把在线电脑列表反馈给 AstrBot，让 Core 询问用户或改派。
- 如果多台电脑重名，`computer_id` 是最终路由依据，`computer_name` 只用于 prompt 和用户可见展示。
- 同一 `task_id` 在同一时间只能绑定一台电脑，避免执行事件串线。

### AstrBot Core

AstrBot Core 负责把对话意图提升为任务级委托：

- 是否需要使用远程执行器。
- 要委托给哪个执行器能力。
- 目标软件、任务目标、输入上下文和成功标准。
- 本轮任务的权限约束和用户可见说明。

Core 不应该直接承担本机执行细节。它输出的是任务级命令，例如：

```json
{
  "type": "operator.task",
  "task_id": "task_001",
  "target": {
    "kind": "browser",
    "computer_name": "home-desktop",
    "app": "edge"
  },
  "objective": "打开浏览器，搜索指定资料，并总结关键结论。",
  "inputs": {
    "query": "OpenCode CLI usage"
  },
  "success_criteria": [
    "打开目标浏览器",
    "找到相关资料",
    "返回摘要和来源"
  ],
  "constraints": {
    "allow_file_write": false,
    "allow_shell": false,
    "require_confirmation": false,
    "timeout_seconds": 180
  },
  "reporting": {
    "progress": true,
    "artifacts": ["screenshot", "log"],
    "final_summary": true
  }
}
```

### Local Bridge / SDK

Codex app-server / Local Bridge / SDK 是用户电脑上的连接层。它负责：

- 接收任务级命令。
- 连接本机 Codex app-server，并把任务转成 app-server 可执行的 prompt / turn。
- 当前 Windows 操作路径会先通过 app-server `skills/list` 查找 `computer-use:computer-use`，再把该 skill 和任务文本一起作为 turn 输入。
- 可选连接 OpenCode CLI、Playwright/CDP、shell、文件工具和其他桌面工具。
- 管理本机权限、确认、取消、超时和日志。
- 回传进度事件、artifact、错误和最终结果。

Codex CLI app-server 或 OpenCode CLI 才是具体的本机 agent executor。AstrBot 不需要知道 executor 内部每一步具体怎样做。

### 当前 AG99live 实现状态

当前实现不是独立 SDK server，而是 Adapter 直接按配置连接 Codex app-server endpoint：

- `_conf_schema.json` 中的 `remote_operator_computer_entries` 配置 computer key、用户可读名称和 app-server WebSocket endpoint。
- `RemoteOperatorRuntime.refresh_online_status()` 会 probe 每台电脑 endpoint，并把在线电脑写入 remote operator prompt registry。
- `AG99liveRemoteOperatorPromptContributor` 只在存在在线电脑时注入远程执行器能力说明。
- 对“操作电脑/桌面/软件”类请求，remote operator middleware 会覆盖核心执行 prompt，要求核心只输出 `{"computer","profile","prompt"}` 三字段 JSON。
- `RemoteOperatorRuntime.execute()` 根据 computer 和 profile 选择 endpoint / model / effort，然后通过 `CodexAppServerClient` 启动 app-server thread/turn。
- `CodexAppServerClient` 在 turn 输入中插入 `computer-use:computer-use` skill，因此 Windows 桌面操作由 Codex app-server 和 Computer Use 完成。
- 执行结果会作为 `remote_operator_result` 来源重新进入 AstrBot 事件，并带上 computer、profile、success/error 等 metadata，避免再次触发远程执行器递归。

## 推荐任务协议

第一版任务协议固定以下字段：

| 字段 | 说明 |
|---|---|
| `task_id` | 任务唯一 ID，由 Adapter 或 Core 分配 |
| `target` | 目标对象，例如 browser、workspace、app、desktop |
| `target.computer_name` | 可选，用户可读电脑名称；未指定时走默认电脑 |
| `target.computer_id` | 可选，稳定电脑 ID；存在时优先于 `computer_name` |
| `objective` | 自然语言任务目标 |
| `inputs` | 查询词、文件路径、用户补充文本等结构化输入 |
| `success_criteria` | 完成条件，供 SDK 自检 |
| `constraints` | 权限、超时、确认、允许目录、允许应用 |
| `context` | 可选上下文，例如当前会话摘要、截图说明 |
| `reporting` | 进度、截图、日志、最终摘要要求 |

任务级命令应该比普通自然语言更具体，但不能细到坐标级动作。合理粒度是：

- 打开哪个软件。
- 做什么任务。
- 使用哪些输入。
- 什么算完成。
- 哪些操作允许或需要确认。

## 推荐事件协议

SDK 向 Adapter 回传事件流：

```json
{"type": "operator.started", "task_id": "task_001"}
```

```json
{
  "type": "operator.progress",
  "task_id": "task_001",
  "message": "正在打开浏览器"
}
```

```json
{
  "type": "operator.approval_required",
  "task_id": "task_001",
  "approval_id": "approval_001",
  "message": "需要运行 OpenCode CLI 读取工作区文件。",
  "risk": "medium"
}
```

```json
{
  "type": "operator.artifact",
  "task_id": "task_001",
  "artifact": {
    "type": "screenshot",
    "id": "shot_001",
    "mime_type": "image/png"
  }
}
```

```json
{
  "type": "operator.completed",
  "task_id": "task_001",
  "summary": "已完成资料检索并返回摘要。",
  "evidence": ["已打开浏览器并读取目标页面。"]
}
```

失败和取消也必须是显式事件：

```json
{
  "type": "operator.failed",
  "task_id": "task_001",
  "error": "browser_navigation_timeout",
  "message": "浏览器页面加载超时。"
}
```

```json
{"type": "operator.cancelled", "task_id": "task_001"}
```

## Prompt 注入目标

Adapter 的 prompt contributor 注入的内容应包括：

- 当前是否有 SDK 在线。
- 在线电脑列表、默认电脑和每台电脑的能力列表，例如 `codex`, `opencode`, `browser`, `workspace`, `desktop_preview`。
- 每个能力的适用范围和限制。
- 当前任务是否允许自动委托。
- 哪些操作需要用户确认。
- 如何构造任务级命令，以及未指定电脑时会使用默认电脑。

Prompt 注入不应该鼓励模型输出底层操作步骤，例如坐标点击、具体 UIA selector 或 shell 命令细节。模型只需要给 SDK 明确任务、目标、约束和成功标准。

## 结果获取目标

Adapter 的结果阶段负责把 SDK 事件接入当前 turn：

- `operator.progress` 显示为过程状态。
- `operator.approval_required` 显示为确认 UI。
- `operator.artifact` 显示为截图、日志或文件附件。
- `operator.completed` 汇入最终回复或作为可见执行结果。
- `operator.failed` 显示失败原因，并允许 AstrBot 决定是否重试、换能力或向用户说明。

结果展示不能破坏现有文本、音频、动作同步链路。远程执行器事件应作为独立 client object 或独立系统消息接入，而不是混进 `engine.motion_*` 协议。

## 已落地范围

当前最小闭环已经覆盖：

1. 配置多台 Codex app-server endpoint，上报/刷新在线电脑状态。
2. Adapter prompt 注入远程执行器状态、在线电脑列表和默认电脑。
3. AstrBot 对桌面/电脑/软件操作请求产出任务级 JSON，而不是直接调用 shell/browser/CUA 工具。
4. Adapter 连接本机 Codex app-server，并要求 app-server 使用 `computer-use:computer-use` skill。
5. app-server 返回最终文本结果，Adapter 把结果重新投递为 `remote_operator_result` 事件。

当前浏览器或 Windows 桌面控制不再由 AstrBot 主模型直接执行，而是作为 Computer Use 可完成的本机任务交给 app-server。

仍未完成的部分：

- 前端专用的远程执行器进度 UI、确认 UI 和取消入口。
- 细粒度 `operator.progress / operator.artifact / operator.approval_required` 事件流展示。
- 更严格的本机权限策略、敏感截图策略和人工确认策略。

## 后续阶段

### 第二阶段：事件流与确认

- app-server / SDK 回传 progress、artifact、approval_required、cancelled 等结构化事件。
- 桌宠前端展示过程、截图、日志和用户确认入口。
- Adapter 将确认/取消继续转发给对应 task。

### 第三阶段：浏览器与工作区专用执行器

- Playwright 或 CDP 控制 Edge/Chrome，作为 Computer Use 之外的可选 executor。
- OpenCode CLI / Codex CLI 作为代码任务执行者。
- Codex app-server 作为优先 executor；OpenCode CLI 作为可选 executor。
- 支持读文件、搜索、运行测试、给出修复建议。
- 写文件和破坏性命令必须确认。

### 第四阶段：Windows 桌面执行器深化

- 在 Computer Use 之外补充 Win32 / UI Automation / 截图 / OCR / 键鼠输入组合。
- 先适配少量高频软件。
- 所有桌面点击、输入、发送、删除类动作默认需要确认。

## 安全原则

- 默认最小权限。
- 写文件、运行命令、发送消息、下载、删除、桌面输入必须可配置确认策略。
- SDK 需要本机侧取消能力。
- 每个任务必须有日志和任务 ID。
- artifact 不应无限制上传；截图、日志和文件都要受大小与敏感信息策略约束。
- Codex app-server、OpenCode CLI 或 Codex CLI 不应裸跑在无限权限环境中，外层必须有 policy / approval / audit。

## 当前判断

这条路线实现难度可控，因为 AG99live Adapter 已经具备 prompt contributor、result contributor、桌宠 WebSocket 基础，并已经能连接 Codex app-server / Computer Use 完成 Windows 操作委托。后续新增能力主要是：

- 把当前最终结果回传扩展为结构化事件流。
- 增加前端远程执行器状态、确认、取消和 artifact 展示。
- 增加更细的权限策略和审计日志。
- 将 Codex app-server 之外的 OpenCode CLI、浏览器专用执行器或本地 SDK executor 接进同一任务协议。

最重要的边界是：Adapter 是中枢，Codex app-server / Local Bridge / SDK 是连接层，Computer Use / OpenCode CLI / 浏览器执行器是执行者，AstrBot 给任务级命令，桌宠负责可见交互。
