## 1. 当前结论

增强版主链路仍保持统一：

```text
AstrBot
-> Adapter output.segment.v4
-> TurnPlaybackSessionStore
-> PlaybackTimeline
-> ModelEngine
-> engine.parameter_plan.v3
-> AG99 Live2D Runtime
   -> ActiveParameterMixer：收集 raw contributions，合成最终目标
   -> ParameterPresentation：对最终非口型目标执行一次响应
-> Official Cubism Physics / model.update / draw
```

正式主链路的所有权仍然统一，没有发现需要推倒 SessionStore、PlaybackTimeline、ModelEngine、
ParameterMixer 或 AG99 Runtime 分层的结构性理由。动作替换、ModelEngine 停止失败收口和组件销毁
所有权已经按现有边界统一，当前源码复核没有保留尚未修复的活动缺陷。
`WebSDK/src` 与官方 Cubism `Framework/Core` 的历史目录混用仍属于架构债务，已在
[角色表演主流程与编排职责审计](./19-角色表演主流程与编排职责审计.md) 记录，但不是本轮的运行时根因。

## 3. 当前修复批次

当前源码修复批次已完成复核，包含两个边界收口：

1. Electron 的 pet / overlay 窗口统一通过 renderer `did-finish-load` 后再显示；overlay 使用
   固定窗口尺寸和 `query.window=overlay` 角色参数，不再通过内容测量和 IPC 动态改变窗口高度。
   透明窗口重建也沿用同一 ready gate，避免 renderer 未加载、角色错误或透明表面重绘时把输入框
   显示成空窗口。
2. SegmentJobExecutor 与 MotionRuntimeScheduler 的动作启动失败都进入现有
   `rejectMotionBeforeStart()` / Timeline terminal 路径。动作 sink 返回拒绝、启动异常、非法
   `receivedAtMs` 或 Timeline 准备失败都不会留下开放 required sink；已确认启动的动作不会被
   误判为启动失败。这里没有新增队列、fallback、第二套 Timeline 或第二个动作入口。

代码级校验完成后，下一步只剩真实 Electron、音频和 Live2D 运行验收；二期功能继续以
[二期角色表演系统总体规划](./18-二期角色表演系统总体规划.md) 为唯一计划来源。

新问题仍应直接修改现有所有者，不新增第二套队列、兼容调度器、错误转换器或动作入口。自动测试只
做最基础输入输出 smoke；最终仍需用真实 AstrBot、Electron、TTS 与 Live2D 链路观察行为。
