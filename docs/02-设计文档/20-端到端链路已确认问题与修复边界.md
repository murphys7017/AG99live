# 端到端链路已确认问题与修复边界

本文只保留当前仍开放的链路问题与验收缺口。已被源码替换的历史实现不在此留档；产品阶段定义以
[一期完成边界与二期入口](../01-架构与结构/06-一期完成边界与二期入口.md) 为准，表演质量规划以
[二期角色表演系统总体规划](./18-二期角色表演系统总体规划.md) 为准。

AG99live 插件源码位于仓库根目录的 `astrbot_plugin_ag99live_adapter/`；AstrBot 运行目录中的
`data/plugins/astrbot_plugin_ag99live_adapter/` 只是同步副本，AstrBot Core 则属于外部配套仓库。

## 1. 已确认的主链路

```text
AstrBot
-> Adapter output.segment.v4
-> TurnPlaybackSessionStore
-> PlaybackTimeline
-> ModelEngine / PerformanceSchedule
-> engine.parameter_plan.v3
-> AG99 Live2D Runtime
   -> ActiveParameterMixer：以 Cubism base 为基准融合 direct plan 与 lip-sync
   -> ParameterPresentation：对融合后的非口型目标执行一次响应
-> Official Cubism Physics / model.update / draw
```

SessionStore、PlaybackTimeline、ModelEngine、ParameterMixer 与 AG99 Runtime 的职责边界保持统一。
AG99 的动作输出契约现已统一为稀疏 `motion_steps` 轨道语义；详见
[动作输出契约与序列结构统一](./22-动作输出契约与序列结构统一方案.md)。

## 2. 当前开放项

### 2.1 AstrBot 逻辑消息完成的失败语义

增强版 Core 已接入 `complete_visible_message(message_id)`，AG99 会在收到它后立即发送对应原子段。
仍需修正一个外部 Core 风险：物理消息链允许逐项 best-effort 发送，当前只要任意一项成功就会返回成功；
因此 Core 必须区分“至少一个物理发送成功”和“全部物理发送成功”，并且只以后者确认逻辑消息。否则
Adapter 可能把缺少后续物理材料的段当作完成。

AG99 不为此补发、猜测 slot 或保留整轮统一 flush；未完成段在 Turn 收口时会显式失败。

### 2.2 真实端到端验收

AG99 的源码调用链已经收口，但还需要真实 AstrBot、Electron、TTS 和 Live2D 共同确认：

- 合法的单姿态和稀疏序列是否进入 `engine.parameter_plan.v3` 并实际开始播放。
- 多物理组件的一条逻辑消息是否只在全部成功后产生一个即时 `output.segment`；部分发送失败时不得确认该段。
- 只在后续 step 首次声明的参数是否在此前保持未激活。
- 后续 step 首次声明的参数是否在完成响应前保持计划所有权，而不是随原音频时长提前淡出。
- 后续省略是否保持，显式 `0` 是否回到语义中性。
- 非法结构是否以准确的 Motion Feedback 结束，而不是被前端误报为播放失败。

这项验收不应通过增加 fallback、第二条队列、兼容调度器或默认动作替代。

## 3. 不属于本轮根因的边界

- WebSDK 只执行 `engine.parameter_plan.v3`，不解释 Persona Effect 或 `motion_steps`。
- `performance_curve` 与 TTS 生命周期不属于动作输入契约。
- 官方 Cubism `Framework/Core` 只负责最终参数写入后的 Physics 与渲染。
- 官方 `<@anim>` V4 兼容入口是传输边界，不是增强 Persona Effect 失败后的 fallback。

自动测试只做基础输入输出 smoke；真实效果由运行日志和画面共同确认。
