# 返回电脑后的主动互动

## 目标与边界
AG99live只观察系统锁屏/休眠与输入空闲时长，形成一次返回机会，复用AstrBot RuntimeObservationSensor、Gate、Personal Policy、Persona、TTS和Live2D动作链路。无按键内容、截图、桌面分析或独立模型请求。默认关闭，不调整用户的安静时段、模型或已有桌面变化阈值。

## 检测规则
Electron主进程使用powerMonitor的lock/unlock、suspend/resume及系统空闲时间。状态机保留在主进程，渲染窗口不拥有离开状态。活动样本首次读取只建立基线；初次就已空闲/锁屏的周期不补欢迎。新的连接监视身份或检测参数变更会重建基线，旧返回不重放。

| 来源 | 形成候选 | 确认 |
| --- | --- | --- |
| 锁屏/休眠 | 持续至少minimum_away_seconds，默认60秒，之后恢复输入 | 默认3秒后仍有新的输入 |
| 普通输入空闲 | 达到idle_after_seconds，默认300秒，之后恢复输入 | 同样确认；仅说明恢复操作，不断言身体离开 |

空闲时间为整数秒：确认时推算的最后输入时间须比首次候选至少前进1.5秒，且当前空闲不超过2秒；确认窗口默认3秒（可配置3～10秒），15秒未确认丢弃。一碰鼠标之后空闲时间持续增长、自动唤醒后无人输入，都不能满足该条件。最短锁屏可配置10～3600秒，输入空闲30～3600秒，便于测试与实际校准。

每个已确认周期递增序号，形成唯一事件。unlock、resume和input_resumed三种依据保留区分。监视快照只保留当前状态及最近一次返回，内存存储，不写用户历史。

## 传输与会话
配套前端协商ag99live.desktop_presence.v1能力；AG99live独立请求/结果消息无chat turn。启用且会话插件准入允许时，每个连接串行约每秒读取一次；5秒逻辑截止，前端限制一个在途IPC，迟到旧连接结果不发送给新连接。
身份包含连接代次、client_uid和主进程boot_id；断连、配置变化或插件卸载取消任务，接收侧首个快照只对齐序号，之后只消费递增的新事件，不因WebSocket重连产生欢迎。检测监视身份在同一已启用平台/客户端配置下跨普通断线保留，因此Electron主进程已记录的休眠可以在唤醒重连后继续等待新的实际输入确认；不会重放先前已经确认的返回。禁用来源、改变配置、客户端或插件重新加载会创建新监视身份，重建基线。
准入使用基础AstrMessageEvent检查同一会话权限，不创建交互轮次，也不每秒运行适配器输出配置或动作接线。失败/未知状态不按返回处理，并撤销尚未完成的旧机会。

## 主动表达与优先级
每个返回事件最多向Sensor提交一次事实。对话输入准备、实际PTT/VAD语音、排队/执行轮次和未完成播放期间丢弃机会，不留到对话后补发。此来源不等待数学桌面观察的60秒空闲窗口，避免欢迎被无关延迟拖过期。
提交的模型材料只有自然语言事实说明和无输入持续秒数，不携带boot_id、序号、请求ID等诊断标识。策略仍使用用户已有模型配置，决定忽略、观察、表达或延后；最终语音和动作经统一Persona输出，未增加纯动作策略类型。
独立的返回机会冷却默认15分钟（0～86400秒可配），按平台/客户端计算，从机会提交尝试开始计时；即使Policy选择安静，同周期也不重试。该冷却为进程内状态。单条事实有效期30秒，含快照年龄、传输及后续等待，不补播过期欢迎。Policy延后仍服从该期限；一个机会不等于固定只调用一次策略。
提交时附带独立撤销信号，并监听已有会话输入信号。用户先开口、下一次无操作/锁屏、来源关闭、会话禁用或断连，会撤销旧机会及相关工作；同次欢迎不自动追加追问。已发送片段无法追回，既有播放打断机制继续负责。

真实验收：
1. 启用返回互动及已有Personal Policy，确认测试不在安静时段。
2. 锁屏至少60秒，解锁后持续操作3～5秒；观察inactive→confirming→active、candidate、submitted和Policy Gate日志。策略允许时，经现有语音/动作表达；不要求每次必说。
3. 再次短暂锁屏或同一周期持续操作，不应重复产生欢迎。
4. 空闲至少5分钟后只碰一下鼠标，不应直接触发；持续恢复操作可形成input_resumed机会。
5. 返回后先与她说话，旧欢迎应丢弃/撤销；重连和首次启动不补欢迎。正常对话保持优先。

触摸回应、对话事项跟进和独立纯动作主动策略不在本轮范围。
