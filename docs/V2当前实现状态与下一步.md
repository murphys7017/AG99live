# V2 当前实现状态与下一步

快照日期：2026-05-12

## 一句话状态

V2 主链路已经稳定收口到：

```text
后端生成语义动作意图
-> 前端 TurnPlaybackSession 收口文本/音频/动作轮次
-> Orchestrator 负责起播软同步
-> ModelEngine 本地编译并执行
-> Completion Coordinator 负责播放完成回执与收尾
```

当前重点已经从“把链路跑通”转到结构收口：

1. 继续收口前端 Adapter / Turn Pipeline / Runtime Bridge 边界
2. 继续明确 session / segment 是播放事实来源
3. 结构稳定后，再继续校准真实模型上的动作体感与同步体验

## 最新进展

### Adapter（AstrBot 插件）

- V2 协议主链路稳定：`input.* / output.* / control.* / system.* / engine.*`
- 默认动作生成模式仍为 `inline_first`
  - 主请求注入 `<@anim {...}>` 契约
  - 主回复内优先提取 `engine.motion_intent.v2`
  - 提取失败时可回落到 reply 后动作生成
- 备选模式仍保留：
  - `split_after_reply`
- realtime 主路径产物为 `engine.motion_intent.v2`
- 后端不再长期承担执行 plan 编译；前端负责 `intent -> parameter_plan.v2 -> playback`
- `semantic_axis_profile` 仍由后端维护为 canonical source

### Frontend（Electron + Vue）

- 前端已经落地 `TurnPlaybackSession`：
  - `frontend/src/turn-playback/session.ts`
  - `frontend/src/turn-playback/selectors.ts`
  - `frontend/src/composables/useTurnPlaybackSessionStore.ts`
- 当前前端播放轮次真源已经从散装 pending/nonce 状态收口到 session + segment queue
- `message_id` 是 segment ID，同一条回复片段的文本、音频和动作写入同一个 `TurnPlaybackSegment`
- `useAdapterConnection` 负责把协议事件双向写入 session：
  - 文本
  - 音频
  - 动作
  - `turn_started / turn_finished / interrupt`
- `useTurnPlaybackOrchestrator` 已切到按 session 协作
  - 文本、音频、动作尽量一起起播
  - 动作晚到时先释放文本/音频，后续再补播动作
  - 无音频时按明确 absence 语义处理
- `usePlaybackCompletionCoordinator` 已切到按 session 协作
  - 后端输出队列关闭、本地播放完成、后端 turn 收口三层条件已分离
  - 当前职责边界为：

```text
control.synth_finished => 后端不会再追加新的 segment
synth_finished 已到且所有 segment 本地 settled => 前端发送 control.playback_finished
后端收到 playback_finished 后返回 control.turn_finished => 前端将 session 标记 completed 并清理上下文
```

注意：一个 user input 对应一个 turn，但一个 turn 内可以有多个 assistant output segment。`synth_finished` 是队列关闭信号，不是单条回复播放完成信号。

当前后端已经通过 turn 输出队列关闭点发送 `synth_finished`。后续不能再把它退化成单条音频生成完成信号。

- `useModelEngine` 仍保留“进入引擎后等待音频起播”的短兜底，但读取音频时序时优先读取 session
- `usePetRuntimeSnapshotPublisher` 已把 active session 摘要投影到桌面 bridge snapshot
- 当前前端自动化测试已覆盖：
  - `turnPlaybackOrchestratorCore`
  - `turnPlaybackSessionStore`
  - `playbackCompletionCoordinator`

### Dynamic Semantic Axis / Tooling

## 本轮已经明确成立的事情

1. 前端播放轮次已经有统一对象
   - 不再只是 scattered pending 字段拼起来的语义
   - 当前统一对象是 `TurnPlaybackSession -> TurnPlaybackSegment`
2. 文本、音频、动作的起播与收尾已经分层
   - Orchestrator 管开始
   - Completion Coordinator 管结束
3. `synth_finished`、`playback_finished` 与 `turn_finished` 的职责已经重新对齐
   - `synth_finished` 表示后端输出队列关闭
   - `playback_finished` 表示前端本地播放已完成
   - `turn_finished` 表示后端确认本轮收口
4. Session 状态已经能投影到 runtime snapshot
   - 当前至少可看到 active session id / phase / 部分 text-audio-motion-backend 摘要

## 仍然没完成的事情

- 还没有做到音素级口型 / 动作同步
- 还没有完成真实模型上的系统化动作体感验证
- 前端 UI 层仍缺少更高层级的联调 / 端到端自动化测试
- `DesktopRuntimeSnapshot` 仍偏运行时摘要，不是完整调试面板
- 结构方向文档里的一些“工具域进一步拆分”还没完全结束
- motion late routing 和调试投影还需要继续向 session/segment 事实来源收口

## 当前主要风险 / 仍需关注的点

### 1. 体感同步还只是软同步

当前已经做到：

- 同轮聚合
- 晚到动作短等待
- 无音频显式 absence
- 本地播放完成与后端 turn 收口分离

但还没有做到：

- 音素级同步
- 字幕逐词对齐
- 动作节奏逐帧耦合

### 2. Session 已经是播放真源，但调试可见性还不够厚

现在 bridge snapshot 里只有 active session 的摘要字段。

如果后续要继续排查复杂时序问题，建议补：

- release reason
- ack sent / awaiting turn_finished
- session 数量与最近终态 session 列表

### 3. 架构方向文档需要继续跟进现实代码

`后端主导数据边界与执行计划` 仍然是正确方向，但其中部分“当前偏差”已经被新代码消掉，后续需要继续同步。

   - 无动作
