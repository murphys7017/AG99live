# 前端适配器拆分与优化方案

本文描述前端适配器的拆分与优化方案。

这里的“适配器”指前端中负责连接后端 Adapter、处理协议收发、管理输入输出运行时副作用，并向上层运行时暴露稳定接口的模块集合。

当前重点不是改动作引擎，也不是整理动作库，而是先把动作引擎外部的协议和运行时入口收清楚。

## 1. 背景判断

当前前端适配器已经从单文件实现演进成多个小模块，但组合根仍然集中在：

```text
frontend/src/composables/useAdapterConnection.ts
```

它当前同时承担：

- WebSocket 连接生命周期
- 地址、偏好、连接状态
- 入站协议解析与分发
- 出站协议发送
- 文本 / 音频 release 队列
- 音频播放运行时
- 麦克风采集运行时
- PTT 状态
- history feature client
- motion tuning sample feature client
- semantic axis profile save
- model sync 消息转发
- session store 写入桥接
- UI history 和 statusMessage 投影

这说明当前适配器的方向是对的，但 facade 仍偏厚。继续在这个形态上直接做动作引擎，会让引擎被协议细节和 IO 状态牵住。

## 2. 目标

拆分目标：

```text
让 useAdapterConnection 退回“适配器 facade”，不再承担所有内部实现。
```

优化目标：

1. 数据协议和运行时副作用分开。
2. 出站消息统一走一个 outbound client。
3. 入站消息先归一化为内部事件，再由 runtime handler 写入状态。
4. 音频、麦克风、PTT 形成独立 runtime service。
5. feature client 独立管理 history、motion tuning、profile save。
6. 对动作引擎暴露稳定的、协议无关的输入。
7. 对上层 `usePetDesktopController` 保持短期 API 稳定，降低迁移风险。

## 3. 非目标

当前阶段不做：

- 不重写动作引擎内部结构。
- 不重构动作库和调参面板。
- 不改 Adapter V2 协议语义。
- 不改变 `TurnPlaybackSession` 的事实来源地位。
- 不做大规模文件搬迁式重构。
- 不追求一次性拆完 `useAdapterConnection.ts`。

## 4. 目标分层

建议把前端适配器分为四层：

```text
Adapter Facade
Adapter Runtime
Adapter Data
Adapter Core
```

### 4.1 Adapter Facade

代表目标：

```text
useAdapterConnection.ts
```

职责：

- 对 `usePetDesktopController` 暴露稳定 API。
- 组合 data/runtime/core services。
- 暴露只读状态 projection。
- 维持短期兼容，避免上层大面积改动。

不负责：

- 直接处理 WebSocket raw message。
- 直接播放音频。
- 直接采集麦克风。
- 直接实现 feature protocol。
- 直接拼复杂 dispatch deps。

### 4.2 Adapter Core

职责：

- WebSocket transport。
- 地址候选。
- envelope 构造。
- protocol version 校验。
- inbound raw message 解析。
- outbound send 基础能力。

当前相关文件：

| 文件 | 当前职责 |
| --- | --- |
| `transport.ts` | WebSocket 打开和事件回调 |
| `address.ts` | 地址标准化、候选地址、错误消息 |
| `envelope.ts` | envelope 构造和 message id |
| `inboundProtocol.ts` | 入站协议 envelope 校验 |
| `protocolMessageTypes.ts` | 协议消息类型常量 |
| `preferences.ts` | 连接地址和相关偏好 |

目标优化：

- 把 socket 当前状态和 send 能力封装为 `AdapterSocketClient`。
- 让 feature client 不再直接依赖完整 facade，只依赖 `sendEnvelope` / `buildEnvelope`。
- 减少散落的协议 type 字符串。

### 4.3 Adapter Data

职责：

- 协议消息到内部数据事件的归一化。
- 模型同步。
- 历史记录。
- semantic profile 保存。
- motion tuning samples 同步。
- resource URL 重写。

当前相关文件：

| 文件 | 当前职责 |
| --- | --- |
| `inboundEvents.ts` | envelope -> inbound event |
| `inboundPayloads.ts` | payload validation |
| `inboundDispatcher.ts` | 入站事件应用到 session/model/history/motion tuning |
| `modelSyncRewrite.ts` | ws/http URL 重写 |
| `historyPayload.ts` | history payload normalize |
| `motionTuningPayload.ts` | motion tuning sample normalize |
| `useAdapterHistory.ts` | history feature client |
| `useAdapterMotionTuning.ts` | motion tuning feature client |
| `useModelSync.ts` | 当前模型能力 store |

目标优化：

- 把 `inboundDispatcher.ts` 进一步拆成 feature handlers。
- 将 model/history/profile/motion tuning 的数据写入从运行时 IO 中分离。
- 让 data layer 输出更稳定的 `NormalizedAdapterEvent` 或按 feature 分组的 handler。

### 4.4 Adapter Runtime

职责：

- 音频播放运行时。
- 麦克风采集运行时。
- PTT 状态和输入段 identity。
- 文本/音频 release queue。
- playback_finished 回执触发所需的 adapter 端能力。
- connection reset 时清理运行时副作用。

当前相关文件：

| 文件 | 当前职责 |
| --- | --- |
| `audioPlayback.ts` | HTMLAudioElement 播放运行时 |
| `audioPlaybackActions.ts` | 播放音频并回写 adapter/session 状态 |
| `adapterAudioBridge.ts` | adapter audio state 与 session store 桥接 |
| `microphoneCapture.ts` | 麦克风采集 |
| `microphoneDevices.ts` | 麦克风设备枚举 |
| `playbackReleaseQueue.ts` | text/audio pending release |
| `connectionRuntimeState.ts` | 连接关闭时清理运行时状态 |
| `orchestrationIds.ts` | orchestration id 相关工具 |

目标优化：

- 把 microphone capture 从 `useAdapterConnection.ts` 中抽成 `AdapterMicrophoneRuntime`。
- 把 audio release/playback 从 `useAdapterConnection.ts` 中抽成 `AdapterAudioRuntime`。
- 把 PTT 运行时和 Electron IPC/keyboard 入口关系理清。
- 让 turn playback pipeline 只依赖窄 port，不依赖整个 adapter。

## 7. 优化点

### 7.1 状态拆分

当前 `useAdapterConnection.ts` 的 `state` 同时包含：

- 连接状态
- UI status
- 当前 turn identity
- 音频播放状态
- 麦克风状态
- history 状态
- motion tuning 状态
- profile save result
- pending text/audio queues

建议拆成内部状态域：

```text
connectionState
runtimeIoState
playbackReleaseState
featureDataState
uiProjectionState
```

短期可以不立刻拆 reactive object，但文档和新模块 API 应按这些域设计，避免继续加字段到一个大 state。

### 7.2 出站消息统一

当前出站动作大多集中在 `outboundActions.ts`，并已通过 `outboundClient.ts` 统一完成 socket 状态检查、envelope 构造和 JSON 发送。

`useAdapterConnection.ts` 仍负责装配 socket 与 `buildMessageEnvelope`，但 action 层已经不再直接持有这些细节。

建议形成：

```ts
interface AdapterOutboundClient {
  send(type: string, payload: unknown, turnId?: string | null, orchestrationId?: string | null): boolean;
  sendText(text: string): Promise<boolean>;
  sendPlaybackFinished(...): void;
  sendMotionPreview(...): boolean;
}
```

收益：

- feature clients 不需要知道 socket。
- runtime services 不需要自己 JSON.stringify。
- 后续协议打点、失败统计、重试策略只加一处。

### 7.3 入站分发分域

当前 `inboundDispatcher.ts` 已经比早期清楚，但仍同时处理：

- server info
- model sync
- history
- motion tuning
- output text/audio/image/transcription
- turn started/finished/interrupt
- motion payload
- protocol error

建议拆为：

```text
adapterDataDispatcher
adapterPlaybackDispatcher
adapterRuntimeDispatcher
adapterFeatureDispatcher
```

短期第一步可以只抽出 feature handlers：

- history handler
- motion tuning handler
- profile save handler
- model sync handler

### 7.4 音频运行时独立

当前音频运行时跨越：

- `audioPlayback.ts`
- `audioPlaybackActions.ts`
- `adapterAudioBridge.ts`
- `useAdapterConnection.ts` 内的 pending queue/release 函数

建议形成：

```ts
interface AdapterAudioRuntime {
  queueAudio(messageId, url, turnId, orchestrationId): void;
  releaseAudio(messageId, turnId, orchestrationId): boolean;
  stop(reason?: string): void;
  markTerminal(...): void;
}
```

收益：

- `useTurnPlaybackOrchestrator` 对 audio 的依赖可以更窄。
- interrupt/reset/audio terminal 逻辑更集中。
- 后续做音频时序调试会容易很多。

### 7.5 麦克风运行时独立

当前麦克风逻辑在 `useAdapterConnection.ts` 内包含：

- capture start/stop
- device change restart
- input orchestration id 分配
- socket bufferedAmount 防护
- dropped 标记
- PTT origin
- `input.raw_audio_data` / `input.mic_audio_end` 发送

建议形成：

```ts
interface AdapterMicrophoneRuntime {
  start(origin): Promise<boolean>;
  stop(reason): Promise<boolean>;
  toggle(): Promise<boolean>;
  refreshDevices(options?): Promise<void>;
  setDevice(deviceId): void;
}
```

收益：

- PTT 和普通麦克风共用一套 capture runtime。
- socket 积压、dropped、input orchestration id 的语义集中维护。
- 以后接入 VAD 或分段录音更顺。

### 7.6 Facade API 分组

当前 `useAdapterConnection()` 返回对象是一组平铺函数。

建议逐步改成内部按域组织，外部短期兼容：

```ts
adapter.connection.connect()
adapter.input.sendText()
adapter.input.microphone.start()
adapter.playback.releaseAudio()
adapter.features.history.load()
adapter.features.motionTuning.save()
```

短期仍保留：

```ts
adapter.connect()
adapter.sendText()
adapter.releaseAudioForPlayback()
```

这样 `usePetDesktopController.ts` 不需要第一时间大改。

- Phase 5 已开始并完成第一刀：已新增 `frontend/src/adapter-connection/outbound/outboundClient.ts`，`outbound/outboundActions.ts` 已改为通过 outbound client 统一发送协议消息。

当前下一步：

```text
Phase 5 第二刀：迁移 feature clients 到 AdapterOutboundClient
```

原因：

- `outbound/outboundActions.ts` 已经不再直接碰 socket/envelope/stringify。
- `useAdapterHistory.ts`、`useAdapterMotionTuning.ts` 等 feature client 仍各自接收 `getSocket` / `buildMessageEnvelope`，后续容易继续复制发送细节。
- 下一步把 feature clients 也迁到 outbound client，可以继续收窄 `useAdapterConnection.ts` 的发送依赖。
- 出站端口收窄后，动作引擎以后只需要面对稳定输入，而不是 WebSocket/envelope/JSON 细节。

本阶段仍不进入动作引擎内部，也不调整动作库和调参面板。

### Phase 2：抽 AdapterMicrophoneRuntime

目标：

- 将 `startMicrophoneCapture` / `stopMicrophoneCapture` / `toggleMicrophoneCapture` / device restart 从 facade 抽出。
- `useAdapterConnection.ts` 只做转发。

建议原因：

- 麦克风逻辑相对独立。
- 它当前占据 facade 大量逻辑。
- 可以明显减少 `useAdapterConnection.ts` 体积。

验收：

- PTT 相关测试通过。
- `input.raw_audio_data` 和 `input.mic_audio_end` orchestration id 语义不变。
- device_change、dropped、bufferedAmount 防护不变。

当前结果：

- 新增 `adapter-connection/runtime/microphoneRuntime.ts`，集中维护麦克风启动/停止、设备切换重启、PTT origin、输入段 `input:*` orchestration id、socket bufferedAmount 防护和 dropped 标记。
- `useAdapterConnection.ts` 保持原有外部 API，包括 `setMicrophoneDevice`、`refreshMicrophoneDevices`、`toggleMicrophoneCapture`、`setPttMode`、`startPttCapture`、`stopPttCapture`。
- 已通过 `npm run test:adapter-connection` 和 `npm run typecheck`。

### Phase 3：抽 AdapterAudioRuntime

目标：

- 将 pending audio queue、release audio、audio playback terminal、stop audio 归入音频 runtime。
- Turn Playback Pipeline 只依赖 `PlaybackReleasePort`。

验收：

- segment audio started/terminal 语义不变。
- interrupt 时 audio terminal failed 语义不变。

当前结果：

- 音频播放、pending audio、missing audio 标记、interrupt terminal 逻辑已从 facade 私有函数中移出。

### Phase 4：拆 inboundDispatcher feature handlers

- `inboundDispatcher.ts` 聚焦 turn/playback/runtime event。

### Phase 5：抽 AdapterOutboundClient

目标：

- 把 socket send、buildEnvelope、send action 包成独立 outbound client。
- `useAdapterConnection.ts` 不再直接持有出站发送细节。

当前结果：

- 新增 `frontend/src/adapter-connection/outbound/outboundClient.ts`。
- `AdapterOutboundClient` 当前提供 `canSend()` 和 `send(type, payload, turnId, orchestrationId)`。
- `outbound/outboundActions.ts` 已通过 outbound client 发送 `input.text`、`control.interrupt`、`system.semantic_axis_profile_save`、`engine.motion_intent` / `engine.motion_plan`、`control.playback_finished`。
- `useAdapterConnection.ts` 仍负责装配 outbound client，但 action 层不再直接持有 socket 或 build envelope。
- 已补充 `useAdapterConnection.test.ts` 出站 envelope 断言，覆盖 `sendText` 和 `sendMotionPayloadPreview`。

建议改动：

- 已在 client 中统一封装：
  - `getSocket`
  - `buildEnvelope`
  - `socket.readyState` 检查
  - `JSON.stringify`
  - 基础发送失败返回
- 已让 `outbound/outboundActions.ts` 优先依赖 outbound client，而不是直接依赖完整 facade context。
- 后续再逐步让 `useAdapterHistory.ts`、`useAdapterMotionTuning.ts` 等 feature 发送也走同一个 outbound port。
- 保持 `useAdapterConnection()` 的外部 API 不变。

建议接口草案：

```ts
interface AdapterOutboundClient {
  send<TPayload>(
    type: string,
    payload: TPayload,
    turnId?: string | null,
    orchestrationId?: string | null,
  ): boolean;
  canSend(): boolean;
}
```

短期不要一次性把所有 feature client 都迁完。第一刀已完成：只让 `outbound/outboundActions.ts` 使用 client。后续再迁 history / motion tuning。

验收：

- 外部 `sendText`、`interruptCurrentTurn`、`sendMotionPayloadPreview` 等 API 不变。
- outbound client 可作为 history/motion tuning 的统一发送端口。
- `npm run typecheck`
- `npm run test:adapter-connection`
- 必要时补跑 `npm test`

### Phase 6：收敛 facade return API

目标：

- 保留兼容 API。
- 内部新增分组 API。
- `usePetDesktopController.ts` 可按需逐步迁移到分组 API。

验收：

- 外部窗口 command 行为不变。
- settings/history/action lab/profile editor 均仍通过 bridge command 工作。

## 9. 建议下一刀

建议下一刀做：

```text
迁移 useAdapterHistory / useAdapterMotionTuning 到 AdapterOutboundClient
```

理由：

- `outbound/outboundActions.ts` 已经完成第一步迁移。
- history / motion tuning 仍各自拿 `getSocket` 和 `buildMessageEnvelope`，这是下一个重复点。
- 迁完 feature clients 后，`useAdapterConnection.ts` 的出站发送装配会更窄。
- 这一步仍然不进入动作引擎内部，风险比直接做动作引擎低。

下一刀不要做：

- 不改 `useAdapterConnection()` 外部返回 API。
- 不把 facade return API 分组和 feature client 迁移混在一起。
- 不碰动作库和动作引擎内部。
- 不改变 Adapter V2 协议语义。

## 10. 风险与保护

主要风险：

- 拆 runtime 时改变 session/audio terminal 语义。
- 拆 microphone 时破坏 `input:*` orchestration id。
- 拆 outbound 时造成某些 command 没有发送。
- 拆 dispatcher 时引入 stale turn 或 message_id 归组错误。

保护策略：

1. 每个 phase 都保持外部 API 不变。
2. 每个 phase 都只移动一个职责域。
3. 每个 phase 都跑 `npm run typecheck` 和 `npm test`。
4. 涉及麦克风、音频、turn lifecycle 时优先补或保留对应测试。
5. 不做顺手格式化和大规模目录移动。

## 11. 完成后的理想关系

重构完成后，主路径应接近：

```text
usePetDesktopController
-> useAdapterConnection facade
   -> AdapterCore socket/outbound
   -> AdapterData inbound/features/model/history/profile/motion-tuning
   -> AdapterRuntime audio/microphone/PTT/release queues
-> TurnPlaybackSessionStore
-> TurnPlaybackOrchestrator
-> MotionEngine
```

动作引擎看到的世界应该是：

```text
normalized motion payload
current turn/audio timing context
play request
```

而不是：

```text
WebSocket envelope
adapter pending queue
socket url rewrite
history/motion tuning/profile feature state
```

这就是本次适配器拆分最核心的优化方向。
