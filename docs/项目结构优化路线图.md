# 项目结构优化路线图

快照日期：2026-05-12

本文是当前下一阶段的结构优化入口。

当前策略是：

```text
先把项目结构边界收稳
再继续做动作引擎细节
```

原因是文本、音频、动作主链路已经基本跑通，但前后端仍有几处边界没有完全硬化。如果此时继续堆动作能力，复杂度会再次压回 `useAdapterConnection`、`TurnCoordinator` 和 `ModelEngine`。

## 1. 当前结构判断

当前项目已经形成两个核心运行域：

```text
AstrBot Adapter
  -> 协议接入、turn 生命周期、文本/音频/动作输出

Electron Frontend
  -> TurnPlaybackSession、segment queue、起播编排、动作执行、播放完成回执
```

前端已经从旧的散装状态推进到：

```text
TurnPlaybackSession
  -> 多个 TurnPlaybackSegment
      -> text / audio / motion
```

这是一个正确方向。

当前最需要继续优化的不是动作参数算法，而是：

- 后端输出队列关闭语义
- 前端协议接入层边界
- 前端播放管线对 Adapter 的依赖面
- 运行时 snapshot 和工具域投影边界
- 前后端协议契约治理

## 2. 当前最终语义

当前统一语义如下：

```text
一个用户输入
-> 一个 turn
-> 多个 assistant output segment
-> 每个 segment 绑定 text / audio / motion
```

三个结束信号必须拆开：

```text
control.synth_finished
= 后端输出队列关闭
= 当前 turn 不会再追加新的 output.* / engine.motion_* segment

control.playback_finished
= 前端本地播放完成
= synth_finished 已到，且所有 segment 都 settled

control.turn_finished
= 后端确认整轮闭环收口
= 后端收到 playback_finished 后发出
```

因此：

- `synth_finished` 不是某条音频生成完成。
- `synth_finished` 不是整轮完成。
- 音频播放结束也不是整轮完成。
- 前端只有在队列关闭且所有 segment 本地 settled 后，才发送 `playback_finished`。
- 前端收到 `turn_finished` 后，才把 session 标记为 `completed`。

## 3. 第一优先级：后端输出队列语义收口

### 当前问题

文档和前端当前把 `control.synth_finished` 解释为：

```text
当前 turn 的输出队列关闭
```

但后端现状中，`TurnCoordinator.emit_message_chain()` 会在发送某条 `output.audio` 后发 `control.synth_finished`。

如果 AstrBot 在同一 turn 内多次调用 `emit_message_chain()`，这会让 `synth_finished` 退化成：

```text
当前 audio segment 已发送
```

这和当前协议语义不一致。

### 目标

后端需要有一个明确的 turn 输出队列关闭点。

只有当后端确认当前 turn 不会再追加新的：

- `output.text`
- `output.audio`
- `engine.motion_intent`
- `engine.motion_plan`

才发送：

```text
control.synth_finished
```

### 验收

- 单 turn 多 segment 时，前端不会在后续 segment 到达前收到 `synth_finished`。
- 前端收到 `synth_finished` 后，可以安全认为当前 session 的 segment 集合完整。
- 后端收到前端 `playback_finished` 后，才发送 `turn_finished`。

## 4. 第二优先级：收窄前端播放管线端口

### 当前问题

`useTurnPlaybackOrchestrator` 和 `usePlaybackCompletionCoordinator` 仍然直接依赖完整 adapter 返回对象。

这让播放管线可以看到太多 adapter 细节。

### 目标

把依赖收成窄端口：

| Port | 调用方 | 职责 |
| --- | --- | --- |
| `PlaybackReleasePort` | Orchestrator | release text / audio / motion |
| `PlaybackAckPort` | Completion Coordinator | 发送 `control.playback_finished` |
| `MotionPlaybackPort` | ModelEngine | 执行动作参数计划 |
| `RuntimeProjectionPort` | Snapshot Publisher | 获取模块摘要投影 |

### 验收

- Orchestrator 不再拿完整 adapter。
- Completion Coordinator 不再拿完整 adapter。
- Adapter 只通过端口暴露播放管线需要的最小能力。

## 5. 第三优先级：继续拆薄 `useAdapterConnection`

### 当前判断

`useAdapterConnection.ts` 已经完成了重要收口：

- inbound protocol parser
- inbound event mapper
- payload runtime validation
- segment-aware session 写入

但它仍承担：

- WebSocket 连接管理
- dispatcher
- 音频 bridge
- 文本 / 音频 pending release facade
- history client
- motion tuning client
- profile save client
- UI 状态投影

### 目标

继续收成：

```text
AdapterConnectionTransport
AdapterInboundDispatcher
AdapterOutboundClient
AdapterAudioBridge
AdapterRuntimeFacade
Feature clients
```

### 验收

- `useAdapterConnection` 更像组合 facade。
- feature client 不再向主文件继续膨胀。
- 文本/音频 release 队列从协议接入逻辑中分离出来。

## 6. 第四优先级：明确音频事实来源

### 当前问题

音频状态现在同时存在于：

- adapter state
- `TurnPlaybackSegment.audio`

这不是立即错误，但长期容易产生双真源。

### 推荐方向

以：

```text
TurnPlaybackSegment.audio
```

作为事实来源。

adapter state 里的 audio 字段保留为：

- UI 投影
- 兼容字段
- 最近播放摘要

### 验收

- Completion Coordinator 只看 session segment。
- Orchestrator 只看 session segment。
- adapter audio fields 不再参与完成判定。

## 7. 第五优先级：协议契约治理

### 当前问题

前后端协议仍是双份维护：

- 后端：`protocol/constants.py`、`protocol/parser.py`、`protocol/builder.py`
- 前端：`types/protocol.ts`、`adapter-connection/protocolMessageTypes.ts`、`inboundPayloads.ts`

短期已经能工作，但长期会增加协议漂移风险。

### 短期目标

- 继续集中前端 message type 字符串。
- 后端 `parse_inbound_message` 应严格校验 `version === "v2"`，不要默认吞掉缺失版本。
- 为 `control.synth_finished / playback_finished / turn_finished` 建立明确测试。

### 中期目标

考虑用协议清单或 JSON Schema 生成 Python / TypeScript 契约。

## 8. 暂缓动作引擎细节

当前暂缓：

- 新动作参数算法
- 更复杂的动作引擎库
- 音素级口型同步
- 帧级 motion mixer

这些都应该等结构边界更稳后再做。

否则动作能力会继续把复杂度压到还没有完全收口的模块上。

## 9. 建议执行顺序

```text
1. 修正后端 synth_finished 发送点
2. 补后端多 segment / playback_finished / turn_finished 测试
3. 给前端播放管线抽窄端口
4. 继续拆薄 useAdapterConnection
5. 明确 audio session 真源
6. 补协议治理
7. 回到动作引擎细节
```

## 10. 当前不建议做的事

- 不建议继续扩大 `TurnCoordinator`。
- 不建议继续扩大 `useAdapterConnection`。
- 不建议为了减少文件行数做机械拆分。
- 不建议在 `synth_finished` 语义未闭合前继续加复杂动作同步。
- 不建议把动作引擎做成新的跨域中台。

## 11. 结构目标

理想结构是：

```text
边界层负责防御
协议层负责契约
Session 负责事实
Orchestrator 负责起播
Completion Coordinator 负责结束
ModelEngine 负责动作编译和调度
Avatar Runtime 负责执行
工具窗口只通过 command / snapshot 协作
```

做到这里之后，再继续做动作引擎细节会更稳。
