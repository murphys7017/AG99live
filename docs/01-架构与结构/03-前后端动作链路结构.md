# 前后端动作链路结构

本文描述当前正式动作与播放链路。旧的 `output.text / output.audio / engine.motion_intent` 分片聚合、独立 performance-curve patch 和前端 late-motion 缓冲已移除。

## 1. 总体链路

```text
Persona Runtime
  -> spoken_reply + effect_calls[ag99live.motion]
  -> AG99 result contributor
  -> engine.motion_intent.v4
  -> 后端 PendingOutputSegment.motion
  -> output.segment.v3.motion
  -> 前端严格归一化
  -> SessionStore 原子提交
  -> TurnPlaybackOrchestrator
  -> PlaybackTimelineRuntime
  -> ModelEngine
  -> engine.parameter_plan.v2
  -> Live2D WebSDK
```

主模型在同一次回复中生成文本和动作语义，Adapter 负责把 Persona Effect 参数转成可校验的 motion intent。前端 ModelEngine 才拥有模型相关采样、关系约束和参数计划编译。

## 2. Persona Effect 与兼容入口

### 2.1 主入口

主入口读取：

```text
view.effect_calls
  -> name = ag99live.motion
```

当前 Persona Effect 输出九级 `axis_levels: -4..4`、`intent_tags`、可选资源 ID 和 duration hint。它不输出连续 Live2D 参数，也不决定逐帧曲线。

### 2.2 官方兼容入口

只有 Persona Effect 注入函数不存在时，Prompt 才允许官方 `<@anim ...>` 形式。Adapter 在后端解析该标签，并把结果写入同一个原子段的 motion slot。

`<@anim>`：

- 是 AstrBot 官方原版环境的输入兼容。
- 不是 Persona Effect 校验失败后的 fallback。
- 不会在前端形成第二条动作播放链。
- 不允许与有效 Persona Effect motion 同时竞争。

## 3. 后端段聚合

AstrBot 可能为同一回复产生多个物理组件：

- Plain 可见正文。
- Record WAV 与 canonical assistant text 候选。
- 图片。
- motion client object。
- result contributor 登记、并在 TTS `generating` 状态到达时启动的可选 performance curve 请求标识。

`TurnCoordinator` 以 `turn_id + message_id` 获取 `PendingOutputSegment`：

```text
Plain.content        -> segment.text
Record.file          -> segment.audio_path
Record.text          -> segment.text（与 Plain / semantic text 必须一致）
motion client object -> segment.motion_payload
Picture              -> segment.images
TTS request id owned by curve runtime -> segment.performance_curve_request_id
```

曲线 Provider 从只读 `on_tts_state_changed` 监听器收到 `generating` 后启动，并直接使用该次 `tts_request_id` 作为请求身份。没有进入 TTS 的回复不创建曲线请求。段出站只同步读取已经 ready 的结果；未 ready 时取消请求并
发送原 motion，不等待、不补默认曲线、也不在 segment 之后发送 patch。

冲突处理是 fail-visible：

- 同一字段出现两个不同值：报冲突。
- 同一段出现多个音频文件：报错。
- 多个 motion object：报错。
- motion schema 或资源非法：报错。
- WebSocket 发送失败：保留未发送段并报错。

曲线 attached/skipped 记录、上一动作 Prompt snapshot 和 Motion Lab assistant output 都只在 `output.segment` WebSocket 发送成功后提交；发送失败的段不会推进这些状态。

输出队列关闭时，后端先发送每个完整 `output.segment`，成功后才从 pending map 删除；全部段发送成功后再发送 `control.synth_finished`。

## 4. 原子外部协议

正式回复只使用：

```text
output.segment
payload.schema_version = output.segment.v3
```

每段必须完整声明：

```text
text: present | absent | failed
audio: present | absent | failed
motion: present | absent | failed
images: string[]
```

表演曲线若已就绪，只存在于 `motion.payload.performance_curve_hint`，不再拥有 segment 顶层副本。

正式 turn 不再发送：

- `output.text`
- `output.audio`
- `output.image`
- 独立 `engine.motion_intent`
- 独立 `engine.performance_curve_hint`

独立 `engine.*` 只属于动作实验室和手动预览。

## 5. 前端接收边界

前端在任何状态写入前完成：

1. 信封版本和身份校验。
2. tagged slot 结构校验。
3. motion `message_type` 与 payload schema 一致性校验。
4. 音频 URL 重写与非空校验。
5. motion payload 领域归一化。
5. 重复 `turn_id + message_id` 检查。
6. session 阶段与 `synth_finished` 边界检查。

通过后调用一次：

```text
SessionStore.commitOutputSegment(turnId, messageId, material)
```

该函数在局部构造完整 segment，最后一次性放入 session map。提交成功前不会修改文本队列或音频队列。

`control.synth_finished` 到达时，SessionStore 会断言所有内部段已经完整解析。发现 idle slot 时直接报告一致性错误，不自动补成 `absent`。

## 6. Release 与执行

`TurnPlaybackOrchestrator` 只观察 SessionStore：

- 不保存第二份 slot readiness。
- 不等待后续分片。
- 不运行 text/audio/motion 补齐定时器。
- 每个完整段只创建一个 `SegmentJob`。

`PlaybackTimelineRuntime` 在构造时获得固定 execution ports，并拥有：

- text sink release。
- audio sink 与真实时钟。
- lip-sync sink。
- required motion sink。
- sink started / terminal 状态。

App composition root 直接创建唯一的 `PlaybackTimelineRuntime` 和 `BrowserAudioTimelineSink`。Adapter 只提供 queued segment、SessionStore projection 与音频状态桥接 ports；它不接收 Timeline factory，也不拥有 Timeline 实例创建权。

有音频时，Timeline 在 Audio metadata 给出真实 duration 后预编译语义动作或内部 `speech_only` request；Audio `playing` 事件携带绑定本段 AudioElement 的时钟，并立即启动已准备计划。禁止从全局 active audio element 反查时钟。动作自身的入场时机由 performance curve / parameter plan 决定，不再叠加固定延迟。audio 明确 `absent` 时才允许 synthetic motion-only timeline；audio `failed` 时不允许转成 motion-only。

## 7. ModelEngine 与 WebSDK

ModelEngine 的输入是归一化 motion intent 和 matched timeline snapshot。主要阶段：

```text
intent validation
  -> axis level sampling
  -> relation graph
  -> resource policy
  -> timing
  -> speech gesture track
  -> parameter_plan.v2
```

ModelEngine 负责：

- 九级锚点内的确定性采样。
- profile revision 校验。
- 轴关系图与硬约束。
- expression / motion resource 冲突。
- speech gesture 规划。
- 在起播前根据真实音频总时长生成 timing；晚到的显式非音频路径才使用自身时钟语义。

Live2D WebSDK 负责：

- 逐帧曲线求值。
- velocity / acceleration 限制。
- speech gesture delay。
- lip-sync 和 speech energy 写入。
- Cubism 参数、physics 和最终 clamp。

同一类调整只能有一个主要所有者，避免 Adapter、ModelEngine 和 WebSDK 重复修正同一轴。

## 8. 终态

本地段 settled 要求：

- text 已 delivered。
- audio 为 `completed | failed | absent`。
- motion 为 `completed | failed | absent`。

全部段 settled 且收到 `synth_finished` 后，CompletionCoordinator 发送 `control.playback_finished`。后端随后发送 `control.turn_finished`，前端 session 才进入 completed。

零 sink 段允许：

```text
collecting -> ready -> settling -> completed
```

正常播放段使用：

```text
collecting -> ready -> playing -> settling -> completed
```

## 9. 关键文件

- `middleware/interaction_motion.py`：Persona Effect 与 prompt/result contributor。
- `runtime/output_segment.py`：后端原子段缓冲。
- `runtime/turn_coordinator.py`：聚合、发送和 turn 控制。
- `adapter-connection/inbound/`：前端严格协议入口。
- `turn-playback/useTurnPlaybackSessionStore.ts`：唯一 segment 事实源。
- `turn-playback/useTurnPlaybackOrchestrator.ts`：SegmentJob release。
- `playback-timeline/playbackTimelineRuntime.ts`：统一时钟和 sinks。
- `model-engine/`：动作编译。
- `live2d/WebSDK/src/lappmodel.ts`：逐帧执行。
