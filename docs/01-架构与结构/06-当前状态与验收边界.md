# 当前状态与验收边界

截至 **2026 年 10 月 20 日**，本文区分已经进入当前源码的能力和仍需真实运行确认的行为。协议版本以 `protocol/schema_manifest.json` 为唯一事实来源；历史实施过程与被删除方案不在此重复维护。

## 已进入源码

- AG99 Adapter 的文本、流式麦克风、图片和平台事件入口。
- 两种动作来源：Persona Effect；独立 Provider 为每个非空 Persona speech 段生成动作，并按段索引关联 TTS/输出段。段流关闭时在 Persona 结果回调后按段生成；OLV 段流与 Core 能力检查通过时，在对应 speech 段到达后启动动作请求。路径使用 `turn_id`、`persona_result_id` 和段索引关联动作与 TTS。
- `output.segment.v6` 原子段、同段后到动作 `output.segment_motion`、`engine.motion_intent.v4` 和 `engine.parameter_plan.v3`。Schema 版本见 manifest。
- OLV M2 增量文本、二进制 PCM 和动作事件已接通有界队列、累计音频信用、取消与终态；当前实现仅覆盖 immediate Persona，委派后的 Core-final 仍走完整结果路径。
- 轻量预动作由有效 ASR 文本触发，使用独立短动作请求并复用 ModelEngine；失败不阻塞正式对话。尚无真实 Provider、扬声器和 Live2D 首动作现场验收。
- 桌面大范围变化观察使用分块 SSIM 与颜色差进行纯数学比较；对话期间暂停，输入可撤销旧观察事实。
- 返回电脑互动观察锁屏/休眠与系统输入空闲时长，确认后向 Personal Runtime 提交一次短期事实；默认关闭，不能据此断言用户身体离开。
- SessionStore、PlaybackTimeline、ModelEngine、ActiveParameterMixer 和 Live2D runtime 的单条播放路径。
- Profile Editor、Motion Lab、模型扫描、动作资源预检与语音随动资料。
- Windows 原生麦克风采集、全局 PTT、透明宠物窗口和多窗口桥接。
- Windows Spout2 Sender `AG99live.Live2D`，发布绘制后的预乘 Alpha Live2D canvas。
- 独立的 VTube Studio 发现、采样、SQLite 录制、查询和删除 CLI。

## 仍需运行验收

以下结论不能只从源码或单元边界检查得出：

| 场景 | 需要确认的结果 |
| --- | --- |
| AG99 与 TTS | 多逻辑消息按 `sequence` 播放，物理发送失败不会被当作逻辑消息完成。 |
| Persona 分段动作 | 多段/即时与最终 Persona 结果、动作 Provider 超时、TTS 失败/迟到、重复身份和中断时，动作不串段，Core finalizer 与输出段能正确收口。 |
| 首段播放 | 首个音节、字幕、口型和参数动作没有可感知错位或截断。 |
| 中断与切换 | PTT、VAD、模型替换、设备切换和断线后没有残留音频、口型或动作所有权。 |
| Motion Lab | 真实输入、编译诊断、计划和终态能按同一段追溯。 |
| Spout2 与 OBS | 输出透明度、边缘合成、帧率、Sender 异常和桌面端重启恢复符合直播使用要求。 |
| VTube Studio 录制 | 20 Hz/30 Hz 的 RTT、抖动、模型切换和 tracking 状态能在目标机器上得到可用记录。 |
| M2 增量输出 | 真实 Provider 到桌面首采样、音频听感、口型、动作交接、信用回执与断连清理。 |
| 轻量预动作 | ASR 后首个合法动作被真实 Live2D 接纳的延迟、正式动作接管及用户打断。 |
| 主动桌面互动 | 大范围变化与返回事件在真实系统事件下的误报/漏报、Personal Policy 决策和实际语音/动作。 |

## 静态检查

当前最小契约检查：

```powershell
python scripts/check_protocol_schema_manifest.py

cd frontend
npm run typecheck
```

VTube Studio 录制器的测试在其目录内运行：

```powershell
cd vts-data-recorder
python -m pytest
```

这些检查分别证明清单、类型或本地存储边界符合预期。它们不替代完整桌面环境中的运行验收。

桌面交互的配置、默认关闭状态和加载要求见 [AG99live Adapter README](../../astrbot_plugin_ag99live_adapter/README.md)；算法与规则见 [桌面变化观察计划](../desktop-observation-plan.md) 和 [返回电脑互动计划](../desktop-return-plan.md)。

## 当前非目标

- 不把 AG99live 定位成独立于 AG99 的桌面客户端；它是 AG99 的身体运行时。AG99 桌面主应用的统一入口、配置和管理体验仍需在 AG99 侧逐步形成。

- 不新增与 AG99 平行的对话队列、动作播放器或播放时钟。
- 不让大模型输出模型参数 ID、文件路径或逐帧参数数组。
- 不用默认姿态、旧协议或宽松解析掩盖非法动作。
- 不把可选 performance curve 变成 TTS 或基础播放的前置条件。
- 不把 Cubism Physics 并入 AG99 的语义参数处理。
