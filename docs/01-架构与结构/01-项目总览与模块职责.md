# 项目总览与模块职责

本文是 AG99live 的长期维护型结构总览文档，合并了仓库结构、模块职责、依赖方向和维护规则。

目标：稳定回答下面这些问题：

1. 这个项目当前有哪些一级目录和一级模块
2. 每个模块负责什么，不负责什么
3. 模块之间的大致依赖方向是什么
4. 后续重构时，应该优先把变更落在哪个模块

## 1. 项目定位

AG99live 是一个**桌面虚拟宠物（桌宠）实时交互系统**，由前端 Electron 桌面应用 + 后端 AstrBot 插件适配器组成，通过 WebSocket 协议通信。

核心数据流：

```
用户输入（文本/语音）
  → 前端 Electron 应用
    → WebSocket 发送到后端
      → AstrBot 适配器协调 AI 模型
        → 返回文本回复 + 音频 + 动作指令
          → 前端播放：文字显示 + 音频播放 + Live2D 模型动作渲染
```

## 2. 仓库目录结构

```text
AG99live/
  .ai/                          # AI 代理治理入口和状态文件
  analysis/                     # 分析材料、实验或临时研究产物
  astrbot_plugin_ag99live_adapter/  # 后端 AstrBot 适配器、运行时、协议和动作服务
  docs/                         # 架构、协议、设计文档
  frontend/                     # Electron + Vue 前端桌宠运行时和工具窗口
  tools/                        # 仓库级开发辅助脚本和校验工具
```

## 3. 系统总体分块

从职责上看，项目分为四个大系统：

```text
前端桌宠运行时
后端适配器与服务
动作与模型能力体系
文档与治理体系
```

更贴近数据流的表达：

```text
用户 / 辅助窗口
  → 前端运行时
    → 后端适配器
      → 模型与动作服务
        → 前端回放与渲染
```

## 4. 前端架构

前端位于 `frontend/`，是桌宠系统的运行时核心。当前建议理解为 **9 个一级模块 + 2 个横切层**。

### 4.1 模块总览

```text
桌面宿主           → Electron 窗口管理
多窗口桥接         → 窗口间状态同步与命令转发
主控制器           → 主窗口组合根（装配所有模块）
适配器协议层       → WebSocket 协议收发与边界校验
播放管线           → 文本/音频/动作播放轮次编排
模型能力管理       → 模型能力事实维护
动作引擎           → 动作意图编译与参数计划生成
虚拟形象运行时     → Live2D 渲染与参数执行
创作工具           → 设置/历史/动作实验室/档案编辑

音频输入输出 (横切) → 音频播放与麦克风采集
协议契约     (横切) → 前后端协议与窗口间通信类型定义
```

模块关系：

```text
桌面宿主
  → 多窗口桥接
      → 主控制器
          → 适配器协议层
          → 播放管线
          → 模型能力管理
          → 动作引擎
          → 虚拟形象运行时
          → 创作工具投影
```

数据方向：

```text
适配器协议层 → 播放管线 → 动作引擎 → 虚拟形象运行时
模型能力管理 → 动作引擎
模型能力管理 → 创作工具
主控制器 → 多窗口桥接 → 创作工具
```

### 4.2 桌面宿主

**位置**：`frontend/electron/main/`、`frontend/electron/preload/`

**职责**：
- 创建宠物窗口、覆盖层、设置、历史、动作实验室、档案编辑器
- 管理透明窗口、鼠标穿透、窗口拖动
- 提供右键菜单和桌面截图
- 暴露预加载接口：`window.ag99desktop`

**边界要求**：
- 不理解适配器 V2 协议
- 不理解播放会话对象
- 不直接参与动作编译和 Live2D 参数计划

### 4.3 多窗口桥接

**位置**：`frontend/src/desktop-bridge/`、`frontend/src/types/desktop.ts`

**职责**：
- 主宠物窗口发布运行时快照和模型能力投影
- 辅助窗口发送运行时命令
- 档案编辑器使用独立的档案编辑命令与快照
- 使用浏览器广播通道实时同步，本地存储兜底恢复

**边界要求**：
- 辅助窗口不直接持有适配器连接
- 辅助窗口不直接修改播放管线内部状态
- 主窗口负责解释命令并调用对应运行时模块

### 4.4 主控制器（组合根）

**位置**：`frontend/src/app/`、`frontend/src/views/PetDesktopView.vue`

**职责**：
- 装配所有核心模块：适配器、会话存储、播放编排器、完成协调器、动作引擎、动作播放器、桌面桥接、快照发布器
- 处理辅助窗口命令和档案编辑器命令
- 计算连接状态、连接标签、阶段消息、人工智能状态
- 触发自动连接适配器
- 通过主窗口子控制器承接按键说话、右键菜单、ambient motion 偏好应用

**边界要求**：
- 可以装配模块，但不应发明新的播放语义
- 可以转发命令，但不应把具体协议处理写在自己内部
- 主窗口特有监听和桌面桥接细节应落到 `frontend/src/app/use*Controller.ts` 或同级小模块中

**当前主窗口子控制器**：

| 文件 | 职责 |
|---|---|
| `usePetDesktopController.ts` | 主窗口组合根，装配核心模块并返回 View 所需投影 |
| `usePushToTalkController.ts` | Push-to-talk 键盘与 IPC 监听 |
| `useAmbientMotionPreference.ts` | ambient motion 偏好应用与重试 |
| `useDesktopContextMenu.ts` | 桌面右键菜单桥接 |

### 4.5 适配器协议层

**位置**：`frontend/src/adapter-connection/useAdapterConnection.ts`、`frontend/src/adapter-connection/`

**子目录结构**：

```text
adapter-connection/
  useAdapterConnection.ts → 适配器协议层 facade
  core/        → 网络连接、消息信封、地址解析、本地偏好、协议常量
  history/     → 后端历史会话操作
  inbound/     → 消息信封校验、事件映射、领域分发器
  model-sync/  → 模型能力同步状态
  motion-tuning/ → 动作调参样本操作
  outbound/    → 统一出站客户端、出站动作
  runtime/     → 音频、麦克风、释放队列、连接重置
  state/       → 适配器连接状态容器
  features/    → 历史记录、动作调参、模型同步载荷归一化
```

**入站流程**：

```text
WebSocket 原始消息
  → 解析入站信封
    → 映射为内部事件
      → 分发内部事件
        → 写入会话/模型/音频/历史/动作调参状态
```

**出站流程**：

```text
运行时动作
  → 构建消息信封
    → WebSocket 发送
```

**常见出站协议**：`input.text`（发送文本）、`control.interrupt`（中断）、`control.playback_finished`（播放完成）、`system.history_*`（历史操作）、`system.semantic_axis_profile_save`（保存档案）、`system.motion_tuning_sample_*`（动作样本）、`engine.motion_intent` 预览

**边界要求**：
- 协议信封和载荷校验应在这一层完成
- 进入运行时的事件应尽量是已经定型的内部事件
- 适配器层不应该直接包含动作编译逻辑

### 4.6 播放管线

**位置**：`frontend/src/turn-playback/`

**核心对象**：

```text
播放会话
  → 后端状态 / 阶段 / 是否被中断
  → 片段集合: 映射<messageId, 播放片段>
       → 文本 / 音频 / 动作
```

**建模原则**：

```text
一次用户输入
  → 一个播放会话
    → 多个播放片段
      → 每个片段 = 文本 + 音频 + 动作
```

**标识符契约**：

| 标识符 | 归属层级 | 作用 | 缺失时策略 |
|---|---|---|---|
| `turn_id` | 交互轮次层 | 连接输入、输出、动作、播放完成、轮次结束 | 缺失时不再创建交互会话 |
| `message_id` | 单条回复片段 | 绑定同一片段的文本/音频/动作 | 新协议路径必须携带，缺失时作为协议错误 |

**会话标识解析方式**：`turn:<turn_id>`

**起播策略常量**：
- `AUDIO_MOTION_SYNC_WAIT_MS = 820` — 等待晚到动作加入同轮起播
- `TEXT_ONLY_RELEASE_WAIT_MS = 260` — 避免纯文本回复被过度延迟

**完成语义（三层信号）**：

```text
control.synth_finished    = 后端输出队列关闭，不会再追加新片段
control.playback_finished = 前端本地播放完成（合成完成已到 + 所有片段已稳定）
control.turn_finished     = 后端确认整轮闭环收口
```

**边界要求**：
- 管线不应该理解 WebSocket 原始消息
- 管线不应该编译动作
- 管线只应该通过窄接口通知适配器发送播放完成信号

### 4.7 模型能力管理

**位置**：`frontend/src/adapter-connection/model-sync/useModelSync.ts`、`frontend/src/types/protocol.ts`、`frontend/src/action-lab/parameterActionPreview.ts`

**职责**：维护后端同步来的模型能力事实，包括：
- 当前会话/配置信息、选中模型、可用模型列表
- 资源扫描和参数扫描
- 动作资源池、基础/参数动作库
- 语义轴档案、校准档案
- 运行时缓存错误

**边界要求**：
- 是模型能力事实来源
- 动作引擎和创作工具消费它
- Live2D `Expressions/*.exp3.json` 不作为动作主轴、prompt 示例或动作参考池来源
- Live2D `Motions/*.motion3.json` 用于反推真实动作骨架、参数幅度和轴选择依据，不直接作为 LLM 输出协议
- Action Lab 左侧以 tab 区分历史动作和已保存动作样本；保存样本复用同一套参数编辑器继续优化
- 不负责播放编排

### 4.8 动作引擎

**位置**：`frontend/src/model-engine/`

**当前文件**：

| 文件 | 职责 |
|---|---|
| `useModelEngine.ts` | 引擎 facade：持有状态、装配 runtime/start 依赖、暴露对外 API |
| `normalize.ts` | 动作意图和参数计划的入站归一化 |
| `planParser.ts` | 参数计划解析与克隆 |
| `compiler/compileMotionIntent.ts` | compile 主入口，装配 pipeline 并收口结果 |
| `compiler/compileContext.ts` | compile 共享上下文与中间 state |
| `compiler/contracts.ts` | compile 契约、diagnostics、timing/result 类型 |
| `compiler/registry.ts` | 静态 stage 注册、排序和启用入口 |
| `compiler/stages/*.ts` | compile 各阶段实现 |
| `runtime/motionRuntimeScheduler.ts` | pending queue、音频等待、过期清理、启动调度 |
| `runtime/motionStart.ts` | payload 启动、compile 触发、playPlan 调用、启动结果写回 |
| `runtime/contracts.ts` | runtime 调度、启动、状态控制、依赖端口类型 |
| `timing.ts` | 时机决策（提示/音频同步/默认） |
| `settings.ts` | 强度倍率设置 |
| `contracts.ts` | 入站动作 payload 的边界类型 |
| `constants.ts` | 默认时长、等待窗口、参数轴常量 |

**输入**：动作意图载荷、参数计划载荷、当前模型摘要、当前语义轴档案、动作引擎设置、音频播放上下文

**输出**：编译后的参数计划、播放器执行计划、动作播放记录

**主轴设计口径**：
- 动作主轴负责姿态和动作骨架，包括头部偏转、身体扭转/摇晃、眼睛开闭等。
- 表情辅轴负责面部表情、态度和细节微调，包括嘴角笑意、眉毛、视线偏移等。
- 嘴巴开闭是重要动作轴，但说话场景下主要由 runtime/lip sync 管理。
- 身体扭转和摇晃参与表达情绪强弱，不应只作为视觉附带效果看待。
- Motion 文件用于校准主轴/辅轴选择，Expression 文件不作为主轴来源。

**边界要求**：
- 不直接处理 WebSocket
- 不直接决定文本和音频何时释放
- 可读取必要的会话/音频时机信息，但不应成为播放管线的事实来源
- compile 侧扩展当前以 `SpeechPoseStage` 这类 plan 级增强为主，不承接逐帧连续表现

### 4.9 虚拟形象运行时

**位置**：`frontend/src/components/DesktopPetCanvas.vue`、`frontend/src/live2d-renderer/`、`frontend/src/live2d/WebSDK/`

**职责**：
- 初始化 Live2D 引擎、加载模型和纹理
- 渲染透明桌宠画布
- 执行动作参数计划
- 支持平滑交接
- 处理待机/空闲动作
- 承接后续 SDK 侧连续表现层 `ParameterPresentationLayer` 的落点，统一处理逐帧惯性、衰减、残留和层间混合

**边界要求**：
- 不理解后端协议
- 不理解播放会话
- 只接受模型加载、参数计划执行和运行时表现层控制请求

### 4.10 创作工具

**位置**：`frontend/src/views/SettingsWindowView.vue`、`frontend/src/views/HistoryWindowView.vue`、`frontend/src/views/ActionLabWindowView.vue`、`frontend/src/views/ProfileEditorWindowView.vue`、`frontend/src/components/MotionTuningPanel.vue`、`frontend/src/components/SemanticAxisProfileEditor.vue`、`frontend/src/components/BaseActionPreviewPanel.vue`

**交互模式**：

```text
工具窗口
  → View 读取 desktop-bridge 快照
    → 组件通过 props 展示和编辑
      → 组件通过 events 表达操作
        → View 转成桌面命令
          → 主控制器
            → 对应运行时模块
              → 快照回传工具窗口
```

**边界要求**：
- 工具窗口不直接连接适配器
- 工具窗口不直接写主运行时状态
- 窗口 View 可以访问 `useDesktopBridge()`
- 组件不直接访问 `desktop-bridge`、`adapter-connection` 或 WebSocket
- 组件通过 props 接收快照投影，通过 emits 输出保存、删除、预览、同步等操作

### 4.11 音频输入输出（横切层）

**位置**：`frontend/src/adapter-connection/runtime/audioRuntime.ts`、`frontend/src/adapter-connection/runtime/audioPlayback.ts`、`frontend/src/adapter-connection/runtime/microphoneRuntime.ts`、`frontend/src/adapter-connection/runtime/microphoneCapture.ts`、`frontend/src/adapter-connection/runtime/microphoneDevices.ts`

**输出音频方向**：

```text
收到音频 → 排队音频 → 释放音频 → 启动本地播放
  → 标记音频开始/终止 → 完成协调器
```

**输入麦克风方向**：

```text
麦克风采集 → 分配活跃麦克风输入段标识
  → 发送原始音频数据 → 发送麦克风音频结束
```

**关键语义**：
- 一段采集期内的所有原始音频块与结束信号共用同一个新的 `turn_id`
- 不再借用当前助手播放轮次的任何额外编排 ID
- 如果发送缓冲积压，前端标记为损坏，结束信号携带丢弃标记
- 后端收到丢弃标记后直接清空音频缓冲，不做残缺转写

### 4.12 协议契约（横切层）

**位置**：`frontend/src/types/protocol.ts`、`frontend/src/types/desktop.ts`、`frontend/src/types/semantic-axis-profile.ts`、`frontend/src/adapter-connection/core/protocolMessageTypes.ts`、`frontend/src/adapter-connection/inbound/inboundPayloads.ts`

**包括**：适配器 V2 信封、消息类型、`turn_id + message_id` 标识契约、动作模式定义、模型同步载荷、桌面运行时命令/快照、档案编辑命令/快照、语义轴档案

## 5. 后端架构

后端核心位于 `astrbot_plugin_ag99live_adapter/`，是前端桌宠运行时的协作编排后端。

### 5.1 目录结构

| 路径 | 职责 |
|---|---|
| `runtime/` | 轮次状态机、主运行时编排、协议收口 |
| `protocol/` | 协议消息定义、解析、构建 |
| `transport/` | WebSocket 服务器和静态资源路由 |
| `services/` | 上层服务组合（语音、媒体、历史、前端系统） |
| `motion/` | 动作处理（内联动作、实时动作计划、输出清理、大模型动作过滤） |
| `middleware/` | 中间处理层（交互动作贡献者） |
| `prompts/` | 提示词和模型交互文本资源 |
| `live2d/` | Live2D 相关（语义轴档案、扫描器、运行时缓存） |
| `assets/` | 静态资源 |
| `tests/` | 测试 |

### 5.2 核心模块

**`runtime/turn_coordinator.py`** — 后端协议和轮次编排中枢：
- 接收入站协议、建立轮次
- 广播文本输出/音频输出/动作意图
- 在音频轮次下等待前端播放完成
- 收到后发送轮次完成

**`runtime/session_state.py`** — 后端单连接轮次状态机：
- 管理当前协议 `turn_id` 与轮次阶段
- 区分阶段：空闲 → 思考中 → 合成中 → 播放中
- 在有音频时等待前端播放完成

**`protocol/`** — 协议层：
- `constants.py` — 协议消息类型常量
- `parser.py` — 入站消息解析
- `builder.py` — 出站消息构建
- `models.py` — 协议数据模型

**`services/`** — 服务层：
- `speech_service.py` — 语音输入处理（语音转文字入口）
- `media_service.py` — 音频文件缓存与服务
- `history_service.py` — 历史增删改查
- `frontend_system_service.py` — 前端系统消息处理
- `message_factory.py` — 消息工厂

**`motion/`** — 动作处理：
- `inline_motion.py` — 内联动作提取与验证
- `realtime_motion_plan.py` — 实时动作计划
- `output_sanitizer.py` — 输出文本清理
- `action_llm_filter.py` — 大模型动作过滤

### 5.3 后端职责总结

后端承担：
- 维护轮次生命周期
- 接收前端输入
- 广播输出/控制/引擎消息
- 同步模型能力和档案
- 提供动作调参样本存储与读取
- 语音输入处理
- 音频文件缓存与网络服务

## 6. 关键主流程

### 6.1 文本对话主流程

```text
辅助窗口输入文本
  → 发送文本命令
    → 主控制器
      → 适配器发送文本
        → 文本输入到达后端
          → 轮次开始
            → 输出文本/音频/动作
              → 适配器分发
                → 播放会话存储
                  → 播放编排器释放
                    → 文本显示/音频播放/动作引擎
                      → 合成完成关闭片段队列
                        → 所有片段本地稳定
                          → 播放完成
                            → 轮次完成
                              → 会话完成
```

### 6.2 模型同步主流程

```text
后端扫描模型
  → 系统模型同步
    → 适配器连接
      → 模型同步
        → 选中模型/选中语义轴档案
          → 动作引擎/创作工具/运行时快照
```

### 6.3 动作测试主流程

```text
动作实验室/档案编辑器
  → 预览动作载荷
    → 主控制器
      → 动作引擎本地播放
        → 适配器发送预览载荷到后端记录
```

## 7. 推荐依赖方向

后续维护时坚持以下方向：

```text
创作工具 → 多窗口桥接 → 主控制器

主控制器 → 适配器协议层
主控制器 → 播放管线
主控制器 → 模型能力管理
主控制器 → 动作引擎
主控制器 → 虚拟形象运行时

适配器协议层 → 播放管线
播放管线 → 动作引擎
动作引擎 → 虚拟形象运行时
模型能力管理 → 动作引擎
模型能力管理 → 创作工具
播放管线 → 适配器协议层（仅播放完成信号，通过窄接口）
```

**不建议出现**：
- 虚拟形象运行时直接访问适配器协议层
- 创作工具直接修改播放会话
- 动作引擎直接发送 WebSocket 消息
- 适配器协议层内部编译动作计划
- 桌面宿主理解业务协议

## 8. 当前判断与维护规则

### 8.1 关键判断

1. 前端是**桌面运行时系统**，不是普通页面应用
2. `usePetDesktopController.ts` 是前端主装配根
3. `adapter-connection/` 是适配器核心实现区，包含核心、入站、出站、运行时和特性模块
4. 适配器层通过 facade 对外暴露连接与协议能力
5. `model-engine/` 是动作引擎独立区域，扩展能力通过 compiler stage registry 挂载
6. `action-lab/` 与相关组件是动作库/调参工具区，组件层保持 props + events 边界
7. `astrbot_plugin_ag99live_adapter/` 是后端主业务区，不只是简单桥接壳
8. 当前动作路线分为两层：compile 侧优先推进 `SpeechPoseStage`，SDK/runtime 侧承接连续表现层 `ParameterPresentationLayer`

### 8.2 维护规则

1. 只写"当前真实结构"，不要把未来设想伪装成现状
2. 每当新增一级模块或一级职责，就补到本文
3. 每当一个模块职责明显变化，就更新"负责什么 / 不负责什么"
4. 每当重构完成一个大边界，就同步删掉过期描述
5. 如果某个文档更偏时序或实现细节，就写到其他架构文档，不要把本文写成大杂烩
