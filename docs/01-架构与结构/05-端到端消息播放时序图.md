## 2. 当前主链路

```text
WebSocket 建连
  -> system.server_info.schema_manifest 严格握手
  -> RuntimeState 校验扫描缓存并投影 live2d_scan.v3
  -> system.model_sync 分别应用模型能力和 runtime cache diagnostics
  -> 才允许进入业务消息处理

Prompt 构建
  -> 增强版 Core：主模型一次生成 spoken_reply + effect_calls
  -> 增强版 Core：Persona Effect result contributor 生成 motion_intent.v4
  -> 官方 Core：on_llm_request 注入同一能力，回复末尾生成 <@anim> V4
  -> 输出规范化阶段清洗隐藏标记
  -> 增强版 Core 的 TTS generating 状态触发可选曲线请求
  -> TTS 生成 WAV Record
  -> TurnCoordinator 在后端按 turn_id + message_id 聚合物理消息链
  -> 输出一个 output.segment.v3（唯一 canonical text + audio URL + motion）
  -> 前端严格解析并预校验全部 slots
  -> SessionStore.commitOutputSegment() 原子提交
  -> Orchestrator 在没有开放 required Timeline 时释放一个 SegmentJob
  -> PlaybackTimelineRuntime 按本段实际 slots 建立 sinks
  -> HTMLAudioElement metadata 提供真实时长，ModelEngine 预编译动作
  -> 语义阶段完成九级采样、timing 和 relation graph
  -> 模型参数阶段完成 speech gesture、parameter binding 和 resource policy
  -> audio playing 同时释放字幕、启动口型和已准备动作
  -> Live2D WebSDK 逐帧插值、动力学、口型和参数写入
  -> Timeline 回写终态
  -> synth_finished 确认后端不再产生新段
  -> SessionStore 槽位 settled 且同 Turn required Timeline 全部关闭
  -> playback_finished / turn_finished 收口
```

已完整提交的 segment 可以立即起播，不需要等待 `control.synth_finished`。`synth_finished` 是输出队列关闭和最终完成回执的屏障，不是播放启动屏障。

动作主协议是 `engine.motion_intent.v4`。`<@anim>` 只在 Persona Effect 注入能力不存在时由后端解析，并转换为同一个 `output.segment` 的 motion slot；它不是动作失败后的兜底，也不会形成独立前端播放链。

官方 AstrBot 不提供 `TTSState`。兼容模式只把最终 `Record` 解释为音频生成成功，并由
`after_message_sent` 关闭原子输出队列；没有 `Record` 时无法区分未触发与失败，只声明
`audio=absent`。该模式不启动 performance curve，也不构造假的 `tts_request_id`。

## 3. 原子段契约

一个逻辑段由以下复合键唯一标识：

```text
turn_id + message_id
```

AstrBot 可以把同一句回复物理拆成 Plain、Record、图片和 client object，但这些内容只在后端 `PendingOutputSegment` 内合并。前端不会再接收 `output.text`、`output.audio` 或独立正式 motion patch。

`output.segment.v3` 一次声明完整事实：

- `text`: `present | absent | failed`
- `audio`: `present | absent | failed`
- `motion`: `present | absent | failed`
- `images`: 本段图片列表

motion 的三个状态不能互换：`absent` 表示协议明确没有语义动作；`failed` 表示本段根据
`ag99live_motion_schedule` 应有动作，但 effect、payload 或动作链失败；`present` 才携带正式
动作意图。`failed` 不允许启动 speech-only，且会让最终播放回执为失败。

表演曲线只允许附加在 `motion.payload.performance_curve_hint`，不存在第二份顶层曲线事实。

增强版 Core 只有在真实进入 TTS Provider 调用后才启动曲线请求。其 TTS 失败由 Adapter 发送
`audio.state=failed`；官方 Core 因缺少失败通知，只能按最终是否存在 `Record` 投影
`present | absent`，这一兼容限制不能反向放宽增强版链路。

Plain、Persona semantic text 与 `Record.text` 只允许汇聚为一份 `text.content`。不同来源值不一致时后端拒绝该段；`audio` slot 只保存 URL，不再维护 caption 副本。

前端处理顺序固定为：

1. 校验信封、slot 标签和必填字段。
2. 重写并校验音频 URL。
3. 归一化并校验 motion payload。
4. 调用 `commitOutputSegment()` 一次性写入完整段。
5. 原子提交成功后，才把文本和音频加入待释放队列。

`commitOutputSegment()` 成功后会立即把 collecting 会话推进到 ready；无文本、无音频、无动作的完整段也能按合法状态机收口。若 Store 声明需要释放文本或音频但待释放队列缺项，会话直接失败，不会继续等待。

## 4. 所有权

| 层 | 唯一职责 | 不应承担 |
| --- | --- | --- |
| Persona Runtime / LLM | 回复语义、动作意图与九级轴强度 | Live2D 参数动力学、播放时钟 |
| AG99 adapter | effect_calls 校验、物理消息聚合、协议转换、资源与 profile 校验 | 前端逐帧插值 |
| SessionStore | 原子保存协议槽位和稳定生命周期投影 | 推测缺失 slot、判断开放 sink 是否结束 |
| TurnPlaybackOrchestrator | 从 SessionStore 生成一次 SegmentJob | 等待分片、运行补齐定时器、模拟终态 |
| PlaybackTimelineRuntime | 统一创建 sinks、时钟、生命周期和终态 | 动作语义决策 |
| ModelEngine | 轴采样、关系图、资源策略、timing、parameter plan | HTMLAudioElement 所有权 |
| Live2D WebSDK | 每帧曲线、动力学、口型值和 Cubism 参数写入 | 消息聚合与 turn 收口 |
| CompletionCoordinator | 本地 settled 后发送播放回执 | 写入各 sink 的执行终态 |

Timeline 的 execution ports 在构造时注入且不可替换；缺少 sink 接线属于启动错误，不走运行时 fallback。
Orchestrator 和 CompletionCoordinator 都订阅 Timeline execution state：前者用它阻止下一段
与开放 required sink 并发，后者用它阻止 speech-only 尾段尚未结束时提前回执。

## 5. 起播与时钟

`SegmentJobExecutor` 根据原子段的 audio / motion slot 进入执行分支；文本是否显示由同一段的音频事实决定：

1. audio 为 `absent` 时立即显示 canonical text；audio 为 `present` 时字幕保持待释放。
2. audio 为 `present` 时启动 audio sink；metadata 给出真实 duration 后，ModelEngine 预编译语义动作或内部 `speech_only` request。
3. Audio `playing` 携带绑定本段 AudioElement 的真实 clock，并从同一事件释放字幕、启动口型与已准备动作。
4. Lip sync 绑定同一个 AudioElement 和 WebAudio RMS，不运行第二套音频时钟。
5. motion 为 `present` 时启动该段的语义动作；motion 为 `absent` 且当前模型具备 voice-following profile 时启动已准备的内部 speech-only plan。
   两者使用同一 segment Timeline clock reader，但只有正式 motion 改写 SessionStore motion 生命周期；speech-only 不覆盖稳定的 `motion absent`。
6. 动作视觉入场延迟由 performance curve / parameter plan 表达，不存在固定毫秒桥接延迟。
7. audio 明确为 `absent` 且 motion 为 `present` 时，才创建 synthetic motion-only clock。
8. audio 为 `failed` 时，待显示字幕和已声明动作都失败，不将故障改写为正常 text-only / motion-only。

Lip sync 是 Timeline 内的可选 sink，它的 started / terminal 归 Timeline 管理。SessionStore 的 segment 收口事实仍是 text / audio / motion，因此不应把口型终态画成第四种 segment slot。

## 6. 失败规则

| 情况 | 当前规则 |
| --- | --- |
| 后端物理组件冲突或同段多音频 | 中止该段出站并暴露错误 |
| slot 结构非法 | 拒绝整段，不写 SessionStore |
| motion 领域校验失败 | 拒绝整段，不显示文本、不排队音频 |
| 重复 `turn_id + message_id` | 拒绝整段并关闭错误连接，不覆盖旧段 |
| `synth_finished` 前存在不完整内部段 | 报协议一致性错误，不自动标记 absent |
| audio absent | 允许 text-only 或 motion-only |
| audio failed | 待显示字幕失败；动作失败；不转换为 text-only 或 motion-only |
| motion 应有但缺失/非法 | motion failed；音频/字幕可继续，禁止 speech-only 替代 |
| lip sync 主路径失败 | 记录明确错误；允许已定义的随机开合降级，但不得影响 speech energy |
| sink 或真实 audio clock 缺失 | 对应 timeline/segment 失败，不安装伪造时钟 |
| Live2D 模型加载中被替换 | 取消旧 generation，旧异步回调不得访问已释放实例 |

`control.synth_finished` 是队列关闭断言：它之后不接受新的 `output.segment`，也不存在晚到
slot 补播。它、本地 segment 全部 settled、同 Turn 不存在开放 required execution Timeline
三者共同触发 `playback_finished`，但不阻止已提交 segment 提前播放。

## 7. 当前评估

当前链路的主要结构已经自洽：

1. 后端物理拆分被限制在 Adapter 内部，外部协议只有一个原子段。
2. SessionStore 是 text/audio/motion 槽位和稳定投影事实源，Timeline 是 required sink
   实时执行事实源；Orchestrator 不复制二者。
3. 正式动作只存在于 segment motion slot；前端独立 motion patch 和 performance-curve patch 已移除。
4. Timeline 在构造时获得固定 sinks，运行中不再重新配置执行端口。
5. `absent`、`failed` 与协议非法彼此分离，不使用 fallback 掩盖接线或数据错误。
6. `synth_finished` 的完成屏障与 segment 的起播条件已分离，避免后端整轮生成耗时阻塞首段播放。
7. WebSocket 断开先停止在飞 AstrBot event，再清理映射；前端停止 Timeline，迟到输出不会重建链路。

真实 Electron 端到端实测需要确认 WAV、WebAudio、GPU 渲染、Live2D 模型切换和透明窗口环境。performance curve 小模型若在段关闭前未完成，会明确记录 `skipped`；若 hint 已附加但当前音频时钟无法套用，ModelEngine 记录 `performance_curve_skipped:*` 并继续基础动作。这是非阻塞质量策略，不改变主播放协议。
