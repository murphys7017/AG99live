# 端到端消息播放时序图

本文把 AG99live 当前“收到消息 -> 后端响应 -> 前端播放 -> 回执收口”的主链路画成两张图：

- 一张详细版，适合排查问题和看边界
- 一张浓缩版，适合讨论和快速对齐

图中流程基于当前真实实现，主要对应：

- `astrbot_plugin_ag99live_adapter/runtime/turn_coordinator.py`
- `frontend/src/adapter-connection/inbound/adapterInboundRuntime.ts`
- `frontend/src/turn-playback/useTurnPlaybackSessionStore.ts`
- `frontend/src/turn-playback/useTurnPlaybackOrchestrator.ts`
- `frontend/src/model-engine/*`
- `frontend/src/turn-playback/usePlaybackCompletionCoordinator.ts`

## 1. 详细版

```mermaid
flowchart TD
    A[前端用户发送 input.text] --> B[WebSocket 发到 AG99live adapter]
    B --> C[TurnCoordinator.handle_msg]
    C --> D[绑定或确认 turn_id]
    D --> E[_commit_inbound_message 提交给 AstrBot]

    E --> F[AstrBot 主回复生成]
    F --> G[interaction middleware 注入动作能力]
    G --> H[主模型返回文本 + effect_calls/ag99live.motion]

    H --> I[TurnCoordinator.emit_message_chain 拆回复链]
    I --> J[抽取 output.text]
    I --> K[抽取 output.audio Record]
    I --> L[抽取/归一化 engine.motion_intent.v3]

    J --> M[发 output.text]
    L --> N[发 engine.motion_intent]
    H --> O{启用 performance curve?}
    O -->|是| P[异步请求 performance curve provider]
    O -->|否| Q[跳过]

    P --> R{音频出站前 ready?}
    R -->|随 motion 一起 ready| S[附加到 motion intent]
    R -->|稍晚 ready| T[发 engine.performance_curve_hint]
    R -->|未 ready| U[记录 failed 并回退默认 timing]

    K --> V[缓存/准备 audio_url]
    V --> W[发 output.audio]
    M --> X[前端 adapterInboundRuntime 收消息]
    N --> X
    S --> X
    T --> X
    W --> X

    X --> Y[按 turn_id + message_id 写入 TurnPlaybackSessionStore]
    Y --> Z[useTurnPlaybackOrchestrator 观察 active segment]

    Z --> AA{文本/音频/动作是否齐备}
    AA -->|齐备| AB[释放 text + motion + audio]
    AA -->|音频先到 动作未到| AC[等待 820ms 再决定]
    AA -->|只有文本| AD[等待 260ms 再决定]
    AA -->|无音频确认| AE[按 text-only 或 text+motion 释放]

    AB --> AF[releaseAssistantTextForPlayback]
    AB --> AG[releaseAudioForPlayback]
    AB --> AH[modelEngine.ingestNormalizedPayload]

    AC --> AH
    AD --> AF
    AE --> AF
    AE --> AH

    AH --> AI[ModelEngine normalize + compile]
    T --> AI
    S --> AI
    AI --> AJ[TimingStage 按 audio duration + performance_curve_hint 求 timing]
    AJ --> AK[生成 engine.parameter_plan.v2]
    AK --> AL[usePreviewMotionPlayer 驱动 Live2D 写参]

    AG --> AM[浏览器 Audio 播放]
    AM --> AN[lip sync / 播放终态更新]
    AL --> AO[动作完成回调]

    I --> AP[后端发 control.synth_finished]
    AP --> AQ[前端标记后端输出队列关闭]

    AQ --> AR[usePlaybackCompletionCoordinator 检查所有 segment 是否 settled]
    AN --> AR
    AO --> AR

    AR -->|全部完成| AS[前端回发 control.playback_finished]
    AS --> AT[后端 finalize_turn]
    AT --> AU[后端发 control.turn_finished]
    AU --> AV[前端 session 标记 completed 并清理]
```

## 2. 浓缩版

```mermaid
flowchart LR
    A[前端 input.text] --> B[TurnCoordinator]
    B --> C[AstrBot 主回复 + middleware 动作结果]
    C --> D[output.text]
    C --> E[engine.motion_intent]
    C --> F[output.audio]
    C --> G[可选 performance_curve_hint]

    D --> H[SessionStore]
    E --> H
    F --> H
    G --> H

    H --> I[TurnPlaybackOrchestrator]
    I --> J[文本释放]
    I --> K[音频释放]
    I --> L[动作释放]

    L --> M[ModelEngine 编译 timing/parameter plan]
    M --> N[Live2D 播放]
    K --> O[Audio 播放]

    B --> P[control.synth_finished]
    N --> Q[前端本地 settled]
    O --> Q
    P --> Q
    Q --> R[control.playback_finished]
    R --> S[control.turn_finished]
```

## 3. 阅读提示

- `TurnCoordinator` 是后端轮次和协议编排中枢
- `TurnPlaybackSessionStore` 是前端这轮播放的事实来源
- `useTurnPlaybackOrchestrator` 只负责“什么时候开始放”
- `usePlaybackCompletionCoordinator` 只负责“什么时候这轮真的结束”
- `performance_curve_hint` 只辅助 timing，不替代 `engine.motion_intent`
