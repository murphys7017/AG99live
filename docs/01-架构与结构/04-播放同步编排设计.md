# 播放同步编排设计

本文定义当前原子消息协议下的播放编排。目标是让文本、WAV、口型和动作共享段身份与 Timeline 生命周期，同时不使用等待分片或模拟成功状态的 fallback。

## 1. 核心原则

1. 一个正式回复段只对应一个 `output.segment`。
2. `TurnPlaybackSessionStore` 是协议槽位和稳定生命周期投影的事实源。
3. `TurnPlaybackOrchestrator` 只生成 release job，不播放媒体。
4. `PlaybackTimelineRuntime` 是 sink 生命周期和时钟唯一所有者。
5. ModelEngine 只消费 segment-scoped clock snapshot。
6. 缺少身份、sink、真实时钟或非法状态时失败，不猜测当前 turn。
7. `absent` 是协议事实，不能由超时或缺少消息推导。
8. audio sink 必须在 3000ms 内报告真实 `playing`；期限由 Timeline 持有，ModelEngine 不得另设动作等待计时器。
9. 是否可以释放下一段或发送播放完成，必须同时读取 SessionStore 和开放的 required
   execution Timeline，不能只看槽位是否 settled。

## 2. Segment 数据模型

每个 session 使用 `turn_id` 标识，每个 segment 使用 `message_id` 标识：

```text
TurnPlaybackSession
  segments: Map<message_id, TurnPlaybackSegment>

TurnPlaybackSegment
  text
  audio
  motion
```

入站正式段只能通过：

```text
commitOutputSegment(turnId, messageId, material)
```

创建。重复键、终态 session、`synth_finished` 后写入都直接抛错。
后续 timeline `mark*` 只能更新这个已提交段；缺少 `turn_id + message_id`
对应段时直接抛错，禁止生命周期回调隐式创建 segment。

## 3. 原子提交

dispatcher 在调用 Store 前完成所有可能失败的协议工作：

```text
parse tagged slots
  -> rewrite audio URL
  -> normalize motion payload
  -> build OutputSegmentMaterial
  -> commitOutputSegment
  -> enqueue text/audio release items
```

Store 在局部构造 text/audio/motion/speech 子状态，最后才写入 Map。无效 motion 不会留下可见文本、待播音频或孤立语音提示。

显式 slot 的 Store 映射：

| slot | Store 结果 |
| --- | --- |
| text present | content 已写入，等待 release |
| text absent / failed | delivered + released |
| audio present | URL 已写入，terminal=idle |
| audio absent | terminal=absent |
| audio failed | terminal=failed |
| motion present | normalized payload 已写入 |
| motion absent | absent=true |
| motion failed | failed=true |

## 4. Orchestrator

Orchestrator 观察 Store 的完整 segment。它不再拥有：

- 260ms 文本等待。
- 820ms 动作等待。
- 3000ms TTS 等待。
- audio expected 镜像。
- performance curve 独立 readiness。
- pending motion patch。

完整段进入 `ready` 后，Orchestrator 计算本次 job 是否释放 text、audio 和 motion，并调用一次：

```text
timelineRuntime.startSegmentJob({
  turnId,
  messageId,
  text,
  audio,
  motion
})
```

若 audio 已失败，motion 会被明确标记失败；不会改走 motion-only。

Orchestrator 释放任何新段前会查询 `findOpenExecutionTimelineSegments()`。只要存在未收口的
required sink，就不启动下一段；Timeline 终态变化会主动触发重新调度。当前策略是全局串行播放，
不同 Turn 也不会在同一个 Live2D 模型上并发执行 required Timeline。

## 5. Timeline Runtime

Timeline Runtime 在 composition root 创建时必须收到不可变 execution ports：

- session lifecycle port。
- text sink。
- audio sink。
- motion sink。

运行中不存在 `configureSegmentExecution`。缺少 wiring 是构造错误。

当前组合边界为：`createConversationPlaybackRuntime.ts` 在 app composition root 内创建并持有唯一
`PlaybackTimelineRuntime` 与 `BrowserAudioTimelineSink` 实例；adapter 只提供
协议入站、字幕显示和音频播放 ports，并由该组合模块传给 Timeline，
不拥有 Timeline 或 BrowserAudioSink 的创建权。完整 text/audio/motion/speech 素材只保存在
SessionStore 的 Segment 中，由 Orchestrator 按 SessionStore 顺序选择唯一可播放段，
再随 segment job 直接交给 Timeline sinks，不存在第二套待播 Map。Runtime 内部只有
`sessionProjection` 可以把 audio / motion 的 started、duration 和 terminal
投影到 SessionStore。

只有 `output.segment.motion=present` 建立的正式 motion sink 才投影 motion
started / terminal。`motion=absent` 时由 ModelEngine 内部生成的 speech-only
计划共用该段 Timeline 和 audio clock，但不改写 SessionStore 中已经稳定的
`motion absent` 协议事实。

一个普通音频段的顺序：

1. audio sink start；canonical text 保持待释放。
2. 注册 lip-sync；正式 motion 或已准备 speech-only 存在时注册 required motion sink。该 sink
   负责本段终态结算，但 `requiredForStart=false`，不阻塞音频时钟进入 `playing`。
3. Audio metadata 提供 duration，ModelEngine 预编译语义动作或内部 `speech_only` request。
4. AudioElement 触发 `playing`，事件携带绑定本段 AudioElement 的真实 audio clock。
5. 同一 audio-start 事实释放字幕、启动口型；Timeline 先进入 `playing`，再用同一真实时钟唤醒已准备 motion sink。
6. 动作入场延迟只来自 performance curve / parameter plan。
7. 三类 sink 分别在 Timeline 收口；只有正式 motion 将生命周期投影到 SessionStore。
8. Timeline 在 required sinks 收口后结束。

speech-only 的 required motion sink 属于实时执行事实。它不改写稳定的 `motion absent`，
所以 SessionStore 可能先满足槽位 settled；Orchestrator 和 CompletionCoordinator 必须继续
等待该 Timeline sink 终止。

若 audio sink 在 3000ms 内未进入 `playing`，Timeline 停止 AudioElement，并把 audio、deferred subtitle 和仍开放的 required motion 一并标记 failed。该失败不能转写为 `absent` 或 motion-only。

## 6. 时钟规则

### 6.1 有音频

唯一主时钟是当前 segment 的 `HTMLAudioElement`：

```text
currentTime
duration
playbackRate
paused / playing
```

clock 在 AudioElement 创建时建立，并只随本段 `playing` 事件交给 Timeline。禁止通过
模块级 active audio element 反查时钟。Audio 报告 started 但无法提供真实 clock 时，
audio sink 和 segment 失败，不得创建“永远播放中”的 unavailable clock。

### 6.2 无音频

只有 `audio.state=absent` 时，可以创建 synthetic motion-only timeline。它用于给动作提供确定的本地时间基，不模拟音频。

### 6.3 音频失败

`audio.state=failed` 或实际播放失败时：

- 尚未显示的 audio-backed canonical text 作为本段字幕失败。
- motion 标记失败。
- 不创建 synthetic audio clock。
- 不把 failed 改写为 absent。

只有协议明确声明 `audio.state=absent` 的文本段才按 text-only 正常显示。

## 7. Lip Sync

Lip sync 与 audio sink 使用同一个 AudioElement：

```text
AudioElement
  -> WebAudio analyser
  -> mouth value
  -> independent speech energy
```

真实 RMS 同时产生口型值与独立 speech energy。随机口型降级只写 mouth value，不能驱动头身 speech gesture。口型主路径失败必须记录日志；允许的随机开合降级持续到音频结束，并以 Timeline terminal 收口。

## 8. Motion

Motion sink 在 audio timeline 上注册为 required sink。Audio duration ready 后，PlaybackTimeline 通过应用组合层把 matched snapshot 直接交给 ModelEngine 预编译计划；Audio `playing` 后，同一条直接绑定使用当前 Timeline snapshot 和 clock reader 启动计划。AdapterConnection 不参与这两个动作生命周期事件。

ModelEngine：

- 校验 turn_id + message_id 所有权。
- 校验 profile revision。
- 编译 relation graph 和 parameter plan。
- 使用音频剩余时长求解 performance timing。
- 把 started / terminal 回写同一 Timeline。

AG99 Live2D Runtime 不读取 SessionStore，也不修改 turn 生命周期；官方 Cubism `Framework` / `Core`
只负责模型、Physics 和渲染，不参与播放编排。

V4 的 `motion_resource_id` 只允许从已完成模型加载时预载的 motion 缓存同步启动。模型未 Ready、缓存缺失、时钟无效或 SDK 拒绝时直接返回 `rejected`；获得有效 Cubism handle 并触发 `onStarted` 后才返回 `started`。运行期不重新 fetch motion，不维护第二套准备期 run，也不增加启动超时或默认动作兜底。缺少 `duration_ms` 的资源动作不进入正式播放。

播放事实写入权固定如下：

| 事实 | 唯一写入者 |
| --- | --- |
| 原子 segment、backend turn/synth 状态 | inbound protocol runtime |
| segment ready | TurnPlaybackOrchestrator |
| text/audio/motion release 与 playing | PlaybackTimeline segment executor |
| audio/motion started、duration、terminal | PlaybackTimeline sessionProjection |
| settling、playback ACK、completed | PlaybackCompletionCoordinator |

ModelEngine 只能向 Timeline 报告动作拒绝、started 和 terminal，不能直接写
SessionStore。Adapter 清理尚未启动的 audio sink 时也只能调用
`rejectAudioBeforeStart()` 或按段停止 Timeline，不能把 UI 播放投影解释为第二份播放终态。

## 9. 完成协议

`control.synth_finished` 到达前，前端先执行：

```text
assertOutputSegmentsResolved(turnId)
```

若存在未声明的 text/audio/motion/speech 状态，则报告协议错误，不自动补齐。

本地 settled 条件：

```text
all segments:
  text.delivered
  audio terminal
  motion absent/completed/failed
```

这只是槽位条件。CompletionCoordinator 还必须确认：

```text
findOpenExecutionTimelineSegments()
  不包含当前 turn_id
```

两类条件都满足后才进入 `settling` 并发送 `control.playback_finished`。收到
`control.turn_finished` 后进入 `completed`。这样 motion slot 已是 `absent` 的
speech-only 尾段也必须真实结束，不能被提前确认或与下一段重叠。

合法阶段：

```text
有 sink:
collecting -> ready -> playing -> settling -> completed

零 sink:
collecting -> ready -> settling -> completed

任意非终态 -> failed
```

## 10. 错误分类

| 错误 | 处理 |
| --- | --- |
| output.segment 信封或 slot schema 非法 | parser 拒绝，不写 SessionStore |
| motion normalize / audio URL 领域预检失败 | 写入已结算 rejected 段，不释放任何播放材料 |
| duplicate segment | 拒绝本次提交，不覆盖首段，不关闭连接 |
| synth_finished 前内部段不完整 | 协议一致性错误 |
| timeline/sink 缺失 | segment failed |
| audio started 无真实 clock | audio/segment failed |
| audio failed | 待显示字幕与 motion failed，不转换为 text-only / motion-only |
| audio start timeout | 停止 audio sink，字幕与 required motion failed |
| 应有 motion 但 payload 缺失/非法 | motion failed；禁止 speech-only 替代 |
| V4 motion resource 未实际开始或未终止 | motion failed，不保留 playing |
| late output.segment | 拒绝本次提交，不补播，不关闭连接 |
| terminal 被再次写入 | 保持首个终态并记录诊断 |
| WebSocket 断开 | 后端先 stop active events，再清状态；前端停止全部 Timeline |

## 11. 运行验收

基础输入输出 smoke 不代表播放链路成立。真实 Electron 对话必须确认：

- WAV 正常播放。
- 口型与声音同启同停。
- 字幕、口型和动作只响应同一个 Audio `playing` 事实，动作视觉入场由曲线控制。
- audio absent motion-only。
- audio failed 不启动动作。
- 快速 interrupt 与模型切换。
