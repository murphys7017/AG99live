# 播放同步编排设计

## 目标

每个 `output.segment` 消息（Payload Schema 为 `output.segment.v5`）都应以一个段为单位播放、停止和完成。音频、字幕、语义动作、语音随动和口型可以有各自的执行器，但它们共享段的开始、时钟和终态。

```text
output.segment（schema: output.segment.v5）
  -> 严格解析
  -> SessionStore.commitOutputSegment()
  -> TurnPlaybackOrchestrator
  -> PlaybackTimelineRuntime.startSegmentJob()
  -> audio / subtitle / motion / lip-sync sinks
  -> segment terminal
  -> SessionStore 稳定投影
  -> control.playback_finished
```

## 所有权

| 对象 | 所有者 | 职责 |
| --- | --- | --- |
| 段业务事实 | SessionStore | 保存已接受段、slot 状态和可见投影。 |
| 段任务 | Orchestrator | 按 `turn_id`、`message_id`、`sequence` 调度。 |
| 时钟和 sink 终态 | PlaybackTimelineRuntime | 统一起播、停止、失败与完成。 |
| HTMLAudioElement | BrowserAudioTimelineSink | 作为有音频段的真实播放时钟。 |
| 音频输出和口型图 | ConversationPlaybackAudioRuntime | 启动音频、绑定/释放口型并结算 Timeline。 |
| 动作执行 | ModelEngine 与 Live2D runtime | 在给定时钟下准备、开始和结束计划。 |

## 时钟规则

有 TTS 音频时，HTMLAudioElement 的真实 `currentTime` 是段时钟。字幕、动作 keyframe、语音随动和口型读取同一事实，不能各自创建模拟计时器。

无音频的动作段使用显式的 motion-only 合成时钟；它仍属于该段 Timeline，不能绕过 SegmentJob。暂停或时钟不前进时，参数表现保留当前状态，不应因为一帧暂停清空弹簧或收势状态。

## 起播与结算

Timeline 只在必需 sink 都可用时把段推进到播放状态。每个 sink 必须报告自己的终态；停止、中断、失败和自然完成都会尝试结算所有仍开放的 sink 和时钟，然后将第一个实际错误向上报告。

音频启动、替换、空闲恢复和释放由对话播放组合根管理。ModelEngine 只接收当前段的时钟与上下文，不能从音频状态推断另一个段的所有权。

## 中断和替换

`control.interrupt` 只作用于其 `turn_id` 的活动段。终止过程会依次处理音频、口型、参数计划、Timeline 和 SessionStore 投影；任一清理步骤失败时，其他步骤仍须继续，避免一个失败把连接或运行状态遗留在半开状态。

一个新的动作候选在替换已有运行前会先完成预检。旧运行结算失败时，新运行不能声明开始；候选自身拒绝也不能覆盖仍在播放的运行状态。

## 验收重点

真实桌面运行应检查：

1. 音频首次 `playing`、字幕首次显示和语义动作首帧是否来自同一段。
2. 快速中断和替换后，口型、计划和 Timeline 是否全部结算。
3. 失败音频、模型切换或断开连接时，其他资源是否仍被释放。
4. 多个逻辑消息是否严格遵循 `sequence`，且不会交叉使用时钟。

静态类型检查只能覆盖边界形状；这些行为需要 AG99、TTS、Electron 和 Live2D 联调确认。
