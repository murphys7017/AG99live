# 连续存在感与注意力表现层方案

更新：2026-10-28

## 1. 目标

为 AG99live 增加一个本地、连续、可打断的角色表现层，让 Live2D 角色在没有聊天输出时仍保持自然存在感，并能对用户注意、输入、返回电脑和对话阶段做出合时的非语言反应。

这个表现层的第一目标不是让角色更频繁地说话，而是让角色在以下时刻有稳定、可解释的视觉状态：

- 待机时有生命感
- 用户靠近或注视时表现出注意到用户
- 对话开始前先准备并转向用户
- 思考时有低幅度的思考表现
- 说话时视线、表情、口型和动作互不打架
- 对话结束或中断后自然收势
- 用户离开后回来时能区分短暂离开和长时间离开

## 当前优先级

当前先使用已有 Motion Lab 记录链路积累 Persona 段与动作生成数据，不扩展样本字段、不新增连续存在行为事件，也不把 NeuroBrain 纳入连续存在感方案。现有动作记录忠实保存 Provider 实际收到的上下文；若某次既有请求包含 NeuroBrain 快照，它仍可能作为该请求的输入事实被记录，不代表连续存在感依赖它。Adapter runtime 在存储目录可用时会创建 raw-event recorder；实际采集仍以新版 Adapter 已加载、相关 Persona/动作回调触发且写入成功为准。

连续存在感与注意力表现层是下一阶段优化方向。开始该阶段前先确认当前记录 schema v3 已在目标 AstrBot 实例加载，并用正常对话积累一批当前行为基线。后续如需记录连续存在行为，单独定义其事实、终态和用途，不与 Persona 动作训练样本混成同一记录类型。

2026-10-28 方案评估结论：整体架构方向成立；阶段 0 基线部分完成，阶段 1 已开始并完成本地诊断接线，但总体仍处于设计与验收阶段。统一注意力仲裁和连续表现事件尚未实施。首批工作建议限于阶段 0 和阶段 1，不同时启动所有行为阶段。进入可见行为改动前，先确认 schema v3 已在目标实例加载、已有数据基线可用，并明确 AG99 正式感知接口及状态所有权。Persona 生命周期计划的阶段 6 尚待目标环境验收；阶段 2 接入前至少要验证本方案会消费的 Turn、Playback、打断、完成和断连边界，避免在表现层重复推导对话状态。

## 2. 非目标

- 不新增主动聊天调度器
- 不让鼠标、键盘或截图直接触发聊天回复
- 不把原始键盘、鼠标、截图内容写入聊天历史或训练语料
- 不在前端重新实现 Persona、Policy、TTS 或 Motion Provider
- 不把随机动作数量作为拟人化指标
- 不把 NeuroBrain 作为本方案依赖；该测试功能不纳入连续存在感主链路
- 不修改 C++ 验证工程

## 3. 当前源码事实

### 3.1 呼吸与自动眨眼已经存在

Cubism 呼吸和自动眨眼已经在 `LAppModel` 中创建和更新，环境动作默认开启。后续工作应先做真实模型验收和参数覆盖检查，不应重复接入一套呼吸或眨眼系统。

需要确认的实际问题是：

- `ambientMotionEnabled` 是否在运行时被关闭
- 当前模型是否声明了眼睛参数和有效的呼吸参数
- 参数混合器是否覆盖或削弱了呼吸结果
- 事件动作期间暂停眨眼是否符合目标体验
- 实际渲染循环和模型切换后效果是否持续

### 3.2 鼠标凝视已经有局部实现

`useCursorGaze` 已完成停留判定、启动、更新和离开停止。它目前是一个局部控制器，尚未与对话阶段、返回电脑、输入活跃度和语义动作共用注意力仲裁器。

### 3.3 桌面观察目前只产生画面变化事实

当前 `desktop_observation` 的流程是：对话安静后截图、比较前后画面变化面积、提交 `desktop_changed`。它没有窗口身份和稳定场景计时，因此不能直接表达“同一窗口停留了 N 秒”。

### 3.4 返回电脑已经有时长事实

`desktop_returned` 当前已经传递 `inactive_seconds` 和返回依据。它可以在事实归一化层增加时长分档，不需要新增截图或 Provider。

### 3.5 uiohook 当前只用于 PTT

Electron 主进程已经加载 `uiohook-napi`，但只监听配置的 PTT 按键。输入活跃度需要新增本地聚合器，不能直接把现有 PTT 监听改成原始输入记录器。

### 3.6 AG99 必须参与语义主动性

连续存在感不能完全封闭在 AG99live 内。需要明确拆成两条路径：

```text
本地表现路径：事实 -> AG99live PresenceStateStore -> Live2D/音频表现
语义表达路径：授权事实 -> Adapter -> AG99 Observation/Policy/Persona/TTS
```

AG99live 拥有：

- 光标、输入活跃度、返回电脑和桌面变化等本地事实的采集与去抖
- 角色当前是否适合立即表现、延后或抑制的本地准入
- gaze、呼吸、眨眼、思考随动、播放同步和模型参数执行
- 事实事件的 TTL、取消、断连和桌面运行时生命周期

AG99 拥有：

- 是否值得形成语义表达
- 应该说什么、采用什么人格和记忆上下文
- 是否调用 Persona、TTS、工具或主动对话流程
- 主动表达的冷却、安静时段、策略和会话历史

Adapter 只负责协议校验、权限和事实桥接，不复制 AG99 的 Policy、Persona 或主动调度器。桌面事实必须经过低频聚合后，使用现有 `RuntimeObservationSensor`/Observation Inbox 进入 AG99；高频本地信号不能直接触发 LLM。

当前 `desktop_returned` 和 `desktop_changed` 已经沿着这条 Observation 路径提交，但连续存在感方案还需要把本地表现和 AG99 语义表达的两个终态明确分开：本地 gaze 可以完成而不产生对话，AG99 Policy 也可以拒绝语义表达而不影响本地待机和收势。

现有返回电脑和桌面变化事实只提供了 Observation 桥接基础，不代表统一表现层已经接入；返回电脑功能仍需配套加载和真实运行验收，`return_band` 尚未实现。进入语义事实桥接前，应核对 AG99 主仓库正式内部感知组件的文档和接口，明确其与 Observation、Policy 的职责关系；本方案不因接口尚未确认而另造主动调度路径。

建议的运行时所有权是：Electron main 负责操作系统级事实采集及本地聚合；preload 只传递受约束的高层事实；renderer 桌面运行时持有唯一的 `PresenceStateStore`，因为模型、Turn/Playback 状态和 Live2D 执行均在该侧组合；Adapter 负责协议校验和授权事实桥接；AG99 继续拥有语义表达策略。实施前需对照真实调用链确认该边界，不能让 main、renderer 和 Adapter 各自保存一份可变表现状态。

### 3.7 NeuroBrain 不属于本方案主链路

当前仓库旁的 `astrbot_plugin_neurobrain` 是开发中的测试功能。本方案不依赖它、不读取它的状态、不扩展现有 OLV 被动动作实验，也不把它作为 AG99 的正式内部感知接口。

连续存在感只依赖两类正式边界：

1. **AG99 Personal Runtime / Observation**：接收经过授权的桌面事实，经过 Gate、Policy、Persona 和 TTS 决定是否形成语义表达。
2. **AG99live Desktop 本地状态**：处理光标、输入、播放、模型和窗口生命周期，并执行本地 Live2D 表现。

目标结构简化为：

```text
AG99 Observation/Policy 结果 ─┐
桌面本地事实 ───────────────┼─> AG99live PresenceStateStore
AG99 Turn/Playback 生命周期 ─┘       -> 本地表现与输出准入
```

## 4. 目标架构

### 4.1 分层

连续存在感表现层分成五层：

```text
输入事实层
  cursor / local input / desktop return / desktop observation /
  connection / conversation / playback

状态归约层
  PresenceStateStore
  renderer 桌面运行时的唯一表现状态所有者，统一处理事件、超时、取消和状态终止

注意力与表现意图层
  attention target / speaking preparation / thinking / settling /
  idle variation / return reaction

动作仲裁层
  ambient / gaze / sway / face / lip sync / semantic motion
  按参数所有权和优先级合并

Live2D 执行层
  ModelEngine / ParameterMixer / Cubism model update
```

输入事实层不直接调用 Live2D，Live2D 执行层也不反向读取桌面截图或键盘事件。

### 4.2 统一角色状态

不要把所有组合情况做成一个巨大的枚举。使用事实状态加派生表现状态：

```text
ConversationPhase:
  idle | preparing | thinking | speaking | interrupted | settling

AttentionTarget:
  neutral | user | cursor | scene | searching

InputActivity:
  active | quiet | unknown

DesktopPresence:
  unknown | away | returned_short | returned_medium |
  returned_long | returned_very_long

PresentationMode:
  offline | idle | noticing | preparing | thinking |
  speaking | listening | returning | settling
```

`PresentationMode` 由归约器根据前面几个事实计算，不能由多个组件分别设置。

### 4.3 事件输入

表现层只接收高层事实事件：

```text
runtime.connected
runtime.disconnected
model.ready
model.capabilities_changed
cursor.dwell_started
cursor.moved
cursor.left
input.activity_changed
desktop.returned
desktop.scene_changed
desktop.scene_stable
turn.started
turn.pre_action_ready
turn.thinking
turn.speaking_started
turn.segment_started
turn.segment_finished
turn.interrupted
turn.finished
playback.started
playback.finished
timer.expired
```

高频事件必须在来源处聚合：鼠标移动不能逐帧进入状态记录，键盘事件不能逐个进入 Core，Motion Lab 只记录状态转换和有意义的终态。

## 5. 表现优先级和参数所有权

### 5.1 优先级

推荐从高到低：

```text
安全与生命周期终止
语义动作 / direct parameter plan
口型与音频同步
注意力 gaze
思考与说话随动
基础呼吸与眨眼
待机动作
```

这是表现意图优先级，不代表所有层互相排斥。不同参数组可以并行：口型可以和 gaze 并行，呼吸可以和眼睛眨动并行。

### 5.2 参数组边界

第一版至少明确以下参数组：

| 参数组 | 所有者 | 允许叠加 | 终止方式 |
| --- | --- | --- | --- |
| 呼吸 | ambient | 与大多数表现叠加 | 设置关闭、模型卸载 |
| 眨眼 | ambient/eye blink | 与非眼部动作叠加 | 设置关闭、模型卸载 |
| 视线 | attention/gaze | 与口型、呼吸叠加 | 目标离开、语义动作接管、超时 |
| 思考随动 | conversation | 与呼吸、视线叠加 | turn 开始、取消、完成 |
| 口型 | audio/lip sync | 与视线、呼吸叠加 | 音频终止 |
| 语义动作 | Persona/Action | 按动作计划决定 | 计划终态、取消、失败 |
| 待机动作 | idle | 只在无高优先级动作时运行 | 对话、输入、模型切换 |

参数混合器必须识别“参数组没有绑定”和“表现执行失败”两种不同情况。模型不支持某个表现时，应降级为空表现并留下可诊断原因。

### 5.3 动作冲突规则

- 语义动作拥有头部、身体和表情参数时，gaze 只保留未冲突的眼睛贡献，或降低权重。
- 说话期间不启动新的待机动作。
- 思考随动不能覆盖已经开始的语义动作。
- 输入活跃度只能抑制或调整主动表现，不能直接中断用户已经发起的对话。
- 返回电脑事件不能绕过 Policy 直接生成第二条语音回复。
- 取消和断连必须同时终止表现意图、计时器和待机恢复任务。

## 6. 各能力的具体方案

### 6.1 基础生命感：呼吸、眨眼、待机

第一阶段不重写 Cubism 效果，而是做一个“基础表现验收层”：

1. 记录模型加载后呼吸和眨眼是否可用。
2. 记录环境动作开关和当前模型能力。
3. 记录基础表现是否因主动作、参数保护或模型切换被抑制。
4. 给每个模型生成一份能力诊断，而不是只显示“已启用”。

后续再调整：

- 眨眼间隔和随机性
- 说话期间是否允许眨眼
- 呼吸幅度和速度
- 不同模型的呼吸参数映射

这些值应属于模型 Profile 或表现设置，不应散落在渲染器常量中。

### 6.2 注意用户：鼠标凝视和说话前转向

把当前 `useCursorGaze` 改成事件来源，交给表现层处理：

```text
鼠标停留达到阈值
  -> cursor.dwell_started
  -> attention target = cursor/user
  -> 短暂转向
  -> 保持低幅度 gaze

鼠标离开或页面隐藏
  -> cursor.left
  -> gaze 进入释放阶段
```

对话开始时复用同一套注意力目标：

```text
turn.pre_action_ready
  -> target = user
  -> 先执行 200~600ms 的 gaze/head lead
  -> 进入 speaking 或 thinking
```

具体时间先由配置或 Profile 控制，第一版不要固化成单一数值。语义动作开始后由动作仲裁器决定 gaze 是否让出头部参数。

### 6.3 说话、思考和收势

表现层不重新判断 Core 的思考状态，而是消费现有 Turn 生命周期：

```text
turn.started
  -> preparing / thinking

pre_action_ready
  -> gaze lead + 可选短动作

playback.started
  -> speaking

playback.finished
  -> settling

turn.interrupted
  -> interrupted -> settling -> idle
```

当前 `usePetDesktopRuntime` 已经计算 `thinking`、`speaking`、`listening` 和 `idle`，下一步应把这些事实接入统一的表现状态，而不是再创建第二套状态判断。

### 6.4 返回电脑：时长分档

在 `desktop_returned` 事实进入 Core 前，增加归一化字段：

```text
return_basis: unlock | resume | input_resumed
inactive_seconds: number
return_band: short | medium | long | very_long
```

分档只作为事实，不直接决定是否说话。Policy 仍然负责：

- 当前是否适合回应
- 是否应该只做非语言表现
- 是否已有未完成对话
- 是否处于冷却期

表现层可以在已确认的返回事件上执行短暂的 attention/returning 表现，但不能创建绕过 Core 的语音路径。

### 6.5 输入活跃度

在 Electron 主进程新增共享的 `LocalInputActivityAggregator`，与现有 PTT hook 共用一次 uiohook 生命周期。

只产生聚合事实：

```text
input.activity_changed {
  level: active | quiet
  last_input_age_ms: number
  source_mask: keyboard | mouse | both
  expires_at: monotonic timestamp
}
```

默认行为：

- 原始输入不离开 Electron 主进程
- 不记录按键内容和鼠标坐标
- 不写入聊天历史
- 不直接触发聊天
- 默认只用于抑制主动插话和调整待机表现
- 是否启用应有明确的隐私设置

输入活跃度只能作为弱证据，不能命名为“用户正在专注”。产品和日志中使用“最近有输入活动”更准确。

### 6.6 桌面稳定场景

当前桌面观察不支持窗口身份，因此第一版只定义“画面稳定”而不是“同一窗口”：

```text
desktop.scene_stable {
  stable_seconds: number
  scene_revision: string
  confidence: low | medium
}
```

触发条件应至少包含：

- 连续多个采样周期没有超过变化阈值
- 当前没有对话、播放或输入冲突
- 事件仍在 TTL 内
- 本轮稳定事件有冷却和去重

这个事件首先用于本地注意力或低频好奇表现，不直接让角色开口。只有经过 Policy 评估后，才允许转成主动对话事实。

如果未来需要真正识别窗口，应另行设计受控的窗口元数据权限，不能把截图内容解析偷偷扩展成窗口观察。

## 7. 状态归约与生命周期

### 7.1 单一所有者

建议新增一个 `PresenceStateStore` 或同等职责的状态对象，由桌面运行时创建并在卸载时销毁。以下组件只能发送事件，不能直接互相修改状态：

- `useCursorGaze`
- PTT/uiohook bridge
- desktop presence/observation bridge
- Turn playback observer
- ModelEngine

### 7.2 事件生命周期

每个事件必须有：

```text
event_id
source
created_at_monotonic
expires_at_monotonic
coalesce_key
cancel_scope
```

单调时钟时间戳只在产生它的运行时内用于计算期限；不得把某一进程的 `performance.now()` 绝对值直接当作另一进程可解释的时间。跨 IPC 或 Adapter 桥接时传递经校验的剩余 TTL/期限语义，由接收方建立本地截止时间。

状态归约器必须处理：

- 重复事件
- 迟到事件
- 事件过期
- 模型切换
- 连接断开
- 用户新输入撤销旧表现
- 对话中断后的收势

### 7.3 输出生命周期

每个表现意图也必须有明确终态：

```text
created
  -> admitted
  -> running
  -> completed | cancelled | suppressed | failed
```

“没有动作”不能同时表示“未启用、模型不支持、被优先级压制和执行失败”。这些原因必须分开记录。

## 8. 观测与未来训练数据

第一阶段只记录高层生命周期事件，建议使用新的本地事件类型：

```text
presence.presentation_event.v1
```

记录：

- 触发来源
- 状态转换前后
- 注意力目标
- 表现意图类型
- 是否被抑制
- 抑制或失败原因
- 持续时间
- 模型 Profile 身份

不记录：

- 原始截图
- 原始键盘事件
- 鼠标轨迹
- 未经处理的桌面内容

如果事件同时提交给 AG99 Observation，训练记录必须区分：

- `local_presentation_event`：AG99live 本地表现事实和终态
- `ag99_observation_event`：提交给 AG99 的授权场景事实
- `persona_output_event`：AG99 最终形成的语义输出及其 Persona 段动作

三者不能因为时间接近就合并成一个“角色反应样本”。Policy 拒绝、延后或取消时，也必须保留事实和决策结果之间的关系。

后续训练不直接让小模型生成 Live2D 参数。更稳妥的两级结构是：

```text
小模型：事实 + 对话上下文 -> 高层表现意图
确定性编译器：表现意图 + 模型 Profile -> 参数计划
```

例如小模型输出：

```json
{
  "attention": "user",
  "expression": "curious",
  "gaze_strength": 0.35,
  "duration_ms": 900,
  "suppress_speech": true
}
```

参数范围、模型轴映射、冲突处理和时序仍由现有编译器负责。这样训练数据的标签更稳定，也不会把某个模型的底层参数绑定到另一个模型。

## 9. 分阶段实施

### 阶段 0：基础表现验收

不新增行为，只确认：

### 阶段 1：统一 PresenceStateStore

接入现有连接、Turn、播放、麦克风、cursor gaze 和模型状态。先固定 renderer 状态所有权、main 到 renderer 的高层事件边界，以及 AG99 Observation/正式内部感知接口的桥接职责；只输出状态快照和诊断，不改变表现策略、不触发新的语义请求。

2026-10-28 实施进度：AG99live 本地诊断切片已接入 Adapter 连接/麦克风/音频状态、Turn Playback 会话阶段、pre-action 接纳结果、cursor gaze 激活状态、模型选择和 Live2D renderer 生命周期。pre-action 取消按 Turn/requestId 关联，并通过单调 revision 拒绝过期清理；ModelEngine 也只屏蔽被取消的 requestId。状态归约器只保留高层状态、版本和单调时钟，不保留对话文本、模型 URL、光标坐标或动作 payload；状态变更日志同样只输出这些脱敏字段。Renderer 仍由 `useLive2dRenderer` 持有事实状态，其他模块只上报。

2026-10-29 生命周期补充：ModelEngine 的预动作终态现在按返回的 Turn/requestId 清除 Presence 准备状态；模型或语义 Profile 切换在取消预动作后也清除当前准备状态。迟到的旧请求终态仍受身份匹配保护，不会清掉更新请求。Renderer 类型检查和 diff whitespace 检查通过；未运行测试或真实桌宠验收。

本次未注册 AG99 `RuntimeObservationSensorHandle`，也未实现 main 到 renderer 的语义事件桥接；当前仓库缺少可核对的 AG99 运行时接口和配对验收环境。阶段 1 整体仍未完成，等待真实桌宠运行检查，以及 AG99 正式感知接口/状态所有权确认。

整体完成标准：所有来源只发事件，状态只有一个所有者；本地表现和 AG99 语义表达有独立终态；重复、迟到、过期、取消、模型切换和断连都有确定结果；idle、preparing、thinking、speaking、settling、interrupted 的诊断快照能由现有生命周期事实解释。当前切片已在源码中处理模型切换和过期终态，但模型切换、异步迟到事件、断连恢复及 AG99 桥接仍需真实运行验收。

### 阶段 2：注意力与对话表现

先做一个窄的端到端表现切片：`turn.started -> pre_action_ready -> playback.started -> playback.finished -> settling`，并覆盖打断、断连和模型切换。基于该切片逐步实现：

- 说话前 gaze/head lead
- 说话时用户视线保持
- 思考随动与语义动作仲裁
- 播放结束后的 settling
- 鼠标凝视接入统一仲裁器

完成标准：不新增 Provider 调用；语义动作对冲突参数仍有优先权；对话开始、播放、打断、完成和断连都能恢复到稳定状态。进入本阶段前，先完成 Persona 生命周期计划中与这些事件重叠的目标环境验收；其余 Motion Lab 导出验收可按原计划继续，不在表现层复制生命周期状态。

## 10. 验收指标

### 连续存在感

- 无对话时模型不会长时间完全静止
- 呼吸和眨眼不会因普通动作导致永久失效
- 待机动作不会与对话播放抢占参数

### 注意力

- 用户停留、输入和返回事件能触发合时的注意表现
- 不因单次鼠标移动或单个键盘事件产生明显跳变
- 语义动作优先级高于普通 gaze

### 生命周期

- 新输入可以取消尚未开始的注意表现
- 播放中断后在有限时间内收势
- 模型切换、断连和重连不会遗留旧状态
- 每个表现意图都有 completed、cancelled、suppressed 或 failed 终态

### 数据质量

- 事件身份稳定且可去重
- 不包含原始键盘、鼠标和截图内容
- 失败与抑制原因可以区分
- 同一个表现事件不被重复记录
- 本地表现完成与 AG99 语义表达的接受、拒绝、延后或取消可分别追踪

阶段 0 先记录当前基线，再为阶段 2 的验收确定可测量口径，包括误触发、表现冲突、打断后的恢复和终态缺失。没有基线前不预设看似精确的阈值。

## 11. 推荐的第一步

首批只实施阶段 0 和阶段 1，不要立即加入截图稳定事件、输入活跃度行为或小模型：

1. 确认 Motion Lab schema v3 已在目标 AstrBot 实例加载，并用正常对话积累当前行为基线。
2. 现场确认呼吸、眨眼、待机、模型切换和参数混合行为，形成模型能力诊断记录。
3. 盘点现有 `aiState`、Turn lifecycle、Playback lifecycle、模型状态和 cursor gaze 的真实所有者与事件来源。
4. 阅读 AG99 正式内部感知/Observation 接口文档，明确语义事实的授权、取消和决策结果边界；不接 NeuroBrain 测试功能。
5. 对齐 Persona 生命周期计划阶段 6 中与 Turn、Playback、打断、完成和断连重叠的目标环境验收。
6. 固定 main 聚合、preload 传递、renderer 唯一状态归约、Adapter 桥接和 AG99 策略的职责后，实现只输出诊断快照的 `PresenceStateStore`。
7. 用可重放的事件序列和真实运行日志验证 idle、preparing、thinking、speaking、settling、interrupted 六种状态；通过后再启动说话前 gaze lead。

第一阶段完成前，不增加新的主动聊天触发，不增加 Provider，不改公共协议。
