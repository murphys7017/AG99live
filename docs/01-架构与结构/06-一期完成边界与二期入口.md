## 1. 一期状态

**一期代码范围已经完成。**

这里的“完成”表示一期功能范围已经具备明确协议、模块所有权和可运行实现，不表示当前源码没有缺陷。
人工体验调校、真实设备观察和运行验收属于使用与调优过程；源码复核确认的故障则进入独立活动缺陷清单，
在修复前不能用一期完成状态替代风险说明。

## 2. 一期包含的能力

- AstrBot 对话、主模型回复、TTS 和 Persona Effect 接入。
- 主模型在同一次回复中生成 assistant text 与 `ag99live.motion`；官方 AstrBot 环境使用 `<@anim>` 传输同一份 V4 动作意图。
- `output.segment.v4` 原子输出段，以及 `turn_id + message_id + tts_request_id` 身份边界。
- SessionStore 与 PlaybackTimeline 分离协议事实和实时播放生命周期。
- `engine.motion_intent.v4` 到 `CompiledSemanticMotion`，再到 `engine.parameter_plan.v3` 的两阶段动作编译。
- 九级语义动作、确定性区间采样、语义轴关系图、模型参数绑定和显式响应策略。
- ParameterPresentation、ActiveParameterMixer、口型、说话随动和 Cubism Physics 的逐帧执行边界。
- Profile Editor、Motion Lab、动作历史、系统设置和模型扫描。
- 文字、麦克风和 B 站直播弹幕输入，以及当前保留的可选远程操作委托。

## 3. 一期固定边界

- AstrBot 拥有对话、事件队列、主模型调用和 TTS；AG99live 不重复实现这些能力。
- Adapter 只负责 Prompt 能力投影、动作协议校验、身份关联和原子输出段交接，不生成 Live2D 最终参数。
- ModelEngine 负责语义动作编译和模型参数计划，不从文本重新决定主动作方向。
- PlaybackTimeline 是字幕、音频、动作和口型的统一播放时钟。
- ActiveParameterMixer 位于 AG99 Live2D 运行时层，收集各模块生成的原始主动参数贡献，合成最终目标并调用
  ParameterPresentation 一次完成非口型响应；它不成为第二套动作规划器，也不属于 Performance Director。
- AG99 Live2D 运行时负责最终主动参数帧、口型信号、向 Cubism Model 的唯一主动参数写入和执行层生命周期；官方 Cubism `Framework` / `Core` 负责底层模型能力、Physics、Pose、模型更新和渲染。
- 非法动作、身份冲突、时钟缺失或参数绑定失败必须显式失败，不使用默认动作或兼容路径掩盖问题。
- optional performance curve 可以失败、超时或被跳过，不能阻塞 TTS、segment 出站或基础动作播放。

## 4. 二期入口与当前进度

二期的总体方向是把一期已经打通的动作链路升级为**角色表演系统**：不再围绕单个动作轴做零散优化，
而是由 ModelEngine 内的 Performance Director 统一编排一段回复的准备、起势、语义动作、停顿、
强调、收势和残留，再沿现有参数时间轨道、ParameterPresentation、ActiveParameterMixer 和
Cubism Physics 链路执行。

Performance Director 是现有 ModelEngine 编译职责的收口，不是第二套播放器、Timeline、
参数融合器或后端动作服务。二期总体规划见
[二期角色表演系统总体规划](../02-设计文档/18-二期角色表演系统总体规划.md)。

### 4.1 阶段 A：统一表演编排输入与输出（已完成）

阶段 A 已经把原本分散在 SpeechPose、sequence compiler 和参数轨道中的时间计算收口到同一份
ModelEngine 内部 `PerformanceSchedule`：

1. 统一 canonical text 的 phrase 分段、标点边界、权重、强调和归一化时间窗口。
2. 根据 sequence 的 `duration_weight` 生成 semantic step 时间窗口，并记录 phrase 与 step 的
   `estimated alignment`；V4 当前没有 phrase identity，因此不伪造精确文本绑定。
3. 统一 semantic-group transition、hold、residual、SpeechPose 和参数节点来源诊断。
4. 删除迁移后仍在原阶段重复计算 phrase、step 或部位时间的旧实现。

阶段 A 不改变 `engine.motion_intent.v4`、`engine.parameter_plan.v3`、PlaybackTimeline、
ParameterPresentation、ActiveParameterMixer、SpeechSignalRuntime、官方 Cubism Physics 或
AG99 Live2D Runtime 的外部边界。

### 4.2 阶段 B：部位级表演策略（源码收口完成，进入运行验收与深化）

gaze、face 生命周期、hesitation 编排和 dynamic residual 已经完成，并消费阶段 A 的同一份 Schedule 和参数轨道投影入口。
主动动力学的部位响应策略收口（B6-1）、语音随动可见性与部位协作（B7-1/B7-2）、以及
audio-backed segment 的 Direct Plan 原子接管（B7-3）已经完成；跨 Turn 动作多样性摘要也已接入现有 Prompt 上下文。
当前优先进行这些能力的真实表现调校，再进入阶段 C 的评价入口建设，具体已有基础、剩余边界和实施顺序只在
[二期角色表演系统总体规划](../02-设计文档/18-二期角色表演系统总体规划.md) 维护。

### 4.4 当前参数融合架构决策

当前采用“编排与逐帧融合分离”的结构：

1. `Performance Director` 只在 ModelEngine 编译期组织 phrase、sequence step、部位事件、起势、保持、释放和 residual，输出参数轨道或 `engine.parameter_plan.v3`。
2. `SpeechSignalRuntime` 提供口型和说话随动的实时信号；direct plan 轨道和 speech gesture 作为原始目标进入 Mixer，不预先经过表现层。
3. AG99 运行时中的 `ActiveParameterMixer` 以当前 Cubism base snapshot 为基准，统一融合 direct plan（含 SpeechPose modulation）与口型，合成最终目标，再让 `ParameterPresentation` 对非口型目标执行一次响应，最后输出唯一 `ResolvedParameterFrame`。
4. 官方 Cubism `Framework` / `Core` 不参与语义编排、参数混合或表现倍率策略，只接收最终主动参数并完成原生 Physics 与绘制；Physics 输出倍率由 AG99 `LAppModel` 在解算后按终端输出增量统一应用。

因此，参数混合保留在 AG99 的运行时适配层是当前的最小且清晰方案；不再让 Performance Director 增加第二套融合器，也不再向官方 Cubism 源码添加业务逻辑。

### 4.5 当前问题分类与处理状态

- **主链路运行时缺陷**：当前没有已确认且尚未修复的问题。Adapter、协议、SessionStore、PlaybackTimeline、ModelEngine、AG99 Runtime 和 Cubism 执行链路已完成源码复核；真实 AstrBot、Electron、TTS 和 Live2D 验收仍由实际运行承担。
- **架构债务**：`frontend/src/live2d/WebSDK/src/` 与官方 `Framework/Core` 历史上共处同一目录。后端输出聚合、观察记录和可选曲线生命周期已从 `TurnCoordinator` 移到独立协调器；剩余目录共处属于结构整理议题，不作为当前运行时缺陷处理，也不为了目录整洁强行重写 WebSDK。
- **表演质量问题**：dynamic residual 已在 B4 收口，audio-backed segment 的跨段 Direct Plan 接管已在 B7-3 收口；语音能量调制质量、主动动力学、跨 Turn 连续性和动作多样性仍属于二期优化，不应通过修改协议、Timeline 或新增第二套控制器解决。音频能量源已经与模型 LipSync 参数能力解耦，嘴部不可用不再终止头身说话随动。
- **模型级 Physics 问题**：setting 级输入、粒子链、输出、速度和衰减诊断尚未完成，属于 Physics 调校路线，不属于 Performance Director 或 ParameterMixer 的职责。
- **精确文本对应**：当前 V4 没有 phrase identity，sequence 与文本只能保持 estimated alignment；只有真实数据证明近似关系不足时，才评估扩展协议。

- 新功能是否属于一期，只能通过修改本文重新定义，不能在专项文档中隐式改写。
